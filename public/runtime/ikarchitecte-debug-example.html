🏛️ IK Architecte - Debug Integration Example

This guide shows how to integrate the Spacetime Debug API into the IK Architecte website to debug the hero letter animations, scroll effects, and project card interactions.

Note: This is a reference implementation. The actual ikarchitecte site may have different structure. Adapt as needed.

Step 1: Add Debug Scripts to HTML

1 Modify ikarchitecte/index.html 
<!-- Existing runtime loading (around line 292) -->
<script src="/__spacetime/runtime.js"></script>

<!-- Add Debug API (localhost only) -->
<script>
  // Auto-load debug on localhost or with ?debug parameter
  if (window.location.hostname === 'localhost' ||
      window.location.search.includes('debug')) {

    const loadScript = (src) => {
      return new Promise((resolve, reject) => {
        const script = document.createElement('script');
        script.src = src;
        script.onload = resolve;
        script.onerror = reject;
        document.head.appendChild(script);
      });
    };

    Promise.all([
      loadScript('/__spacetime/debug.js'),
      loadScript('/__spacetime/debug-overlay.js')
    ]).then(() => {
      console.log('%c🎬 Spacetime Debug Mode Enabled',
        'font-size: 16px; color: #667eea; font-weight: bold;');
      console.log('Try: ST.debug.enable()');
    });
  }
</script>

Step 2: Debug Hero Letter Animations

2 Inspect the staggered letter reveal

The IK Architecte hero section has individual letters that animate in with a stagger effect. Debug them:

// Enable debugging
ST.debug.enable()

// List all timelines
ST.debug.listTimelines()
// Look for timeline named something like 'hero-letter-reveal'

// Show overlay on all letters
ST.debug.showOverlay('.ik-hero__letter')

// Inspect the hero timeline
ST.debug.inspectTimeline('hero-letter-reveal')

// Monitor the load driver
ST.debug.logDrivers((el, info) => {
  return info.type === 'load' &&
         el.classList.contains('ik-hero__letter')
})
Expected Output: You should see 12 overlays (one per letter in "Inès Kettani") showing their individual animation progress.

Step 3: Debug Scroll Animations

3 Monitor scroll-driven project reveals

Projects fade in as you scroll. Debug the scroll driver:

// Log only scroll drivers
ST.debug.logDrivers((el, info) => info.type === 'scroll')

// Show overlay on project cards
ST.debug.showOverlay('.ik-project')

// Get snapshot before scrolling
const before = ST.debug.snapshot()

// Scroll down, watch console for progress updates
// [ST:scroll-driver] .ik-project $progress = 0.234 (Δ 0.012)
// [ST:scroll-driver] .ik-project $progress = 0.567 (Δ 0.333)

// Get snapshot after scrolling
const after = ST.debug.snapshot()

// Compare
console.log('Active elements:', before.activeElements, '->', after.activeElements)

Step 4: Debug Hover Effects

4 Inspect project card hover animations 
// Monitor hover drivers
ST.debug.logDrivers((el, info) => {
  return info.type === 'hover' &&
         el.matches('.ik-project, [slot="cta"]')
})

// Show overlays on interactive elements
ST.debug.showOverlay('.ik-project')
ST.debug.showOverlay('[slot="cta"]')

// Hover over cards and watch console:
// [ST:hover-driver] .ik-project $progress = 0.123 (Δ 0.123)
// [ST:hover-driver] .ik-project $progress = 0.456 (Δ 0.333)

Step 5: Performance Analysis

5 Check animation performance 
// Get complete state snapshot
const state = ST.debug.snapshot()

console.log('Performance Overview:')
console.log('- Total Timelines:', state.timelineCount)
console.log('- Active Elements:', state.activeElements)
console.log('- Timestamp:', state.timestamp)

// Find elements with scroll drivers
const scrollElements = state.elements.filter(el =>
  el.driver?.type === 'scroll'
)
console.log('- Scroll-driven elements:', scrollElements.length)

// Export to JSON for analysis
localStorage.setItem('ik-debug', JSON.stringify(state, null, 2))

Step 6: Timeline Inspection

6 Deep dive into specific animations 
// List all timelines with details
const timelines = ST.debug.listTimelines()

// Inspect hero reveal
const hero = ST.debug.inspectTimeline('hero-letter-reveal')
console.log('Hero Timeline:', hero)
console.log('- Driver:', hero.driver)
console.log('- Elements:', hero.elements.length)
console.log('- First letter progress:', hero.elements[0]?.driver?.progress)

// Inspect nav scroll
const nav = ST.debug.inspectTimeline('nav-scroll')
if (nav) {
  console.log('Nav Timeline:', nav)
  console.log('- Current state:', nav.elements[0]?.animation)
}

Common Debug Scenarios

Scenario 1: Hero Letters Not Animating

// Check if timeline is registered
ST.debug.listTimelines()
// If 'hero-letter-reveal' missing, timeline not created

// Check if elements exist
document.querySelectorAll('.ik-hero__letter').length
// Should return 12 (for "Inès Kettani")

// Check driver status
const firstLetter = document.querySelector('.ik-hero__letter')
const driverInfo = ST.debug.getDriverInfo(firstLetter)
console.log('Driver:', driverInfo)
// Should show: { type: 'load', progress: 0-1, ... }

Scenario 2: Scroll Animation Stuttering

// Monitor scroll driver updates
let updateCount = 0
const startTime = Date.now()

ST.debug.logDrivers((el, info) => {
  if (info.type === 'scroll') {
    updateCount++
    return true
  }
  return false
})

// Scroll for 5 seconds
setTimeout(() => {
  const elapsed = (Date.now() - startTime) / 1000
  const fps = updateCount / elapsed
  console.log(`Scroll updates: ${updateCount}`)
  console.log(`Average FPS: ${fps.toFixed(2)}`)
  // Should be ~60 FPS for smooth scrolling
}, 5000)

Scenario 3: Hover Not Reversing

// Check hover driver config
const card = document.querySelector('.ik-project')
const driverInfo = ST.debug.getDriverInfo(card)

console.log('Hover config:', driverInfo?.config)
// Should show: { trigger: 'hover', duration: 300, reverse: true }

// Monitor hover enter/leave
ST.debug.logDrivers((el) => el.matches('.ik-project'))

// Mouse enter -> progress should go 0 to 1
// Mouse leave -> progress should go 1 to 0

Production Deployment

Warning: Remember to disable debug in production builds!

The conditional loading above ensures debug scripts only load on localhost or with ?debug parameter. For production:

// Build script should strip debug code:
// 1. Don't include debug.js and debug-overlay.js in production bundle
// 2. Use webpack/rollup to replace ST._debugInternal with undefined
// 3. Tree-shaking will remove all debug hooks

// webpack.config.js
new webpack.DefinePlugin({
  'ST._debugInternal': 'undefined'
})

Show All Overlays

List Timelines
javascript:(function(){ST.debug.enable();ST.debug.listTimelines();})();

Console Shortcuts

Save these in your browser console snippets:

// Quick enable
const d = () => ST.debug.enable()

// Quick timeline list
const t = () => ST.debug.listTimelines()

// Quick overlay on selection
const o = (sel) => ST.debug.showOverlay(sel)

// Usage:
d()           // enable
t()           // list timelines
o('.hero')    // show overlay
