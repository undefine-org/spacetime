* 3d module current surface (stdlib/3d)
Macros: @stage @object @light @orbit @parallax @scroll-3d @env @post @gltf @particles
- @object shapes: icosahedron sphere box torus torusknot cone cylinder plane
- materials: standard physical glass basic (PBR + transmission/iridescence)

* Gaps vs. what EverSwap needs (→ module work)
1. *Textured plane layers* (painterly art on geometry) — no texture/map param on @object today.
2. *Parallax depth layers* driven by scroll (the SC_02_P1..P6 stack).
3. *Multi-keyframe camera path* along scroll (hero→over-summit→aerial→lake), not single dollyZ.
4. *Text-to-3D as a textured/extruded mesh* + *ripple/displacement shader* (the wordmark effect).
5. *Animated flow shader* (the glowing river: scrolling UV / additive trail).
6. *Sky gradient + fog* environment, animated clouds, sprite birds.
7. *DOM text-reveal motion language* (blur+stagger, char/word/line split) — pairs with stdlib/text.
8. Coordinated *scroll timeline* with named keyframes shared across many targets (vs one drive).

* Ripple-on-text — feasibility (answer to user Q)
YES, three.js does this easily; two implementation tiers:
- A. *Mesh + vertex displacement*: render text to a CanvasTexture (or use TextGeometry
  via 3d↔text dependency), map onto a subdivided PlaneGeometry, displace vertices in a
  vertex shader by sin(x*freq + t*speed) → travelling ripple. Cheapest, crisp.
- B. *Post/displacement on a layer*: feDisplacement-style — sample a noise/normal map,
  offset UVs in fragment shader (the "heat-haze / water" look). Matches EverSwap's subtle wobble.
- Interface fits existing grammar: a new @text3d macro (depends on stdlib/text for glyph
  geometry/atlas) + a @ripple child directive (amplitude, frequency, speed, axis).
  Lives as a primitive shader behind the macro (vendoring discipline: shader is the escape
  hatch, surfaced as data params — not author-written GLSL).
