* TL;DR
A `@template` body is captured by the Rust-builtin `CaptureType::ComponentBody`, parsed by a
~1100-line hand-written Rust function `parse_component_body` (src/syntax/events/form_compiler.rs)
that hand-codes the grammar of EVERY template-body construct (state decls, injections, class
toggles, @on directives, &refs, @match, HTML). This is the CENTRAL violation of Spacetime's
self-describing-metasystem principle (AGENTS.md: "DO NOT write Rust parsers/fallbacks for
constructs defined in stdlib"; metasystem/ARCHITECTURE.md: "adding a @directive = define
primitive/macro/capture_type in .st, NO Rust changes"). Phase B replaces `parse_component_body`
with stdlib `%capture_type` grammar + a generic reifier + html5ever for the HTML parts, so the
template-body grammar lives in `.st` and NO construct is named in Rust. This is the TRUE full
cutover (the user's standing directive: maximal convergence, zero deprecated paths).

* WHY THIS MATTERS (the principle)
Spacetime's design: Rust is a GENERIC engine (Resolve -> Sort -> Expand -> Emit) + a small set
of structural builtin capture types. EVERY user-facing construct is defined in `.st` via
`%macro` (grammar via `%form`) + `%capture_type` (sub-grammar) + `%primitive` (`%emit js` =
the actual logic). Proof: `@if`/`@else`/`@each`/`@for` are ALL pure `.st` (stdlib/macros/each.st).
The Rust engine should NEVER know what "@match" or "$state" is. Today `parse_component_body`
breaks this for the entire template-body surface.

** The generic %capture_type engine (what hosts the grammar) \u2014 PROVEN VIABLE
- `%capture_type` AST = `CapturePatternAst` (src/parser/meta_ast.rs:~918): a PEG/combinator \u2014
  Capture{var,type,modifier}, Literal, CharClass, Group(*+?), Sequence, Choice(|).
- COMPILED to `Box<dyn CaptureExtractor>` over TOKEN slices by `compile_pattern_with_defs`
  (src/syntax/events/extractors/custom.rs:30, pub). Nested type refs resolve via
  `compile_custom_ref`. CYCLE-GUARDED: a directly self-referential type compiles its recursive
  position as `Expr` (custom.rs:~120) \u2014 NOT true recursion. (component_body is FLAT:
  ( item )*, NESTING is runtime template-ref recursion, so the guard is never hit.)
- REIFIERS (`wrap_reifier`, custom.rs:~149): map the generic parse record (Named / Array<Named>)
  into a domain-typed CapturedValue. ONE reify_* fn per reifying type. THE BRIDGE: grammar in
  .st, a thin generic reifier in Rust maps record -> typed struct.
- PROVEN (this session's spikes, recorded in @research/phase-b-o2-full-convergence.org):
  - A full construct-segment body (`$count number:0; .c:$count; text<-$count;`) parses via a
    composed cb_state|cb_inject|cb_toggle grammar into a discriminated Array record, ALL tokens
    consumed. Choice branch NAME = the discriminator the reifier dispatches on.
  - @match already parses via stdlib match_block grammar (stdlib/capture-types/match-block.st)
    \u2014 but its REIFIER (parse_match_block_via_engine) is still Rust special-case (BUG-060).
- ENGINE GAP found + FIXED (B-Wave 1, committed): multi-token literals (`=>` lexes as EQUALS+GT,
  `@match` as AT_SIGN+IDENT) \u2014 LiteralExtractor now matches across contiguous tokens. AUTHORING
  RULE: use BOUNDED leaf types before a literal (binding/string, not greedy `expr`, which has a
  fixed boundary set and swallows `{`/`=>`).

* DESIGN (the target architecture)
#+begin_example
@template &name($p) { BODY }
        │  CaptureType::Custom("component_body")   (was ::ComponentBody)
        ▼
   stdlib %capture_type component_body  { ( $items:component_item )* }
        │  generic engine (compile_pattern_with_defs over STDLIB_REGISTRY)
        ▼  Array<Named{ <branch> : record }>  (branch name = construct kind)
   reify_component_body  (ONE generic reifier in wrap_reifier, NOT per-construct)
        │   - html-run records  -> component_html_to_exprs/parse_html_skeleton (html5ever)
        │   - construct records -> ComponentBodyDef.{states,directives,injections,refs,matches,...}
        ▼
   CapturedValue::ComponentBody(ComponentBodyDef)   ← UNCHANGED IR; ~9 consumers untouched
#+end_example
- The BUG-059 `segment_component_body` scanner STAYS (generic infra: splits HTML-run vs
  construct-seg). It feeds: HTML-runs -> html5ever, construct-segs -> the engine.
- The stdlib grammar (NEW file stdlib/capture-types/component-body.st):
  %capture_type component_body { ( $items:component_item )* }
  %capture_type component_item {
      ( $state:cb_state ) | ( $exports:cb_exports ) | ( $inject:cb_inject )
    | ( $toggle:cb_toggle ) | ( $on:cb_on ) | ( $ref:template_invocation )
    | ( $sref:cb_selector_ref ) | ( $match:match_block ) | ( $html:cb_html_run ) }
  + leaf grammars cb_state/cb_inject/cb_toggle/cb_on/cb_exports/cb_selector_ref (match the EXACT
  forms parse_component_body accepts \u2014 see "construct forms" below). match_block already exists.
- `reify_component_body`: walks the Array, dispatches each item by its single map key (the Choice
  branch), and fills the corresponding ComponentBodyDef vec. The @match arm folds in here \u2014
  RETIRING parse_match_block_via_engine + the Rust @match branch (closes BUG-060). The reifier
  is GENERIC (dispatches on branch name); it does NOT hardcode construct STRINGS in match arms
  beyond mapping a branch label to a field \u2014 acceptable if the labels come from the grammar, but
  the BUG-060 gate is: no "@match"/"match_block"/ComponentMatch-as-special-case logic.

** Construct forms parse_component_body currently accepts (the grammar must match EXACTLY)
From form_compiler.rs:2190+ classification (verify against the code):
- state decl:   `$name type: value;`            (is_state_declaration; `${...}` is interp, not decl)
- exports:      `@exports { $x, $y: mut }`
- self-prop:    `&self.prop <- $expr;`
- injection:    `text <- $x;` · `[slot="v"] <- $x;` · `[attr="v"] <- $x;` (Selector, BUG-061) ·
                `src <- $x;` (own attr) · with `| filter`
- class toggle: `.cls: $sig;`
- css/behavior: `.sel { ... }` / `[attr] { ... }` / `#id { ... }` \u2014 inner: @on / .cls:$ /
                &self.prop<- / prop:$expr (content binding). Mixed @on + siblings (R-wave P1).
- root directive: `@on ... { ... }` (and other `@name` directives)
- selector ref: `&name .sel { }` / `&name[] .sel { @each }` (E0920/E0921)
- template ref: `&name(args)` / `&$dyn(args)` (dynamic dispatch) / `&name &tmpl(args)`
- @match:       `@match $subj { "p" => &t(args); _ => &t(args); }`  (already stdlib grammar)
- html runs:    everything else (-> html5ever)
- diagnostics:  E0900 (unrecognized), E0920/E0921 (selector-ref/@each mismatch), E0922
                (malformed @match), section_transitions (W0700 interleave). These must be
                PRESERVED \u2014 either expressible in the grammar/reifier or as a post-parse
                validation over ComponentBodyDef.
