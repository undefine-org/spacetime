** The reactive-hole pipeline (what everything converges onto)
=HtmlBlockAst{skeleton, holes}= (parser/ast.rs) -> =treesink::parse_html_skeleton= ->
=Vec<HtmlExpr>= -> =emit::html::emit_all= -> reactive DOM. =HtmlExpr= (ir/code.rs:299):

=AttrPart::{Lit, Hole}= for attr-position holes. Holes carry =JsExpr::Raw(source)= in W1; the
emit phase rewrites them into signal-aware accessors. Sentinels =HOLE_OPEN/CLOSE=
(=\u{E000}/\u{E001}=) mark hole positions in the skeleton (never occur in real markup).

** Interpolation authoring: bare $x vs backtick (the convergence decision)
Backticks =`$expr`= exist to hold ARBITRARY expressions (=`$cart.total | currency`=), parsed
as a full Spacetime expression. Bare =$x= is the legacy template-only shorthand. 96 @templates,
~136 files use bare =$x=. DECISION (clean cutover + minimal authoring churn): the unified
skeletonizer AUTO-NORMALIZES bare =$x=/=$x.path= in HTML text+attr position into holes
(=`$x`=), so existing authoring stays valid AND lowers to the reactive model. Backticks remain
for arbitrary expressions. ONE model (holes); =$x= is sugar the skeletonizer desugars. The
legacy factory regex path is DELETED, not kept as fallback.

* CRITICAL FINDING (2026-06-07) — the reactive-hole renderer does NOT exist yet

Verified from emit/html.rs + PLAN-023 status:
- The file-scope HtmlExpr path is SSG-ONLY. emit_hole emits a STATIC placeholder
  `<!--st-hole:src-->` (html.rs:31); the "reactive emit phase (PLAN-023 W3/W4)" that would
  turn a Hole into a hydrated reactive accessor is EXPLICITLY a TODO (html.rs:29-30) and
  PLAN-023 W4 is BLOCKED/incomplete ("per-item render runtime... NOT an independent slice";
  "reactive HtmlExpr runtime" unbuilt).
- The ONLY working REACTIVE template renderer today is the factory in template.st (the regex
  string-interpolation path) — the very thing O2 proposed to delete.

** Implication
"Converge component templates onto the file-scope reactive-hole model" is converging onto a
model that is NOT reactive yet. Naively doing so REGRESSES every @template from working-
reactive (factory) to static (SSG holes). That violates the goal.

* B-WAVE 3 SPIKE (2026-06-08) — full component-body grammar via engine: VIABLE

Proved the generic %capture_type engine parses a FULL construct-segment body. Grammar:
  %capture_type cb_state  { "$" $name:ident $ty:ident ":" $init:expr ";" }
  %capture_type cb_inject { $target:ident "<-" $val:expr ";" }
  %capture_type cb_toggle { "." $cls:ident ":" $sig:binding ";" }
  %capture_type cb_item   { (cb_state) | (cb_inject) | (cb_toggle) }
  %capture_type cb_body   { ( $items:cb_item )* }
Input `$count number: 0; .c: $count; text <- $count;` -> Array[{state},{toggle},{inject}],
ALL 24 tokens consumed. Choice branch name = discriminator (reifier dispatches on it).
