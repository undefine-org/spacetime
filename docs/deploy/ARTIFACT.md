# The Deploy Artifact (`SiteArtifact`)

**Status**: ratified design (July 2026) · implementation sequenced separately
**Audience**: anyone touching `spacetime build`, `spacetime serve`, or deploy tooling

## Why this exists

There used to be no canonical "deployable thing". `spacetime build` wrote
`dist/` as a side-effect, and anything that wanted to ship a site walked
*a directory* — which is how a deploy once packaged a project's **source
folder** (`.st` files, notes, everything) instead of the build output.
No single step was wrong; the missing abstraction made the failure
inevitable.

`SiteArtifact` is that abstraction. It is the **only** serializable,
shippable representation of a site.

## The one rule

```
build_artifact(site_dir) -> SiteArtifact
```

**One generation path.** The `build` CLI command, `serve --built`, and
any deploy/packaging code all call the same function. `dist/` is a
*rendered view* of the artifact for local inspection — never a source of
truth, never read back as deploy input.

Because deploy code can only serialize an artifact (never a directory),
the entire bug class of "wrong directory / leaked source files" is dead
by construction — not by filter rules that can drift.

## Definition

```
SiteArtifact {
  manifest: Manifest,        // canonical JSON (sorted keys)
  files:    [File],          // path -> bytes, sorted by path
}

Manifest {
  artifact_hash: blake3,     // over the canonical form (below)
  compiler:      "spacetime x.y.z",
  files: [{ path, size, b3, chunks? }],
  site:  {
    deploy:  { ... },        // the @deploy{} fact, verbatim
    locales: [ "en", "fr" ],
  },
}
```

**ONE manifest, generated by spacetime itself.** It carries both
content-addressed file entries and the site metadata consumers need
(the `@deploy{}` fact, locales, compiler version). A second manifest
anywhere else would be parallel-implementation rot.

**Everything is a blob.** A file ≤ 4 MB is one blob (its blake3). A
larger file is content-defined-chunked (fastcdc, ~1 MB average chunks)
and its `b3` is computed over the concatenated chunk hashes
(domain-separated), so chunk-level dedup composes with file-level
identity. Whole file or chunk — one store, one verification path.

The domain separation is ONE pinned construction (ratified 2026-07-20,
first implemented in `spacetime-host-core::deploy` — both sides MUST
match byte-for-byte):

```
file.b3 = blake3::keyed_hash(
              blake3::derive_key("spacetime-host/v2/file-chunks", b""),
              concat(chunk.b3 as raw 32-byte hash, in manifest order))
```

Not the hex strings — the raw 32 bytes of each chunk hash. The context
string `"spacetime-host/v2/file-chunks"` is the entire domain separation;
never version it in place — bump the `/v2/` segment instead.

## Determinism (what makes the hash meaningful)

Same source MUST produce byte-identical output on any machine:

- sorted file walk (lexicographic, NFC-normalized paths)
- zeroed timestamps/uid/gid in any archive metadata
- an emit audit: no wall-clock timestamps or random ids in generated
  HTML/JS/CSS (existing ones get fixed or explicitly seeded)

The determinism test is trivial and load-bearing: build twice, assert
byte-equal artifacts. It runs in CI forever.

## Fingerprint (skip no-op rebuilds)

`fingerprint(site_dir)` = blake3 over sorted `{path, content-hash}` of
the source tree (content hashes, **not** mtimes — mtimes lie). A
consumer (watch mode, deploy push) compares the fingerprint against the
last build's and skips the rebuild when nothing changed. The
changed-files list falls out of the diff for free — that is what a UI
shows as "3 files changed".

## `serve --built` parity mode

Dev mode live-compiles (unchanged — iteration speed wins). `--built`
serves the *artifact* with production semantics instead: no locale
redirects, no live reload, exactly what a deployed runtime would see.
This is the cheap "test what you ship" check — parity is a check you run,
not a tax on every iteration.

## What this enables (forward references)

- **Incremental deploys**: diff two manifests → upload only missing
  blobs. A one-line edit ships in well under a second.
- **Immutable deploys**: every artifact hash is addressable forever;
  rollback is pointing at an old hash.
- **Cross-site dedup**: the shared runtime (`spacetime.js`) is one blob
  across all of a user's sites.

None of these require changes to the artifact — they are consumers of
the manifest. That is the point of getting this layer right.

## Testing

| Test | Asserts |
|---|---|
| `artifact_is_deterministic` | two builds of the same fixture → byte-identical manifest + files |
| `artifact_contains_no_source` | no `.st`/`.org`/`dist/` entries; only build output paths |
| `fingerprint_skips_noop_rebuild` | unchanged tree → same fingerprint; one touched file → new fingerprint + correct changed list |
| `chunked_file_roundtrip` | > 4 MB fixture → chunk manifest; reassembly == original bytes |
