* D1 (W3.1) — the dispatch table lives in the registry entry: `primitive` field

Decision: each driver entry declares WHICH binds primitive the @on resolution
emits (`primitive: intersection`, `primitive: event-driver`, …). The
alternative — one Rust match from driver name to primitive — is the closed
enum this whole plan exists to avoid; the alternative of one @on-head macro
per driver (form.st's kind-is-the-macro shape) does not fit because `@on` is
ONE directive with a driver SLOT, not six directives.

Consequence: adding a driver whose runtime an existing primitive family
covers is a drivers.st-only change (data). Adding a driver needing a NEW
primitive is data + one primitive (the runtime vocabulary — necessarily not
data). Review point: if a later wave adds a Rust `match driver_name`, that is
the rot returning; the field exists so it never has to.

* D2 (W3.1) — `planned:<name>` markers for future primitives

steps, playback, clip, done are registered TODAY with
`primitive: planned:steps-driver` etc. Rationale: the grammar and the
unknown-driver diagnostic (W3.2) should know these words NOW (an author
writing `&.playback` gets "planned, not yet bound", not "unknown driver" —
and certainly not a silent no-op). The marker's shape is pinned by a gate
test so the resolution can match on the prefix.

* D3 (W3.1) — reduced_motion vocabulary: skip | hold | allow

- `skip` — entrance choreography (visible, time, load, steps, clip, done):
  jump to the final state.
- `hold` — ambient/repeating (loop, playback): do not auto-play at all.
- `allow` — user-initiated (hover/click/focus/submit/key, scroll, mouse,
  pointer): interaction-driven and scroll-linked motion is the user's own
  act; common practice (and the CSS media query's intent) allows it.

Review point: this vocabulary predates the reduced-motion implementation; if
the runtime lands different semantics, update the FIELD VALUES (data), not
the vocabulary.

* D4 (W3.1) — params are NOT in the registry entry

The SIP's projection table lists per-driver params (threshold: 0.1, …). They
are deliberately not duplicated into the entry: the @on head grammar owns the
call shape, the primitive owns the arg signature. Three owners, one fact
each. If W3.2 finds a param the grammar cannot express (e.g. `.scroll`'s
`scope: cover`), the grammar grows — not the entry.

* D5 (W3.1) — drivers.st is NOT added to stdlib/index.st

form.st is absent from index.st too: the embedded registry is the always-on
base and covers both plain files and `@import "stdlib"` users (verified:
`@import "stdlib"` + `@form` compiles). index.st's import list is additive
sugar, not the load path. Both files are wired into the three load-bearing
spots: stdlib_embedded.rs, lsp/form_registry.rs, lsp import_resolver.rs.

* D6 (W3.2) — `drive` is a pseudo-primitive expanded between Evaluate and Resolve

The @on macro's `%binds` is one line: `drive(&self, driver: $driver, form:
$form)`. src/pipeline/drivers.rs expands it into the entry's real primitive
(from the registry's dispatch table, D1) + apply-animations (resolved motion
form). Alternatives rejected: a per-driver %if ladder in the macro (the
closed enum in grammar clothing — what this replaces), and making the binds
expander itself registry-dynamic (a bigger metasystem change than the wave
needs; FUP-155's assignment-phase rethink may absorb it later).

* D7 (W3.2) — the @on form slot owns its own unknown-form error

BUG-241's validate_form_refs sees statement-position splices; the @on form
slot is a CAPTURE (`$form:form_application`), invisible to it. The drive
expansion emits E0948 for an undeclared form instead — same class (E0947),
different position. If a general "registry-backed reference validation" pass
ever lands (FUP-155), the two should fold into it.

* D8 (W3.2) — subject-kind checking is only decidable subject-less

`&.playback` (no subject) is checkable: the host is an elem, playback's
on_kinds is media → E0949. `&intro.playback` needs TYPED REFS (is &intro
elem, media, or template?) — W4 territory, SIP-001 §2's kind table. Today's
rule: subject-less → elem check; with-subject → allow, documented.

* D9 (W3.2) — `params` is RETIRED (FUP-040) and bites silently (FUP-151)

The W1 spike grammar and the SIP text use `( $params:params )?` for
call-site args. The stdlib `params` capture type was RETIRED (FUP-040:
param_list is the one declaration surface), and an unknown capture type
falls back to a lenient Expr — the params group then EATS THE NEXT CAPTURE'S
TOKENS (`&.visible --rise` failed as "form_application got SEMICOLON": the
driver's params group swallowed `--rise`). W3.2's capture types therefore
carry NO params groups; call-site args (`--rise(distance: 12px)`,
`&.visible(threshold: 0.5)`) get a real `call_args` capture type in W3.3,
where the parameterized fences live. The W1 spikes keep their lenient
params groups (their accept tests prove nothing about params) — flagged for
W3.3 to replace.

* D10 (W3.2) — a quoted literal in %form is NOT a token literal

`%form { … ";" }` stores the literal as the THREE-CHARACTER string `";"` and
never matches a `;` token (data-kind.st:361's bare `;` is the working
precedent; editable.st's `";"?` sites are suspect for the same reason —
never verified). The BUG-241 spike wrote `";"` and never caught it because
its form was never consulted. Worth a metasystem diagnostic one day (a
quoted single punctuation literal in a %form is almost always a mistake).

* D11 (W3.2) — capture shapes: multi-capture types nest, single-capture types flatten

Verified: `driver_expr` (two+ inner captures) yields
`driver: Named{subject, member}`; `form_application` (ONE inner capture)
yields a FLAT `form: Ident("--rise")`. The drive expansion reads nested-first
with top-level fallback. An absent subject captures as an EMPTY string, not
a missing key.

* D12 (W3.3) — easing sigil normalizes at the emission boundary

Form-registry easing names carry the sigil (`--ease-out-expo`); the runtime's
easing map (public/runtime) is keyed BARE. The drive expansions strip `--`
from easing values when emitting. Full easing-form resolution (an easing
form's curve looked up in the registry and emitted) is its own wave — the
sigil-strip is the honest boundary, documented, not the end state.

* D13 (W3.3) — settings route by the primitive's own signature

`stagger: 70ms;` in a motion body is NOT a keyframe: the root-level
animations builder drops setting props silently. The expansion routes a
no-arrow line to apply-animations ARGS when its name is in the primitive's
own param list (registry data, minus el/driver/animations) — no hardcoded
setting list.

* D14 (W3.3) — mutations route to on-mutation-handler, EVENT drivers only

`@on &.click { $open <- !$open; }` needs no driver primitive (the handler
attaches its own listener); a mutation on a progress/transport driver is
E0949 (progress DRIVES, it cannot fire — the SIP's Gate/Event distinction
applied at compile time). The mutation text is reconstructed from the
capture (`$target <- expr`) verbatim.

* D15 (W3.3) — `raw_until_semicolon` is a dead grammar; `balanced` is the line capture

The pre-existing keyframe_prop/raw_until_semicolon pair fragmented values
(`70ms` → `"7"`, `#8ab4ff` → `"#"`) — unused by any passing path, measured
this wave. `motion_line` uses `balanced(';')` (the keyframes.st precedent).
Left in place (on-actions.st serves the mutation dispatcher), flagged.

* D16 (W3 review) — six findings, and the blast-radius lesson in strict matching

Both reviewers returned "incorrect". Six fixes, each with a regression test:

1. **P1 defaults collapse** — an omitted call arg produced an EMPTY override
   that won over the declaration default. Fixed at the substitute_params
   boundary (empty type_ref = no override). My W3.3 tests asserted the
   override case but never the default-fallback case — the same
   single-variant blindness the W1/W2 reviewers caught.
2. **Statement args ignored** — form_application grew `args` in W3.3 but the
   statement expansion still read the obsolete `form_params`. All three
   slots (statement, arm, body splice) now share resolve_form_with_args.
3. **Substring substitution** — `$x` rewrote `$x2` to `10px2`. Substitution
   is token-bounded now (replace_param_token).
4. **`stagger: 70ms` emitted as a string** — computed NaN at runtime.
   Time-valued settings parse to the NUMBER the primitive signature
   declares. My test asserted the STRING was present — presence is not
   correctness; the fixed assertion is `defaultStaggerDelay = 70` numeric.
5. **Mixed arms+mutation fell through to the WRONG dispatcher** —
   `IdentExtractor` deliberately strips `$` (alias harmonization), so the
   legacy mutation dispatcher claimed `@on $sig { true => --x; $y <- 1; }`
   after on_arm+ rejected it. New `event_name` capture type (no sigil
   strip) for the legacy event slot; the arms failure now surfaces.
6. **Two forms silently dropped** — `@on &.visible --a --b;` matched nothing
   and vanished (the `;` literal's LiteralMismatch is suppressed). The
   trailing-`;` literal is now the statement's COMMITMENT point: leftovers
   before it are ExtraInlineTokens (retained).

**Blast radius of strict matching (41 → 12 → 0):** the body-less
strict-inline extension broke established surfaces that RELY on leftover
tolerance — extra tokens BEFORE an arg list (`@value-change count(duration:
500ms)` names its watcher; 2b's own comment blesses it) and the lone
trailing `;` every body-less statement ends with (`@import "./faq.st";`).
Strict now requires: body-less AND no ARG_LIST present AND leftover beyond a
lone `;`. The general lesson: tightening the matcher is never free — every
leniency is load-bearing somewhere until proven otherwise, and the full
suite is the only honest measurement.

** D19 (2026-07-26, W3.4): the flaky E0804 was a poisoned stdlib binary cache — cache writes are now gated on clean loads

Symptom across the W3.4 sweep: builds of files using retired directives
intermittently failed with `error[E0804]: Directive '%binds' not valid in
this context` at spans inside stdlib macro defs (on-event.st:230, on.st:66,
timeline.st:71), the "missing" parameter varying run to run
('event'/'signal'/'driver'). Fresh full stdlib loads always passed
(measured 25/25, 0 errors, 71 capture types); cached builds failed.

Root cause (measured, not guessed):
1. The E0804 headline was the friendly-error formatter MISLABELING a
   resolve-time `MissingParameter` (any error whose source line contains
   `%binds` is re-summarized as a bind-context error). The real error:
   expanding a matched stdlib macro whose form captures were absent.
2. `IncrementalStdlibCache` wrote `registry.bin` UNCONDITIONALLY — a load
   that raced a mid-edit stdlib state (this session edited on.st /
   drivers.st / the capsule dozens of times while builds ran) persisted a
   partially-populated registry. Cache HITs drop load errors
   (`errors: Vec::new()`), so the poison was silent and sticky until the
   next stdlib mtime change. Which macro failed first varied with per-process
   HashMap iteration order over the match set — the apparent nondeterminism.

Fix: both cache-write sites (`from_dirs`, `refresh_if_needed`) now skip the
write when the load carried errors (log::debug when skipping). Invariant: a
cached registry always came from a zero-error load, so dropping errors on
hit is sound. Proof: 30/30 consecutive CLI builds of a retired-syntax file
pass after the fix (was intermittently failing before).

Secondary fix folded in: `make_error_friendly` mislabeling left as-is (the
underlying load/resolve error now surfaces at the right time and place —
the sticky-poison path that made the mislabel visible is gone).

** D26 (2026-07-26, design probe): `.` = typed facet access; `done` is a PROPERTY, not a projection

User probe: discomfort with `.` representing something that isn't a property.
Diagnosis: `.` is OVERLOADED today — data-space property access
(`$brand.rule`) vs observation-space driver selection (`&hero.visible`). A
W3-built harmony violation (one sigil, two meanings).

Resolution: ONE meaning — typed facet access. The existing driver registry
already IS a facet table: `on_kinds` = declaring subject type, `value_type`
= facet type. Grammar positions are type-checked consumers (@on head:
driver-typed; arms/reactive CSS: value-typed). Types INFERRED from bindings,
never annotated — "between i and iii" per the user.

`as $reveal` binds a progress-TYPED signal (type from the driver's
value_type). Progress bindings carry derived facets: done(bool) =
"progress reached 1", later running(bool). Cascade:
- `@on $reveal.done { true => --subtitle; }` = EXISTING arms surface
  (gate semantics, W3.3) — `.done` registry entry, done-driver primitive,
  and the as-binding analysis pass ALL EVAPORATE.
- Latch question dissolves: time drivers clamp → natural latch; scrub
  flips back → reversible (the ARM SHAPE chooses gate vs latch — W3.3's
  existing distinction).
- `done` readable in expressions via facet lowering (progress >= 1).

Type hierarchy as data: progress-signal <: signal (inherits `change`, adds
done/running); elem facets unchanged.

Residual fork — @value-change's replacement on plain signals:
(alpha) `.change` driver-facet (type driver<event>, params on the driver —
type-clean, RECOMMENDED) vs (beta) inline arm consequences with head params
(deletes more surface but smuggles driver params into the arms head —
repeats the overload mistake class). Awaiting user ruling.
