* Why this document

The SIPs describe a destination. This lists what must be TRUE before the
first implementation wave can start, in dependency order, with the
evidence for each claim. Everything here is either (a) verified against
source and marked so, or (b) explicitly an unknown with a named spike.

Rule applied throughout: **a spike is not done until its NEGATIVE case
fails.** This was learned the expensive way — see P0 below.

* P0 — BLOCKING: =check= must gate on capture-type failure (BUG-229)

**Status: broken. Nothing else can be verified until this is fixed.**

Evidence (2026-07-26): a =%macro= consuming =( $arms:on_arm )+= accepts
BOTH a well-formed body and a deliberately malformed one
(=a -> -> b => ; => cut=). =inspect --layer expansion= shows the body
captured as RAW TEXT, never parsed by =on_arm=.

Same class as BUG-216 (=tests/bug_216_silent_directive_drop_test.rs=),
whose header states the hazard exactly: /"a body that fails to parse is
indistinguishable from a body that legitimately emits nothing, so the
failure is invisible to a green suite."/ BUG-216 fixed the =@test=-body
path; this is the custom-capture-type-in-directive-body path.

Why it is P0 and not "a bug we will hit later": EVERY grammar in this
family (=driver_expr=, =on_pat=, =score_block=, =form_application=) is a
capture type consumed in a directive body. Without the gate, a wave could
ship grammars that never match and a green suite would not notice.

Acceptance: malformed body → non-zero exit + diagnostic naming the capture
type and span; well-formed unchanged; regression test beside bug_216.

Small and mechanical, but ordered here because P2's implementation may
depend on it.

1. Lexer: the =RawToken::Minus= ladder's =-- + Ident= arm emits
   =SyntaxKind::DASHED_IDENT= instead of =IDENT= (text unchanged).
   Vendor prefixes (=-webkit-*=, ONE dash) stay =IDENT=.

3. Parser dispatches on the kind, never =text.starts_with("--")=.

(=lexer.rs=, =css_custom_property_tests=), and =-- foo= (spaced) already
does not merge. So this is a labelling change, not a lexing change.

* P4 — Retire =~= (PRESET_REF) safely

**Verified constraint**: =TILDE= is load-bearing for CSS general-sibling
selectors — =parse_selector= has =SyntaxKind::TILDE => { bump;
parse_selector_part() }= beside =GT= (child) and =PLUS= (adjacent).

∴ retirement removes ONLY: =parse_preset_ref()=, the =PresetRef= AST node,
and the three PREFIX dispatch sites (parser.rs:952, 1132, 1439). It must
NOT touch the infix selector path.

Gate: a test asserting =.a ~ .b= still parses, landed BEFORE the deletion.
Also update ARCHITECTURE.md's prefix table (=~= → =--=), which currently
advertises =~= as live.

* P5 — Projection registry as data

The driver table (=.visible .scroll .clip .playback .done .steps .time
.loop .load .hover .click .focus .submit .key .mouse .pointer=) must load
from stdlib as registry entries, on the same rail as migrations
(=src/metasystem/registry.rs=), NOT as a Rust match.

Each entry declares: name · applicable ref kinds · param signature with
defaults · value type (Progress/Transport/Gate/Event) · measure domain ·
reversibility · reduced-motion behavior.

This is what makes the error messages mechanical (did-you-mean
populations) and the a11y policy declarative rather than per-author.

* P7 — Migration capsule authoring

**Corrected understanding (verified against =src/parser/meta_ast.rs= + the
one real entry)**: the shape is a CAPSULE —

#+begin_src spacetime
%migration <id> {
  %date YYYY-MM-DD
  %docs "…"
  %macro <old> { … }                            // retired defs VERBATIM
  %rewrite <rule> { %match { … } %into { … } }  // mechanical rewrites
  %hint for @directive "…"                      // manual guidance
}
#+end_src

Properties that shape the work (from the real entry's header): the capsule
owns the retired syntax entirely (/"deleting this file deletes the old
syntax from existence"/); retired forms KEEP COMPILING via embedded
=%binds= while a project's =@version= predates the wave; =%into= holes are
backtick-quoted and splice RAW SOURCE SLICES.

Work: recover the 9 retired macro definitions VERBATIM from git history
(=stdlib/macros/{on-event,timeline,loop}.st=), embed them, write the
rewrite rules, write =%hint=s for the two manual cases (=trigger:= strings,
=@pose-track=).

RESOLVED (was a v4 blocker): **no hoisting needed.** Rewrites splice the
old body inline at the call site; extracting shared =@form=s is a REFACTOR
authors do afterward, not something a migration should invent.
