* Design principles

P1. **Three sigils, three categories** (SIP-001c): =&= identity · =$= data ·
    =%= form. Every name in a timeline declaration answers exactly one of
    /which one?/ · /what value?/ · /what shape?/
P2. **Drivers are typed projections of refs.** Registry is DATA.
P3. **Params sit with their owner.** Driver params on the driver, form
    params on the form, template params on the template.
P4. **Parens vs words**: =(...)= = what the function is responsible for;
    trailing words = what the language itself owns (placement, naming).
P5. **Two arrows, two meanings**: =->= motion through values over time;
    ==>= discrete state transition.
P6. **Behavior attaches by selector**; markup stays pure.
P7. **Choreography (=@on=) ≠ arrangement (=@score=)** — one driver grammar
    beneath both.
P8. **Errors are a feature.** Every registry (projections, forms, kinds)
    exists partly to make did-you-mean populations mechanical, because an
    agent's authoring loop is error → repair.

* Ontology — the type map

** 1. Refs, kinds, and =&.=

| Ref | Kind | Meaning |
|-----+------+---------|
| =&.= | Elem | the selector host (THE self-ref; no bare driver words) |
| =&el= | Elem | element instance (template root, DOM node) |
| =&media= | Media <: Elem | audio/video entity instance |
| =&tl= | Timeline | a named =@on= result, a Clip, a named score |
| =&T= | TemplateFn | unapplied template — NO projections |

=&.= is self in EXPRESSION position; =& {…}= is self in SELECTOR position.
Forms (=--x=) have no kind here — they are not things in the world (SIP-001c).

** 2. Projections — how a ref acquires temporal sense

A projection reads a ref's relationship to its own world and yields a
**driver**. Registry data (kinds-as-data):

| Projection | On kinds | Params (defaults) | Yields | Measures |
|------------+----------+-------------------+--------+----------|
| =.visible= | Elem | threshold: 0.1, delay: 0ms, immediate: false | gate + progress | — |
| =.hover .click .focus= | Elem | target: sel?, prevent: false | event (reversible) | — |
| =.submit= | Elem(Form) | prevent: true | event | — |
| =.key= | Elem | key (positional) | event | — |
| =.scroll= | Elem | scope: cover, start: 0, end: 1, scrub: true, axis, distance | progress | %, vh, px |
| =.mouse .pointer= | Elem | axis: both, invert: false | progress (2D) | % |
| =.time= | Elem | duration | transport | ms, s |
| =.loop= | Elem | duration | transport (repeating) | ms, s |
| =.load= | Elem | delay, threshold | event (once) | — |
| =.clip= | Clip-hosts | — | transport (enclosing span) | inherited |
| =.playback= | Media | — | transport (currentTime) | ms, s, beat |
| =.steps= | Elem | advance: event-expr | transport (ordinal) | counts |
| =.done= | Timeline | — | gate | — |

**Driver value-types** (resolves v3's asserted-not-derived composition):

| Type | Semantics | Composition role |
|------+-----------+------------------|
| Progress | continuous 0..1 | DRIVES the motion |
| Transport | seekable progress + play/pause/rate | DRIVES; render-safe |
| Gate | boolean window | MASKS a driver |
| Event | discrete occurrence | TRIGGERS; latches |

=&&= = mask (Gate ∧ driver → driver active only inside the gate; two
Progress sources → min). =\vert= = fallback/either (first AVAILABLE drives;
for Events, either fires). Availability for =.clip= is STATIC (scored or
not) — so =(&.clip \vert &.time(3s))= resolves at compile time, while
=(&.click \vert &.key(" "))= resolves at runtime. Same operator, two
evaluation times, documented (v3 open q C3, resolved by declaring it).

** 3. Timeline facets (signals, not drivers)

=&tl.t= · =.duration= · =.progress= · =.playing= · =.rate= — readable and
writable: =&film.t <- 4.2s=, =&film.playing <- false=.

** 4. Compile-time resolution & errors

| Case | Diagnostic |
|------+------------|
| =&intro.playback= (&intro : TemplateFn) | E-DRIVER-KIND: "&intro is a template, not media — media in scope: &voice, &bgm" |
| =&tl.visible= | E-DRIVER-KIND + Timeline projections (=.done=) |
| =&.clip= with no enclosing score | E-DRIVER-CONTEXT: "no enclosing score; add =\vert &.time(d)= fallback" |
| =@score &.clip= | E-DRIVER-CYCLE |
| =&header.visible= where =.header= matches N elements | E-DRIVER-AMBIGUOUS (=&.= for per-element fan-out) |
| =for 3s= under a scroll score | E-MEASURE-DOMAIN → suggests =%= |
| =.visibel= | E-UNKNOWN-PROJECTION + did-you-mean |
| motion form in a markup hole | E-FORM-KIND (SIP-001c) |

Measure domains nest: an inner score's domain comes from ITS driver, not
the parent's (v3 open q C2, resolved). =%= inside a =&.time= score nested
in a =&.scroll= score is legal — the inner span is time-domain.

** 1. =@on= — driver × form

// mutations — same head, no form slot

%form {
  @on $driver:driver_expr ( $form:form_application )? ( "as" $name:element )? {
    $body:on_actions
  }
}
// VERIFIED 2026-07-26 (PLAN-121 W1): both surfaces parse, and the malformed
// cases are rejected. The SUBJECT is optional (`&.visible` = self, the most
// common form and the launch article's first example); the MEMBER is required,
// since that is what makes it a driver rather than a bare reference. An earlier
// spike required the subject and so would have REJECTED `&.visible`.
// Rejected: `&card` (no member) · `card.visible` (no `&`) · `&card.` · `&.`
%capture_type driver_expr { "&" $subject:ident? "." $member:ident ( $params:params )? }

%capture_type form_application { $form:dashed_ident ( $params:params )? }
// IMPLEMENTED 2026-07-26 (PLAN-121 W1.3). This was written `{ "--" $form:ident … }`,
// which can NEVER match: `--rise` lexes as ONE `IDENT` via the RawToken::Minus
// ladder, so there is no separate `--` token for the literal to consume (BUG-242).
//
// `dashed_ident` now exists as a capture type and is verified to accept `--rise`,
// `--rise(distance: 12px)`, `--ease-out-expo` while REJECTING a bare `rise` and
// `-webkit-thing`. That rejection is the whole point: with `$form:ident` the sigil
// would be omittable, i.e. decoration rather than meaning.
//
// NB it is an EXTRACTOR-level discrimination, not a new SyntaxKind. The lexer keeps
// emitting one IDENT (which CSS compatibility requires); only the capture type asks
// whether this slot demands the sigil. A `DASHED_IDENT` token kind would have changed
// what 348 `SyntaxKind::IDENT` sites see for `--custom-prop` — a large blast radius
// for a distinction only capture types need. SIP-001c's "one lexer change" is
// therefore ZERO lexer changes; the cost landed lower than estimated.
#+end_src

** 2. Signal drivers — arms with =@on='s own pattern type

*** Spike finding (verified against stdlib)

The arm family shares an ARM SHAPE, not a pattern type:

| Host | Pattern capture | Leaves |
|------+-----------------+--------|
| =@match= / =@view= | =match_pat= | variant_pattern \vert string \vert ident |
| =receive= (decode) | =recv_pat= | number \vert ident \vert string — /"mirrors match_pat + numbers"/ |
| =handle= | =handle_arm= (inlined) | ctor + optional payload binding |
| =@data derive= | =match_value_arm= | reuses =match_pat= |

∴ =@on= declares ITS OWN pattern type (as =recv_pat= already did), rather
than adding a branch to =match_pat=. Transitions therefore never leak into
=@match=/=derive=/=receive=/=handle=, where a from-state is meaningless —
**zero blast radius on existing hosts, and no kind-rejection rule needed.**

#+begin_src spacetime
%capture_type on_leaf {
    ( $variant:variant_pattern )    // shared leaf, REUSED not forked
  | ( $lit:string )                 // bare idents land here (FUP-079)
  | ( $wild:ident )                 // only `_` reaches it
}
%capture_type on_transition { $from:on_leaf "->" $to:on_leaf }
%capture_type on_pat {
    ( $transition:on_transition )   // FIRST — discriminated by the INFIX "->"
  | ( $leaf:on_leaf )
}
%capture_type on_arm { $pat:on_pat "=>" $form:form_application ";"? }
#+end_src

**Discrimination is on =->=, not on parentheses.** Parens are noise on a
pattern that is already unambiguous: an arm either contains =->= before
its ==>= (transition) or it does not (final state). Consequences:

- surface is =a -> b => --cut;=, NOT =(a -> b) => --cut;= — one less
  bracket pair per arm, and no "why do I need parens here" question;
- =on_leaf= is a SEPARATE capture type from =on_pat= (not recursive), so
  the transition branch cannot nest transitions — =a -> b -> c= is a parse
  error, which is correct: a transition has exactly two ends;
- branch order still follows the =match-arms.st= hazard (first-match-wins,
  no backtracking): =on_transition= is tried first, and fails cleanly on
  any arm without an =->= before its ==>=.

This also keeps the door open for =receive=/=handle= to adopt transition
patterns later (§Open q9) — a paren-free pattern composes into their
existing arm shapes without re-bracketing.

*** Surface

#+begin_src spacetime
// single arm — bare pattern = FINAL STATE (the 90% case)
.cart  { @on $cart.open true => --slide-in(300ms); }
.panel { @on $tab "billing" => --cross-fade(200ms); }
.stage { @on $route "/pricing" => --whip-pan(300ms); }        // view transitions

// arms — subject hoisted; PURE HOIST of the single form
.drawer {
  @on $cart.open {
    true  => --slide-in(300ms);
    false => --slide-out(200ms);
  }
}

// guarded transition when the SOURCE matters (multicam)
.show {
  @on $take {
    a -> b => --cut;
    b      => --dissolve(6f);
    _      => --cut;
  }
}

// Gate vs Event — a window, not a moment
.nav { @on ($tab == "billing") --highlight; }
#+end_src

**The rule that keeps the two shapes un-confusable**: if the head is a bare
signal subject (no pattern, no comparison), the braces hold ARMS; anything
else and the braces hold a BODY. And arms are a pure hoist of the single
form — same tokens, same order, subject factored out:

#+begin_src spacetime
@on $take { a -> b => --cut; }   ≡   @on $take a -> b => --cut;
#+end_src

Semantics: bare pattern = "arrived at this state, from anywhere";
=from -> to= = "arrived at =to= FROM =from=" (the combinatorial matrix is
OPT-IN, never required — N states do not force N² arms).
=$sig -> value= as a driver HEAD is REJECTED: the pattern belongs in the
pattern position, after the subject.

=->= = a step between values (keyframes AND transitions). ==>= = pattern ⟹
consequence (every arm host). Each keeps one meaning.

*** Gate vs Event on signals

| Spelling | Driver type | Semantics |
|----------+-------------+-----------|
| =@on $tab "billing" => --x= | Event | fires at the MOMENT it becomes billing |
| =@on ($tab == "billing") --x= | Gate | holds WHILE it is billing |

Naming the distinction is what prevents the classic "why does my animation
replay" bug.

*** =@effect= is subsumed

=@effect= exists (its own docs) because /"only animation drivers reacted to
signals"/ — i.e. because =@on= could not take a signal. Now it can:

| =@effect= | =@on= |
|-----------+-------|
| =on: $rows= | the driver: =@on $rows= |
| =debounce: 600ms= | driver param: =@on $rows(debounce: 600ms)= |
| =immediate: true= | driver param: =@on $rows(immediate: true)= |
| body =mutation_actions= | same body, unchanged |

#+begin_src spacetime
// today
.app { @effect(on: $rows, debounce: 600ms) { $previewNonce <- $previewNonce + 1; } }
// after
.app { @on $rows(debounce: 600ms) { $previewNonce <- $previewNonce + 1; } }
#+end_src

**Scope semantics are UNCHANGED** — this is a true subsume, not a merge:
- WHAT IS WATCHED: =@effect= captures =$signal:binding= and does NOT read
  the value (its own note: dotted paths like =$wrap.count= subscribe BY
  PATH — BUG-155 class). =@on $rows= = subscribe to that path. Bare
  subject = any change; a pattern narrows it.
- WHERE MUTATIONS RESOLVE: =%binds { effect-runner(&self, …) }= runs the
  body via =ST.runMutations(host, body)= — the SAME runtime path =@on='s
  mutation bodies already use. =$= in the body means the host, identically.

Cost, stated: =@effect='s name announced "side effect" at the callsite.
Mitigation: =debounce:=/=immediate:= stay visible driver params, and docs
name =@on $sig { mutations }= as the effect form.

*** W4 rulings (design conversation 2026-07-31)

Four questions were open on =@score=. All four are now settled. The through
line: **=@score= adds no runtime concept.** It reuses the driver pipeline
(every driver =%yield=s ONE 0..1 progress signal) and the form registry.

**R1 — the DRIVER owns the time domain; a score never declares one.**

A score inherits the domain of whatever drives it, exactly as =@on
&.time(600ms)= already does. New registry column =domain:=, four values:

| driver | =domain:= | the domain is | placements read |
|--------+-----------+---------------+-----------------|
| =time= =loop= | =declared= | the driver's own param | =at 2s for 3s= |
| =scroll= =visible= =mouse= | =normalized= | 0..1 | =for 30%= |
| =clip= | =inherited= | the span the parent assigned | either, from parent |
| =steps= | =derived= | count of score lines | =at step 3= |
| =playback= | =inherited= | the media element's duration | =at 2s= |

Rejected: (a) always-declared — =&.clip= has nothing to declare, so the video
pole needs a second rule, which the thesis forbids; (b) always-derived —
meaningless for =scroll=, whose progress is inherently 0..1; (c)
declared-with-derived-default — two code paths, per-driver conditionals return.

This buys a compile-time check as a side effect, which is pressure test C2
(measure domains across nesting) satisfied by DATA rather than by a rule an
author must remember:

#+begin_src spacetime
@score &.scroll(cover) { &x at 2s; }
// E-MEASURE-DOMAIN: scroll's domain is normalized; use a percentage.
//                   did you mean `at 20%`?
#+end_src

**R2 — grouping is a score FRAGMENT. No scene keyword.**

=@form score --name { … }= already exists (form.st, the sixth kind marker) and
=score_step= already accepts =$form:form_application=. A group is therefore a
fragment — parameterized, reusable, projection-agnostic:

#+begin_src spacetime
@form score --opening { &title -> &subtitle -> &tagline; }
@form score --closing($cta = "Start") { &logo -> --fade(200ms) -> &cta-button; }

@score &.time(60s) as &film {
  --opening at 0s for 10s -> --whip-pan(300ms) -> --closing(cta: "Try it");
}
#+end_src

Rejected: =@scene "intro" { … }= — it collides with =@scene/camera=
(path-qualified module references, docs/language/module-system.md), and
string-keyed scenes reintroduce exactly the string registry this SIP deletes.
Also rejected: inline anonymous nesting — a second way to say the same thing,
and A7 already routes nested sequences through templates. A scene you cannot
reuse is not worth a keyword.

**R3 — the IR is a WINDOW MAP, not a scheduler.**

A score emits no scheduler object. Each clip's progress is a pure function of
its parent's progress:

#+begin_src spacetime
&lower-third at 2s for 3s        // inside @score &.time(60s)
#+end_src
#+begin_src js
$lower_third_progress <- clamp01(($film_progress * 60000 - 2000) / 3000)
#+end_src

Everything in the score body is a shape of that one map:

| surface | is |
|---------+----|
| =at 2s for 3s= | an affine window — offset + scale |
| =during &opening to &outro= | a window resolved from two named spans |
| =--whip-pan(300ms)= on an edge | a form applied over the OVERLAP window |
| =&.clip= | the clip driver reads the window its parent assigned — which is why its domain is =inherited= |
| =rate:= | the point where the map stops being affine |

That last row is the payoff: =rate= is the DERIVATIVE of the window map.
=rate: 1 -> 2= makes the map the integral of a ramp; =rate: 0= makes it
constant (freeze); =rate: -1= gives it negative slope (reverse). Retiming,
freezing and reversing are not three features bolted onto a scheduler — they
are three shapes of one function.

And because the map is a PURE FUNCTION of parent progress, a score is seekable
by construction: pressure test C4 (render determinism) falls out instead of
being enforced. The IR is a list of ={child, map}=. Live evaluates it on rAF;
render evaluates it at frame /n/. ONE evaluator, two callers — which is the
structural answer to 001b §8.6's warning that live and rendered films diverge.

**R4 — projections stay; =&.clip=/=&.visible= do NOT become sub-types.**

The same score, both models. Projection-member (today):

#+begin_src spacetime
@form score --story { &title -> --dissolve(600ms) -> &demo; }
.film { @score &.time(12s) as &film { --story; } }   // website pole
.clip { @score &.clip       as &shot { --story; } }   // video pole
#+end_src

Sub-typed:

#+begin_src spacetime
@form score --story<P: Transport> { &title -> --dissolve(600ms) -> &demo; }
.film { @score &film<Time(12s)> { --story<Time>; } }
.clip { @score &shot<Clip>      { --story<Clip>; } }
#+end_src

The fragment in model 1 never mentions the projection — the driver is supplied
at the =@score= head — so fragments are ALREADY projection-agnostic. Model 2
makes authors WRITE a type parameter to recover polymorphism model 1 has by
omission. On the four axes: syntax quality worse (ceremony at every call
site); type cost higher (elem-ref becomes a family, while the driver registry
already rejects unknown members at compile time — W3.2's gate); parametricity
payoff nil (nothing consumes a distinction =value_type= + =on_kinds= do not
already carry); and it forks the website and video surfaces into two grammars.
Sub-typing answers a question no pressure test has asked.

** 5. =rate= is a property (closes ramps AND freeze)

DISTINCT from =hold(until:)=, which pauses the whole TRANSPORT (interactive
gate). Freeze = one clip stops while the timeline runs; hold = the playhead
stops. Two operations, two spellings, zero new vocabulary.

@on &.visible(interrupt: settle) --reveal;   // run on to the nearest rest state
@on &.visible(interrupt: cut)    --reveal;   // jump to rest
#+end_src

holds, because a transport has a playhead an interruption should not rewind).

* Code as art & craft

** What is delightful, and why (the reasons generalize)

1. **=\vert= as fallback.** =@on (&.clip \vert &.time($duration)) --life= — a
   catalog block that plays standalone AND obeys a film's transport when
   scored: no conditional, no mode flag, no "preview mode". A special case
   became an operator, and the operator generalized. High-water mark.
2. **=&.= for self.** Completes a family (=& {}= selector · =&.= expression)
   and the common case pays 2 characters. Compare =&self.visible=: correct,
   joyless.
3. **Motion as a form.** 40 near-identical HyperFrames blocks → one template
   + one form + theme values. Not a syntax win — a SCALE win: it changes
   what one person can maintain.
4. **Three sigils answering three questions.** =&= which one · =$= what value
   · =%= what shape. A reader parses a dense line by sigil before parsing it
   by grammar.

** What is un-delightful (kept honest)

1. **Sigil density.** =@on (&hdr.visible && &hdr.scroll(distance: 40px))
   --reveal(600ms) as &r;= is legal and near-unreadable. The READABLE SUBSET
   must be the default: lint composition depth (≥ 3 terms) and encourage
   naming intermediate timelines.
2. **=%= vs =30%=.** Defensible (unit suffix vs sigil) but real. Watch for
   author confusion in the first cohort.
3. **=@score= is a heavy metaphor for a light web job.** Decision: lean IN.
   One strong metaphor (tracks, playhead, marks) beats two weak ones, and
   the NLE framing is the differentiator. Teach it; don't dilute it.
4. **Bare =& {}= inside a form loses its subject.** Mitigation: forms may
   declare region params (=@form --reveal(&target)=) — the same mechanism
   transitions use.

** The UX we are designing for

*Human, video*: a =.st= file beside a preview that scrubs. Every clip
highlights its source line as the playhead crosses it; dragging a clip edge
REWRITES the =in=/=out= words in the file. The studio is not a GUI over the
language — it is a bidirectional projection of it, which is only possible
because arrangement is declarative words, not baked frames. (SIP-001b.)

*Human, website*: never meets =@score= on day one. Writes
=@on &.visible { }=; it works. Meets the score when two sections must share
a playhead — and the score they learn then is the SAME one a film uses.

*Agent*: the type system earns its keep in the ERROR path, not the happy
path. =@on &intro.playback= must answer /"&intro is a template, not media —
media in scope: &voice, &bgm"/. Every registry (projections, forms, kinds)
makes did-you-mean populations mechanical. An agent's loop is error →
repair; **a design that makes good errors cheap is an agent-friendly
design** — the real argument for kinds-as-data over macro heads.

* Migration — wave 2026-07-26 (the CAPSULE model)

Verified against =src/parser/meta_ast.rs= + the one real entry
(=stdlib/migrations/entries/2026-06-09-reactive-surface.st=). The shape is a
CAPSULE, not a bare rewrite list:

#+begin_src spacetime
%migration <id> {
  %date YYYY-MM-DD
  %docs "…"
  %macro <old> { … }                              // retired defs VERBATIM (grammar + %binds)
  %rewrite <rule> { %match { … } %into { … } }    // mechanical rewrites
  %hint for @directive "…"                        // manual guidance
}
#+end_src

Load-bearing properties (from the real entry's own header):
- The capsule owns EVERYTHING about the retired syntax — /"stdlib proper
  carries only current syntax; deleting this file deletes the old syntax
  from existence."/
- While a project's =@version= predates the wave: mechanical shapes are
  auto-rewritten IN MEMORY (W0715) and persisted by =spacetime migrate= or
  the dev-dock pill; retired forms still COMPILE via the embedded =%binds=.
  Once =@version= reaches the wave date, lingering use is E0911.
- =%into= holes are backtick-quoted (=`$x`=) and splice the RAW SOURCE SLICE
  — formatting and expressions survive verbatim. A bare =$x= is literal text.

** The hoisting question (RESOLVED — no hoisting needed)

v4 flagged: does the named-timeline rewrite need =%into= to emit a SIBLING
top-level =@form= declaration? Answer: **no, and it must not.**

=--`$name`(`$duration`)= splices the OLD BODY inline at the call site, so
the rewrite is local — exactly what =%into= does natively. Extracting a
shared =@form= is a REFACTOR (a human judgement about which motions are
worth naming), not a migration. Migrations preserve semantics; they do not
invent abstractions.

∴ the wave rewrites every site to an inline-bodied =@on=; authors extract
=@form=s afterward, where they see repetition. This removes v4's blocking
unknown entirely.
