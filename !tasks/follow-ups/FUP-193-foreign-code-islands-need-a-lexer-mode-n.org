* Why — the residue of FUP-046

FUP-046 is closed: the backtick is a sigil and now lexes as one. Its ORIGINAL
motivating defect survives, in a smaller and better-understood form.

Inside an `@eval` / `@drive` / `@when` payload, or an `%emit js` body, the text
is JAVASCRIPT. There a backtick really IS a template delimiter, and a `{` inside
that template is text. The lexer does not know this — it lexes those bytes with
Spacetime rules — so `parse_arrow_fn_balanced` can still mis-count a brace
inside `` `…}…` `` (its limitation comment, `src/syntax/cst/parser.rs:3733`).

* Why a token cannot fix it, and a MODE can

This is the lesson that cost a full corpus regression. The character is the
same; the LANGUAGE is different. A lexer rule keyed on the character alone must
be wrong in one of the two languages — make the backtick consume and Spacetime's
4,934 holes die; leave it and JS templates stay transparent.

∴ the discriminator is not the character. It is WHERE. That is a mode.

The parser ALREADY knows where these islands are — `parse_emit_body` exists
precisely because "%emit js must not be read as Spacetime", and it solves the
problem by refusing to interpret anything but `%`. The knowledge is present at
the parser and absent at the lexer, and the fix is to move it one layer down.

Precedent to copy: the existing re-lex machinery. `parse_html_element` already
re-lexes a tail with `Lexer::new(&tail)` when a token straddles a region
boundary (:2467). An island can be lexed the same way — scan the region, lex its
bytes under JS rules, splice.
