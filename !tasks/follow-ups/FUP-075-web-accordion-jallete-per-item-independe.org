* Problem
@each-generated lists (FAQ accordion in web/index.st, cart/variant items in
jallete) need PER-ITEM independent reactive state (each accordion item open/
closed on its own; each variant card selected on its own). The retired
@state_machine attempted this per-element but never worked. The PLAN-047
migration replaced it with a page-global signal ($accordionOpen) which COUPLES
all items \u2014 clicking one toggles all. The correct model is per-instance state on
the @each row (the template-instance signal scope, cf the @template body $signal
model that @view/@each instances use).

* Specifics
- web/index.st `.zypsy-accordion__item` (FAQ, @each over $faqs): currently
  `@on click { $accordionOpen <- !$accordionOpen }` + `.is-open: $accordionOpen`
  \u2014 a single global toggle. Needs per-item: each item tracks its own open state,
  ideally keyed by the item id ($q.id) or via a per-instance signal.
- jallete variant/color/size selection: the is-active class per variant card is
  currently handled by the (deferred, FEAT-134) JS controller; the Spacetime-native
  form needs per-card selected-state.

* Design question
Does Spacetime expose a per-@each-instance local signal an `@on click` inside the
row can flip, with a reactive `.cls` in the same row scope reading it? If the
template-instance scope (the one @view/@template bodies use, where `$open` is
per-instance) is reachable from an @each row's @on + reactive class, this is just
authoring. If not, it's a gap: @each rows need the same per-instance signal scope
as @template instances. Verify against the each-with-templates / component-body
scope model (stdlib/primitives/data/each.st, view.st).

* Acceptance
- web/ FAQ accordion: clicking one item toggles ONLY that item.
- A headless probe proving per-item independence (two items, click one, assert
  only it has .is-open).
