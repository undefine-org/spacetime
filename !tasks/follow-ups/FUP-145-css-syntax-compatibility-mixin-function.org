* The CSS surface we would be compatible with

=css-mixins-1= (W3C draft; custom functions SHIPPING in Chromium):

#+begin_src css
/* value-returning — @function */
@function --double(--x) { result: calc(var(--x) * 2); }
.a { width: --double(20px); }          /* call in VALUE position */

/* block of declarations — @mixin + @apply */
@mixin --card { border-radius: 12px; box-shadow: 0 2px 8px rgb(0 0 0 / .08); }
.b { @apply --card; }                   /* splice in STATEMENT position */
#+end_src

Key spec facts:
- Names are =<dashed-ident>= — must start with =--=, case-sensitive.
- =@function= params are dashed-idents, locally scoped custom properties;
  a CSS type or =type()= constrains them; body yields =result:=.
- =@apply --foo;= is identical to =@apply --foo();= (spec).
- Only custom FUNCTIONS have browser support; MIXINS are specced, unshipped.

* What SIP-001c ships instead (and why)

ONE directive, =@form=, with kind inferred from body blocktype:
style (≡ @mixin) · value (≡ @function, =result:=) · motion (Spacetime-only:
keyframe-path bodies, which CSS has no equivalent for) · easing ·
score-fragment. Splice is a bare =--name;= statement (no =@apply= keyword).

Rationale for deferring parity: we do not yet know whether authors want
the CSS-shaped split (=@mixin= vs =@function= as separate directives, with
=@apply=) or the unified =@form=. Deciding after real use avoids shipping
two declaration families we then have to reconcile.

* What this FUP should decide (post-exercise)

1. Accept =@mixin= / =@function= / =@apply= as ALIASES of =@form= + splice,
   so CSS authors' muscle memory compiles? (Cheap: registry entries.)
2. Implement =@function= semantics faithfully (=result:= descriptor,
   =type()= param constraints, local custom-property scoping) so a
   Spacetime =@form= value-kind IS a CSS custom function — meaning it could
   even EMIT native =@function= where supported, with a compile-time
   fallback where not (the existing dual-rail pattern).
3. Whether motion/easing/score forms should carry a distinct declaration
   keyword to keep the CSS-parity subset crisply identifiable.
4. Native emission: when a form is style-kind AND the target supports
   =@mixin=, emit native CSS instead of expanding at compile time (same
   dispatch logic as animate.st's CSS-vs-JS choice).
