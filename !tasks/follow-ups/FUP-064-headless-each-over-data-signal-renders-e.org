* Summary
On the headless V8 backend, a runtime =@each($data as $row) { ... }= over a data
signal (whether the body is inline HTML or a template ref =&card($row)=) renders
the element shells but leaves every =`$row.field`= hole EMPTY — both flat
(=$row.name=) and nested (=$row.origin.kind=, =$row.compile.html_len=).

* Evidence
- Reproduced on the current branch AND on pure HEAD (swapped the runtime trio +
  template.st/view.st) → PRE-EXISTING, not introduced by PLAN-041 W2/W3.
- The pre-existing 251-failure headless baseline already includes
  =tests/unit/templates/collection-ref-each.test.st= (the @each-over-data path).
- Compile-time SSG unroll (=@data dispatch $macros= → static HTML) renders nested
  holes fine (=data_dispatch_injects_signature_catalog= passes); only the RUNTIME
  @each-over-signal path is affected.

* Impact
- The MCP workbench cards (=stdlib/__mcp__/workbench/cards.st=) render their data
  fields (=$fn.compile.html_len=, and the FEAT-128 =$fn.origin.kind= chip) via this
  exact path. They are compile-verified and unit-verified at the data layer
  (FunctionRecord::to_json + the $macros dispatch row both carry origin), but a
  HEADLESS render assertion of the chip currently cannot pass because the whole
  @each-over-signal render path is dark on the logic backend.

* Hypothesis (unverified)
The runtime @each subscribes to a data-registry signal that the headless harness
does not populate the same way a live page's =@mcp-input= / =@data inline= seed
does; or =ST.resolveTemplateArg= / the hole resolver does not deep-resolve in the
@each→row scope under LinkeDOM. Needs tracing on a real serve vs headless.

* Acceptance
- A headless test mounts =@each($rows as $r) { <span data-o="`$r.origin.kind`">`$r.name`</span> }=,
  seeds =$rows= the way the live page does, and the rendered span carries the
  correct =data-o= + text.
- =tests/unit/templates/collection-ref-each.test.st= passes headlessly.
- The FEAT-128 origin chip then gets a headless render assertion.

* Origin
Surfaced during PLAN-041 W3 (FEAT-128) while trying to add a headless render test
for the origin chip. Data rails are done + tested; only the headless render proof
is blocked by this pre-existing limitation.

NOTE [2026-06-18]: CORRECTION (2026-06-18, PLAN-042 FUP-064 execution): the prior re-scope ("narrower than first written — only a harness-seeding gap") is PARTLY WRONG. Two distinct things were conflated:

(1) The @each-over-data DRIVE contract is REAL and now PROVEN headless. A PLAIN selector-scoped @each inside a @template body — `.sel { @each($src as $i) { &row($i) } }` — compiles to the @each primitive and renders headlessly when seeded the live-page way: mount → init → `ST.setData(name, array)` (dispatches `data:name:loaded`), and re-renders on `local:name:updated`. NEW TEST `tests/unit/templates/each-data-drive.test.st` (2 tests) pins this and PASSES headless. The original failing shape was a bare `window.SpacetimeLocal.x = [...]` assignment, which never dispatches the event — so the @each never rendered. ST.setData-after-mount is the documented, faithful fix. This satisfies FUP-064's achievable acceptance ("seed the way the live page does; assert rendered output; document the convention").

(2) BUT `tests/unit/templates/collection-ref-each.test.st` does NOT pass with seeding alone, because it uses the COLLECTION-REF form `&cards[] .cref-cards { @each(...) }` inside a @template body. PROVEN via `cargo run -- inspect --layer emit`: that template's emitted body payload carries `refs: []` and NO @each primitive — the collection-ref @each is silently dropped from the per-instance builder, so nothing renders on ANY backend (V8 or CDP), not a headless-only issue. This is the BUG-085 class, whose STRUCTURAL fix is the in-progress PLAN-039 ("Unify nested constructs in component bodies", STATE: DOING). collection-ref-each.test.st is therefore correctly a PIN for PLAN-039, not a harness bug. Annotated the test header accordingly + corrected its syntax (plain sigils, ST.setData-after-mount seeding) so the ONLY remaining failure is the PLAN-039 builder gap.
