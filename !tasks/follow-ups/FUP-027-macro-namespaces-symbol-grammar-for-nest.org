KIND: research / design decision.

* Why
The CMS =@cms= macro logically BELONGS TO / nests under =@type= — it is meaningless
on its own and only configures a =@type=. This raises a general, unanswered language
question: *what symbol and grammar express that one macro belongs to (nests under)
another?* We need this decided before =@cms= settles on a final name, so it can live
in its appropriate namespace rather than squatting the global =@= directive space.
Future nested hints (=@type.view=, =@type.index=, per-field hints, =@theme= tokens)
will need the same answer.

* The question space
Candidate notations for "the =cms= macro within the =type= namespace":

| Notation        | Example                      | Notes |
|-----------------+------------------------------+-------|
| dot             | =@type.cms { … }=            | familiar; risk of clash w/ property access =$.field=? |
| double-colon    | =@type::cms { … }=           | Rust-flavoured; clear "path" reading; verbose |
| slash           | =@type/cms { … }=            | path-like; clash w/ division / regex? |
| namespace block | =@type { %ns { cms: … } }=   | explicit container; more nesting |
| bare + scope    | =@cms= + body-scope rule     | simplest; relies on the body-scope FUP for legality; no namespace symbol |

* What to investigate
1. Lexer/parser impact: which symbol is unambiguous vs existing Spacetime tokens
   (=$.=, =&template=, =%primitive=, =@directive=, math, selectors)? Check
   =src/parser/= and =tree-sitter-spacetime/=. NOTE: the codebase is settling on
   PARENTHESES for type arguments (capture maps, =$v:balanced(';')= at
   src/parser/mod.rs:3583) — so parens are "taken" for type application; the
   namespace symbol should not collide with that reading.
2. Registry/resolution: how does =src/metasystem/registry.rs= key a namespaced macro?
   Flat name with a parent field, or a hierarchical path?
3. Authoring ergonomics: does it read well in stdlib and user code? Does it scale to
   other nested cases?
4. Relationship to body-scope (the companion FUP): namespace (naming) is likely
   ORTHOGONAL to body-scope (legality). Decide explicitly whether one implies the other.
5. Backwards-compat / migration: if =@cms= ships bare in V1, what is the rename path
   to its namespaced form?
