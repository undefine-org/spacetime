* Current ssg_unroll matching constraints (src/html/ssg_unroll.rs)
unroll_scope only injects rows when ALL hold:
1. the @each BODY is INLINE HTML (each_body_html) — NOT a template invocation.
2. the target CONTAINER is an empty element captured in the SAME .st html_blocks
   (inject_rows matches scope.selector against .st-captured blocks).
3. the source resolves to a compile-time array (now incl. file sources — DONE W6).

Real sites (unkn) violate 1 and 2:
- bodies are TEMPLATE calls: `@each($talents …) { &unkn-talent-card($t); }`
- containers are produced by section TEMPLATES (`&unkn-section-roster()`), or live in
  index.html, not the @each's own .st block.
∴ unkn's roster/services/reasons/strip @each do NOT prerender despite the data loading.

* Scope (when picked up)
1. TEMPLATE-BODY UNROLL: when an @each body is a `&template($item)` invocation, expand
   the template at build time per row (build-time template instantiation) and inject the
   resulting HTML. Reuse the template registry + the same row-binding ($item.field /
   holes) the runtime each-inline hydration uses, preserving unroll==hydrate.
2. CROSS-BLOCK / TEMPLATE-CONTAINER injection: resolve the target container even when it
   is created by a section template or lives in index.html, not the @each's own block.
3. Keep the invariant: prerender output must byte-match what runtime each-inline produces
   (so hydration adopts cleanly, no double-render).
