* The design question this raises

Lowering at the emitter is a string rewrite over opaque text — it cannot see
compound values without re-parsing. The alternative is to lower where the value
is still STRUCTURED (the CSS value parser, where a token reference could be a
node), which is more work but handles compounds for free and puts the knowledge
in one place.

Do NOT ship the string-rewrite version for compounds. A regex over CSS values is
how you turn `content: "--not-a-token"` into garbage.

NOTE [2026-08-13]: THE MODEL, AND THE ANSWER TO YOUR MARGIN NOTE.

* Your annotation (p4, at the `enum ValueNode`): "Could this be fully defined with a capture type?"

YES — and it already is, in this repo, for colour. The enum I sketched was a
parallel implementation of a pattern that ships:

    %capture_type color {
        ( $core:color_core ) | ( $wide:css_wide ) | ( $ref:binding )
    }

Named arms, tagged variants, alternation, composition by reference — a sum type
as DATA. `stdlib/capture-types/css-values.st` states the doctrine in its header:
"EVERY scalar below ends with a `( $ref:binding )` arm", because "a value
position in Spacetime is reactive", and the arm is listed LAST so a literal
always wins the alternation. The same file also records the cost of the closed
enum it replaced: "a closed `CaptureType` enum with a hand-written extractor per
arm. Adding one scalar cost ~14 Rust edit sites, measured twice."

So `ValueNode` as a Rust enum would have re-introduced exactly what PLAN-122
W1.2 deleted. The variants belong in the grammar.

ONE HONEST LIMIT (from the research, and it is real): the grammar can define the
variant VOCABULARY and shape, but the runtime still needs a GENERIC sum
representation to hold the result (`{tag, payload}` — we already have
`CapturedValue` and named-record forms) and generic dispatch on the tag. It
also cannot eliminate the lexer/CST token categories that distinguish the
sigils in the first place. The enum is not needed; a generic carrier is.

* The mathematical model: gradual typing's CONSISTENCY relation (Siek & Taha)

Not Hindley-Milner. Two relations, deliberately distinct:

  ≤  PRECISION / subtyping — DATA-defined, transitive.
     `length ≤ length_percentage`; `number ≤ time` only under a declared unit
     policy. Transitive closure over registry rows.

  ~  CONSISTENCY — the admission predicate. Accept iff `observed ~ expected`.
     Unknown ~ T and T ~ Unknown, for every T. T ~ T. Compounds are consistent
     recursively when their known components are.

THE KEY PROPERTY: `~` is INTENTIONALLY NON-TRANSITIVE. `Unknown ~ length` and
`Unknown ~ color` do NOT license `length ~ color`. That is precisely
"admit, do not claim" — the semantics we have been hand-rolling with escape
lists. Accept on `~`; propagate a CLAIM only on `≤` or a concrete grammar arm.

Unknown is therefore NOT lattice top and NOT bottom. Top-like acceptance lives
in `~`; precision stays in `≤`. This is why the naive "make unknown the top
element" instinct is wrong: top would claim everything, and we need something
that refuses to claim while refusing to refuse.

WHY A FALSE REFUSAL BECOMES IMPOSSIBLE: an unresolved reference enters as
Unknown, and the admission predicate has an unconditional Unknown rule. Later
resolution may REFINE the claim without invalidating the earlier acceptance.
A concrete literal that definitively fails its DATA grammar or the lightningcss
branch is still rejectable — the two cases are separated by construction rather
than by a list of characters.

lightningcss's `Unparsed`/deferred maps to Unknown, never to Error.

* Datalog's one genuine advantage, and why it still loses

A Datalog relation expresses the transitive closure of coercions more
declaratively than a growing matcher:

    subtype(a, c) <-- direct_subtype(a, b), subtype(b, c);
    accepts(expected, actual) <-- subtype(actual, expected);

That IS nicer than hand-rolled closure. But it only helps with a RUNTIME
interpreter whose rules are data — and ascent/crepe are both compile-time. A
hand-written transitive closure over the 14 scalar rows is smaller today than a
rule compiler that translates `.st` into generated Rust.

Keep the relational MODEL. Skip the engine.

The maximalist claim, stated so it can be argued with: Spacetime is already
unusual in that its TYPES are data. If the RELATIONS are also data, then
coercion, overload resolution, diagnostic suggestions, editor widget offers, and
migration safety all stop being hand-written mechanisms and become queries over

THE DISCIPLINE THAT MAKES IT SAFE: an edge in `≤` is a claim about the whole

silent. Anything conditional is a TERNARY relation keyed by the declaration
site, or it is not a relation at all.
