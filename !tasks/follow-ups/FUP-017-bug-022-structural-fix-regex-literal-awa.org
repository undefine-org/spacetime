The structural fix below remains.

* Scope

In-scope:
- Teach the CST lexer to recognize JS regex literals inside `%emit js { ... }` bodies so brace-bearing regexes round-trip without confusing the brace counter.
- Cover regex flags `[gimsuyd]*`, character classes `[...]` (where `}` is literal), and escape sequences `\\X`.
- Disambiguate `/` as division vs regex start using the standard precedes-token rule (regex starts after operators, `(`, `[`, `,`, `;`, `=`, `:`, `?`, `!`, `&`, `|`, `^`, `~`, return/typeof/delete/void/in/of/instanceof keywords; division otherwise).

Out-of-scope:
- Full JS lexing fidelity (we only need brace-depth correctness inside emit bodies).
- Template literals with `${ ... }` interpolation — file separately if the body-counter mishandles those too.

* Tests

- Flip =src/metasystem/tests.rs::grammar::test_brace_regex_in_emit_body_surfaces_diagnostic= from `is_err()` to `is_ok()` and verify the emit body content round-trips both `styleRe` and `simpleRe`.
- Add a positive test for character classes with literal `}` (e.g., `/[^}]/`).
