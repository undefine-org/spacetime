* Context

PLAN-122 §Unlocks item 7 + crack C9 (the table is the LANGUAGE's scalar table, not a CSS table — media/url/date/slug/relation ride the same machinery).

* Change

Let `url`/`media` %scalar_type entries carry a build-time check column: existence, dimensions, duration, poster frame, byte size. The compiler then refuses at BUILD what currently renders as a black frame or a broken image.

Motivating case (live, PLAN-128 @score):

  &broll(src: "city.mp4") in 4s out 9s;

- `city.mp4` missing → compile error at the literal's span, not a black frame at playback.
- `out 9s` beyond the real media duration → compile error naming both (trim bounds checkable ONLY because both the measure and the media are typed).
- `<image>` without dimensions → the compiler knows them, so it can emit width/height (CLS elimination) and warn on aspect-ratio mismatch.

* Why it belongs to the value layer, not to a build script

An asset-checking script is a second source of truth about what a page references; it drifts. Reading the check off the same registry entry that parses the value means "what is a media reference" has one definition. It also generalises: `date` gets a format check, `slug` a uniqueness check, `relation` a target-exists check — same column, no new subsystem.

* Edge

- Remote URLs: existence is NOT build-checkable (network at build = non-hermetic). Check shape/scheme only; document the boundary.
- Missing-asset severity should follow FUP-138's ruling (a build-time file read that fails is a build WARNING, not only a rendered stub) — align rather than invent a second policy.
- Media probing needs a decoder: prefer an existing vendored dependency behind the primitive (AGENTS: vendor + own behind a primitive, don't hand-roll).
