* Repro
#+begin_src spacetime
@template &probe-mix() {
  $open bool: false;
  <div class="mix-box">Click</div>
  .mix-box {
    @on click {
      $open <- !$open;
    }
  }
}
<main class="page"></main>
.page { &mixInst &probe-mix(); }
#+end_src
Compiles + runs correctly (the mutation fires, headless @claim confirms), but
emits: =⚠ E0909: `<-` content injection used outside component body context=.

* Root cause (partial trace, not fully isolated)
=src/pipeline/mod.rs::check_injection_outside_template= scans FormMatch
captures (=StyleProperties=/=String=/=Expr= values) for any =" <- "= or
=<-= substring, skipping only =template=/=template-inline=/=handle=/=data=
macro names. A SCOPED =.sel { @on click { $var <- expr; } }= inside a
@template body is not itself a =template= FormMatch — it is a nested
scope/selector match — so the skip-list doesn't catch it, and the scan
false-positives on the legitimate mutation's =<-=.

* Fix direction (not yet implemented — low priority, warning-only)
=check_injection_outside_template= needs to know it's inside a template's
lexical scope, not just check the immediate FormMatch's macro name. Likely
fix: thread a "within @template body" flag through scope traversal (the
same instance-scope tracking PLAN-039 already established), and skip the
injection check whenever that flag is set — mirroring the existing
=handle=/=data= carve-out.

* Priority
Low — warning-only (does not fail compilation or affect runtime behavior).
File for whoever next touches =check_injection_outside_template=.
