* Context

PLAN-122 §Unlocks item 8 — the boldest consequence, and the one that decides whether PLAN-128's central bet survives contact with the value layer.

stdlib/macros/score.st states the bet: "a website and a video differ only in WHICH SIGNAL DRIVES THE TIMELINE." That is true at the TIMING layer — a score is a pure derivation over a driver's 0..1 progress signal, so it is seekable by construction. It is NOT true at the VALUE layer: a canvas compositor, a WebGL pass, an ffmpeg filter graph or a PDF writer cannot consume `oklch(0.7 0.15 200)` or `8px` as text. Every non-browser backend would need its own CSS value parser — which is precisely the "type-as-text drift" class this plan exists to end, re-created once per backend.

* Change

Let a %scalar_type carry a repr MAP rather than a single repr:

  %scalar_type color {
    capture: color
    repr: { css: hex-or-fn, canvas: rgba-tuple, render: linear-float4 }
  }
  %scalar_type length {
    capture: length
    repr: { css: identity, canvas: device-px, render: frame-relative }
  }

One authored value, N backends, each reading its own column. The browser keeps
today's string (PLAN-122 decision 1 is unchanged and remains the default column);
other backends get a representation they can actually compute with.

* Why this is the load-bearing one

- Rendering a score to video is otherwise blocked on a value story, and nothing else in the repo makes non-CSS backends tractable — the value layer is the last text-shaped seam in the pipeline.
- Colour space becomes explicit: `render: linear-float4` says linear, `css` says sRGB-encoded — the difference that silently ruins composited video when values are strings.
- Length resolution becomes explicit: `canvas: device-px` needs a DPR; `render: frame-relative` needs frame dimensions. Making the column declare its context is what stops each backend inventing its own rule.

* Non-goal (scope discipline)

This FUP is the VALUE half only. It does not build a renderer; it removes the reason a renderer would need to parse CSS. Do not let it grow a backend — if a backend appears in the diff, re-scope.

* Acceptance

- A scalar with two repr columns emits the correct representation per backend from ONE literal, proven by a test that renders the same score to (a) a page and (b) a non-CSS surface with matching values.
- Adding a repr column requires no Rust (registry data).
- The css column output is byte-identical to today's (no regression on the browser path).

* Relation
