* Change

With grammars as data, the language server answers value-position questions STRUCTURALLY rather than by token kind or regex:

- Completion knows what is legal AT THE CURSOR: inside a `duration` → s/ms/us; inside a `color` → named colours + rgb/oklch/color-mix; inside a `%unit_set length` position → only length units. Today completion cannot know, because "which value type is this position" is not represented.
- Hover renders the grammar itself (the self-documenting property — same source as the docs gallery, FEAT-084).
- Colour swatches come from the same %scalar_type entry that PARSES the colour, so the swatch and the compiler can never disagree — deleting the private scanner.
- Diagnostics-as-you-type inherit the grammar's own error messages ("expected 3/4/6/8 hex digits"), no second message table.

* Why it is more than parity with CSS tooling

A CSS language server hardcodes the property→value-type table from a spec snapshot. Here the table is the project's own registry, so a PROJECT-DEFINED scalar (%scalar_type currency) gets completion, hover, and swatches with zero editor work. Editor intelligence extends with the language.

* Acceptance

- Completion inside a typed seed field offers exactly that field's legal vocabulary (unit list from the %unit_set, not a global list).
- lsp/colors.rs private hex scanner deleted; swatches sourced from the registry.
- Adding a stdlib %scalar_type yields completion + hover with no src/lsp changes.
