* Why
The Framer-killer admin must let a designer edit brand/theme. Today projects keep
tokens in =_theme.st= as =var(--<proj>-*)= by convention + an AGENTS.md rule (see
projects/unkn/modules/_theme.st and projects/unkn/AGENTS.md). String-scraping that
file from the admin is fragile. A first-class =@theme= makes tokens typed,
introspectable, and editable like any other generated form.

* Proposed construct
#+BEGIN_EXAMPLE
@theme unkn {
  color    accent    #FF0020;
  color    ink       #000000;
  color    paper     #FFFFFF;
  font     display   "Oranienbaum", serif;
  length   gutter    24px;
  duration reveal    800ms;
}
#+END_EXAMPLE
- TYPED tokens (color/length/duration/font/…) → the theme editor renders the RIGHT
  control per token type (color→swatch, length→slider, font→picker) using the SAME
  schema→widget logic as @type forms. Brand editing becomes "just another generated
  form."
- Compiles to the =:root { --unkn-* }= custom properties already in use, so consumers
  keep reaching tokens via =var(--unkn-*)= unchanged.
- The admin reads/writes the =@theme= block via EditAst (round-trip already handled).

* Why it's a feature, not a limitation
Editing TOKENS (not arbitrary values) makes brand integrity STRUCTURAL: a designer
picks =accent=; they cannot smear rust-orange where scarlet belongs (unkn AGENTS.md
hard rule: accent = #FF0020, NOT rust). Framer gives infinite rope; Spacetime gives a
designed palette. Constraint = feature.

* Scope / open questions
1. Grammar + parse of =@theme=; the token type vocabulary.
2. Registry representation (sibling to the type registry) + an introspection endpoint
   (extend /__spacetime/dev/types.json, or a new /theme.json) so the admin reads tokens.
3. Compile to =:root= custom properties; reconcile with the existing =_theme.st=
   =var(--*)= convention. A MIGRATION PLAN for projects already using _theme.st.
4. Could subsume responsive/dark token sets later (a design-system editor, not just a
   color picker) — note as a larger opportunity.
5. Interacts with FEAT-017 (dev panel Brand tab / CSS-var inventory + literal
   promotion) — the introspection + promote-to-token plumbing may share code.

* Acceptance
- =@theme= parses, registers typed tokens, compiles to =var(--*)= custom properties.
- An introspection endpoint exposes tokens + types for the admin.
- The admin renders type-appropriate controls and round-trips edits via EditAst.
- A migration path for =_theme.st=-based projects is documented.
