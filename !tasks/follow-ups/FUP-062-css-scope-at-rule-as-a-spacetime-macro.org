* Context — Fork 4 resolution
The unified MCP environment isolates per-bundle CSS by wrapping each bundle's stylesheet at registration time in native CSS =@scope ([data-st-region="{id}"]) { ... }=. v1 (FEAT-129) does this wrapping in the bundle-registration runtime helper (a string transform over the bundle's CSS), with a lint+document posture for the two known gaps:
- =@keyframes= are global even inside =@scope= (names collide page-wide).
- custom properties on =:root= leak across regions.
v1 asks bundle authors to avoid top-level keyframes / =:root= vars (lint warns); acceptable because bundles are small template-style functions.

* What this FUP tracks
The PROPER primitive: a Spacetime =@scope= at-rule authored as a stdlib macro (=%macro scope { %scope selector ... }=) that:
- rewrites keyframe names per region (namespace by region id) so animations confine,
- confines =:root=/=html= custom-property declarations to the region selector,
- is the one author-facing mechanism for scoped CSS (not just an MCP-internal registration transform).
Generalises MCP region isolation into a language-level affordance any Spacetime component can use — consistent with the elegance bar (one mechanism, deletable special-case).

* Harmony note
This must REPLACE the MCP registration-time @scope wrapping (delete that special-case in FEAT-129) once it lands; the MCP registration helper calls the macro instead of hand-wrapping. Not parallel impls.

* Out of scope for the unified-env v1 wave
Everything in this FUP. Filed for after PLAN-041 ships + the @scope macro is designed on its own merits (uses beyond the MCP).
