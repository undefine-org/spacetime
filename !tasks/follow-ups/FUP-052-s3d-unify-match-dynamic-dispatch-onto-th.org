* The blocker (precisely characterized)
A body-root render-dispatch (`&$w()`, `@match $kind {...}`) must resolve its
NAME/SUBJECT against the HOST INSTANCE's params at mount. CONFIRMED FACT
(stdlib/primitives/template.st:247,275): the factory seeds params on the instance
root synchronously via `ST.set(element, name, data[name])` BEFORE append \u2014 so
`ST.resolve(node, name)` from a body descendant DOES resolve the param. The S3d
attempt (committed-then-reverted: template-invoke-dynamic macro +
invoke-template dynamic resolution) failed with "Template not found: w" because
the body-root `&$w()` flat match emitted as a selector-init with no instance
container under the resolving node \u2014 the WRONG mount path. The injection unifier
(injection_scopes_from_body, S3c) already solved exactly this shape for
content-bindings: a body-root construct becomes a SYNTHESIZED nested scope on the
template that mounts per-instance via registerSelectorInit and resolves via
ST.resolve. Reuse that pattern.
