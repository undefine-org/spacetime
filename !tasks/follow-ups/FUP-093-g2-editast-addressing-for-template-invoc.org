* The gap (verified 2026-06-20)
EditAst's address resolver (handle_edit_ast_inner -> parse_ast_selector) matches a
directive by macro_name against ast.scopes[].matches (FormMatch). But &template
INVOCATIONS are NOT FormMatch directives: they parse as ElementRefStmt/ElementRef
CST nodes (src/syntax/cst/ast.rs:549-554). So "<css> §card" will NOT locate a
&card(...) call -> the instance-args editor + the &template editor target have no
write path.

* The fix
Add a DISTINCT address-resolution path for template invocations:
- resolve a &name(args) call's source span via the element-ref AST (ElementRef
  carries the call + its args; find the target invocation by its position/scope or
  a data-st-id-style provenance).
- once the span is known, REUSE apply_text_patch (the same named-arg patcher that
  already handles paren-arg-lists) to rewrite the invocation's named args.
- expose this as an EditAst arm (or extend the selector grammar with a template-
  invocation form, e.g. "<css> &card" or an &-prefixed selector) so the inspector
  emits a correct-by-design patch.

* Complete implementation design (2026-06-20, turnkey) \u2014 ready to build as one verified unit
Investigated deeply this session. The pieces + their exact sites:

** What's already proven (no work needed)
- apply_text_patch (src/sync/handlers.rs:626) rewrites a named arg WITHIN a span
  by finding `key:` and replacing the value to the next depth-0 terminator,
  INCLUDING the `)` of a paren-arg-list (BUG-098 logic). So given an invocation's
  span, patching its named args WORKS TODAY (verified for @macro params, FUP-089).
- TemplateRef is harvested with span info available: scope_refs builds from
  m.span.start (parser/mod.rs); the FormMatch HAS the span.

** The 3 layers to build
1. CARRY THE SPAN: add `pub span: SourceSpan` to TemplateRef
   (src/syntax/form_match.rs:205). BLAST RADIUS (measured): 11 construction sites
   + Serialize (so every bundle `refs: [...]` snapshot changes) + the feat119
   oracle. Use #[serde(default)] + #[serde(skip_serializing_if)] to MINIMIZE
   snapshot churn (a default/zero span serializes to nothing). Populate it in
   invoke_refs_from_matches (parser/mod.rs, the helper extracted this session)
   from m.span.
2. PROJECT THE ADDRESS: in stage_structure_from_bundle (src/mcp/live.rs), add to
   each node an `addr: { file, invoke_span: [start,end] }` (file = the guest's
   resolve context). The walk already has the TemplateRef per child; carry its
   span through `walk(... r, ...)` (r already passed for ref_name/args).
3. EDITAST BY SPAN: extend the EditAst handler (src/sync/handlers.rs
   handle_edit_ast_inner) with an invocation-address form. Cleanest: a selector
   like `<file> @invoke <start>-<end>` OR a new patch field `__invoke_span`.
   Resolve to the span directly (no parse_ast_selector CSS lookup needed \u2014 the
   span IS the address), then call apply_text_patch(content, start, end, patch)
   with the named-arg patch. REUSES apply_text_patch (no parallel patcher).

** Disambiguation is FREE with spans
The span uniquely identifies ONE invocation (vs occurrence-index gymnastics). A
template called N times -> N distinct spans in the projection -> the inspector
edits exactly the selected instance. No data-st-id hashing needed for the .st
edit (data-st-id stays for the rendered-DOM click->select mapping; the span is
the source-write address).

** Build + verify as ONE unit (why not piecemeal)
The 3 layers only deliver value together + need the edit->render round-trip
verified live (mount a guest with &card("A") twice, edit instance 1's arg in the
inspector, confirm ONLY that instance updates + source patched). Build behind a
single commit with: a handler unit test (patch one invocation's named arg by
span, assert the .st diff), a multi-invocation test (two &card calls, patch the
2nd, assert the 1st is untouched), and a live builder gate. Do NOT land the
TemplateRef span field alone (wide snapshot churn for no standalone value).

** Sequencing
After BUG-130 (so @each-driven children are addressable too) OR independently for
statement-form invocations. Pairs with PLAN-051 B5 two-level Instance mode (the
inspector's editable rows write through this).
