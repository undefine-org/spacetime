* Symptom — measured, and SILENT

Two related defects in the capture-type PATTERN parser, both involving a
backtick, both found while writing the `compound_value` production.

** 1. `balanced('`')` drops its own production

A `%capture_type` whose pattern contains `balanced('`')` is absent from the
registry after load. Its NEIGHBOURS load fine, so nothing looks wrong — no
diagnostic, no warning, just a production that is not there. Measured with a
three-production probe file:

: %capture_type m1 { $b:balanced('`') }   -> MISSING
: %capture_type m2 { $b:balanced('$') }   -> PRESENT
: %capture_type m3 { $b:balanced(';') }   -> PRESENT

The delimiter itself parses correctly — a debug print shows
`Balanced('`')` in the AST — so the loss happens after pattern parse, or the
production's span is mis-scanned in the enclosing file.

** 2. A backtick literal AFTER a capture destabilises the pattern

A LEADING literal is fine: `%capture_type hole { "`" ( $binding:binding |
$name:ident ) "`" }` ships and works (11/11 in `tests/value_node_arm_test.rs`).
But a backtick literal placed after a capture does not:

: %capture_type p1 { $b:balanced(';') "`" ( $g:binding | $n:ident ) "`" }

matches nothing at all, including inputs it obviously should match.

* Why it matters

It blocks the COMPOUND HOLE arm of `value_node` — `border: 1px solid `$c.tint``,
a CSS shorthand whose colour slot is a hole. The sibling compound arms for
bindings and token references both work (`balanced('$') $binding:binding` and
`balanced('-') $token:token_ref`), so the shape is right and only the backtick
delimiter fails.

Nothing is refused TODAY: all 19 corpus values with a non-leading backtick are
diagnostic prose inside quoted strings, not declaration values. But the moment
one appears it is a FALSE REFUSAL — a build the author cannot fix — which is the
failure mode this whole arc treats as worse than a missed diagnostic.

Defect 1 is the more serious of the two on its own terms: a silently-dropped
production is exactly the class of failure `every_capture_type_file_on_disk_is_embedded`
was written to catch, one layer down.
