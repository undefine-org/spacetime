* Problem
FUP-042 made the ST.Editable MODEL region-complete (project/lift/validate/resolvePath
all descend regions, proven by 29 model tests + nested-tree fuzz). But the LIVE SURFACE
(stdlib/editable/primitives/editable-surface.st) predates regions and is FLAT-ONLY:
- E.project(doc) ✓ already dispatches projectBlock → region blocks RENDER correctly.
- E.insertText/deleteRange/splitBlock ✗ all call E.resolve (flat), never resolvePath.
- E.posFromDOM / E.domFromPos ✗ the selection bridge: collectTextNodes() walks straight
  through region hosts (data-st-region), flattening all regions into one text run.
∴ A region block (list, columns) renders in the admin but CANNOT be edited: the caret math
collapses regions, so typing in the right column lands at the wrong position. This is the
"edit ops through PATHs / cross-region selection needs CDP" deferral from the FUP-042 close-out.

* Decision (USER, 2026-06-12)
Approach A: ONE contenteditable host, PATH-aware selection bridge. DOM stays a render
target (the kernel invariant) — do NOT give the browser back authority via nested
contenteditables (approach B rejected: nested-CE selection leakage, focus/paste/undo
coordination). Spacetime-native, beautiful, powerful.

* CDP IS available here
CORRECTION to inherited assumption: /usr/bin/google-chrome-stable exists, src/cdp.rs
find_chrome() locates it, `--features cdp` wires chromiumoxide. The live-click proof CAN
run here. Author the @drive CDP test AND headless-provable mapping unit tests.

* Waves (each proves itself on the rung it can)
- S1 PATH selection bridge: posFromDOM/domFromPos descend data-st-region hosts → return/accept
  PATH-consistent integer positions (docSize-consistent across region boundaries). The MAPPING
  LOGIC is unit-testable against projected DOM in V8 (LinkeDOM) — no real browser needed.
- S2 Region-aware ops: insertText/deleteRange/splitBlock route through resolvePath so an op
  inside a region edits that region's content, not a flattened run. Pure, fuzz-testable.
- S3 Surface rewire: editable-surface.st beforeinput funnel calls the path-aware ops + bridge.
  Thin glue.
- S4 CDP @drive gate: live-click region editing (type in a list item, in the left column;
  caret lands correctly; client doc == server-validated doc). Run under `--features cdp`.

* Gate
A project with @editable + a region block (list or columns): user clicks into a region,
types, caret is correct, persistence round-trips, server validates. Flat docs unchanged
(byte-identical floor — all existing surface behaviour preserved).
