** 1. [FIXED, commit 2a032acf] Quote-wrapped param defaults on canvas
A composed guest with declared defaults rendered `"Ship faster"` WITH literal delimiter quotes. Root cause: ParamSpec.default carried the raw source token; the JSON-bundle path serialized the quotes as literal content (the JS-codegen path was correct). Fixed by evaluating the token to its value at ParamSpec::from (eval_param_default). Live-confirmation pending the next server restart (running server holds the pre-fix binary; compile is in-process). An element-binding OVERRIDE already rendered clean ("Ship at lightspeed"), isolating the bug to the default-seed path and proving the fix direction.

** 2. [FRICTION] puppeteer `open {url}` lands on about:blank
The browser tool's `open` with a url left the page at about:blank; a SEPARATE `goto` was required to actually navigate. Every automation/verification session pays this tax. Worth a harness-level fix or a documented convention (always goto after open). NB: this is a Spell-tool friction, not a Spacetime one.

** 3. [FRICTION] Binding-row inputs show the PARAM NAME as placeholder, not the value
In the inspector's SELECTED FRAME section the title/subtitle/cta inputs render `title`/`subtitle`/`cta` as PLACEHOLDER text (the param name), so a populated field reads as empty/unlabeled. Contrast: the EDIT CONTENT input (node-detail) shows the actual value `Ship faster`. Two editors for related concepts surface the current value inconsistently. Polish: show the live value in the binding-row input (value=`$b.value`, which is already populated — the placeholder is redundant with the adjacent `mcp-param-name` code chip).

** 4. [FRICTION] Two selection-highlight vocabularies for ONE $selectedNode
The canvas marks the selected node with the `.is-selected-node` CLASS (dashed ring); the navigator marks it with the `data-active` ATTR. Both are driven by the same `$selectedNode` signal (correct, unified), but a reader maintaining the styles must learn two mechanisms for one concept. Polish: converge on a single reactive marker (e.g. `data-selected` attr, or the class) across both hosts so the selection vocabulary is singular.

** 5. [POLISH] `0 param(s)` on an element node reads oddly
The node-detail card shows `$node.param_count param(s) · depth N`. For an ELEMENT node (e.g. h1.hero-title with a $title hole) param_count is 0 — technically true (elements have bindings, not params) but it sits directly above the EDIT CONTENT/title control, so "0 param(s)" then an editable "title" reads contradictory. Polish: for element nodes show binding_count (or suppress the arity line and show "1 binding") so the header agrees with the controls below it.

** 6. [VERIFICATION FRICTION, not a product bug] Synthetic DOM events don't reach page-world mcp-action listeners
puppeteer `dispatchEvent(new Event('change'))` and `fill`+Enter did NOT fire the `@mcp-action` change handler (0 signal posts). Calling the handler function directly (input.__stMcpHandlers[key]({target})) worked end-to-end — regionInput override set + canvas updated to "Ship at lightspeed". So the wiring is SOUND; the friction is that isolated-world synthetic events don't cross into the page-world listener. For future live-edit verification: drive via real puppeteer keyboard type + a genuine blur (click elsewhere), or invoke the handler directly. Document in docs/testing/AUTOMATION.md.
