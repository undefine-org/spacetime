Established by PLAN-117 W1: =tests/lang/README.md= defines one placement rule.
This FUP applies it to the strays.

* Problem

=.test.st= files currently live in five places with no rule distinguishing them:

| location | count |
|----------+-------|
| =tests/= (root) | 12 |
| =tests/bugs/= | 17 |
| =tests/integration/= | 10 |
| =tests/component-model/= | 5 |
| =tests/e2e/= | 1 |

Rust tests are equally split: =tests/bug_*.rs= at root vs =tests/integration/*.rs=.
Placement tells a reader nothing about what a file proves.

* Rule (already documented)

See =tests/lang/README.md=. Language-surface behaviour -> =tests/lang/<area>/=;
bug regressions stay in =tests/bugs/= keyed by BUG id; component semantics stay
in =tests/component-model/=; pipeline integration stays in =tests/integration/=.

* Why this was NOT done inside PLAN-117 W1

A rename storm across ~45 files would have buried the actual design diff. The
rule was established and applied to NEW files first, deliberately.

* Scope

- Classify each of the 12 root-level =.test.st= files (language surface vs bug
  regression vs dev-tooling) and move accordingly. The =dev-*.test.st= cluster
  (10 files) looks like a =tests/dev-tools/= area rather than =tests/lang/=.
- Root =tests/bug_*.rs= -> alongside their =.test.st= siblings in =tests/bugs/=,
  registered via =[[test]]= entries (cargo does not auto-discover subdirs - see
  the =registry_addressing_diagnostics= entry in Cargo.toml for the pattern).
- Update any path references in docs and AGENTS.md command lines.

* Acceptance

- every =.test.st= sits under a directory whose README explains what it holds
- =cargo run --features headless -- test tests/ --headless= runs the same count
  before and after (no file silently lost in the move)
- =cargo test= target list unchanged except for intended additions
