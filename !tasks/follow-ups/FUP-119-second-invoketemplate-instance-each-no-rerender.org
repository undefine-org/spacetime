* Found by
BUG-188 fix verification (PLAN-078, 2026-07-18): the pin's uppercase test
invoked the same @template ('price-list') into a SECOND host element; its
@each list never re-rendered on a later global ST.setData — it kept showing
the first instance's data (observed ELECTRONICS where WIDGETS was set).

* Symptom
Two `Spacetime.invokeTemplate('same-template')` instances bound to the same
global @data list: the FIRST instance updates on ST.setData, the SECOND
does not (or vice-versa wiring depending on init order). Verified with
direct probes in a headless test world.

* Impact
Dashboard-style pages repeating the same list component in multiple regions
bound to shared data silently show stale content in all but one region.

* Notes
- The first instance updates correctly; the second instance's @each watcher
  appears never to fire (or never gets wired by ST.initElement).
- Workaround used in the BUG-188 pin: distinct @data + distinct @template
  per instance.
- Needs a root-cause dig in the @each runtime binding + invokeTemplate /
  ST.initElement wiring (public/runtime/*.js), then a RED pin with two
  instances of one template on shared data.
