* Origin
Deferred from PLAN-024 W5 (text module). The heaviest/most experimental of the
proposed text macros; no W5 demo required it, so it was left out to ship the
module lean. The other four (@measure/@balance/@fit + reveal-lines fusion) landed.

* What
=@flow(around: &figure)= — editorial text that wraps AROUND a floated/absolute
element (image, pull-quote), which plain CSS cannot do for arbitrary shapes. Uses
the vendored pretext rich layout API: =prepareWithSegments= + per-line
=layoutNextLineRange(prepared, cursor, maxWidth)=, where each line's maxWidth is
narrowed by the obstacle's bounds at that line's vertical band. Render the laid-out
line ranges as positioned spans (or via a canvas/SVG text path for shaped flow).

* Shape (text module, follows the established pattern)
- =stdlib/text/primitives/flow-text.st= (%emit js, references the pretext global)
- =stdlib/text/macros/flow.st= (@flow(around: &obstacle, ...))
- register in =stdlib/text/index.st=; exports already include layoutNextLineRange?
  -> add =layoutNextLineRange= / =layoutNextLine= to pretext-entry.ts + %vendor
  exports + PROVENANCE, then =cargo run -- vendor build text --force=.
- emit-level test in =tests/text_module_test.rs= (flow primitive emits, demand-injects)
- demo: =demos/editorial-flow/= (text wrapping a floated figure) — the "CSS can't
  do this" showcase.

* Risks / open questions
- Obstacle geometry: rectangular band is straightforward; arbitrary shape (alpha
  mask / polygon) is a bigger lift — scope rectangular first.
- RTL + multi-obstacle layout interaction.
- Accessibility: keep a normal-flow sr-only copy (mirror reveal.st's srSpan).
