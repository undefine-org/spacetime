#+STATE: ITEM
#+CUSTOM_ID: FUP-152-tilde-retirement-needs-a-migration-wave

* The correction

SIP-001c recorded `~` as retirable this wave on the basis that it was "live in
lexer/parser/AST/registry, **zero stdlib `%form` uses**". Measured (2026-07-26,
PLAN-121 W1.4):

REMEASURED per scope (2026-07-26, after review found the first figures
mis-scoped). Method: =grep -rhoE '~[A-Za-z][A-Za-z0-9_-]*'= over =*.st= and
=*.st.md=, counting OCCURRENCES (not lines), per directory:

| scope    | `~name` occurrences |
|----------+---------------------|
| projects |                 295 |
| tests    |                  79 |
| stdlib   |                  54 |
| demos    |                   5 |
| web      |                   2 |
| examples |                   0 |
| **total**|             **435** |

Tilde DECLARATIONS (=[%@]preset <kind> ~name=): **97**.

The first pass reported 267 / 106. Both were wrong: 267 counted matching LINES
in =projects/= only (missing =tests/=, =stdlib/=, =web/= entirely, and
under-counting multi-occurrence lines), and 106 conflated tilde declarations
with =&=-sigil ones the retirement does not touch. The corrected total is
LARGER, which strengthens the deferral rather than weakening it.

NB =tests/= at 79 matters most for the wave: those are executable and must be
migrated with everything else, and the original figure would have left them out
of the gate.

Live in `stdlib/macros/presets.st` (43 easing/duration/style presets), in
`demos/spacetime-docs/`, in tracked `tests/`, and in the
**`projects/ora-ventures.com/` landing site** across at least six modules.

The original survey searched for `~` in `%form` PATTERNS. It is not used there —
but that was never the question. `~` is used in `%preset` DECLARATIONS and at
every CONSUMPTION site (`easing: ~ease-out-expo;`). Retiring it as "dead" would
have broken a live project silently.

* What was done anyway (kept)

`tests/css_combinators_test.rs` landed FIRST, asserting that the INFIX `~`
(CSS's general sibling combinator, `.a ~ .b`) survives — including chains and
alongside `+`, `>`, and descendant. That test was the precondition for any
retirement and is worth having regardless: `parse_selector`'s TILDE arm sits
beside GT and PLUS, and nothing else covered it.

* What retirement actually requires

Not a deletion — a MIGRATION WAVE, of the same shape as the `@on`/`@scroll`
cutover:

1. A `%migration` capsule owning `%preset` + `~name` verbatim, so existing
   sources keep compiling while `@version` predates the wave.
2. A `%rewrite` rule mapping `@preset easing ~x: v` -> the `@form` equivalent
   (SIP-001c makes easings `--ease-*` forms), and every `~x` consumption site to
   `--x`.
3. Idempotence + compiled-output-equivalence gates over all **435** occurrences
   across =projects/=, =tests/=, =stdlib/=, =demos/= and =web/= — not just
   =projects/=.
4. Prose/comment occurrences must NOT be rewritten. A =%rewrite= operating on
   source slices needs to be syntax-aware here, or documentation showing the old
   syntax gets silently mangled.

∴ `~` retirement belongs in PLAN-121 W6 (migration) alongside the `@on` cutover,
NOT in W1 (grammar foundations). Sequencing it early would mean migrating twice.

* Correction: =parse_preset_ref()= has SEVEN call sites, not three

SIP-001c says "three call sites". Measured: =src/syntax/cst/parser.rs= lines
363, 983, 1163, 1470, 1806, 2593, 3526. Anyone using the spec's number as the
removal map would leave four parser contexts still accepting the retired form.

* Why this matters beyond `~`

This is the second load-bearing assumption about `~` to fail: the first was
"TILDE probably isn't used for CSS sibling combinators" (it is —
`parse_selector`, beside GT/PLUS). Both were stated from memory of a grep rather
than from a measurement. The SIP's deletion list should be re-measured
item-by-item before W6 plans around it.

* Acceptance

- SIP-001c's `~` claim is corrected (done).
- `~` retirement is scheduled in the migration wave with the 267 sites counted.
- Every other entry on SIP-001's deletion list is re-measured the same way.
