* Context

PLAN-122 §Unlocks item 4. FEAT-108 derives — `$hover : $brand.scarlet | darken(0.12)`, `$muted : $brand.ink | alpha(0.55)`, `mix(...)` (live in demos/cms-testbed/index.st) — compute at RUNTIME today, because the input is a string that src/color/mod.rs parses at compute time.

* Change

When a derive's inputs are all typed literals (no signal in the chain), fold at BUILD time and emit plain CSS custom properties. The page then ships NO JavaScript for token derivation.

  @data inline $brand Brand : { scarlet: #FF0020 };
  $hover : $brand.scarlet | darken(0.12);
  →  :root { --hover: #cc0019 }        // no runtime, no ST.resolve, no color parse

Mixed chains (a derive over a signal — theme switching) keep the runtime path; the fold is a static-input optimisation, not a restriction.

* Why it matters beyond bytes

AGENTS: "Spacetime websites should NOT have custom javascript; they should ONLY rely on Spacetime for everything." Runtime token derivation is Spacetime shipping script to do what CSS can hold statically. Folding makes the common case (a brand palette derived once) genuinely static — better first paint, no FOUC on tokens, and the emitted CSS is inspectable/diffable.

* Acceptance

- cms-testbed: $hover/$muted/$tintbg appear as literal custom properties in the emitted CSS; the emitted JS contains no darken/alpha/mix call for them.
- A derive over a signal still emits the runtime path (proves the fold is scoped, not global).
- Fold result is byte-identical to what the runtime produced for the same input (a differential test against src/color/mod.rs).
