* Why #A
A SELECTABLE LIST is a universal UI primitive (a navigator, a tab bar, a menu, a
data grid, a kanban). Today Spacetime cannot express "highlight the @each item
whose id equals an EXTERNAL selection signal" in pure Spacetime. This blocks the
PLAN-051 builder navigator's selected-row highlight (B3) AND every other
selectable list. It is the highest-leverage substrate strengthening surfaced by
the builder build.

* The need (concrete)
@each($items as $item) { &row($item); } where the row for which
`$item.id == $selectedSignal` should get a reactive `.is-selected` class. The
selection signal is EXTERNAL to the @each item (set by a click handler).

* Verified closed paths (investigated 2026-06-20, all confirmed non-working)
1. Reactive ATTR with a comparison hole: `data-active="\`$node.id == $selectedNode\`"`
   on the template root renders NULL (attr dropped). Even a pure item-only
   comparison `\`$node.depth == 1\`` renders null. So a backtick hole in ATTRIBUTE
   position does NOT support a binary/comparison expression (only a bare path
   like `$node.field`), despite docs/language/data-and-rendering.md saying a hole
   is "a full Spacetime expression". GAP A: attr holes are path-only.
2. Reactive CLASS inside a @template body: `.mcp-nav-node { .is-selected: $node.id
   == $selectedNode; }` inside @template &row($node){...} FAILS compile — `$node`
   is read as an undeclared LOCAL STATE ("Declare it with: $node bool: false"),
   not the template PARAM. GAP B: a reactive-class predicate in a template body
   can't see the template's params.
3. Reactive CLASS in the @each body: the @each %form only admits
   `$invocations:template_invocation+` + animation clauses (:entering/:exiting/
   :move) \u2014 no reactive-class slot. GAP C: @each body has no reactive-class slot.
4. External signal in an @each item template HOLE: `data-sel="\`$selectedNode\`"`
   (a non-item signal) also renders null in an @each-rendered template. GAP D:
   @each item templates may not resolve outer-scope signals in holes.

* The functional state today (what DOES work)
Click -> $selectedNode <- $.dataset.node (the proven $.dataset idiom) -> a
FILTERED @each `@each($struct as $n, when $n.id == $selectedNode)` correctly
re-renders the selected node's detail in the inspector. So selection + filtering
on an external signal WORKS at the @each-container level; only the per-item
in-list HIGHLIGHT is missing.

* Candidate fixes (for the design pass; pick the one that generalizes best)
- FIX-A (attr holes support expressions): make a backtick hole in ATTRIBUTE
  position evaluate a full expression (incl. ==, &&) like text holes claim to.
  Smallest surface IF text holes already do; verify text-position first.
- FIX-B (template params visible to a template-scoped reactive class): let a
  reactive-class predicate inside a @template body resolve the template's PARAMS
  (not just local state). Makes "self-styling components" possible generally.
- FIX-C (@each item templates resolve outer signals): allow an @each item
  template's holes to close over outer-scope signals (GAP D). Most powerful;
  biggest semantics change (capture + subscription per item).
- FIX-D (a built-in selection affordance): a first-class `@each(... selected:
  $sig key: $item.id)` that adds an `.is-selected` class to the matching item.
  Narrowest, but DATA-as-feature: selection is common enough to be a primitive.
  Likely the cleanest (one registry entry, generalizes to every list).

* Recommendation
Investigate FIX-A first (is it just attr-position holes? a small fix unblocks the
most). If the comparison-in-hole is fundamentally text-only, prefer FIX-D (a
selection clause on @each) as the elegant, data-as-feature primitive \u2014 every
selectable list benefits, one mechanism. Verify with a RED test: a list whose
selected row gets .is-selected from an external signal.

* Root-cause narrowing (2026-06-20 investigation continued)
Traced the attr-hole failure deeper:
- PARSER: attr-position holes and text-position holes BOTH capture the full inner
  expression as the SAME HTML_HOLE CST node (src/syntax/cst/parser.rs:1999-2010 +
  the attr-string branch ~2100). The parser does NOT restrict the expression \u2014
  `$node.depth == 1` is captured whole in both positions.
- TEXT position WORKS at codegen: a comparison hole in text emits a real JS
  expression (verified: built /tmp probe, the emitted spacetime.js contains
  `depth == 1)` as an evaluated comparison).
- So the divergence is in HTML_HOLE -> reactive-binding LOWERING, which differs by
  POSITION (text child vs attribute value). The attr-value lowering path is where
  a comparison/external-signal hole drops to null. THAT is the fix site.
- ALSO confirmed (separate from comparison): an EXTERNAL signal `\`$selectedNode\``
  (no comparison) in an @each item template attr ALSO renders null \u2014 so the
  attr-value lowering may only subscribe to ITEM-scoped paths. Two sub-gaps at
  the same site: (i) binary expressions, (ii) outer-scope signal subscription.
- ∴ FIX-A is now precise: the HTML_HOLE->attr-binding lowering must (i) evaluate a
  full expression and (ii) subscribe to its full dependency set (item + outer
  signals), matching what the TEXT-position lowering already does. Best lead:
  find where text-hole lowering builds its dep set + expression eval, and bring
  the attr-hole lowering to parity (likely they should share one lowering).
- Recommendation refined: FIX-A (unify attr-hole lowering with text-hole lowering)
  is now the FIRST thing to try \u2014 text already does it right, so this is parity,
  not new semantics. FIX-D (selection clause) remains the fallback if attr-binding
  reactivity is structurally item-only by design.

* EXACT ROOT CAUSE LOCATED (2026-06-20, deep trace) \u2014 ready to fix
The mechanism is precisely identified at src/syntax/form_match.rs.
- transpile_signal_expr_with(expr, scope) (form_match.rs:1013) rewrites EVERY
  `$name` in a hole via signal_read(scope, name) with ONE scope for the whole
  expression. In an @each item template, scope = SignalScope::Element, so BOTH
  `$node` (a template PARAM \u2014 correctly element-scoped) AND `$selectedNode` (an
  EXTERNAL page signal) become `ST.get(__el, '...')`. The external signal isn't on
  the item element's scope \u2192 null. THIS is why `\`$node.id == $selectedNode\``
  renders null in an @each item template attr (and text).
- collect_signal_deps (form_match.rs:1066) ALREADY returns both ["node",
  "selectedNode"] correctly \u2014 dep detection is fine; only the READ SCOPE is wrong.
- html_reactive.rs lowering is correct for single-scope holes (docstring shows
  reactive attr expressions work); the bug is the SINGLE-SCOPE assumption when an
  item template references an outer signal.

** The fix (scoped, well-defined)
signal_read must choose scope PER-NAME inside an item template: a name that is a
template PARAM or a declared LOCAL STATE \u2192 Element scope (ST.get(__el, name)); any
OTHER `$name` \u2192 Global/page scope (the page signal store). This needs the
transpile to know the template's param + local-state name set (available at
template-scope construction). Plumb that set into transpile_signal_expr_with (or a
new transpile_signal_expr_in_template(expr, params, locals)) so each `$name` reads
from the right store, and html_reactive subscribes each dep to its correct store.
- Watch: the WATCH side (ST.watch) must subscribe the external dep to the GLOBAL
  store, the param/local deps to the element store \u2014 mirror the per-name scope.
- Test (RED->GREEN): an @each list where each item template references an outer
  selection signal in a hole; assert the matching row reacts when the signal
  changes (the PLAN-051 navigator highlight is the live consumer).

** Why this is the elegant fix (vs FIX-D selection clause)
This makes ANY outer signal usable in ANY item template hole \u2014 not just selection.
It generalizes: per-item highlight, per-item conditional content, per-item theming
from a global theme signal, etc. One scope-aware transpile change unlocks the
whole class. FIX-D (a bespoke selection clause) is narrower. Prefer this.
Estimated surface: transpile_signal_expr_with + its callers (thread params/locals)
+ the watch-subscription scope in html_reactive. Medium, well-bounded.
