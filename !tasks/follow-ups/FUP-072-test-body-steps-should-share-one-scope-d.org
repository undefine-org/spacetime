* Parent
BUG-108 fixed the @let "X is not defined" cluster (376/238 → 452/162) with a targeted fix: @let emits a bare global assignment, and emit.rs uses `let el` (not `const el`) when a fragment reassigns `el`. This works but is a PER-NAME workaround around a structural mismatch.

* The structural mismatch
A @test body is conceptually ONE sequential scope, but the pipeline compiles each step (@let/@eval/@then/@when/@assert) as a separate file-scope directive wrapped in its OWN IIFE `(function(){ const el = document.body; <step> })()`. Consequences:
- A `const`/`let` in one step is invisible to the next (why @let must leak a global).
- Every step re-injects `const el = document.body`, so `el` can NEVER be rebound to persist across steps. Tests like tests/unit/assertions/binding.test.st do `@let (el = querySelector(...))` then `@eval (ST.set(el, ...))` in the NEXT step — where `el` is document.body again, so the signal lands on the wrong element and the later `@then $sig on .selector` reads undefined. ~14 binding/state residual failures stem from this.

* Proposed fix (principled)
Make test-body step directives share ONE scope: emit them as `JsScope::Inline` (no per-step IIFE) WITHOUT the `const el = document.body` preamble, so the @test async fn body is a single lexical scope. Then `@let (NAME = value)` → a normal `const NAME = value` visible to every later step, for ANY name including `el`, with no global leak and no per-name `let` workaround.

Design questions:
- How to mark a directive as "test-scoped / inline"? The test macros (stdlib/testing/test.st) have no `%scope`; JsScope is decided in src/pipeline/expand.rs::ir_to_expanded by Phase/selector/exports. Options: (a) a macro attribute (`%scope inline` / a `test` phase) the test macros opt into; (b) the runner compiles a @test body as one fragment rather than N file-scope directives; (c) detect the test context. Prefer (a) — a declared, data-driven property, consistent with the metasystem.
- The `const el` preamble exists for selector/global primitives that use `el`. Test directives that DON'T reference `el` shouldn't get it. expand.rs already returns `el_init: None` for selectorless globals with no exports/cleanup — yet the emit still shows `const el`; investigate why (the synthetic emit-js path may force Body). Fixing that root removes the preamble for @let/@eval naturally.
- Must NOT regress the IIFE isolation that media-query / selector primitives rely on (two `const mql`). Only TEST-BODY directives change scope, not site directives.

NOTE [2026-06-19]: FIXED 2026-06-19 (root-cause variant of the proposed fix). The spurious per-step `const el = document.body` preamble came from ir_to_expanded (src/pipeline/expand.rs): a file-level test directive resolves through `.with_selector(...unwrap_or_default())`, turning selector None into Some("") , and the Phase::Global arm treated `Some("")` (empty) as `Some(_) => ElInit::Body` → preamble. Fix: treat an empty-string selector exactly like None — only bind `el = document.body` when the primitive actually %yields exports or registers %cleanup; otherwise el_init=None (no preamble).
