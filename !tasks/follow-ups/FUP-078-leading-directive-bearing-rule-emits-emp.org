* Symptom
When the FIRST CSS rule in a .st file carries a directive (e.g. `h1.x { @balance(...) }`
or `canvas.a { @stage{...} }`) and NO plain CSS rule precedes it, the
`/__spacetime/runtime.js` route emits 0 bytes (HTTP 200, content-length 0). `cargo run
-- check` passes, masking it. Adding any preceding plain rule (`body { margin: 0 }`) fixes
it -> 1MB+ runtime.

* Reproduced (2026-06-20, not 3d-specific)
- core1.st: `@import "stdlib/text"` + `h1.x { @balance(lineHeight:1.2) }` -> 0 bytes
- core2.st: same + leading `body { margin: 0; }` -> 289KB
- Same with `stdlib/3d` `@stage`. So it's a CORE emit/codegen edge keyed on
  "first scope block is directive-bearing", independent of which module.

* Impact
Low for authored sites (they always have page-level CSS first), but it's a silent
foot-gun: `check` is green, the page is blank, no diagnostic. Found while validating
stdlib/3d (PLAN-050) - worked around by ensuring showcases lead with a `body {}` rule.

* Likely area
src/emit or src/pipeline runtime-route assembly: probably the first scope block is being
consumed as a file-leading construct (similar class to BUG-070/BUG-047 import-swallow).
Needs: a failing test (leading directive rule -> non-empty emit) then fix.
