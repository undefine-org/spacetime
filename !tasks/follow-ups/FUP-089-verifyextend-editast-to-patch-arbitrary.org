** Mechanism (verified)
1. Address resolves to a SOURCE SPAN: "<css> §<directive>" (scoped directive) or
   "$name §data" (file-scope binding). Resolved by scanning ast.scopes for the
   scope whose matches contain the directive (handles a selector appearing in
   multiple blocks).
2. apply_text_patch(content, span.start, span.end, patch): for each patch key,
   find "key:" (bare directive arg) or "\"key\":" (object-literal entry) WITHIN
   the span, replace the value up to the next DEPTH-0 , ; ) ] } (respects nested
   ()[]{} + quoted strings).

** What ALREADY WORKS (no new code)
- @macro(named: arg) PAREN-ARG-LIST params are patchable: the value-terminator
  logic EXPLICITLY handles "the ) of a paren-param list" (BUG-098 comment). So
  @object(roughness: 0.15) + patch {roughness: 0.3} rewrites the arg TODAY, once
  the address resolves. THE KEYSTONE EDIT WORKS.
- Directive-body props (duration: 800ms;) — the original shipped case.
- Value coercion is correct-by-design upstream: the widget emits a string/number;
  apply_text_patch writes it verbatim (bare) or JSON-escaped (quoted object entry,
  BUG-093 sanitization).

** The PRECISE remaining gaps (were vague; now sharp)
G1. ABSENT defaulted params need INSERTION, not replacement. @object(roughness:
    0.15) with NO metalness in source -> patch {metalness: X} fails "Property not
    found". Setting a defaulted-but-omitted param must INSERT "metalness: X" into
    the arg list (using the %form param list to know it's valid + where to place
    it). Build task: teach apply_text_patch (or a sibling) an insert mode keyed
    by the form.
G2. &template INVOCATIONS are NOT FormMatch directives — they are
    ElementRefStmt/ElementRef CST nodes (src/syntax/cst/ast.rs:549). So
    parse_ast_selector (matches by macro_name) WON'T locate them. The @editor
    (&template) target needs a DISTINCT addressing path: resolve a template call's
    span via the element-ref AST, then patch its named args with the SAME
    apply_text_patch span logic. Build task: an element-ref address resolver +
    EditAst arm for template invocations.
G3. POSITIONAL params (no "key:") can't be found by key. Low priority: stdlib
    uses named args throughout; defer until a positional case appears.
