* Why (the gap)
Forms are where LiveView is strongest and the bridge is currently SILENT. The
bridge does realtime toys (counter, kanban) but has no story for the most common
LiveView surface: a changeset-backed form with server validation, inline errors,
and optimistic client-side feedback. Winning here makes the bridge viable for
real CRUD apps, not just multiplayer demos.

* Design thesis (fits the existing bridge, adds ONE assign type + ONE macro)
A form is not a new subsystem — it is:
  1. a new server ASSIGN TYPE: assign(:form, :changeset) — the reconciler already
     diffs assigns; a changeset serialises to a typed envelope
     {values, errors, valid?} that flows as DATA (never a rendered <form>).
  2. a new client SUBSCRIBE shape that decodes that envelope into a form signal:
     @data form $signup from $auth : form ; (sibling of @data subscribe).
  3. field binding + submit reuse EXISTING grammar: field inputs bind with the
     established value<- / @on input pattern; submit is just a @data signal with
     a tagged reply; validation feedback is @handle — NO second mutation or
     decode vocabulary (bridge principle 4 "one decode vocabulary").

The changeset envelope is the shared schema; E0928 checks the page's declared
fields subset of the changeset's cast fields (a typo'd field name = compile
error, same family as send emit "typo").

* Initial syntax (settled enough to spike against — NOT final)

** Server half (Elixir) — declare a changeset-typed assign
: assigns do
:   assign(:form, :changeset)          # NEW assign type; reconciler serialises
: end                                  # to {values, errors, valid?} envelope
: events do
:   event(:validate, form: :map)       # per-keystroke recast (optional)
:   event(:submit,   form: :map)
: end
: def mount(_p, _s, socket),
:   do: {:ok, assign(socket, form: to_form(Accounts.change_user(%User{})))}
: # validation round-trip: recast, reply with the fresh envelope tag
: def handle_event("validate", %{"form" => params}, socket) do
:   cs = Accounts.change_user(%User{}, params) |> Map.put(:action, :validate)
:   {:reply, %{tag: "invalid", reply: form_envelope(cs)}, assign(socket, form: to_form(cs))}
: end
: def handle_event("submit", %{"form" => params}, socket) do
:   case Accounts.create_user(params) do
:     {:ok, user}  -> {:reply, %{tag: "ok",      reply: %{id: user.id}}, socket}
:     {:error, cs} -> {:reply, %{tag: "invalid", reply: form_envelope(cs)},
:                       assign(socket, form: to_form(cs))}
:   end
: end

The form_envelope/1 helper (lives in Spacetime.LiveView, not per-page) turns a
changeset into %{values: %{...}, errors: %{field => [msgs]}, valid?: bool} — the
ONLY thing that crosses the wire. No HEEx <.form>, no <.input>.

** Client half (.st) — @data form + field bindings + @handle
: @import "stdlib/macros/data-kind"
: @import "stdlib/macros/handle"
: @import "stdlib/macros/form"        // NEW: @data form + field helpers
: @import "./$hosts.st"
: @type SignupForm { email: string; password: string; }
: // NEW: subscribe a changeset-typed assign as a FORM signal. Binds:
: //   $signup.values.<field>, $signup.errors.<field>, $signup.valid
: // E0928 checks the fields read here subset of the changeset's cast fields.
: @data form $signup SignupForm from $auth : form ;
: // submit + live validate are ordinary signals (existing grammar)
: @data signal $validate($form map) to $auth {
:   send emit "validate" { form: $form }
:   receive to Validated { "invalid" => Invalid($.reply); _ => Ok($.reply); }
:   policy latest
: }
: @data signal $submit($form map) to $auth {
:   send emit "submit" { form: $form }
:   receive to Submitted { "ok" => Saved($.reply); "invalid" => Rejected($.reply); }
:   policy latest
: }
: .signup {
:   @handle $validate { receive {
:     Invalid(env) => { $signup <- env; }      // server-authoritative errors
:     Ok(env)      => { $signup <- env; }
:   }}
:   @handle $submit { receive {
:     Saved(_)     => { $signup.submitted <- true; }
:     Rejected(env)=> { $signup <- env; }       // inline errors from the changeset
:   }}
: }
: // Field binding reuses the ESTABLISHED value<- / @on input pattern.
: .signup .field-email input {
:   value <- $signup.values.email;
:   @on input { $validate({ email: $.value, password: $signup.values.password }); }
: }
: .signup .field-email .error { text: $signup.errors.email; }
: .signup button.submit { @on click { $submit($signup.values); } }

* What's actually NEW vs reused (elegance-bar audit)
- NEW server: assign(:form, :changeset) handling in the reconciler +
  form_envelope/1 helper. One assign type, DATA-driven serialisation.
- NEW client: @data form macro (a specialised @data subscribe that names an
  envelope shape and exposes .values/.errors/.valid), optional field() binding-
  sugar macro. Both are stdlib entries, not Rust.
- REUSED: reconciler diff path, signal round-trip, @handle continuity, receive
  matcher, E0928 contract check. No new subsystem.
- DELETES potential: obviates ever reaching for HEEx <.form>/<.input> inside a
  bridged page.

Passes the AGENTS elegance bar ONLY IF the changeset-envelope + @data form can
be expressed as registry/stdlib data + the reconciler's existing diff path. If
assign(:form, :changeset) needs a Rust match-arm per changeset shape → it FAILS
the bar and stays an FUP for more spikes (which is the intent here).

- `assign(:form, :changeset)` flows through the server DSL and `mix

*** Three concrete seams that JUSTIFY a `@data form` primitive (the real payload)
1. **`@data subscribe` carries no type + seeds `null`.** Grammar (data-kind.st)
   is `@data subscribe $name:binding from $host:binding : $assign:ident ;` — NO
   `$type:typeref?` slot, and `%binds local-state-impl(initial: null)`. So the
   `@type FormEnvelope` I wrote is DECORATIVE (W0203 "defined but never used")
   and EVERY nested read compiles to a defensive `try { … } catch { return; }`
   against the null seed. A `@data form $signup FormEnvelope from $auth : form ;`
   would bind the type AND seed `{values:{},errors:{},valid:false}` so reads are
   total, not guarded. → primitive closes this.
2. **Cross-field stale read — the sharp one.** Each field's `@on input` rebuilds
   the whole params map by reading the SIBLING field from `$form.values.*`:
   `$validate({ email: $.value, password: $form.values.password })`. But
   `$form.values.password` is the LAGGING SERVER ECHO. Typing fast in both
   fields → a validate fires with a stale sibling value → the browser SHOWED a
   stuck "can't be blank" email error after both fields were valid (reproduced;
   settled/sequential input clears correctly). This is the canonical forms bug a
   primitive fixes by keeping a LOCAL client-authoritative `values` signal (the
   inputs write it directly) and treating server `errors/valid` as the only
   authoritative-echo fields. `@handle optimistic{}` is the existing tool, but
   wiring it by hand per field is exactly the boilerplate `@data form` should
   absorb.
3. **Field boilerplate.** value-bind + `@on input` reconstruction + error-text +
   (aria-invalid) is 4 lines PER FIELD, and the input reconstruction is where
   seam #2 hides. A `field(&self, $signup, :email)` sugar collapses it to one
   call AND removes the chance to hand-write the stale-sibling bug.

*** Elegance-bar ruling (per AGENTS)
`@data form` EARNS its place: (1) small extension of existing `@data subscribe`
grammar (adds a type slot + non-null structured seed + `.values/.errors/.valid`
accessors); (2) variants are stdlib/registry data, not Rust arms; (3) it DELETES
the decorative `@type`, the per-read `try/catch`, and the hand-wired cross-field
reconstruction; (4) testable by the same @clock/browser machinery. The `field()`
sugar is a SEPARATE, weaker call — spike its expansion before committing.

** field() sugar — proposed design (stdlib binding-sugar %macro)
Modeled on the local-pointer %macro shape (%form carries the call, %binds wires
signals). Two ergonomic tiers:

*** Tier A — selector-scoped binder (no HTML ownership; binds onto host skeleton)
Placed in a field's input selector; wires value + input + validate in one call
against a typed form signal, reading/writing the LOCAL values signal (so the
stale-read is structurally impossible):
: .signup .field-email input { @field($form, email) }
expands to (the pattern SPIKE 3 proved):
: value <- $form.values.email;
: @on input {
:   $form.values <- Object.assign({}, $form.values, { email: $.value });
:   $validate($form.values);
: }
and the sibling error element:
: .signup .field-email .error { @field-error($form, email) }
:   → text: $form.errors.email;
NB requires the STRENGTHENED subscribe (typed, non-null seed) so `$form.values`
is always an object — otherwise the Object.assign spreads undefined. This is why
subscribe-first is the right order.

*** Tier B — template projection (owns the whole labelled field markup)
A @template that projects a complete field once FUP-121 emits skeletons from the
page (so the page owns structure too):
: @template &field($form, $name string, $label string) {
:   <label class="field field-`$name`">
:     <span class="field__label">`$label`</span>
:     <input value="`$form.values[$name]`"
:            aria-invalid="`$form.errors[$name] ? 'true' : 'false'`"
:            @on input { $form.values <- Object.assign({}, $form.values, { [$name]: $.value }); $validate($form.values); } />
:     <span class="field__error">`$form.errors[$name]`</span>
:   </label>
: }
usage:
: &field($signup, "email", "Email");
: &field($signup, "password", "Password");
OPEN Q for Tier B: dynamic key `[$name]` in Object.assign + `$form.values[$name]`
read — does the compiler support computed member access in holes/JS bodies? (a
SPIKE 4 item). If not, Tier A (static per-field name) is the shippable form.

** TWO REAL FINDINGS surfaced building the primitive (both generalize)
*** Finding A — `const el = %&el` SHADOWING FOOTGUN in %primitive bodies.
The selector-init wrapper binds the element as `el` (`init = function(el){…}`),
so a primitive body that writes `const el = %&el;` compiles to `const el = el;`
— a self-referential dead binding (the inner const shadows the param and reads
undefined/TDZ). Symptom: the primitive's listeners never attach, silently. FIX:
never name a primitive-body local `el`; use `node`/`self`. This is a latent trap
for ANY primitive author — worth a lint (`W: primitive body binds `el`, shadows
the selector-init param`) or a doc note in the %primitive authoring guide. Filed
as its own note below.

*** Finding B — file-scoped signals live in `window.SpacetimeLocal`, NOT `ST.set`.
The killer. A `@data inline $values` is a FILE-scoped signal → its shared store
is the `window.SpacetimeLocal` Proxy (writing there broadcasts
`local:<name>:updated`). My first cut used ELEMENT-scoped `ST.set(node,'values',…)`
— which gives EACH input its OWN private `values` copy. So email's field wrote
{email} and password's field wrote {password}, each clobbering the other's key,
and every validate sent a half-empty map → the stuck-email symptom REAPPEARED
even WITH a local values signal. FIX: read/merge/write `window.SpacetimeLocal[
valuesSig]` so all fields share ONE object identity; then a same-tick two-field
update merges correctly. This is the actual mechanism SPIKE-3's SURFACE
`$values <- Object.assign(…)` used (the compiler lowers `$x <-` to
`SpacetimeLocal[x] = …`) — my primitive had to replicate it, not use ST.set.
LESSON for the real feature: `@field`'s primitive must target the file-signal
store; a typed `@data form`/strengthened-subscribe (FUP-144) that OWNS its values
signal would encapsulate this so no primitive author picks the wrong store.

** Ruling refinement (still: subscribe-first + sugar, NOT a new primitive)
`@field` works as a thin selector-macro over a file-scoped values signal + the
signal-call registry. It does NOT need `@data form` as a mechanism. BUT Finding B
shows the sugar is only safe if the values signal is a well-known shared store;
that's an argument for the values signal being DECLARED by the form construct
(so the sugar can't target the wrong scope), which a strengthened `@data
subscribe` seed (FUP-144) or a tiny `@data form` wrapper provides. Net: ship
FUP-144 first; `@field` sugar rides on top; `@data form` optional convenience.
