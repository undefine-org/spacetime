* Found by
BUG-188 fix (PLAN-078, 2026-07-18). The runtime hydrate paths now honor the
filter pipe in interpolation (template factory builder + each-inline
fillHolesOnly both apply ST.filter). The SSG unroll path does not.

* Gap
src/html/ssg_unroll.rs render_row / fill_holes substitutes backtick holes at
BUILD time and would leave `` `$p.price` | currency("$") ``'s pipe as
literal text in statically-exported HTML — the same leak BUG-188 fixed for
the runtime, breaking the "unroll == hydrate" parity invariant (BUG-081).

* Why not fixed alongside
Applying filters at build time means EVALUATING the stdlib-defined filter
set (%primitive currency etc. + ST.filters) in Rust — AGENTS.md explicitly
bars writing Rust re-implementations of stdlib-defined constructs ("don't
write Rust-based parsers/fallbacks; the metasystem is self-describing").
The right fix is a build-time filter EVALUATOR driven by the stdlib
registry (filters are data), not a Rust mirror of 6 functions.

* Scope
- ssg_unroll fill_holes: detect the trailing pipe after a hole; evaluate
  via the stdlib filter registry at build time; error loudly on unknown
  filter (better than silent leak).
- Parity test: a static-export fixture whose row uses | currency /
  | truncate asserting filtered output in the exported HTML.

BUG-188 (runtime fix), FUP-119 (second-instance @each), src/html/ssg_unroll.rs.
