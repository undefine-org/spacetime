* Origin / vision
The builder loop is view -> select -> edit -> ADD. The palette is the ADD verb and
the INVERSE of the inspector on the same introspection rail:
- inspector: ONE construct's %form -> widgets (read one node's params).
- palette: the WHOLE component/template registry -> insertable blocks (read all).
Same introspection, opposite direction. Inherits "for free": register a @template
-> it appears in the palette next build (the spacetime-docs law, now for BUILDING).
Mockup: session screen 82 (palette mid-drag, ember drop-zone, inspector dims).

* Source-anchored properties
- Each block = a registered template/component; it LIVE-PREVIEWS because a block
  IS its bundle render (register-template + the bundle pipeline). 
- Blocks are ORIGIN-TAGGED (Stdlib/Env/Project) from the flat registry + origin
  metadata (PLAN-041).
- Insert routes through EditJsonArray Insert (shipped: saveArrayInsert in
  dev-save) into the target slot's children; reorder via Reorder.
- The drop-target SLOT declares what it accepts (the form's &children* / region
  type, e.g. builtins.st &list(&items[])) -> the palette can FILTER to valid
  blocks for the drop context. Grammar guards creation (you cannot drop an
  invalid child), the same way it guards editing.
