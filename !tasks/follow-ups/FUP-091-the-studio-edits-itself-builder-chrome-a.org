* Vision (owner: "for the fun of it, try it at the end of the plan")
The builder's OWN chrome (navigator, inspector, palette, panels) is built from
ordinary Spacetime constructs (templates + stdlib primitives, per AGENTS:
Spacetime-only chrome). Therefore the builder can EDIT ITSELF: select a builder
panel, flip the inspector to "Component", and edit the panel's definition live —
the studio editing the studio. This is the deepest dogfood + the tangible form of
the __mcp__/__admin__/__dev__ convergence north-star (two-consumer rule: the
builder is its own first consumer).

* Why it falls out for free (if we don't block it)
- The two-level edit model (Instance | Component, PLAN-051) routes definition
  edits through EditAst at the definition's source span. A builder panel IS a
  construct with a data-st-origin / a known source file. So "edit Component"
  pointed at a builder panel is the SAME machinery, no special case.
- The introspection-generated inspector (PART A/B) reads ANY construct's form —
  including the builder's own templates. Nothing privileges "user page" over
  "builder chrome"; both are constructs.

* The architectural constraint (the ASK for the whole plan)
DO NOT special-case the builder chrome in a way that would block self-editing:
- builder panels = @template/primitives, NOT hardcoded Rust-emitted HTML.
- builder state = ordinary signals, introspectable like any page's.
- the chrome's constructs carry the same provenance (origin/structure projection)
  as guest constructs.
If every rung of PLAN-051 honors "chrome is just constructs", self-host is a
late-plan experiment, not a rewrite.

* The experiment (end of PLAN-051, timeboxed)
1. Mount the builder's own inspector panel as a guest in a second builder
   instance (builder-in-builder).
2. Select a panel row; flip to Component; change a label/spacing in its
   definition; observe the live builder chrome update via hot-reload.
3. Record what worked / what leaked (where chrome assumed it was privileged).

* Record (this FUP is the home for the ideas)
- Risks: infinite-mount recursion (builder mounting itself) — bound by NOT
  auto-mounting the active builder instance; a "snapshot" copy as the guest.
- Boundary: editing the chrome's DEFINITION affects all builder instances — gate
  behind an explicit "edit builder chrome" mode (not the default loop).
- Payoff: proves the convergence thesis end-to-end; a designer could reskin the
  studio in the studio.

* Acceptance (experiment-level, not production)
- A builder panel's definition is editable via the Component toggle in a
  builder-in-builder mount, with a live update, WITHOUT engine special-casing.
- A written record (here) of leaks + the path to making self-host first-class.
