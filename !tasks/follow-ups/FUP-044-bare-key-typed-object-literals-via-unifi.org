* Goal
Support bare-identifier keys + domain scalars in object literals so a typed
singleton can be written `$brand Brand : { scarlet: #FF0020, ink: #0a0a0a,
radius: 8px }` instead of quoted `{ "scarlet": "#FF0020", "radius": "8px" }`.

* Why this is NOT 3-parser surgery (oracle 65-BrandSingletonScope)
Bare keys are a TYPED-LITERAL LOWERING problem, not a parsing one. ExprExtractor
(src/syntax/events/extractors/simple.rs:315) returns CapturedValue::Expr(raw
source) VERBATIM — no key-quoting, no scalar stringification. Quoted-key objects
work because `{ "scarlet": "#FF0020" }` is already valid JS. A bare-key/color/
length object would emit literally `{ scarlet: #FF0020, radius: 8px }` = invalid JS.

Two gaps, ONE place each:
- GRAMMAR GATE: src/syntax/events/grammar/directives.rs:387 `starts_object_literal`
  = nth(1)==STRING && nth(2)==COLON (quoted-key only). Widen to accept IDENT keys.
- LOWERING: a typed object-literal %capture_type owning key-quoting +
  color/length/duration → JS-string stringification, in ONE place.

* Approach
Unify-one-place typed object-literal %capture_type (metasystem owns it, no Rust
special-cases). CST parse needs no change (events parser gates emit; a CST
parse_inline_value_braced experiment was reverted as dead + mandate-violating).

* NB
Not blocking: the brand singleton ships on quoted keys.
