* Research summary

** MCP server options (as of 2026-07-04 web search)
- ~ahujasid/blender-mcp~ — most widely adopted / original. Blender addon (receives commands) + Python MCP server (stdio/HTTP, compatible w/ Claude Desktop, Cursor, VS Code). Exposes create/edit objects, materials, scene inspection, arbitrary Python execution, render, import/export (FBX/OBJ/GLTF-GLB/STL/PLY/Alembic), asset-library downloads.
- ~djeada/blender-mcp-server~ — 22-27 tools across 6-7 namespaces (create objects, materials, render, export scenes, execute Python, async job mgmt).
- ~dcc-mcp/dcc-mcp-blender~ — embeds a Streamable-HTTP MCP server directly inside Blender's own Python interpreter (no separate server process / client config file); 150+ tools (scene mgmt, mesh/UV editing, rigging, materials, rendering, scripting).
- Official blender.org lab MCP server also exists (blender.org/lab/mcp-server) — natural-language interface over Blender's Python API + doc access.

** Security note (from upstream docs, verified via search, not yet independently confirmed against our sandbox)
The MCP server executes LLM-generated Python code inside Blender with NO sandboxing/guardrails — recommend running in a VM or a machine with no access to sensitive data/credentials. This needs a concrete decision before we wire it into the main dev workstation.

** Constraint on the Spacetime consumption side (already verified in repo)
`stdlib/3d/primitives/three-gltf.st` / `three-entry.ts` build EXCLUDES `DRACOLoader` (its `import.meta.url` usage breaks the classic-script runtime bundling). Any Blender export MUST be uncompressed glTF/GLB (no Draco) or the model silently fails to load client-side. This is a hard requirement to bake into whatever export step/documentation we add.
