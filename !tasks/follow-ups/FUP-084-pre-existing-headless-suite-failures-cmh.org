* Two root causes (both predate this session)

** 1. CMHT-001/002/003 tests misuse @given for signal state (commit 776c9a62, 2026-03-07)
tests/component-model/{scoped-state,reactive-props,content-binding,exports,template-refs}.test.st
write `@given .el { $count number: 0; }`. But the @given macro
(stdlib/testing/test.st:267) sets DATA ATTRIBUTES / CSS / content via
element.dataset/style — it does NOT declare Spacetime signal state (no ST.set).
So `$count number: 0` is parsed as a property key (→ E0900 "a `$count` hole cannot
be a state declaration") and the subsequent `ST.get(el,'count')===0` assertion
fails (undefined). FIX: rewrite these tests to seed state via `@eval (ST.set(el,
'count', 0))` (the pattern the passing counter.test.st uses), OR extend @given to
recognize `$sig type: value` state declarations and lower them to ST.set.

** 2. V8 (`--headless`/logic) backend lacks browser APIs (by design — FIDELITY_LADDER)
Many failures are the EXPECTED fidelity refusals + missing-API errors on the fast
logic backend: "needs 'layout' fidelity but the current backend tops out at
'logic'" (layout assertions), `DOMParser is not defined`, `el.animate is not a
function`, `IntersectionObserver`/`MutationObserver` not firing, focus assertions,
`registerTimeline`/`clearErrors` debug-runtime hooks. These tests should run under
`--cdp` (real Chromium), not `--headless`. Per docs/testing/FIDELITY_LADDER.md a
layout assertion REFUSES on --headless rather than faking green — so these
"failures" are the ladder working as intended, but the suite counts them as fails.
