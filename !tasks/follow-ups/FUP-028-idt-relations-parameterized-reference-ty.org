User decision (2A): relations are =id(Agent)=, NOT bare =Agent=.

* Why
The CMS needs relations between content entries (a Talent has an Agent; a Talent has
Campaigns). The user decided these are REFERENCES, expressed as a parameterized type
=id(Agent)= — NOT a bare =Agent=. Rationale:
- A bare =Agent= field would NEST a full Agent object inside the Talent JSON:
  denormalized, duplicated, not editable as its own entry.
- =id(Agent)= keeps =Agent= a first-class collection and =Talent.agent= a POINTER.
  Normalized, relational, correct.
The parens form matches where the codebase is going (PARENTHESES for type args — cf.
capture maps, =$v:balanced(';')= at src/parser/mod.rs:3583).
