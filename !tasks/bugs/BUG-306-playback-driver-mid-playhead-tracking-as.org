* Evidence
`cargo run --features cdp,headless -- test tests/score/playback-driver.test.st --cdp` → 2 passed, 2 failed. The two PASSING tests are the negative-first ones (clip still before the playhead advances). The two FAILING tests are the positive mid-playhead ones:

The playback (media-clock) score driver passes its suite while its core promise — progress TRACKS currentTime — is unverified or broken in real Chromium. This is the exact silent-red class BUG-252 warns about: the negatives prove "not driven by something else", the positives that would prove "driven correctly" are red.

* Note
Unknown whether this is a real driver bug or a CDP-harness media-stub issue (the test stubs duration/currentTime via __defineGetter__ on the element; a real driver polling currentTime per frame would observe the stub, but if the runtime caches the media element's clock source at init, later stubbing may be invisible to it). The test header says "NB --cdp: media timing is paint-adjacent; --headless refuses it" — so the failure is on the only rung where it can run.
