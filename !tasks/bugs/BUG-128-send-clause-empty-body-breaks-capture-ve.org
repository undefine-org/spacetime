* Symptom
In a `@data signal`/`@data stream`, a `send` clause with an EMPTY body block
drops the whole clause's captures (verb, target, body all absent):

  send emit "inc" { }        // ← verb/target NOT captured
  send emit "inc"            // ← works (no body)
  send emit "inc" { x: 1 }   // ← works (non-empty body)

Downstream: the signal's emitted request loses method/target, and the Wave-B
LiveView contract check (E0928) silently can't see the event (no target → no
PageIntent → no check). Discovered building demos/liveview-counter (FEAT-135).

* Root cause (suspected)
`%capture_type send_clause` (stdlib/capture-types/signal-receive.st):
    "send" $verb:ident $target:string ( "{" $body:balanced('}') "}" )?
`balanced('}')` over an EMPTY run returns None (BalancedExtractor: "Returns None
if no non-whitespace content precedes the delimiter/EOF"). Inside the optional
group that None appears to fail the group such that already-matched verb/target
are rolled back, not the body treated as empty. Confirm in form_compiler
body-group matching + BalancedExtractor empty handling.

* Fix direction
Prefer making `balanced(delim)` yield an EMPTY Expr (not None) for an empty run,
so the optional body matches with an empty body. Other optional balanced bodies
(`optimistic { }`, etc.) likely share the bug. Alt: make the optional group's
inner failure not roll back preceding leaves.

* Acceptance

- Wave-B E0928 fires for an empty-body emit with a bad event name.
