* Symptom

Three of the ten standing =cargo test --lib= failures assert on syntax the repo
has since REMOVED. They are not detecting a regression; they are pinning a
corpse. Each will fail forever until rewritten, and while red they mask any real
regression in the same area.

** 1. =syntax::events::form_compiler::pdc_diagnostic_tests::test_component_body_known_directive_stays_silent_with_registry=

: a KNOWN directive (@effect) must not emit E0900

`@effect` was DELETED in =0000c27d= ("@effect retires onto @on $sig.change — 15
consumers migrated"). `stdlib/macros/effect.st` does not exist. E0900
("not a known directive") is now the CORRECT answer, so the test asserts the
compiler must stay silent about a directive it is right to reject.

The test's INTENT is still valuable — it guards BUG-167 against over-widening,
i.e. a directive the registry DOES know must not produce a false E0900. The fix
is to re-point it at a directive that still exists (its own comment names
`@portal` and `@fn` as equally valid choices), NOT to delete it.

** 2. =lsp::workspace::import_resolver::tests::test_stdlib_resolution=

: Expected Stdlib for 'stdlib/macros/fade-in', got File("…/stdlib/macros/fade-in.st")

Directly contradicted by =1b24e320= ("BUG-340: an opt-in stdlib module resolves
to the FILE ON DISK, not a dead end"). `File(...)` is the new, deliberate
behavior; the test still encodes the pre-BUG-340 expectation. Update the
expectation to match the decision that superseded it.

** 3. =compiler::snapshot_tests::snapshot_mixed_file_level_and_selector_scoped=

Not stale syntax — a real defect. Split out as BUG-346 (CSS property mutation
has no grammar).

walks in unnoticed. The number must be driven to zero or each remaining failure
