=cargo run -- check= →
: error[E0806]: internal: template body scope '@template:greeting' was not built (primitive 'register-template')
: hint: This is a compiler invariant break, not an author error: every
: body-bearing construct (@template, &name(){}, @editable-*) is named and its
: World-A scope is built during parsing. Please file a bug with the source

The hint EXPLICITLY names =&name(){}= as a construct that should have this
invariant hold — it doesn't, for this exact shape.

* Root cause (traced)
=stdlib/macros/template.st::%macro template-inline= declares:
#+begin_src
%form {
  &$name:ident($params:param_list) {
    $body:component_body
  }
}
#+end_src
This is an =ElementRefStmt= CST node (an =&name(...) { }= ref with a body), NOT
an =@=-prefixed =Directive= node. But the template-scope-construction loop in
=src/parser/mod.rs= (~L590, the one that builds each =@template:<name>=
=ScopeBlock=) iterates ONLY =root_node.directives()=
(=src/syntax/cst/ast.rs::Root.directives= → =self.syntax.children().filter_map(Directive::cast)=),
which structurally cannot match an =ElementRefStmt=. =is_body_bearing_construct=
(the registry check gating which directives get a scope built) is ALSO only
ever called with a =Directive='s name — so even though
=registry.is_body_bearing("greeting")= would correctly return =true= (the
=%form='s =$body:component_body= capture IS registered), the calling loop never
reaches an =ElementRefStmt= to ask the question in the first place.

∴ =template-inline='s registered form (=%registers template($name){...}=,
identical to =@template='s) NEVER gets a =@template:<name>= World-A scope built,
so ANY invocation of a =&name(){ }=-declared template hits the E0806 fail-loud
guard (correctly firing — the invariant IS broken, just not by the invoking
code).

* Structural fix (chosen)
Extend the template-scope-construction loop to ALSO walk top-level
=ElementRefStmt= nodes with a body (mirroring the existing top-level ENTITY
scope harvest at =src/parser/mod.rs= ~L481, which already walks
=root_node.element_ref_stmts()= for the =&name { @directive }= entity-scope
shape — same node kind, different disambiguation: an entity scope has NO
=arg_list= and NO =selector_text=; the template-inline form HAS an =arg_list=
(=($params:param_list)=) and a body). Concretely:

1. In the loop that currently does =for directive in root_node.directives()=
   building =@template:<name>= scopes, ALSO iterate
   =root_node.element_ref_stmts()=, filtering to ones with =ers.arg_list().is_some()=
   AND =ers.body().is_some()= (the same disambiguation already used to SKIP
   entity scopes at ~L487: =if ers.arg_list().is_some() { continue; }= for
   entities — invert that same check here to SELECT the template-inline shape
   instead).
2. Confirm via the registry that this name IS body-bearing
   (=registry.is_body_bearing(name)= — the check already exists, just needs a
   second call site for this node kind) before building the scope, so a
   non-template =&name(args) { body }= shape (if any other macro ever reuses
   this exact CST shape) doesn't get mis-adopted.
3. Reuse the IDENTICAL scope-construction body already written for the
   =Directive= case (tmpl_name extraction, =body_html= reconstruction via
   =reconstruct_template_body_html=, =nested_scopes= harvest, =@media= harvest
   from BUG-167, states/exports/refs back-fill) \u2014 factor it into a shared
   helper taking (name, body, body_range) so the two call sites (Directive-based
   =@template=, ElementRefStmt-based =template-inline=) converge on one
   implementation rather than duplicating the ~150-line scope-building block.
