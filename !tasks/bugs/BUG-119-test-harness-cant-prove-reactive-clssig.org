* Symptom
A `.test.st` that drives a reactive class toggle fails even though the feature
WORKS in production:
```
@given .btn { @on click { $bt <- !$bt; } }
@given .target { .is-active: $bt; }
@when .btn click
@then ... .target has class is-active   // FAILS (class never applied)
```
This is the canonical $-signal idiom (the migration target of PLAN-047), so the
harness gap blocks proving every state-machine→$-signal migration.

* Root cause — THREE distinct test-fidelity artifacts (NOT a production bug)
Verified by subagent diagnosis (read agent transcript; probes cited inline).

** (1) @given drops nested reactive CSS scopes
stdlib/testing/test.st:312-340 — the `given-directives` macro emits `%$body.js`.
A nested `.is-active: $bt;` is a CSS SCOPE, not a directive macro; its
reactive-binding JS is produced by `emit_scope_css_inner` over `ast.scopes`
ONLY. Inside a macro body block that JS is never generated → no
`registerSelectorInit` / `local:<name>:updated` listener exists at all.
Probe: inspect of a `@given .target { .is-active: $bt }` page shows
`ST.runMutations` for .btn but ZERO `is-active` / `__stBind` / `local:bt:updated`.

** (2) File-scope reactive-binding JS is appended AFTER test-directive JS
src/compiler.rs:721-725 — `compile()` does
`format!("{}
{}", js, scope_binding_js)`, appending scope bindings after the
pipeline JS. In a test body the `@when` click therefore runs BEFORE the
`.target { ... }` `local:<name>:updated` listener is attached → the mutation's
event fires into the void → `render()` never invoked → class never toggled.
Probe (/tmp/rcbug_seeded_render.test.st, properly seeded proxy): @when click at
emit line ~5931, the binding `addEventListener("local:bt:updated", ...)` at
~6068; render-count probe = `{renderCount:0, afterResolve:true, class:false}`
— i.e. ST.resolve returns true, event fired, but listener attached too late.

** (3) Undeclared auto-init signal mutation silently throws
public/runtime/st.js:589-597 + 670-680 — `transformExpr('!$bt')` →
`!SpacetimeLocal.bt`. If `SpacetimeLocal` is undefined (undeclared signal),
`eval(jsExpr)` throws ReferenceError; inner catch returns undefined; outer
`if (value !== undefined)` skips ALL write branches → no write, no event.
Probe: `{typeofBare:"undefined", evalError:"SpacetimeLocal is not defined"}`.
NB this DOES affect production for genuinely-undeclared signals — see below.

* Production impact (important nuance)
- Declared signals (@data / localStorage / local-state — how jallete & jeton
  declare $cart etc.): NOT affected. All init/handler/binding JS runs
  synchronously on page load before any user interaction, so ordering (2) is a
  non-issue and the proxy exists so (3) is a non-issue. Reactive .cls:$sig
  works in production for declared signals.
- Genuinely-undeclared auto-init signals (`$x <- !$x` with no @data/local decl):
  AFFECTED in production too via (3) — the RHS eval throws and the mutation is
  a silent no-op. Either the runtime should ensure a local proxy before eval,
  or the compiler should require/auto-declare the signal.

* Recommended fix (from diagnosis)
1. (2) Test emission ordering: in src/compiler.rs:721-725, when compiling a
   TEST body, place `scope_binding_js` BEFORE the pipeline `js` (or hoist scope
   init to the top of each @test body), so `local:<name>:updated` listeners
   exist before @when clicks. (Production already loads synchronously; this is
   a test-path ordering fix.)
2. (1) @given nested scopes: extend the @given/block compiler
   (stdlib/testing/test.st:312-340 + block path) to emit reactive scope-binding
   JS for scopes nested inside @given, not only top-level ast.scopes.
3. (3) Robust mutation eval: public/runtime/st.js:589-597 — make transformExpr
   safe when SpacetimeLocal is undefined (fall back to window._localState[name]
   or run ST._ensureLocalProxy() before eval) so undeclared writes still fire
   the update event. This is the one with real production reach.
