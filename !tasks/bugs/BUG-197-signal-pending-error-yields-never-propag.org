* Symptoms
A `@data derive` reading a signal's auto-yielded `_pending` flag
(e.g. `$pushPreview_pending`) NEVER reacts. Concrete user-facing case
(PLAN-075 host widget): click "Push preview" → real POST fires (19s in
flight) → zero visual feedback: dot stays turquoise, state label never
shows "Working…", button label static. On completion the widget re-fires
$status and lands on the identical settled state. User experience:
"clicked, silent, nothing happened" — but the push DID happen (verified
server-side via status.json preview_hash changes; reproduced twice via
instrumented fetch in headless Chromium).

This is NOT push-specific: `$status_pending`, `$promote_pending`,
`$addDomain_pending`, `$pushPreview_pending` are ALL dead. The orange
"in flight" dot introduced in FEAT-155 has never worked for any signal.
The widget's working `$statusFailed` ("Host unreachable") deliberately
does NOT use `_error` — it's a manual `@data inline` set from `@handle`
receive arms (BUG-031 comment, index.st:223) — so no `_pending`/`_error`
auto-yield was ever live-verified until now.

* Root cause (fully traced, two breaks)

Break 1 — WRITE side: the `%binds` alias never reaches the emitted
ST.set key for INTERPOLATED aliases.
- stdlib/macros/data-kind.st %macro data-signal binds:
  `signal-call(...) -> { $call as $name, $pending as ${$name}_pending, … }`
- stdlib/primitives/signal.st yieldState: `%yield pending -> $pending`
  → src/emit/js.rs:974 lowers to `ST.set(el, <resolved>, pending)` where
  <resolved> consults ctx.outputs (resolve_signal_name, js.rs:619).
- BUG-154 wired bind outputs → ResolvedPrimitive.outputs →
  PrimitiveArgs.outputs → ctx.outputs (expand.rs:442) — BUT
  src/pipeline/resolve.rs (~:434) only inserts mappings for PLAIN-ident
  aliases, explicitly skipping interpolated ones:
  "An interpolated alias pattern (`${$name}_loading`, data-kind macros)
  is resolved elsewhere and must NOT become a literal ST.set key."
  That "elsewhere" does not exist on the write path: compiled widget JS
  (served /__spacetime/host/runtime.js) contains
  `ST.set(el, "pending", pending)` — raw export name. Every signal
  instance writes the same undifferentiated "pending" key on its element
  store; nothing ever writes `pushPreview_pending`.

Break 2 — READ side: even with the right key, element-scoped yields
don't cross to the global plane the derive reads.
- `@data derive $isOrange … : ($status_pending || …)` compiles to
  reads of `SpacetimeLocal['pushPreview_pending']` + listeners on
  `local:pushPreview_pending:updated` (stdlib/primitives/data/
  derived-signal.st, watched.forEach).
- ST.set writes the ELEMENT-scoped store only, unless the name was
  registered via `ST._bridgeExport(name)` — the BUG-069 bridge that
  mirrors to SpacetimeLocal + dispatches the event.
- html_hydrate.rs:221 DOES emit `ST._bridgeExport(dep)` for text/attr
  binding deps; the derive watcher in derived-signal.st does NOT.
- Live probe during a real in-flight push: zero `local:*:updated`
  events; `SpacetimeLocal` has no `pushPreview_pending` key at all.

Fix:
1. resolve.rs — run interpolated aliases through the EXISTING
   `resolve_yield_name` (src/analysis/mod.rs:1403, BUG-126 helper;
   make pub(crate)) with the invocation's captures, so
   `${$name}_pending` → `pushPreview_pending` lands in output_mappings.
   Bare-`$cap` aliases keep today's behavior (minimal blast radius).
2. derived-signal.st (and computed-source.st, same watcher shape) —
   `ST._bridgeExport(d)` before subscribing, mirroring
   html_hydrate.rs's binding path. No-op for already-global deps.

* Resolution (fixed this session)

** Write side (src/pipeline/resolve.rs)
Interpolated %binds output aliases now resolve through the EXISTING
`resolve_yield_name` (src/analysis/mod.rs, BUG-126 helper, made
pub(crate)) against the invocation's captures: `${$name}_pending` →
`pushPreview_pending` lands in ResolvedPrimitive.outputs, so
`%yield pending -> $pending` emits `ST.set(el, "pushPreview_pending", …)`.
A missing capture falls back to the raw alias, which still fails the
plain-ident gate exactly as pre-fix (graceful, never a garbage ST.set
key). Bare-`$cap` aliases (`$call as $name`) keep historic behavior.
Unit tests: `test_interpolated_bind_output_alias_resolves_against_captures`
+ `…_missing_capture_yields_no_mapping` (src/pipeline/resolve.rs).

** Read side (3 surfaces, one one-liner each — arm the BUG-069 bridge)
- stdlib/primitives/data/derived-signal.st — derive watcher now calls
  `ST._bridgeExport(d)` before subscribing (mirrors html_hydrate.rs's
  text/attr path). No-op for already-global deps.
- stdlib/primitives/data/computed-source.st — same watcher shape, same fix.
- src/emit/html_reactive.rs (SignalScope::Global arm of emit_subscribe) —
  Global reactive-class bindings (`.is-x: $rawYield`) now bridge too.
