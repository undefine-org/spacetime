* Symptom

A directive body whose custom =%capture_type= CANNOT match still compiles
green. Both of these pass =spacetime check= identically:

#+begin_src spacetime
%capture_type on_leaf { ( $lit:string ) | ( $wild:ident ) }
%capture_type on_transition { $from:on_leaf "->" $to:on_leaf }
%capture_type on_pat { ( $transition:on_transition ) | ( $leaf:on_leaf ) }
%capture_type on_arm { $pat:on_pat "=>" $form:ident ";" }

%macro spike-two {
  %form { @spike-two $subject:binding "{" ( $arms:on_arm )+ "}" }
  %binds { spike-noop(subject: $subject, arms: $arms) }
}

// WELL-FORMED — passes (correct)
.show { @spike-two $take { a -> b => cut; b => dissolve; } }

// MALFORMED — ALSO passes (WRONG: `a -> -> b => ;` is not an on_arm)
.show { @spike-two $take { a -> -> b => ; => cut } }
#+end_src

=inspect --layer expansion= shows the body captured as RAW TEXT
(="arms: a -> b => cut; b => dissolve;..."=) with "(macro not found in
registry)" — i.e. the body is passed through opaquely rather than parsed
by the declared capture type.

* Why #A

Same class as BUG-216 (=tests/bug_216_silent_directive_drop_test.rs=):
"a body that fails to parse is indistinguishable from a body that
legitimately emits nothing, so the failure is invisible to a green suite."

custom-capture-type-in-directive-body path.

Consequence for design work: **grammar spikes cannot be validated with
=check= alone.** A green result proves nothing about whether the capture
type matched. Any SIP claiming "spiked, works" needs a positive AND a
negative case, with the negative confirmed to FAIL.

TWO DEFECTS, both closed:
(A) `parser::rematch_with_user_macros_in` registered same-file `%macro` definitions into the augmented registry but never same-file `%capture_type` definitions — a user grammar was therefore ALWAYS absent from the registry meant to enforce it.
(B) With the extractor absent, form_compiler's Custom body-capture branch fell back to `Some(CapturedValue::String(inner))` to "preserve historical lenient behavior", so the capture SUCCEEDED holding unparsed raw text. The form matched and check reported success on malformed source. Then `cst_to_stfile_with_registry` discarded every match diagnostic except a hardcoded `@data subscribe` case (BUG-234), so even a produced failure never reached StFile::diagnostics.

WHAT MY REPRO TAUGHT ME ANYWAY (worth keeping — it cost an hour and will cost the next person the same):

1. A `%form` body written as a GROUP — `"{" ( $arms:x )+ "}"` — compiles against STDLIB capture types only, so a same-file `%capture_type` is invisible there and the directive never matches AT ALL. Written as a direct repeated body capture — `{ $arms:x+ }` — it resolves through the augmented registry and sees the user grammar. The existing test documents this in a comment on GRAMMAR; my probe used the group form and spent several rounds on a self-inflicted null result. The two spellings look interchangeable and are not.

2. `cargo run -- check <dir>/` on a directory with no page compiles NOTHING and still prints "✓ All 1 file(s) passed". My whole first repro was vacuous — `build` reported `Pages: 0`. A green check on a fixture you have not proven is a PAGE is not evidence. Establish a control that MOVES (my `@cursor` control shifted the bundle 9329 bytes) before trusting any A/B.

3. `inspect --layer expansion` is the discriminator the existing test correctly uses: exit 0 does not distinguish "matched" from "silently vanished", which IS the bug class. Assert the directive appears in the expansion, not merely that check passed.
