Found + fixed during FEAT-106. handle_edit_ast_inner (src/sync/handlers.rs) scoped-directive branch used `ast.scopes.iter().find(|s| s.selector == css_selector)` — the FIRST scope block matching the selector. When a selector appears in MULTIPLE blocks (e.g. `.masthead { background: ... }` for tokens AND `.masthead { @scroll reveal(...) }` for motion), the directive edit resolved to the sibling block that lacks the directive → spurious "Directive not found" reject, edit silently dropped.

REPRO: projects/cms-testbed/index.st has two `.masthead {}` blocks; editing the @scroll stagger param in the admin Motion pane sent EditAst selector `.masthead §scroll` → rejected (matched the token block at line 59, not the motion block at line 67).

FIX: filter ALL scopes by selector, find_map the first whose matches CONTAIN the target directive. Commit alongside FEAT-106.
