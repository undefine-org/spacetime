* Symptom
Declarative SVG markup (<svg viewBox><circle cx></circle></svg>) parses and builds cleanly (verified by probe), but the elements NEVER PAINT in the browser: they are created in the HTML namespace, so <circle>/<path>/<text> become HTMLUnknownElement.

* Root causes (two render paths, both wrong)
1. Reactive builder: emit_element (src/emit/html_reactive.rs:385) emits `document.createElement(tag)` unconditionally. SVG-tagged subtrees need `document.createElementNS('http://www.w3.org/2000/svg', tag)`; a <foreignObject> child reverts to HTML namespace.
2. @each rows: makeRow (stdlib/primitives/data/each-inline.st:209-211) does `tpl.innerHTML = rowHtml; tpl.content.firstElementChild`. Parsing `<circle>` OUTSIDE an <svg> ancestor yields HTML-namespace unknown elements. When the each container is itself in the SVG namespace, rows must be parsed in SVG context (wrap in <svg>…</svg> and unwrap) so the parser assigns the right namespace.
