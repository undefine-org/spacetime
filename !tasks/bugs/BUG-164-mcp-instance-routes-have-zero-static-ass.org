* Root cause
`src/mcp/live.rs`'s instance router registered exactly five routes for an
instance: `/`, `/input.json`, `/css`, `/js`, `/bundles`. There was NO
static-asset passthrough at all -- unlike `src/server.rs`'s dev-serve
`catch_all_handler`, which explicitly resolves `.glb`/`.gltf`/`.bin`/
`.ktx2`/`.hdr`/`.exr`/`.draco`/images/video/fonts against `site_dir` (see
the big `path.ends_with(...)` dispatch chain there, ~line 1072). Every
relative asset reference a mounted function's markup makes (any `stdlib/3d`
`@gltf`, any `<img src="...">` pointing at a repo-relative file, any
`@import`-adjacent binary) silently 404s the moment it's driven through
`st_mount` instead of `cargo run -- serve`.

This wasn't a "the fix workaround-hacked it" situation -- the underlying
mechanism (`FunctionRecord.resolve_root`, already tracked per-function
precisely so `@import`s and the `/bundles` recompile resolve against the
right root) already had EXACTLY the information needed. The route surface
had simply never been extended to serve raw bytes from that root.

* Fix
Added `GET /__mcp/instance/{id}/{*path}` (axum wildcard catch-all,
registered AFTER the five literal routes -- axum resolves literal segments
before wildcards, so `/css`/`/js`/`/bundles`/`/input.json` are unaffected)
-> `instance_asset`: looks up the instance's `FunctionRecord.resolve_root`
(the SAME root the function's own `@import`s already resolve against),
guards against `..` path-traversal components, reads the file as raw bytes,
and returns it with a MIME type from a small extension table mirroring
`server.rs`'s existing dispatch (`.glb`->`model/gltf-binary`, `.gltf`->
`model/gltf+json`, images/video/fonts/etc.) -- not a new mechanism, just
extending the existing route surface with the existing root-resolution
convention.

* Files
- `src/mcp/live.rs`: added `instance_asset` handler + `guess_asset_mime`
  helper; registered `/__mcp/instance/{id}/{*path}` route.
