* Found by
Live user report this session, with a screenshot: after a page
reload, the widget's "Promote to production" button and the
"app.example.com" domain input rendered with dark backgrounds and
low-contrast text, described by the user as "unreadable because dark
mode isn't implemented properly."

* Root cause (confirmed via a live, controlled repro)
`.st-host-widget` (the panel's own container style,
`stdlib/__host__/index.st`) is UNCONDITIONALLY light-themed by design
(white background `#ffffff`, near-black text `#111111`) -- a
deliberate, injected dev-tool overlay, never meant to follow the host
page's own theme. But it declared no `color-scheme` at all. Without an
explicit `color-scheme`, a browser under an OS/browser dark-mode
preference still renders the panel's OWN native form controls
(`<input>`/`<button>`) using DARK native chrome -- `color-scheme` is
inherited from the ROOT document by default, and a plain
`background`/`color` on `.st-host-widget` itself has ZERO effect on
native form-control rendering, which is governed exclusively by
`color-scheme`.

Confirmed live: forcing `document.documentElement.style.colorScheme =
'dark'` reproduced the user's EXACT screenshot (dark input/button
backgrounds with low-contrast text) even though nothing else in the
panel's own CSS changed.

* Precedent
`stdlib/__mcp__/workbench/styles.st` already establishes the fix
pattern for the mirror-image problem: a deliberately-DARK overlay
keeping ITS OWN guest form controls light via `color-scheme: normal`
(with an inline comment documenting exactly this rationale). This
widget is the opposite case -- a deliberately-LIGHT overlay needing
`color-scheme: light` so its inputs/buttons render with light native
chrome regardless of what color-scheme the surrounding page or OS
prefers.

* Fix applied
Added `color-scheme: light;` to `.st-host-widget`'s container rule.

* Verification
Live browser test: with `document.documentElement.style.colorScheme`
forced to `'dark'`, the widget's own inputs/buttons now render with
light chrome and legible text (before/after screenshots captured this
session).
