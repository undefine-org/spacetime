* Summary
The headless (`--headless`, V8 + LinkeDOM) test runner executes EVERY test file in ONE shared V8 context with NO reset of global runtime state between files (and only a partial reset between tests). A single page-global `MutationObserver` installed by `public/runtime/st.js`, plus shared singletons (`ST._dataRegistry`, `ST._selectorInitializers`, `Spacetime.templates`, accumulated `document.body` DOM), persist across files. Once a SECOND file mounts elements / drives data, the leaked observer fires on stale nodes from the first file and throws `Cannot read properties of null (reading 'nodeType')`, turning passing tests RED purely because of run ORDER.

This is order-dependent cross-contamination: each affected file PASSES in isolation and FAILS when any sibling `@each`/mount file runs before it. It is a large, hidden component of the standing headless baseline (~251 failures) — the headline `tests/ --headless` number understates real correctness because many "failures" are this harness artifact, not product bugs.

* Severity / impact
- P1 for test SIGNAL integrity. The full-suite headless number is not trustworthy: a green test silently flips red when a neighbor is added, and a real regression can hide behind the noise floor. It also blocks honest acceptance gating for any feature whose headless test mounts elements (e.g. PLAN-043 kit tests, each-data-drive, body-directives).
- NOT a runtime/product bug: the live page (one document, one observer) is correct. The defect is purely test-harness isolation.

* Root cause (confirmed, not guessed)
Two structural facts in the harness combine:

1. ONE shared V8 context for all files. `src/test_runner.rs` loads the combined runtime once and runs each compiled test file's script in the SAME context (`__spacetime_register_test` accumulates into one module-global `__st_tests`; `__spacetime_run_tests` iterates them). There is no fresh isolate/context per file.

2. The per-test reset clears almost nothing. In `src/test_runner.rs` `window.__spacetime_run_tests` (~line 985), the only between-test cleanup is:
   #+begin_src js
   for (const machine of window.__st_machines.values()) { machine.destroy(); }
   window.__st_machines.clear();
   #+end_src
   There is NO `observer.disconnect()`, NO `ST._dataRegistry.clear()`, NO `ST._selectorInitializers` reset, NO `Spacetime.templates.clear()`, and NO `document.body` reset between tests OR between files.

The leaked actor is the page-global MutationObserver in `public/runtime/st.js` (bottom of file):
   #+begin_src js
   const observer = new MutationObserver((mutations) => {
     for (const m of mutations) {
       for (const node of m.removedNodes) { ST._handleRemovedNode(node); }
       for (const node of m.addedNodes) {
         if (node.nodeType === Node.ELEMENT_NODE) { ST._scheduleInit(node); }  // <-- throw site class
       }
     }
   });
   if (document.body) { observer.observe(document.body, { childList: true, subtree: true }); }
   #+end_src
   It is installed ONCE (module load), observes `document.body` for the WHOLE run, and is never disconnected. Fixtures/mounts from file N remain in `document.body`; when file N+1 mutates the DOM, the observer's `_scheduleInit` / `_handleRemovedNode` callbacks run over a mix of live and stale nodes. A stale/null node reaches a `node.nodeType` / child-walk read and throws `Cannot read properties of null (reading 'nodeType')`, which surfaces as the failing test's error.

Shared singletons compound it: `ST._dataRegistry = ST._dataRegistry || new Map()` (st.js ~line 100) persists `data:<name>:loaded` listeners and loaded flags across files, so a later file's `ST.setData('x', …)` fires a PRIOR file's `@each` listener bound to a removed container; `Spacetime.templates` keeps every file's templates (name collisions / stale builders); `ST._selectorInitializers` keeps every file's selector inits.

* Fix options (prefer A; B is a cheap stopgap)
A. TRUE per-file isolation: run each test file in a FRESH V8 context (new isolate/`HandleScope` + re-loaded combined runtime + fresh LinkeDOM document) in `src/test_runner.rs`'s file loop (~line 352). Cleanest; eliminates ALL shared-singleton leakage (observer, registries, templates, DOM) by construction. Cost: re-eval the runtime per file (acceptable; files are few relative to tests).
B. Between-file (and ideally between-test) RESET hook in the harness, invoked in `__spacetime_run_tests` and at each file boundary:
   - `ST._teardownForTest()` in `public/runtime/st.js` that: `observer.disconnect()` then re-`observe` a CLEARED body; `ST._dataRegistry.clear()`; `ST._selectorInitializers.length = 0` (or snapshot+restore the runtime-owned ones); `Spacetime.templates.clear()`; `ST._pendingInit.clear()`; reset `document.body.innerHTML = ''`.
   - Call it before each test in the run loop (replacing the machines-only reset) AND/OR between files.
   Risk: must NOT clear runtime-owned selector inits that the bootstrap installs once; snapshot the baseline set after runtime load, restore to it (don't zero). Option A sidesteps this subtlety.

Recommendation: A (fresh context per file) for correctness, with B's `document.body` reset retained as a fast between-TEST guard inside a file.
