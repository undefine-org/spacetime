* Summary

`@on &.visible(threshold: 0, once: true) { … }` compiles clean. `.visible` now
binds `load-driver`, which has no `once` parameter, so the argument reaches
nothing. `check` reports ✓ and the build succeeds.

Today the consequence is benign — `load-driver` disconnects its observer after
the first intersection, so it is one-shot ANYWAY and `once: true` is a
redundant truth rather than a lost intent. But the RULE is wrong: an argument
naming a parameter the target primitive does not have should be refused, the
way `E0960` refuses an unknown argument to a FORM.

Live example: `tests/unit/macros/on-load.test.st` line 46.

* Why it is worth fixing

This is the silent-acceptance class the project bans (BUG-229/BUG-243). A
driver's parameter list is registry DATA and the primitive's signature is
introspectable (`registry.get_primitive(name).params` — `typed_primitive_arg`
already reads it), so the check is a lookup, not a new subsystem.

The same lookup would have caught BUG-322 from the other side: an unnamed arg
landing in a param the author never meant.

* Expected

`E09xx: `.visible` has no parameter `once` — declared parameters: duration,
delay, threshold, immediate`, with the driver's real parameter list in the
hint.

* Care needed

Row constants (`primitive_args: "trigger:mouseenter,…"`) and renames
(`param_map`) mean the author-facing name and the primitive-facing name differ.
The check must run AFTER `param_map` resolution, against the primitive's
signature, or it will reject legal spellings (`.text-change(stagger: …)` →
`charStagger`).

* Acceptance

1. RED-first: `@on &.visible(once: true)` is refused, naming the real params.
2. Every legal spelling in `tests/` and `stdlib/` still compiles — in
   particular the `param_map` drivers (`.text-change`) and the event drivers
   that carry row constants.

** What the driver actually is

stdlib/macros/drivers.st:94 — `visible` binds `load-driver`, NOT `intersection`.
Changed deliberately (BUG-323/BUG-315): intersection published the ratio as
progress, so a partly-visible element sat permanently mid-animation and
re-entering the viewport reverted a completed entrance.

`load-driver` (stdlib/primitives/animation/drivers.st:1857) declares exactly:
name, duration, delay, threshold, immediate. No `once` — and it does not need
one, because it is one-shot BY CONSTRUCTION, twice over:

: if (started) return;        // :1878 — play() can never run a second time
: started = true;

: if (entry.isIntersecting) { // :1923
:   play();
:   observer.disconnect();    // the observer is gone after the first fire
: }

So `@on &.visible` already never repeats. `once: true` was asking for behavior
the driver already guarantees unconditionally.

** Resolution

The refusal from BUG-352 is the whole fix, and its enumeration is now accurate:

: error[E0960]: unknown argument `once` for driver `visible`
:   — declared parameters: delay, duration, immediate, name, threshold

An author who wanted one-shot gets told `once` is not a parameter, and the
listed params are the real surface. Nothing to implement.
