* Root cause (chain)
1. =@test= macro form is =@test $name:string { $body:block }=; emit is
   =window.__spacetime_register_test(%$name, async () => { %$body.js });=
2. =parse_capture_type_name= (src/syntax/events/form_compiler.rs:1431) maps
   ="block" => CaptureType::HtmlBlock=.
3. HtmlBlock captures as =CapturedValue::String(inner)= (form_compiler.rs:1077) —
   the raw body SOURCE TEXT, with nested directives UNcompiled.
4. =%$body.js= is substituted by =substitute_params_simple= →
   =captured_value_to_emit_string(String, Some("js"))= (src/pipeline/evaluate.rs:425):
   the =(String, _)= arm returns =s.clone()=, IGNORING the =.js= field.
5. Result emitted: the raw body text as a string-literal expression with a
   trailing =.js=. The async test fn body does nothing; nothing throws; "passes".

Confirmed PRE-EXISTING (reproduces at commit fdf1dc3b, before PLAN-024).

* What "block" capture must actually do
=$body:block= / =$content:block= must yield a structured value exposing:
- =.html= -> raw inner text (what @fixture innerHTML needs)
- =.js=   -> COMPILED nested directives (matched_children FormMatches lowered to JS)
The compiled children already exist on =body_node.matched_children= (used by the
=$children*= collector -> =CapturedValue::Block=). The fix must route =:block= to a
Named/Block value AND make the =.js= / =.html= field accessor compile the Block
(via the resolve.rs nested_form_matches path) rather than stringify it.
