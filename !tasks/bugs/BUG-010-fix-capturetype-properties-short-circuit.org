* Scope
** In Scope
- Fix ~CaptureType::Properties~ handling in ~src/syntax/events/form_compiler.rs~ so it uses ~PropertiesExtractor~ instead of short-circuiting to ~CapturedValue::String~
- This bug causes ~TypeRegistry::from_form_matches~ to produce types with zero fields because ~get_properties("fields")~ returns ~None~ when the capture is a String
** Out of Scope
- ~CaptureType::HtmlBlock~ — must remain in the short-circuit arm. HtmlBlockExtractor delegates to ExprExtractor which produces ~CapturedValue::Expr~ (not ~String~), changing the downstream codegen semantics for template invocations. Removing it would cause JS syntax errors.
- TypeRegistry itself — no changes needed, it correctly handles ~CapturedValue::Properties~ already
- JSON schema generation — no changes needed, ~generate_json_schema~ correctly walks TypeDef fields
** Boundary Rationale
The bug is a single incorrect match arm in the form compiler. The PropertiesExtractor exists and works correctly — it's just bypassed. The fix is to remove Properties from the short-circuit so it falls through to the extractor-based path. HtmlBlock must stay because its extractor produces a different CapturedValue variant that would break template invocations.

* Implementation
** File: ~src/syntax/events/form_compiler.rs~
Line 1013, the match arm:

Current code:
#+begin_src rust
CaptureType::Properties | CaptureType::HtmlBlock => {
    Some(CapturedValue::String(inner.to_string()))
}
#+end_src

Change to (remove Properties, keep HtmlBlock):
#+begin_src rust
CaptureType::HtmlBlock => {
    Some(CapturedValue::String(inner.to_string()))
}
#+end_src

This makes ~CaptureType::Properties~ fall through to the ~_ =>~ arm at line 1019, which:
1. Collects descendant tokens from the body node
2. Filters out braces and EOF tokens
3. Looks up the extractor: ~extractors.get(&capture_type)~ → finds ~PropertiesExtractor~
4. PropertiesExtractor parses ~name: type;~ pairs into ~Vec<PropertyDef>~
5. Returns ~CapturedValue::Properties(props)~

The downstream consumer ~TypeRegistry::from_form_matches~ calls ~fm.get_properties("fields")~ which pattern-matches on ~CapturedValue::Properties~ and extracts fields correctly.
