* Root cause (not yet fully traced into bootstrap.py's boolean_op impl, needs
  a follow-up read)
The boolean union (Blender's Boolean modifier applied then collapsed) appears
to leave an EMPTY material slot (index 0, =None=) on the resulting mesh
alongside the real "Bronze" slot added by =assign_material=. The doc comment
at =set_face_material='s definition already anticipates a version of this
("Assign a second (or Nth) material slot... Call assign_material first to
create the material, THEN this to place it on a face subset") but the slot
list it enumerates isn't guarded against a =None= entry from the boolean op's
own slot management.

* Fix
In =tools/blender-mcp/bootstrap.py='s =_dispatch= handler for
=set_face_material= (around line 378), guard the slot search:
#+begin_src python
slot_index = next((i for i, m in enumerate(obj.data.materials) if m is not None and m.name == mat_name), None)
#+end_src
And separately: investigate whether =boolean_op='s union path should be
CLEANING UP empty/None material slots on the result mesh as part of the
operation (the more correct fix — a boolean result shouldn't carry a stray
empty slot at all), vs just guarding the read site. Read =boolean_op='s impl
first before picking; don't guess.

* Fixed (2026-07-06)
Applied the guard fix directly (`tools/blender-mcp/bootstrap.py`'s
`set_face_material` handler): `m is not None and m.name == mat_name` in the
slot search, mirroring `assign_material`'s existing empty-slot guard for its
OWN slot handling. Chose the read-site guard over a boolean_op-level
slot-cleanup fix (per the ticket's two options) — simpler, matches the
existing precedent already in the same file, and doesn't risk changing
`boolean_op`'s output shape for other callers.
