* Source
Found verifying BUG-029 (cart-demo). @data src: inline; value: [...] works when value: is single-line, but a MULTI-LINE nested array/object literal is not captured (the value never reaches the runtime; @each renders nothing).

* Evidence (verified)
- single-line: value: [ {"id":"p1","name":"Moroccan Rug",...}, {...} ];  => emits, renders 2 cards live (port 4798).
- multi-line: same content split across lines => emitted JS contains 0 occurrences of the value; @each renders nothing.

* Root cause (hypothesis)
ExprExtractor (src/syntax/events/extractors/expr.rs) tracks bracket depth and stops at ';' / closing bracket at depth 0 — it WOULD handle nesting. So the break is upstream: the @data form body parser likely splits the brace block into lines / clauses BEFORE the extractor runs, so a value: whose literal spans newlines is truncated at the first newline. Investigate how form body clauses (src: / value: / cache:) are tokenized in the metasystem form matcher — newlines inside a clause value must not terminate the clause.

* Fix direction
Ensure clause-value capture for value:$value:expr? consumes a full balanced literal across newlines. Either feed the whole brace-block token stream to ExprExtractor (it already balances) or stop splitting clause values on newline when bracket depth > 0.
