* Symptom
A `.test.st` that defines a `@template` INSIDE a `@mount { … }` block and then
invokes it (`&name(…)`) fails to compile with E0402 "template does not exist",
even though the template is defined. This blocks the Spacetime-native `.test.st`
harness from exercising template factories — the exact feature PLAN-039 ships —
so Rust v8_runtime tests are currently the only reliable gate for per-instance
template behavior.

* Root cause (agent://22-ReviewTestCoverage)
`validate_template_refs` (src/pipeline/mod.rs:627) collects `register-template`
names from the OUTER flat `primitives` list and checks `invoke-template`/`&name`
refs against it. But `@mount` (stdlib/testing/test.st:1066) captures its body as a
`$content:block` and emits the sub-compiled `%$content.js` inline — the inner
`@template`'s `register-template` primitive is produced inside the BLOCK
sub-program, so it never appears in the outer primitive list the validator scans,
while a file-scope (or other-mount) invocation does ⇒ false E0402. It is a
per-sub-program collection asymmetry, NOT a harness-only artifact.

* Fix options
1. Hoist `register-template` names produced inside `@mount`/`%$x.js` block
   sub-programs into the outer validation set before E0402 checking.
2. OR scope E0402 validation per sub-program (a block validates its own template
   universe).
Option 1 is the smaller change; option 2 is more correct if blocks should be able
to reference outer templates.

* Related (P3, same harness gap)
Nested `@each` in a @template body emits a raw `$r` row reference into a JS
position under the headless `@mount` sub-compile path (a SyntaxError), whereas the
browser page builder leaves `$r.field` inside the HTML row string handled by
each-inline/ssg_unroll at render time. Triage whether the @mount block sub-compile
routes nested @each through a different emit than the page builder
(stdlib/primitives/data/each-inline.st:155). If confirmed harness-only after
triage, downgrade; until then prefer Rust v8_runtime tests for these constructs.
