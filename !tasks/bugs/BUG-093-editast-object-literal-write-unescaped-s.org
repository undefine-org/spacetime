* Problem (reviewer 67-ReviewWaveBBrand, P1)
apply_text_patch (src/sync/handlers.rs) wrote an object-literal string value via
`format!("\"{}\"", new_val_str)` with NO escaping. new_val_str is the raw
browser-supplied EditAst value. A value containing `"`, `\`, newline, or `}`:
- CORRUPTS the .st literal (e.g. a font value `"Inter", sans-serif` →
  `"font": ""Inter", sans-serif"` → unparseable file → broken site).
- INJECTS .st source: a crafted value `z"; } @data evil { …` closes the string +
  brace and writes an arbitrary directive to disk — an injection boundary reached
  directly from a dev-ws ClientMessage::EditAst.
The EditJson path serde-escapes + sanitizes; this branch did neither.

* Fix
Write object-literal STRING entries via serde_json::to_string(new_value) (proper
JSON escaping of quotes/backslashes/newlines). The breakout `"` becomes `\"`, so a
payload survives only as an escaped string value — the literal still parses as one
object. Bare directive values + non-string object values keep verbatim text.

- test_apply_text_patch_object_literal_injection_neutralized: a breakout payload
  is contained as an escaped string; the literal stays one 2-key object.
