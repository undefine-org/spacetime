#+TITLE: value <- signal binding never reflects into the field
#+STATE: ITEM
#+CUSTOM_ID: BUG-288-value-signal-binding-never-reflects

* Symptom

An input declared `value <- $stmt` does not update when `$stmt` is
assigned elsewhere (e.g. cleared from a `@handle` reply arm after
submit). The signal updates (subscribers fire), the DOM field keeps the
old text.

* Impact

Two-way field state is one-way only: the field writes the signal on
input, but the signal cannot write the field. A form that must come back
EMPTY after a successful submit cannot do so declaratively. Found in the
knowledger desk sign-off strip (2026-08-05) — worked around by making the
whole act strip a server-projected `@each($sign_off_act)` template, born
empty per selection.

* Repro

#+begin_example
@data inline $stmt string : "" ;
.sign-off__statement @on input { $stmt <- value; }
input.sign-off__statement { value <- $stmt; }
#+end_example

Type, submit, assign `$stmt <- ""` from a handle arm — the field retains
the typed text.
