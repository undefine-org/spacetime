* The bug (eleventh silent-drop instance)
src/pipeline/expand.rs:187: a ResolvedPrimitive whose name resolves to nothing
gets `// Primitive not found: <name>` emitted INTO THE SHIPPED BUNDLE and the
build reports success. Two unit tests (expand.rs:2185, 2244-ish) PIN the stub
— the BUG-252 class: gates asserting the degrade, not the contract.

* Inventory (probed across demos/* + examples/*, 2026-08-03)
Four producers reach the stub, only ONE of them legitimate:
1. `none` (9x score-launch) + `noop` (3x) — INTENTIONAL `primitive: none`
   driver rows (drivers.st:316): the row positively states "nothing to start".
   These should resolve to a REAL empty primitive, not fall through "not found".
2. `version` (2x) — `@version 2026-06-09;` is a compiler directive that still
   produces a ResolvedPrimitive("version"); routing gap, it should never reach
   primitive expansion.
3. `type` (6x) — `@type Card { … }` declarations (type-data.st) produce a
   ResolvedPrimitive("type") with no primitive; a type declaration is
   registry data, not an emit target.
4. `preset` (1x, demos/spacetime-docs, right after the pretext vendor bundle)
   — the text module references a `preset` name that resolves nowhere.
   Suspicious after the ~preset retirement (caceec89): may be a stale
   reference that should error LOUDLY, not stub.

* Fix shape
- Intentional no-output (none/noop): an explicit resolvable empty primitive
  (or the expander recognizes the registry's `primitive: none` marker
  directly — one mechanism, not two).
- @version / @type: route them out of primitive expansion at the point the
  ResolvedPrimitive is created (they are compiler directives / registry data).
- `preset` in the text module: find the reference; if stale post-retirement,
  it errors loudly.
- THEN the not-found path becomes E0956 (unknown primitive) and the two
  pinned tests are rewritten to assert the error — a test asserting the
  degrade is debt (the arc's rule).
