* Initial Message
Surfaced by FUP-142 SPIKE 4 (2026-07-24) writing a `@field` primitive.

* Symptom
A `%primitive` whose `%emit js` body binds a local named `el` from `%&el`:
: %emit js {
:   (() => {
:     const el = %&el;   // <-- footgun
:     el.addEventListener(...);   // never runs
:   })();
: }
compiles into the selector-init wrapper, which ALREADY binds the element as `el`:
: const init = function(el) {
:   if (el._st_init_xxx) return;
:   el._st_init_xxx = true;
:   (() => {
:     const el = el;   // <-- self-referential: inner const shadows param,
:                      //     reads the not-yet-initialized inner `el` (TDZ/undefined)
:     ...
:   })();
: };
Result: the primitive's body silently no-ops (listeners never attach, no error).

* Reproduction
FUP-142 field.st first cut used `const el = %&el` → the @field input listener
never fired; browser showed values never updating. Renaming the local to `node`
fixed it immediately (verified: `const node = el` is valid; 4 occurrences, all
work).

* Root cause
`%&el` substitutes to the literal identifier `el` (the selector-init param name).
Any primitive body that reintroduces `const el = %&el` creates `const el = el`,
which JS evaluates as a self-reference in the TDZ of the inner binding.

* Fix options (pick, then implement)
1. LINT (preferred, cheap): warn when a `%emit js` body declares `const/let el`
   (or any name colliding with the selector-init param) — "primitive-body local
   `el` shadows the selector-init element param; rename to `node`/`self`". This
   catches every future author.
2. RENAME the selector-init param to something unlikely to collide (e.g. `__el`)
   so `const el = %&el` is safe. Riskier (touches emit for every primitive) and
   just moves the collision surface.
3. DOC: add a "do not name a primitive-body local `el`" note to the %primitive
   authoring guide. Weakest (relies on authors reading it).

RECOMMEND option 1 (lint) + option 3 (doc). Option 2 only if the lint proves
insufficient.

* Acceptance
- A `%primitive` with `const el = %&el` in its body triggers a compile warning
  naming the shadow.
- The %primitive authoring doc notes the reserved `el` name.

* Relation
Found via FUP-142 forms `@field` sugar. General primitive-authoring trap,
orthogonal to forms.
