#+CUSTOM_ID: BUG-373-a-third-of-the-diagnostic-table-can-never

* Summary

32 of 97 declared =DiagnosticCode= variants are referenced NOWHERE outside
their own declaration in =src/diagnostics/codes.rs=. Each one names a real
authoring mistake, carries a docstring describing what it catches, and cannot
be produced by any code path in the compiler.

This is the BUG-367 pathology one level up: BUG-367 was a validator that never
ran, found because its input was always empty. These are error CODES that no
validator ever constructs. Same consequence — a promise of refusal that the
compiler does not keep — but invisible to =rustc=, because a declared enum
variant that is never constructed in a =pub enum= is not a dead-code warning.

references to =DiagnosticCode::<code>= across =src/=, excluding the declaration

** Confirmed by live CLI, not just by grep

E0605 / E0916 promise "template/component not defined". A page whose entire
body references a component that does not exist:

    <main>
      <NoSuchComponent />
    </main>

    $ cargo run -- check
    ✓ All 1 file(s) passed

Nothing is defined, nothing is refused, nothing is emitted for it.

* Why this matters more than the count suggests

E0406 ("wrong number of function arguments") and E0407 ("invalid function
argument type") are the SAME two checks BUG-367 was filed about. BUG-367
deleted the dead validator and replaced the type half with E173 at the driver
argument loop — where it provably runs. These two codes are the residue of that
older, never-reachable attempt, and their continued presence in the table reads
as coverage that does not exist.

Several others describe checks a user would reasonably assume exist: filling a
nonexistent slot (E0403/E0603), writing to a read-only export (E0915), a
=&name[]= collection marker with no =@each= (E0921).

* Suggested resolution — triage, do not bulk-delete

Each code needs one of three verdicts, and the verdict differs per code:

  1. WIRE IT UP — the check is wanted and the site is known.
     Requires a RED test through =collect_document_diagnostics= first
     (the CLI path), per the BUG-367 lesson.
  2. DELETE — the feature it guarded is retired, or the check moved
     (E0406/E0407 → superseded by E173).
  3. KEEP, DOCUMENTED AS RESERVED — genuinely reachable-in-future, marked so
     nobody reads it as live coverage.

Do NOT bulk-delete: some of these are likely wanted checks whose wiring was
simply never finished, and deleting them silently discards the design intent
recorded in their docstrings.

* Gate for whichever verdict

A code that stays in the table should have a test that produces it. The cheap
version is a single table-driven test asserting that every declared
=DiagnosticCode= is either constructed somewhere in =src/= or listed in an
explicit =RESERVED= allowlist with a reason. That converts "33% of the table is
a lie" from a thing discovered by an audit into a thing that fails CI.
