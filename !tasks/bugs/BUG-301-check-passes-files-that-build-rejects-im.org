#+begin_src sh
$ spacetime check exact926.st

Reproduced for both import-validation codes:

| file | =check= | =build= | CSS emitted |
|------+---------+---------+-------------|
| =@typo/badge= (unbound alias) | *✓ passes* | E0926 | 0 |

| valid =@b/badge= | ✓ passes | ✓ passes | 1 |

Note the third column: in both failing cases the module's CSS is silently
absent. So =check= reports success on a page that builds to nothing \u2014 the
banned silent-drop class, reached through the tool whose entire job is to
report problems before a build.

* Root cause

=check_file= (=src/main.rs:1703=) never calls =CompileContext::with_imports=.
=import_scope= stays =default()=, and the validation pass is gated:

#+begin_src rust
// src/pipeline/mod.rs:1487
if !context.import_scope.is_empty() {
    let import_diagnostics =
        check_import_visibility(raw_matches, &context.import_scope, &context.meta_registry);
    output.diagnostics.extend(import_diagnostics);
}
#+end_src

An empty scope is indistinguishable from "no namespaced imports", so the whole
pass is skipped rather than failing loudly. =build= goes through
=compiler.rs:1313=, which DOES call =.with_imports(&ast.imports)= \u2014 hence the
divergence.

* Why no test caught it

=module_system_unbound_qualifier_errors_e0926= and
=module_system_hiding_list_hides_name_e0927= (=src/compiler.rs:3556=, =:3583=)
both pass \u2014 they drive =Compiler::from_file(...).fresh_registry().compile()=,
i.e. the BUILD path. The inputs I used above are byte-identical to those
fixtures. The feature is genuinely implemented and genuinely tested; only the
=check= entry point is unwired, and nothing tests =check= as a path.

This is FUP-058's thesis ("unify =check= and =build= compile paths \u2014 they
diverge") with a concrete, user-visible consequence.

* Fix

1. Thread =.with_imports(&ast.imports)= into =check_file=. Minimal, unblocks
   the immediate divergence.
2. Better (FUP-058): give =check= and =build= ONE context-construction path so
   a pass wired into one is wired into both by construction. Every
   =with_*= builder call that only one entry point makes is a latent instance
   of this bug \u2014 audit the rest of them.
3. Consider making the =is_empty()= gate explicit: a file WITH namespaced
   imports and an empty scope is a wiring bug, not a no-op.

* Acceptance

- A test that runs the =check= ENTRY POINT (not the compiler API) over the
  E0926 and E0927 fixtures and asserts the codes fire.
- An audit note listing every =with_*= call present on one path and absent on
  the other.
