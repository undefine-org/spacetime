* Source
Found completing the reactive cart showcase. Inside @template bodies, `.sel { text: $sig; }` wires correctly (BUG-026). At FILE/TOP-LEVEL scope it compiles clean but emits NO DOM binding.

* Evidence (verified)
- `.tot { text: $cartTotal; }` at file scope -> emitted JS contains the @computed source wiring but `.tot` selector never appears; no ST.watch binds it. Same for `.sel { @bind { text: $sig } }` (and @bind is deprecated, W0707).
- cart-demo: @each over $cart renders items reactively, add-to-cart appends items, but `.total-amount` / `.cart-count` stay at initial because their file-scope bindings don't wire.

* Root cause
Reactive-property extraction (ContentBinding) runs only for @template ComponentBody (src/pipeline/scope.rs ~L168). File-scope selector declarations (src/compiler.rs compile_scope_block ~L412) always emit Declaration::Property as CSS; values that reference a signal ($) are never routed to a content binding.

* Fix (consistent $-sigil syntax, no @bind block)
Make file-scope `.sel { prop: $expr; }` emit the SAME ContentBinding runtime path templates use:
- In compile_scope_block, detect declarations whose value references $ (reuse collect_signal_deps + transpile_signal_expr from src/syntax/form_match.rs).
- Emit a runtime binding: for each dep, ST.watch(dep, () => document.querySelectorAll(sel).forEach(el => el[prop]=apply())); run once initially.
- text/content -> textContent; other names -> attribute/property; same mapping as make_content_binding.
- Non-$ values stay CSS. One mental model: any `prop: $expr` is reactive, at file scope or in a template.
