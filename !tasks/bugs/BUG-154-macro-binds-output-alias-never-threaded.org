Compiler dataflow bug (librarian-traced, source-cited agent://20-AliasThreading). Surfaced as the deeper half of BUG-153 (workbench action feedback dead).

** Symptom
A `%macro`'s `%binds { prim(...) -> { $export as $alias } }` output alias is NOT applied when the `%primitive`'s `%emit js { %yield expr -> $export }` compiles. The yield writes the RAW export name, not the alias.
Proven: mcp-host yields `%yield lastMessage -> $lastMessage` with `%binds { ... $lastMessage as $mcpLastMessage }`; compiled JS = `ST.set(el,"lastMessage",lastMessage)`, ZERO `ST.set(...,"mcpLastMessage",...)`. A page reading `$mcpLastMessage` (→ `ST.resolve(__node,'mcpLastMessage')`) gets undefined. Same for $mcpConnected/$mcpError.

** Root cause (dataflow gap, 4 sites)
The write-time remap EXISTS and is correct: js.rs:589 resolve_signal_name consults ctx.outputs; js.rs:913 the yield calls it; metasystem_codegen.rs:352 fills ctx via args.outputs. The alias is PARSED correctly into BindDecl.outputs and stored for CHAINING (resolve.rs:429 extended_captures). But it is NEVER passed into the ResolvedPrimitive → PrimitiveArgs.outputs, so ctx.outputs is empty at yield time.
Missing:
1. src/pipeline/types.rs:61 ResolvedPrimitive has no `outputs` field.
2. src/pipeline/resolve.rs:446 build output_mappings from bind_decl.outputs + .with_outputs(...) on the ResolvedPrimitive.
3. src/pipeline/expand.rs:~440 (resolved_to_primitive_args) transfer primitive.outputs -> prim_args.output(...).
4. src/emit/metasystem_codegen.rs:352 already correct (applies args.outputs -> ctx.with_output).

** Why it matters beyond the workbench
mcp-input's `$data as $mcpInput` has the SAME bug; it only "works" because publishWorkbenchSources() MANUALLY republishes `data` under derived names (a data-registry side-channel). That republish is a WORKAROUND for this bug. Fixing (A) lets the native alias work + removes the need for that special-case (AGENTS elegance bar: deletes a special-case, no parallel impl).
