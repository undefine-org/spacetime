* Root cause (traced to source via targeted debug instrumentation, not guessed)
`src/main.rs::check_file` builds its lint/analysis registry via:
#+begin_src rust
let (meta_registry, _) = spacetime::compiler::cached_stdlib_registry();
analysis.analyze_dispatch(matches, &meta_registry);
...
analysis.register_macro_yield_signals(matches, &meta_registry);
#+end_src
`cached_stdlib_registry()` (`src/compiler.rs::load_stdlib_registry`) loads
ONLY six CORE stdlib directories:
#+begin_src rust
let dirs = [
  "stdlib/capture-types", "stdlib/runtime", "stdlib/primitives",
  "stdlib/syntax", "stdlib/macros", "stdlib/testing",
];
#+end_src
`stdlib/__mcp__` (and `stdlib/3d`, `stdlib/text`, every OTHER non-core
module) is NOT in this list. So `@mcp-input` (defined in
`stdlib/__mcp__/primitives/host.st`) is simply ABSENT from the registry
`check_file` hands to `register_macro_yield_signals` — confirmed by
instrumenting the lookup: `registry.get_macro_by_form_directive("mcp-input")`
returned `None`, and a full registry dump showed 227 macros, none named
`mcp-input` (only an unrelated `input-bind` macro matched a substring
search).

Meanwhile the REAL compile pipeline (`compiler.rs::compile_pipeline`)
correctly registers every macro from `ast.meta_defs` — which INCLUDES
`@import`ed modules, since `resolve_imports` (called earlier in `check_file`
itself, and already used to build `ast`) folds imported meta-defs into
`ast.meta_defs`. `check_file` already has everything it needs (`ast.meta_defs`
post-`resolve_imports`) sitting right there — it just never registers it into
the registry it hands to the dispatch/yield-signal analysis passes, using the
bare CORE-only cached snapshot instead.

* Fix (already applied, see this commit)
`src/main.rs::check_file`, right before `analyze_dispatch`:
#+begin_src rust
let (mut meta_registry, _) = spacetime::compiler::cached_stdlib_registry();
for def in ast.meta_defs.clone() {
    let _ = meta_registry.register(def);
}
analysis.analyze_dispatch(matches, &meta_registry);
#+end_src
Mirrors exactly what `compile_pipeline` does with `ast.meta_defs` — one extra
registration loop, no new registry-loading mechanism, no new stdlib-dir list
to maintain in two places.
