* Summary

The `as` binding on a driver DEFINES a signal, but the E0408 analysis does not
know that — so correct, current syntax is reported as an undefined signal.

Minimal repro (pure current syntax, no retired directives):

#+begin_src spacetime
.a { @on &.visible(600ms) as $reveal { opacity: 0 -> 1; } }
.b { opacity: var(--st-reveal, 0); }
#+end_src

#+begin_example
error[E0408]: Signal 'reveal' is used but not defined
1 error(s), 0 warning(s)
#+end_example

The signal IS defined — by the `as $reveal` clause, which is the documented
way to name a driver's progress signal and is exactly what the retired
positional-name form migrates INTO.

* Impact

This is a hard error on the recommended surface, so it blocks the very syntax
the on-cutover migration steers people toward. Hit in `demos/starter-pack/`
(the tutorial that IS the program it teaches) the moment its retired
`@on visible demo-reveal(650ms)` was migrated to
`@on &.visible(650ms) as $demo-reveal` — the E0911 cleared and two E0408s
took its place.

31 sites across 10 files use the `(...) as $binding` shape, so the exposure is
wide.

* Provenance

E0408 was IMPLEMENTED long ago but only WIRED to the author in `040d0411`
("fix(check): E0408 wired…", 2026-08-06) — the day before this was found. So
the false positive is as old as the check but only became visible when the
diagnostic started being reported. It is NOT caused by the hard cutover
(`bfc6e7da`); the cutover merely migrated a demo onto the shape that trips it.

* Fix direction (NOT YET VERIFIED)

`src/analysis/signals.rs` collects signal DEFINITIONS. It evidently walks
declarations and `%registers binding(...)` outputs but not the `as` alias
capture. Greping for `alias` / `as_binding` in that file returns nothing,
which is consistent.

The alias is already structural elsewhere — `form_compiler.rs:686` has a
dedicated `alias_capture` path that consumes the `as` keyword and binds the
following name, and BUG-344 just taught `IdentExtractor` that `as` is
structure rather than a name. The definition collector needs the same
awareness: an alias capture is a signal definition site.

Check whether `@each($items as $item)` and `@presence(...) as $name` have the
same gap — they use the same alias mechanism, so if E0408 covers them there is
an existing pattern to copy; if it does not, they are silently affected too.
