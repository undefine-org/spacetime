* Initial Message

BUG-206 — @on hoisting in nested selector blocks. Severity: correctness-breaking, silent.
 The natural way to write a page is nested blocks (.counter { > .controls { > button.inc { @on click … } } }). With nesting, the event binding registered on the outer element — so one click on + bubbled to
 .counter and fired every handler bound under it. In the counter: one click → inc and dec → net zero → the button appears to do nothing. Against a real server it's worse: double-dispatched events — one user
 gesture, two handle_event calls, two state mutations. In a checkout or a booking flow that's a duplicate-submission bug, the class that costs money. The diagnostic surface is brutal too: nothing is visibly
 broken, the count just "doesn't move," and the only evidence is pairs of lines in the server log. The workaround (top-level compound selectors) is fine but unguessable. Any real page with layout nesting +
 events hits this on day one — it should be P1 for the next compiler pass. NB: text/style bindings resolve nested paths correctly (.counter > .value emitted fine) — the hoist is specific to the event-binding
 lowering, which is also the tell for where the fix lives.

 BUG-207 — W0201 false positive. Severity: trust-erosion, not runtime.
 $error is used in a text: binding and in @handle arms, yet check warns it's "never used" — while $count, used in the same positions, doesn't warn. Nothing breaks; the page is correct. The damage is to the
 diagnostic channel itself: a linter that cries wolf teaches authors to ignore warnings — and W0201 shares a check pass with E0928, the contract check that's supposed to be the bridge's safety spine. A noisy
 check output is a check output people stop reading, which quietly devalues the real contract errors when they appear. Fix is a usage-scan hole (one position in the scan misses a source with no subscriber-like
 usage); small fix, outsized hygiene value.
