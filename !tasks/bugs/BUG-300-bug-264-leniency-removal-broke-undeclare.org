* Initial Message

* Symptom

BUG-264 (=fe2c4bee= / =6c5d8cb5=) closed the "trailing tokens are silently
ignored" leniency for body-less forms. That is CORRECT — the leniency was
hiding real near-misses. But several shipped directives relied on it to carry
clauses their =%form= never declared, so they now fail E0946
("Unexpected N extra inline token(s) after directive").

Measured at =5da43c15= with a freshly built binary:

| target | codes |
|--------+-------|
| =demos/= | E0946 (=@type=, =@version=, =@edit-toggle=) |
| =stdlib/= | E0946, E0956 |
| =examples/= | E0946, E0956 |
| =tests/fixtures/= | E0946 |
| =projects/= (6 of 23) | E0946 / E0956 / E0904 |

=@use= and =@exports= were the same class and are fixed in BUG-299; this item
covers the remainder.

* Root cause

The same one, per directive: a clause that is REAL (the parser reads it, the
docs teach it, pages use it) but is not declared in the directive's =%form=.
While leniency held, an undeclared clause was dropped silently and everything
appeared to work. With leniency gone, the undeclared clause is junk.

∴ each affected directive needs its clause DECLARED as a =%capture_type= named
from its =%form= — the BUG-299 fix shape (=use_alias= / =use_filter=, modelled
on =on_as=). This is stdlib grammar work, not Rust.

* Why this is worth doing properly rather than restoring leniency

Restoring leniency would re-hide the near-miss class BUG-264 exists to catch,
and would leave the grammar lying about what these directives accept. The
declarations are the fix; the E0946s are an accurate report of a debt that was
always there.

* Scope

1. Enumerate every directive tripping E0946 across =examples/=, =demos/=,
   =stdlib/=, =tests/fixtures/= and =projects/= (start: =@type=, =@version=,
   =@edit-toggle=).
2. For each: read what the parser actually consumes, declare it in the =%form=
   via a =%capture_type=, keep the name/shape parallel to =on_as=/=use_alias=.
3. =pulsar= trips an =@exports= E0904 that BUG-299's comma fix does not clear —
   diagnose separately.
4. Gate: a corpus check with ZERO E0946/E0956, plus a test that compiles the
   shipped examples (see the acceptance note below).

* Acceptance note — the missing gate is the real story

=examples/modules/index.st= is the shipped module-system demo. It was broken
(E0946, zero CSS emitted) and NO test noticed, because no test compiles the
examples tree. Every directive fixed here should be covered by compiling a real
page, not by asserting on a matcher in isolation.

∴ add a test that compiles =examples/**= and =demos/**= and fails on any
diagnostic. That gate would have caught this whole wave on the commit that
introduced it.

NOTE [2026-08-07]: SELECTOR-LESS =@then= DECLARED [2026-08-07] — one slice of this item closed.

=%macro then-group= added to =stdlib/testing/test.st=, beside =then-claims=:

#+begin_src spacetime
%form { @then { $body:block } }
%emit js { { %$body.js } }
#+end_src

Disjoint from =then-claims= by construction — =$subject:selector= cannot match
an empty head — so declaring both introduces no ambiguity. Declared as its OWN
macro rather than making the subject optional: a =$subject:selector?= would let
=@then { … }= parse AS then-claims, and every nested =@find=/=@assert= would
then be read as a CLAIM (=<prop> <op> <value>;=) and fail far from the cause.

E0946 cleared at all 13 sites (=stdlib/editable/tests/surface.test.st= ×6,
=tests/dev-editable-single-object.test.st= ×3,
=tests/fixtures/native-template/{optional-element-param,template-factory}.test.st= ×3,
=tests/fixtures/w8-seed/state-claims.test.st= ×1).

*The gate caught a dead first version, and this is the load-bearing part.*

was green — but interpolates source TOKENS rather than the expanded emission.

compile to anything". =%$body.js= (what =%macro test= itself uses) fixed it.
∴ this feature's gate is a headless RUN, never a compile check; a =check= gate
would have passed the dead version. Exactly the AGENTS "a source assertion is
not a behavior assertion" case, caught by the harness rather than by review.

(group of subject assertions · group carrying =@assert= · the subject form
