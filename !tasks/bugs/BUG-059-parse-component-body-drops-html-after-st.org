* Summary
=parse_component_body()= (=src/syntax/events/form_compiler.rs:1701=) segments a
=@template= body with LINE-ORIENTED, first-token heuristics rather than the
brace/tag-aware tokenizer used everywhere else in the compiler. Three failure modes
result, all verified by reading EMITTED JS (not check exit codes):

1. *state-before-HTML drops the HTML*. A body whose first non-trivia line is a state
   decl (=$count number: 0;=) followed by HTML emits =html: ""= — the markup is lost.
2. *multiline HTML desyncs* =html_tag_depth=, so a trailing behavior block
   (=.b { @on click { ... } }=) is consumed as HTML and the referenced =$count= is
   reported as =E0806 "references an undefined state variable"=.
3. *unrecognized constructs are swallowed*. Any token the line-classifier does not
   recognize (e.g. =&$w()=, =@match=, =[slot]<-$x=) falls through into the HTML
   string and silently no-ops — check still passes.

This single parser is why Spacetime's component model "exists" on paper (PROJ-101..106
landed) but collapses on any REAL multi-element component, and therefore why the CMS
admin is still a 1330-line hand-written =%emit js= block.

* Root cause detail
=parse_component_body= walks =inner.lines()= and classifies each line by its first
token (=$=, =.=, =[=, =@=, =<=, =&=), maintaining =html_tag_depth= via
=update_html_tag_depth= (line 2856). Problems:
- HTML detection is line-granular; an element split across lines, or HTML following a
  non-HTML line on the same logical flow, is mis-bucketed.
- =html_tag_depth= is advanced only on the "default: HTML content" branch (end of loop),
  but state/CSS/directive lines =continue= before depth is updated, so interleaved
  content desyncs the counter.
- The =else { default HTML }= path is the catch-all that swallows anything unrecognized.

* Approach
Replace the line-heuristic segmentation with a BRACE/TAG-AWARE mini-tokenizer that
walks the body once at byte/token granularity, tracking three depths (angle-bracket
HTML tag depth, brace depth, paren depth) and emitting typed segments:
  state-decl | exports-block | css-or-behavior-block | content-injection |
  class-toggle | template-ref | dispatch-call | match-block | html-run | directive-block
HTML runs accumulate verbatim (including newlines) between non-HTML segments; segment
boundaries are recognized only at tag-depth 0 AND brace-depth 0, so a =.b { ... }=
block after a multiline =<div>...</div>= is correctly seen as a behavior block, and a
state decl before HTML does not consume the HTML.

Keep the structured =ComponentBodyDef= output shape (html, states, directives,
injections, exports, css_rules, refs, selector_refs, diagnostics) — only the
SEGMENTER changes. Add new segment kinds (dispatch-call, match-block, attr-injection)
as EMPTY-producing stubs here so FEAT-073 can fill lowering without re-touching the
segmenter. =[slot]<-$x= attribute-target injection (currently a parse error) is fixed
as part of the injection segment (FEAT-072 depends on it but the PARSE belongs here).

* RESOLUTION (2026-06-06, main thread)

** Root cause (corrected by instrumentation, not hypothesis)
Dumped `ComponentBodyDef` for R1/R2/CONTROL directly. The bug was NOT "multiline
desync" as first hypothesized — it was line-atomic classification:
- A single line holding `$decl; <html>` was consumed wholesale as ONE construct, so
  whichever came second (HTML or decl) was dropped (R1 + CONTROL).
- The injection probe (`contains(" <- ")`) fired BEFORE the behavior-block check, so
  `.b { @on click { $x <- v } }` was misread as a content injection and the @on
  directive was LOST → downstream false E0806. The canonical scoped-behavior form
  (`.sel { @on ... }`, per template-component-model.org) was therefore NEVER wired.
- The fast-path gate `has_component_body_sections` was ALSO line-atomic and diverged
  from the parser, so `<div/> $n number:0;` on one line bypassed the full parse.

** Fix
- New brace/tag/string-aware `segment_component_body()` scanner splits the body into
  typed `BodySegment`s at true construct boundaries (HTML tags via `scan_html_tag`
  with void/self-closing/comment handling; brace blocks via `scan_brace_block`;
  `;`-or-line via `scan_to_semicolon[_or_line]`). Construct-start recognized at tag
  depth 0 even mid-HTML-run, flushing the pending HTML first.
- `classify_construct_start` decides state-decl / @exports / directive / css-or-behavior
  block / class-toggle / injection / ref / dispatch by leading token + terminator.
- The full parse loop now iterates segments (each a COMPLETE construct), reusing every
  existing `parse_*` helper unchanged. Behavior blocks recognize an inner `@on` FIRST
  via re-segmentation + new `parse_on_event_block_scoped` (binds to enclosing selector).
- `has_component_body_sections` delegates to the segmenter — ONE segmentation truth.
- Deleted now-dead `consume_braced_section` + `update_html_tag_depth`.
