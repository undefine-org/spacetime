* Root cause (two independent gaps, both required for the 404)

1. EXPORT never discovers sibling `.st` pages.
   src/export/discover.rs::collect_st_dirs only records directories that
   contain an `index.st` (`st_dirs`). A sibling page like `<site>/brand.st`
   is therefore not a bundle, gets no compile, and src/export/emit.rs has
   no route to emit for it. FEAT-093 taught the DEV SERVER to resolve a
   clean path `/p` -> `p.st` then `p/index.st`
   (src/server.rs::try_serve_st_page) but the STATIC EXPORT path was never
   taught the same resolution -> dev and deploy disagree. This violates the
   deploy-parity rule stated in discover.rs itself and in
   docs/deploy/ARTIFACT.md: "what `spacetime serve` serves, the edge serves".

2. EDGE has no clean-URL convention for an extensionless path.
   Split out to =commercial/host= BUG-034 (separate repo, separate deploy):
   `normalize_pathname` appended `index.html` only for a trailing slash or
   the empty path, so `/brand` looked up the key `{project}/{hash}/brand` —
   a key no export writes. Fixed there; needs the Worker redeployed.

3. A THIRD defect surfaced while verifying gap 1 and is filed as BUG-219:
   the export compiled every entry WITHOUT `site_dir`, so `@doc(src:)` and
   SSG `@each` resolved their build-time file reads against the process CWD.
   The deployed /brand rendered "Document not found" where dev rendered the
   real 1898-char guideline. Independent root cause, same dev/deploy
   divergence class. Both must be fixed for the page to be correct.

* Fix
Gap 1 (this repo): generalize export discovery from "dirs with index.st"
to "route dir -> entry .st", so a sibling `p.st` becomes route dir `p`
with entry `p.st`, reusing the SAME resolution order as the dev server
(`p.st` wins over `p/index.st`). Emit then needs no new branch: the
existing `.st`-only synthesis loop (emit.rs, FUP-039) already turns a
bundle with file-scope markup and no authored `.html` into a page —
it just never received these bundles. Page-vs-module is decided by the
existing criterion (empty compiled `html` => not a page), and bundle
assets are written only for bundles something actually references, so
`modules/*.st` fragments emit nothing instead of a 740KB junk bundle each.

Gaps 2 and 3 are tracked and fixed under BUG-034 (host repo) and
BUG-219 respectively.

* Design notes (why this shape)
- ONE resolution rule, two callers. `st_dirs: BTreeSet<dir>` became
  `st_entries: BTreeMap<route dir -> entry .st>`, and the sibling form is
  collected BEFORE the recursive descent so `p.st` wins over `p/index.st`
  exactly as `try_serve_st_page`'s candidate array does. Dev and export
  cannot drift because they now encode the same order.
- NO new emit branch. The existing `.st`-only synthesis loop (FUP-039)
  already turned "bundle with file-scope markup and no authored .html"
  into a page; it simply never received these bundles. Discovery was the
  whole defect.
- Page-vs-fragment uses the criterion already in the code: empty compiled
  `html` => not a page. `modules/theme.st` is styles, so it emits nothing
  — without this, each of 11 modules would have shipped a ~700KB runtime
  bundle under a URL nothing links to.
- `_`-prefixed siblings are partials by the SAME naming convention
  `path::is_denylisted` already applies to directories — reused, not
  reinvented.
- Compile diagnostics are still reported for EVERY entry, page or not: a
  fragment that fails to compile breaks the pages importing it, and
  silence there is how a broken build looks green.
