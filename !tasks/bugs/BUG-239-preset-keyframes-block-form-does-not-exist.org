#+TITLE: @preset with a keyframes block matches no form (examples/data-binding)
#+STATE: ITEM
#+CUSTOM_ID: BUG-239-preset-keyframes-block-form-does-not-exist

* Symptom

`examples/data-binding/styles.st:207` writes:

#+begin_src spacetime
@preset quick-reveal {
    opacity: 0 -> 1;
    translate-y: 40px -> 0;
    duration: 600ms;
    easing: &ease-out;
}
#+end_src

The only `@preset` form (`stdlib/macros/presets.st:22`) is:

#+begin_src spacetime
%form { @preset $category:ident $name:ident : $value:expr }
#+end_src

i.e. `@preset easing ~spring-bounce: spring(300, 15, 1)` — a category, a name, and
a single value. There is NO block-bodied `@preset`. The example's usage matched
nothing and was silently dropped; `check` was green.

* Found by

BUG-229's E0946 gate (`$name` could not be captured as `Ident`).

* Open question — resolve with SIP-001c

`~name` is the PRESET_REF sigil that SIP-001c retires. This example may be
pre-`~` syntax that was never migrated, in which case the fix is deletion or
rewrite as a `@form`, not a new `%form`. Decide alongside the `~` retirement
(PLAN-121 W1.4) rather than adding a block-bodied `@preset` that is about to be
replaced.

* Acceptance

- `examples/data-binding/` compiles clean.
- The decision (migrate to `@form` vs support a block body) is recorded here.
