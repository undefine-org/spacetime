* Summary
A file-scope `@param` declaration followed by a body-bearing `@template &main(){…}`
makes the whole function UNMOUNTABLE with an INTERNAL compiler-invariant error
(E0925 "template body scope '@template:main' was not built (primitive
'register-template')"). E0925's own hint says it is "a compiler invariant break,
NOT an author error … Please file a bug with the source that triggered it."

This is a REGRESSION + escalation of round-3's C1a. Round 3
(@research/mcp-workbench-review-2026-06-19-round3.org R3-C1a) found file-scope
`@param` produced an EMPTY contract (soft, mountable). It is now a HARD crash —
the function cannot be registered/mounted at all.

* Live repro (verified 2026-06-19 against the running MCP server)
RED (fails):
  @param $name string = "world"
  @template &main() {
    <p>Hi `$name`</p>
  }
→ st_fn_put: "registered with 1 diagnostic(s) -- NOT mountable until fixed:
   x [E0925] internal: template body scope '@template:main' was not built
   (primitive 'register-template')"

CONTROL (compiles clean — isolates @param as the trigger):
  @template &main() {
    <p>Hi there</p>
  }
→ "Function fn-9 revision 1 compiled and registered." ✓

So the trigger is the file-scope `@param` decl preceding the template, not the
template itself.

* Why it matters (vision impact)
"Declare page params at file scope, then a main template" is an idiomatic
authoring style for a parameterised mini-page — exactly what the workbench
gallery/inspector wants to introspect and seed. Today that style is a hard
crash with an INTERNAL error message (not an author-facing diagnostic). The
signature-param form (`&main($name string = "world")`) DOES work and extracts
type+default correctly (verified round-4) — so the two surfaces have diverged
(AGENTS harmony: one need, one impl). The param registry should not care whether
a param was declared in the signature or with `@param`.

* Root cause (source-traced, needs the implementer to localize)
- E0925 = CompileErrorKind::BodyScopeMissing, emitted at src/compiler.rs:~1609.
- Invariant: "every body-bearing construct (@template, &name(){}, @editable-*) is
  named and its World-A scope is built during parsing." A file-scope `@param`
  preceding the template apparently perturbs scope-building so the `@template:main`
  body scope is never built before `register-template` runs.
- Scan site for register-template definitions: src/pipeline/mod.rs:~708-771.
- Likely: the file-scope `@param` consumes/!shifts the scope sequence (an
  unterminated-directive-swallows-following-scope shape, cf. the BUG-047/BUG-070
  family), so `@template &main` is mis-segmented and its body scope is absent.
