#+CUSTOM_ID: BUG-311-dev-server-sends-no-accept-ranges-media

* Initial Message

continue

* Symptom

`cargo run -- serve` answers a `Range: bytes=0-1023` request for an .mp4 with `200` + the full body and no `Accept-Ranges` header (verified 2026-08-05, curl against :3366/reel.mp4).

* Consequence

Chromium marks the media `seekable: [0, 0]` — `video.currentTime = t` is a silent no-op. Real users cannot seek video on any dev-served Spacetime page, and playback-score verification via scripted seeks is impossible (only natural playthrough works). Found in PLAN-135 W6 verifying `stdlib/showcases/hero/media.st`.

* Fix direction

Honor Range for static assets in the dev server (206 + Content-Range + Accept-Ranges: bytes). Production export (dist/) is unaffected — that's the user's static host's job.

* Acceptance

`curl -H "Range: bytes=0-1023" …/reel.mp4` → 206 with 1024 bytes; in a browser, `video.seekable.end(0) === video.duration` and scripted seeks drive `&.playback` scores.
