* Symptom
Any macro whose only output is via `%binds { prim(...) -> { $a, $b } }` (no
`%registers binding($x)`) raises E0405 "Binding in '<scope>' references '<x>',
which does not exist" when its yields are referenced (e.g. in `@each`).

Reproduced (2026-06-20):
- `@realtime todos: Todo[] { channel: "todos" }` then `@each($items ...)` → E0405 on `items`.
- `@presence(room: "r") as v` then `@each($users ...)` → E0405 on `users`.
- The repo's OWN `examples/realtime-demo/presence.st` fails identically — pre-existing.

* Root cause
`src/analysis/signals.rs::collect_form_match_signals` discovers a directive's
yielded signals from a HARDCODED `HashMap<&str, Vec<&str>>` listing only
pointer/scroll/gesture/tick/resize/intersection/media/mutation/fetch. Macros
outside that list (realtime, presence, signal-call, collection, …) contribute
NO signal names, so `Analysis::reactive_source_names()` never learns them and
`validate_binding_sources()` rejects every reference.

This is the AGENTS anti-pattern: a hardcoded Rust list shadowing the
self-describing registry. The `%binds … -> { $items }` clause ALREADY declares
the yields as data; the registry even indexes them (`MetaRegistry.provider_index`
via `rebuild_provider_index`, queryable with `get_providers`). The analyzer just
doesn't consult it.

* Fix
Drive signal discovery from the registry, not the map. Add a registry-aware pass
that, for each FormMatch, resolves its macro (`get_macro_by_form_directive`) and
registers every `%binds` output (resolving `as $alias` / `${$name}_x` patterns
against the match's captures) as a tracked signal. Keep/retire the hardcoded map
as a fallback only for primitives invoked without a matching macro form.

* Acceptance
- `@realtime`/`@presence`/`@data collection`/`@data signal` yields resolve; no

- `examples/realtime-demo/presence.st` passes `check`.
- `cargo test --lib` green; a new RED→GREEN test asserts a `%binds`-only macro's
  yield is referenceable.
- Hardcoded map no longer the source of truth (registry is).

* Impact on the LiveView-Kanban prototype
Blocks the SHARED substrate's dedicated `@presence` cursors + the contended-drag
tension moment (needs presence yields). Worked around in the demo via a
`@data collection via dev-ws` peer model; this fix restores the first-class path.
