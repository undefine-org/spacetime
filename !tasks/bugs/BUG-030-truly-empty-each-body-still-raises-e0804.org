* Source
Follow-up from BUG-028. After making the @each invocations capture optional (+ -> *), realistic bodies (slot-binding, template-invoke) compile. But a TRULY empty body still fails:

  .g { @each($products as $p) { } }   => error[E0804]: Missing required parameter 'invocations'

* Root cause (hypothesis)
With slot/template content present, the body brace-block is parsed and the `invocations` capture registers as an empty array, so bind resolution + is_form_param_optional (ZeroOrMore) succeed. With an empty `{ }`, the body block parse is skipped entirely, so `invocations` never registers as a (present-but-empty) capture and bind resolution at src/pipeline/resolve.rs (~L770) raises MissingParameter -> E0804.

* Fix direction
Ensure a matched form with an empty body still registers ZeroOrMore body captures as empty arrays (so they're 'present'), OR make bind resolution treat an unregistered ZeroOrMore body capture as an empty array rather than missing. Verify is_form_param_optional reaches body-block captures (not just form.params/body_params).

* Severity
Low — a truly empty @each renders nothing, so it's a degenerate authoring case. Realistic reactive lists always have a body.

* Acceptance
- `.g { @each($xs as $x) { } }` compiles with no diagnostics.
- Existing slot/template @each tests stay green.
