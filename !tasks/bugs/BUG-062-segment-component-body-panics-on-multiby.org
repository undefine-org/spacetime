* Symptom
`classify_construct_start(inner, i)` does `&inner[i..]` where `i` is a byte index advanced
byte-by-byte by segment_component_body's default (HTML-content) branch. When a multibyte UTF-8
char (e.g. `…`, `—`, non-ASCII) sits at tag-depth 0, `i` lands mid-char and the slice panics:
`byte index N is not a char boundary; it is inside '…'`.

* Root cause
Shared segmenter (src/syntax/events/form_compiler.rs ~1829). Pre-existing: parse_component_body
hits it too; only surfaced now because the Phase B FLEET differential (FEAT-079 B3c) harvested a
real @template body containing `…` at depth 0.

* Fix (structural)
classify_construct_start guards `inner.is_char_boundary(i)` up front: a construct never starts
mid-multibyte-char (all construct triggers $ @ . # [ & and `<-` are ASCII; UTF-8 continuation
bytes are >=0x80, never a trigger). Not a boundary -> return None (HTML content); the byte loop
advances to the next boundary safely.

* Found by / fixed in
FEAT-079 Phase B B3c fleet differential. Regression test: the fleet differential itself (panics
pre-fix), plus a targeted unit test with a multibyte body.
