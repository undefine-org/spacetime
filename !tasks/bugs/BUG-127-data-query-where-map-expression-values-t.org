* Symptom
A `@data query` (or any macro body property) whose value EXPRESSION starts or
ends with a quoted string silently corrupts:

  @data query $todo from $cards { where: $.col == "todo"; }

emits JS `filterText = "$.col == \"todo"` — the CLOSING quote is dropped, so the
predicate is invalid JS, the runtime `new Function` throws, `filterFn` stays
null, and the query filters NOTHING (every row passes). On a Kanban board this
rendered all cards in every column.

* Root cause
`src/syntax/events/form_compiler.rs::convert_property_value` did:
    let clean = value_str.trim().trim_matches('"').trim_matches('\'');
`trim_matches('"')` removes a quote from BOTH ends greedily, so an expression
that merely ENDS (or starts) with a string literal loses that quote. It was
intended only to unwrap a WHOLE string-literal value (`"hello"` → `hello`).

Compounding it, `CapturedValue::to_js` for the `Expr` variant emitted the
expression RAW in a DoubleQuoted context, so even an intact expression embedded
as a `string`-typed primitive param (`filter: string`) would collide with the
wrapping quotes. Both needed fixing.

* Fix
1. `convert_property_value`: replace blind `trim_matches` with
   `strip_wrapping_quotes`, which unwraps ONLY a single pair of matching outer
   quotes that spans the ENTIRE value (scans the interior for an early-closing
   unescaped quote; leaves `"a" == "b"` and `$.x == "y"` intact).
2. `CapturedValue::to_js` (src/syntax/form_match.rs): the `Expr` arm now
   JS-escapes quotes/backslashes in SingleQuoted/DoubleQuoted contexts (mirrors
   String quoting), so an expression embedded as a JS string literal can't be
   truncated by quote collision.
