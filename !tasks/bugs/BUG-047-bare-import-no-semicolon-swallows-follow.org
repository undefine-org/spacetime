* Symptom
A bodyless directive like =@import "stdlib/text"= with NO trailing =;=,
followed by =
.box { ... }=, consumed =.box= as an inline arg and ={ ... }= as
the import's body — so the scope vanished (scopes=0). The =import= FormMatch span
covered the whole region (e.g. 0..44 instead of 0..26).

* Impact
Silently broke ALL directory-module imports, including the established
=stdlib/mobile= (=examples/mobile-tasks/app.st= emitted 0 bytes). The 98 bare
=@import= statements in stdlib only ever "worked" because the flat-dir loader
loads those files regardless of import resolution; any site/module relying on
=@import= RESOLUTION hit this.

* Root cause
The directive inline-arg loop accepts =DOT=/=HASH= (for =.class=/=#id= in form
patterns) and did NOT stop at a newline. Present in BOTH parsers:
- =src/syntax/cst/parser.rs= (parse_directive inline-arg loop)
- =src/syntax/events/grammar/directives.rs= (inline_args outer + inner per-token loop)

* Fix (commit e1076acf, PLAN-024 W3)
Break the inline-arg loop when at =.=/=#= AND a newline precedes the token (a new
scope statement, not a continuation). Required new newline tracking in the events
parser:
- =src/syntax/events/input.rs=: precompute =newline_before: Vec<bool>= per token
- =src/syntax/events/parser.rs=: =newline_before_current()=
- CST parser: thread an =inline_crossed_newline= flag via =skip_trivia_has_newline=

* Verification
=import_then_scope_variants= (semicolon / no-semicolon / blank-line / two-scopes)
all preserve scopes; raw parse import span 0..26 not 0..44. lib 2090 + integration
162 green.
