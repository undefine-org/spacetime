NOTE [2026-06-12]: RE-TESTED on fresh build (commit 8548b21f, cargo build now works). Sharpened diagnosis: the scroll-spy PRIMITIVE works correctly — IntersectionObserver fires, ST.set(el,"isActive",active) flips (verified in browser: secB.isActive=true after scrollIntoView). The REAL defect is the `@when &self.scrollSpy.isActive { $state <- ... }` GUARD: its mutation body NEVER emits. Confirmed by grep: in /tmp fixture AND in projects/ora-ventures.com/dist/spacetime.js (committed), the ONLY navTheme write is the init ("default"); there is NO @when-guard setter emitting `navTheme <- "dark"`. So this guard form has NEVER worked anywhere — it is a missing codegen feature, not a regression. Two mismatches: (1) the macro yields a FLAT signal `$isActive`, but usage references `&self.scrollSpy.isActive` (a `scrollSpy.` namespace prefix the runtime never stores); (2) the @when behavior block's body mutations are dropped during lowering. WORKAROUND for consumers: scroll-spy's working `isActive` signal can drive a reactive CLASS binding directly — `.sec { @scroll-spy; .sec--active: &self.isActive; }` compiles+checks clean (the reactive-prop path works); use that, or a static nav, instead of the @when→$state mutation. Remaining fix (future): wire @when condition `&self.<ns>.<field>` to a ST.watch on the yielded signal that runs the body mutations; decide whether scroll-spy should yield under a `scrollSpy` namespace or whether usage should be `&self.isActive`.
