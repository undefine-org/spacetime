* Symptom
An @each nested INSIDE a @template body is not compiled — it appears verbatim
in the rendered DOM as text, with holes mis-interpolated:
  @template &card($c) {
    <div class="sig">
      @each($c.params as $p) { <span class="$p.cls">$p.name</span> }
    </div>
  }
renders: `@each([object Object],[object Object] as ) { <span …></span> }`
(the $c.params array stringified into the @each source, $p lost).

* Cause
The reactive builder (FEAT-077) that materializes @template bodies treats the
body as markup + holes; it does not recurse into a nested @each directive. Only
SELECTOR-SCOPE @each (`.sel { @each(...) }`) and FILE-SCOPE @each are compiled.
A template body is neither — so the @each text survives as literal content.

* Impact
Blocks per-item sub-lists inside a card template (e.g. FEAT-092 W4 component
palette param chips). Workaround: shape the sub-list into a single
presentation string in the data-shaping helper (ST.adComponentCards → `sig`),
rendered as one text node. The chips' per-param styling is lost but the data
shows declaratively.
