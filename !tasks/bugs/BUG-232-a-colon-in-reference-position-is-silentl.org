* Reproduction

#+begin_src bash
# with a module defining `@badge` imported as `@use "./badge.st" as b`
.badge { @b/badge("NEW") { color: red; } }   # emits .badge::before into spacetime.css
.badge { @b:badge("NEW") { color: red; } }   # reports "✓ passed", emits ZERO css
#+end_src

Proven by differential build (=cargo run -- build=, grep the emitted
=spacetime.css=): the slash form emits =badge::before=; the colon form produces
an empty stylesheet AND a successful exit code.

* Why it matters

An addressing typo produces a SILENTLY BROKEN PAGE. No error, no warning, no
output — the directive simply vanishes. This is the worst possible failure mode
for a reference: the compiler knew it could not resolve the name and said
nothing.

It also contradicts the fidelity-ladder doctrine (=docs/testing/FIDELITY_LADDER.md=):
refuse rather than fake. A dropped directive is a fake green.

* Root cause (hypothesis, needs confirmation)

The CST lexer emits =COLON= as a token that terminates the directive name run
(=src/syntax/cst/ast.rs:283= — only =SLASH IDENT= continues the run). The
resulting name =b= matches no =%form=, and an unmatched directive appears to be
dropped rather than diagnosed. NOT yet confirmed by reading the drop path.

* Fix

An unresolvable directive/reference name must produce a diagnostic naming the
qualifier and the fix (=E-qualifier-colon= in PLAN-117 §8; =:= belongs inside an
import string, =/= addresses within a registry).

Broader question worth answering while here: is there a general
"directive matched no form" diagnostic, and if not, should there be? A silent
drop of ANY unmatched directive is the same defect class.
