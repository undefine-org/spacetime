* Found
During PLAN-076 W5 live verification (migrations pill): the manual row's
%hint text lost its backticked segments in the DOM — "e.g. `.hidden:

* Root cause (stdlib/primitives/data/each-inline.st)
`fillHoles(rawHtml, item, i) = fillHolesOnly(expandNested(rawHtml, …), …)`.
expandNested substitutes inner rows FIRST (inner fillHolesOnly with the
inner item's data), then the OUTER fillHolesOnly scans the combined result
— re-treating any backticked run in the already-substituted DATA as a hole.
Runs resolving to a property path (`.hidden …` → `$.hidden …`) come back
empty and are erased; runs that look like non-item refs (`$x`,
`$visibility`) are left verbatim — hence the selective mangling.

The outer-after-inner order EXISTS so nested rows can reference the outer
item ($wave.x left verbatim by the inner pass, filled by the outer) — but
it makes substituted data hole-unsafe at any nesting depth ≥ 1.

* Fix (this session)
Protect substituted values, not the template: fillHolesOnly's substitution
now emits data text with backticks sentinel-protected (\uE000), and makeRow
restores them after the final outer pass (before ST.parseHtml). Template
holes left verbatim (outer-item refs) still resolve as designed; data can
never be re-scanned. Regression tests in tests/integration (nested each
with backticked values).
