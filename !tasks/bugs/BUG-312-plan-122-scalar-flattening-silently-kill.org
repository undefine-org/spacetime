* Diagnosis (found PLAN-135 W6, 2026-08-05)

PLAN-122 W1.2 flattened every CSS scalar capture to its SOURCE TEXT (`ScalarSourceTextExtractor`, `src/syntax/events/extractors/custom.rs:256`) — "the serialized repr of a scalar is its CSS string, always". `src/pipeline/score.rs` consumers still expected the OLD typed shapes:

- `measure_value_kind` had arms for `CapturedValue::Time` and `CapturedValue::Length{unit:"%"}` only — a `for 50%` arriving as `String("50%")` matched nothing, so `step.span` stayed `None`.
- `resolve_windows` then read span=0 ("to the end of the score"): the FIRST entry emitted `_swOffset=0, _swSpan=0` (full-range identity) and every later entry `_swOffset=1, _swSpan=0` (extent ≤ 0 → `return 0`, dead).
- `placement_measures`'s `collect` walker had the same blind spot — the E0951 domain check saw no measures at all under String captures.

Effect: EVERY multi-entry score with percentage placements collapsed to "first clip owns the whole window, the rest never animate" — inline AND form-spliced, under `.scroll` (and percentage spans under `.time`/`.loop` scaled wrong). One parse helper, both consumers, inline and fragment paths covered (they share `resolve_windows`/`expand_fragments`).
