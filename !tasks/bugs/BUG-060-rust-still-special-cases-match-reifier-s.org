* Problem
FEAT-073 Phase C moved the @match GRAMMAR to stdlib (stdlib/capture-types/match-block.st,
parsed by the generic %capture_type engine) \u2014 good. But Rust STILL hardcodes @match:
- =parse_match_block_via_engine= (form_compiler.rs): a Rust REIFIER keyed on \"match_block\",
  hand-mapping the engine record \u2192 ComponentMatch. This is a per-construct Rust special-case.
- =ComponentMatch= / =MatchArm= structs (form_match.rs): per-construct typed IR.
- =if ltrim.starts_with(\"@match\")= branch in parse_component_body's segment loop: Rust knows
  the string \"@match\".
- =matches:= serialization + the runtime dispatch keyed on rawBody.matches.
This violates the self-describing principle (AGENTS.md, metasystem/ARCHITECTURE.md): a
construct's grammar AND its lowering should be data-driven, with NO construct name in Rust.
The genuinely self-describing form reifies GENERICALLY from the grammar (like wrap_reifier's
registered reifiers, or better, a %lowers/%emit clause in the .st definition), with zero
\"@match\" string in Rust.

* Deferral (user-approved)
Cleanup deferred to PHASE B (component_body self-describing \u2014 see
[[file:../../@research/phase-b-o2-full-convergence.org]] / the Phase B design). Phase B makes
component_body itself a %capture_type, at which point @match is just another component_item
arm and the full cutover (generic reifier / .st-driven lowering) is possible.
