** The exact chain (two dead half-mechanisms, one shared across the whole family)

`@media("max-width: 1023px") { font-size: 14px }` expands via the `media-query`
macro (stdlib/macros/responsive.st). That macro has TWO paths that should produce
the CSS; BOTH are dead:

*** Dead path 1 — `%when $matches { %applies { $styles } }` (the macro body)
src/pipeline/evaluate.rs:356 evaluates `%when` by resolving its condition at the
EVALUATE stage:
    MacroBodyItem::When(when) => if let Some(v) = ctx.resolve(&when.condition) { if v.is_truthy() {…} }
But `$matches` is a PRIMITIVE OUTPUT (media yields `$matches` at runtime), not an
evaluate-time binding. ctx.resolve("$matches") → None → the `%applies { $styles }`
body NEVER executes → no CSS fragment, css_styles never set. (Semantically wrong
anyway: `%when $matches` gates a RUNTIME signal; CSS can't be conditioned on it at
compile time — that's what the `@media (...)` wrapper is for.)

*** Dead path 2 — the media primitive's `%emit css` block (stdlib/primitives/media.st)
    %emit css { @media (%query) { %self { %styles } } }
This is the CORRECT place to emit the static CSS, but it never receives `$styles`.
The macro's `%binds { media($query) -> { $matches } }` passes ONLY `$query` to the
primitive — NOT the captured `$styles:properties`. So in
src/emit/metasystem_codegen.rs:~493 the CSS branch hits its guard:
    if emit_block.content.contains("%styles") && !args.params.contains_key("styles") { return; }
`args.params` has no "styles" key → EARLY RETURN → css_exprs stays empty,
css_styles stays None.

*** Consequence at the suppress_js guard (src/pipeline/expand.rs:200)
    let suppress_js = !ir.css_exprs.is_empty() && primitive.css_styles.is_some();
Both halves false → suppress_js = false → the matchMedia JS primitive is emitted
(expand.rs:202 `if !ir.js_stmts.is_empty() && !suppress_js`). Pure-CSS output is
never produced.

** Scope: the ENTIRE responsive.st family is affected

* FIX PLAN

The principled fix: route the captured `$styles:properties` into the media
primitive's `%emit css` so it emits `@media (query) { selector { props } }` and
sets css_styles, letting suppress_js drop the JS. Kill the dead `%applies`/`%when`
path (it cannot work — CSS isn't runtime-conditioned). Per AGENTS.md ("don't write
Rust fallbacks for stdlib constructs; fix the stdlib mechanism"), prefer a
stdlib/registry fix over a Rust special-case.

** Option A (PREFERRED) — pass $styles through %binds to the primitive
Wire the capture into the primitive call and let the EXISTING `%emit css` resolve it:
  stdlib/macros/responsive.st  (media-query + every sibling):
    %binds { media($query, styles: $styles) -> { $matches } }
    // drop the `%when $matches { %applies { $styles } }` block entirely
  stdlib/primitives/media.st:
    %primitive media(query: string, styles: properties) { %emit css { … %styles … } %emit js { … } }
Then in metasystem_codegen.rs the CSS guard passes (args.params has "styles"),
css_parser::parse_emit_css resolves `%query`/`%self`/`%styles`, css_exprs gets the
@media rule, AND css_styles must be set so suppress_js fires.
  - VERIFY: does a `:properties` capture flow into `args.params["styles"]` as CSS
    declarations? The css_overrides path (metasystem_codegen.rs ~520, "StyleProperties
    → CSS declarations") already special-cases property captures for CSS — confirm
    media's styles capture lands in css_overrides so `%styles` emits real decls, not a
    JS-quoted blob. If css_overrides is keyed correctly this is mostly stdlib edits.
  - VERIFY: primitive.css_styles is populated from the styles param so the suppress_js
    second conjunct is true. If expand.rs computes css_styles only from a dedicated
    field, thread the styles param into it (small, principled).

** Option B — emit the @media CSS fragment directly in the pipeline for the family
If property-capture→CSS plumbing through %binds proves too invasive, generate the
CSS fragment where the macro is lowered (analogous to generate_state_fragments in
src/pipeline/mod.rs): for a `media-query`-family match with a `$styles` capture and
a `$query`, push a CssFragment `@media (query) { selector { props } }` and set
css_styles. This is a Rust path (less preferred per AGENTS.md) but localized and
mirrors an existing fragment-gen pattern. Use only if A's capture plumbing is shown
to be missing a primitive.

** Either way — delete the dead path
Remove `%when $matches { %applies { $styles } }` from the family macros (it never
runs and misleads). Keep `%binds … -> { $matches }` ONLY if a macro still needs the
runtime `$matches` signal for behavior; for pure responsive styling the media JS
primitive is entirely suppressed, so confirm nothing reads `$matches` before
dropping the bind. (If a consumer DOES use `$matches` reactively, keep the js
primitive un-suppressed for THAT case — suppress_js already guards on css presence,
so a sty=-only @media suppresses JS while a `$matches`-consuming one keeps it.)

** Part 2 — parser: body-shape overload resolution (the surfaced prerequisite)
ROOT CAUSE (deeper than the org plan anticipated): the parse-stage SyntaxRegistry
(`bootstrap_stdlib` over the whole `stdlib/` tree) registers EVERY directive form,
including the opt-in 3D module's `@light(type, …)` (all params defaulted). Forms are
tried by SPECIFICITY (descending). For `@light { color: red }` the high-specificity
3D paren-form matched by IGNORING the brace body, shadowing the responsive
`light-mode` `@light { $styles }` — so `$styles` was never captured and compile hit
E0804. The SAME class of bug silently afflicted `@data fetch … { refresh: … }`: the
bodyless `data-fetch-kind` (ends `;`) matched the body-bearing input and ignored the
options, hardcoding `refresh: 0`.

FIX (src/syntax/events/): a form now knows whether it consumes a body
(`CompiledForm::consumes_body()` = body_capture ∨ body_params ∨ body_groups). In the
MatchSink trial loop, when a node carries a `{ … }` BODY block, a matching form that
does NOT consume it is DEFERRED as a fallback while the loop keeps scanning for a
sibling overload that DOES consume the body; the body-consuming sibling wins. The
fallback is accepted only when no overload consumes the body (e.g. a bodyless
`element-ref` whose trailing `{ … }` is a separate scope) — so element-refs,
synthetic single-form @on, etc. are unaffected. This is BUG-037's named-collision
disambiguation generalized to the syntax layer, and it is DATA-driven (reads the
form's own body-consumer fields), not a per-directive special-case.

NB this is the architecturally-correct subset of the "import-aware parse registry"
direction: rather than make the global SyntaxRegistry per-page import-aware (large,
high-risk; 3D directives are parsed via that same global registry even on importing
pages), the overload AMBIGUITY a leaked form creates is resolved at match time by
syntactic shape. The 3D `@light(…)` form stays registered (3D pages still parse it);
it simply no longer wins a brace-body `@light { … }`.

for BUG-137 (the @media/@dark/@light CSS path — the bug's actual scope — is fully
