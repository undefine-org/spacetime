* Initial Message

Understrand FUP-099 and its root cause, and surface anything else that may come up during the investigation

* Problem

The `:duration` (and `:time`) capture type, *when captured via the brace-body
property path*, stores the raw source token as `CapturedValue::Expr("5m")`
instead of converting it to a number of milliseconds.

src/syntax/events/form_compiler.rs ~1694 (`convert_property_value`):

    CaptureType::Time | CaptureType::Duration => {
        // Parse time/duration: "5m", "300ms", etc.   <-- comment lies; no parse
        CapturedValue::Expr(clean.to_string())
    }

Consequence (PROVEN by CLI build, 2026-06-22):
`@data fetch $x T : "/u" { refresh: 5m }` compiles to

    const refreshInterval = "5m";                 // a quoted STRING
    if (refreshInterval > 0) setInterval(load, refreshInterval);

`"5m" > 0` → `NaN > 0` → false → the guard no-ops; even if it passed,
`setInterval(load, "5m")` is invalid. So a non-zero refresh on `@data fetch`
silently never fires. The value is DOUBLY wrong: numerically (string, not ms)
AND it renders quoted (via `looks_like_css_literal`). Verified for both
`refresh: 5m` (→ "5m") and `refresh: 300ms` (→ "300ms").

* Root cause — one arm, one of three paths

`CapturedValue::Time(ms)` ALREADY EXISTS and already renders to a bare number
(src/pipeline/expand.rs:1592 `CapturedValue::Time(ms) => ms.to_string()`). There
are THREE capture paths for `:time`/`:duration`; only ONE is broken:

| Path | Trigger | Conversion | Status |
|------|---------|-----------|--------|
| token-stream  (extractors/simple.rs:152) | inline/paren tokens `(duration: $d:time)`, bare `$d:time` | `parse_duration_with_unit` → `Time(ms)` | ✓ correct |
| param default (resolve.rs:994)           | `= 300ms` defaults | `* get_time_unit_multiplier` → `Time(ms)` | ✓ correct |
| brace-body property (form_compiler.rs:1696) | `{ key: $v:duration }` property specs | `Expr(raw)` | ✗ BROKEN |

A duration parser already exists and is unit-tested:
src/syntax/conversions.rs::parse_duration_with_unit ("5m"→(300000,"m"),
"300ms"→(300,"ms"), "2s"→(2000,"s")). REUSE it; do not write a new parser.

* Regression surface — bounded to exactly ONE consumer

The brace-body property path fires only when a `%form` carries a `{ key: $v:type }`
property body (`has_property_specs` in form_compiler.rs). Audited every
`:time`/`:duration` spec in stdlib (2026-06-22):

- ALL animation/timing macros (on-event, loop, timeline, fade-in, waapi-*, cycle,
  persist, websocket, effect, presets) use PAREN-form `(duration: $d:time)` →
  token-stream path → already `Time(ms)`. UNAFFECTED by a fix to the brace arm.
- ONLY stdlib/macros/data-kind.st `data-fetch-opts` uses the brace-body path
  (`refresh: $refresh:duration?`, `cache: $cache:duration?`).

∴ The previously-feared regression risks (`@on hover(300ms)`, timeline durations,
CSS timing values) are NOT on this code path. Capture-time conversion of the
brace-body arm is safe.

* Why it surfaced now (NOT a regression)

Pre-existing. Introduced in 934b27e4 ("switch file-level expansion from
MacroCallAst to FormMatch, Phase E") — a gap carried in during a refactor, not a
behavior regression. MASKED until BUG-137: the bodyless `data-fetch-kind` overload
always won form-matching (it ignored the `{ refresh: … }` body and hardcoded
`refresh: 0`). BUG-137's body-shape overload resolution (match_sink.rs) now routes
a `{ refresh: … }` options body to the body-consuming `data-fetch-opts` overload,
which threads the captured `$refresh` to the data-source primitive — exposing the
unconverted string. (BUG-137 filed this exact follow-up.)

* Fix

src/syntax/events/form_compiler.rs ~1694: make the `Time | Duration` arm parse via
`conversions::parse_duration_with_unit(clean)` and emit `CapturedValue::Time(ms)`;
on parse failure (e.g. `{ refresh: $userInterval }` — a binding/expr, not a
literal) FALL BACK to `Expr(raw)` so non-literal refs still pass through.
