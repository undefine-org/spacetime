* Symptom
=@media("max-width: X") { font-size: 14px }= now emits JS (window.matchMedia)
instead of pure CSS =@media= rules. 12 tests/v8_runtime/media_dedup_tests fail
(expect CSS, get JS / 0 CSS bytes). Regression of commit 4de6a0f1
"feat(media): emit pure CSS @media rules instead of JS matchMedia".

* What is CONFIRMED working
- The =media-query= macro CAPTURES correctly: =styles=Properties([{font-size:
  14px}])=, =query=, =children= (verified via parse_matches probe).
- The =media= primitive RESOLVES and expands (trace: "Pushing primitive: media",
  "Expanding primitive 'media'").
- BUT: =--layer css= is 0 bytes; only =%emit js= (matchMedia) fires.

* Suspected cause (bisect needed)
The media primitive has BOTH =%emit css { @media (%query) { %self { %styles } } }=
and =%emit js=. The "CSS-only when styles present" selection is via the macro's
=%when $matches { %applies { $styles } }= / =%binds media($query) -> {$matches}=.
Two candidate causes (uncommitted in worktree during W0-W5 session):
1. MINE: the W1 resolve_single change (=primitive_name = macro_def.name= instead
   of directive name, commit 4c6024c3) may alter how =%binds=/=%applies= resolve
   the conditional CSS emit. HIGHEST SUSPICION \u2014 it changed primitive naming.
2. FOREIGN (concurrent CMS work, uncommitted): src/parser/ast.rs (TypeExpr::Apply),
   src/type_system.rs, src/server.rs \u2014 less likely (media doesn't use @type) but
   present in the worktree.
