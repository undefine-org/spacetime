* Severity
CRITICAL test-integrity compiler bug: silently turns real tests into
vacuous passes. Already present, unnoticed, across the committed suite.

* Symptom
An animation-driver directive whose body is a KEYFRAME list
($body:keyframes capture -- @scroll, @mouse, @load, @on hover/click/
visible/focus with a `prop: a -> b;` body) placed as a step INSIDE a
`@test { ... }` body (bare, or nested in @given/@fixture/@mount) compiles
the ENTIRE enclosing test to `async () => {}` -- empty. No error, no
warning; every step (before and after the directive, including @assert) is
dropped; the runner reports a green PASS.

* Minimal repro (confirmed via inspect --layer emit)
  @test "x" {
    @scroll d(start: 0, end: 1) { opacity: 0 -> 1; }
    @assert (true) "never runs"
  }
Contrast that COMPILES CORRECTLY (isolates the trigger to the keyframes
capture path specifically):
  @test "x" { @on click d { $s <- true; } @assert (true) "runs" }

* Blast radius (verified this session)
ALL SIX tests in tests/unit/animations/mouse-tilt.test.st compile empty
(every "@given .parent { @mouse driver(...) {...} } + assertions" shape) --
the suite has never verified anything. Files sharing the vulnerable shape
(individual tests may still be fine if their driver sits at file scope or
they only use have_timeline):
  tests/unit/animations/mouse-tilt.test.st
  tests/unit/animations/on-visible-mutation.test.st

This also stacked with BUG-196 (no AbortController headless) to hide that
interactive drivers never ran headless at all.

* Workaround (used by BUG-192/BUG-195 pins)
Declare the animated selector at FILE SCOPE (`.class { @scroll ... }` --
how production .st writes it anyway) and keep only markup inside
@fixture/@mount. Compiles and runs correctly.

NOTE [2026-07-19]: FIXED (PLAN-078): root cause was convert_keyframe_body_to_js's lenient content-sniff in captured_to_js_with_registry (src/pipeline/expand.rs) — any captured body text containing `->` + `{`/`:` (e.g. a @test body containing a @scroll directive) was force-parsed as keyframes into garbage, which then failed the block-body fragment re-parse and silently emptied the WHOLE test. Fix: strict fallible try_convert_keyframe_body_to_js (full-grammar consumption required, CSS-ident property names, no @ in selectors) — non-keyframes content passes through raw. Pin 4/4 green.
