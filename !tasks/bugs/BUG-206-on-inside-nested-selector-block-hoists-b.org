* Surfaced by
FEAT-137 (native live transport vertical, elixir/spacetime_lv/frontend/counter.st).

* Symptom
An `@on click { … }` inside a NESTED selector block does not bind to the nested
selector's elements — the emitted `registerSelectorInit` targets the OUTER
block's selector. With two siblings each carrying their own @on:

#+begin_src spacetime
.counter {
  > .controls {
    > button.inc { "+" @on click { $inc() } }
    > button.dec { "−" @on click { $dec() } }
  }
}
#+end_src

…both handlers compiled to `registerSelectorInit('.counter', …)` with
`delegateSelector = null`, so ONE click anywhere inside `.counter` bubbled to the
outer element and fired BOTH mutations (server log: one click → HANDLE EVENT
"inc" AND "dec"; the count never moved: +1 then −1).

Also note: one nesting level that produces a compiled descendant selector works
for OTHER surfaces — `> .value { text: $count; }` inside `.counter { }` correctly
emits `querySelectorAll(".counter > .value")`. The hoist is specific to the @on
event-binding lowering through nested selector blocks.

* Expected
The @on binding registers on the FULLY-RESOLVED nested selector
(`.counter > .controls > button.inc`), exactly as a top-level compound selector
block does today:

#+begin_src spacetime
.counter > .controls > button.inc { "+" @on click { $inc() } }
#+end_src

→ `registerSelectorInit('.counter > .controls > button.inc', …)` ✓ (verified:
this is the workaround FEAT-137 shipped).

* Reproduction
1. Nested form above in any page; build; inspect the bundle: both inits register
   on the outer selector.
2. Click one button → both handlers fire (trace `signal:<name>:fire` events).

* Workaround (shipped in counter.st)
Keep @on in TOP-LEVEL selector blocks (compound selectors fine). Nested blocks
remain safe for text:/style surfaces.

* Suspected layer
The @on/event-binding lowering's selector resolution for nested blocks (it loses
the nested path and falls back to the enclosing block's selector), vs the
text/style lowering which composes the full descendant path correctly.
