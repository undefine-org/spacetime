* BUG — typing in the injected chip-add / relation-multi picker destroys the array

** Parent
[[id:FEAT-076-rebuild-the-cms-admin-multi-file-the-pro]] W4. Data-loss; fixed same-session.

** Symptom (reviewer-found P1)
adHydrateControls injects an un-pathed <input class="ad-chip-add"> into
.ad-chips[data-path][data-widget="chips"] and a <select class="ad-rel-add"> into
.ad-rel-multi[data-path][data-widget="relation-multi"]. The drawer's delegated
@on input/change [data-path] resolves its target via closest('[data-path]'),
which climbs from the sub-control to the CONTAINER div (data-widget chips/
relation-multi). $.value on the div is undefined → adCoerceValue → undefined →
adEditField(path, undefined) overwrites the entire tags/relations array with
undefined in $entries AND persists it via EditJson. Typing one char in "Add…"
destroys the field's array on disk.

** Fix
Route field edits through ST.adFieldInput(el, index): only persist when el is an
ACTUAL widget control (has data-widget + data-path) AND is not a chips/
relation-multi CONTAINER (those add/remove items via dedicated handlers, not the
generic field-edit path). The generic handler now no-ops on the containers.

** Acceptance
- [ ] Typing in chip-add / relation-multi picker does NOT wipe the array.
- [ ] Normal field edits (text/number/toggle/select/single-relation) still persist.
