* Symptom

#+begin_src
@form easing --custom-smooth { cubic-bezier(0.4, 0, 0.2, 1) }
.card { @on &.scroll(name: r, start: 0, end: 1) { opacity: 0 -> 1; easing: --custom-smooth; } }
#+end_src

compiles GREEN. The emitted JS contains `defaultEasing = "custom-smooth"`, but
the CURVE BODY (`cubic-bezier(0.4, 0, 0.2, 1)`) is emitted nowhere. The runtime
(`public/runtime/easing.js`) resolves `easings[name] || easings.linear` → the
animation runs LINEAR. Verified empirically 2026-08-05 (/tmp/formprobe).

Silent wrong-motion: the author declared a curve, the page ships a different
one, nothing complains. The existing gate
(`tests/sip001_easing_forms_test.rs::custom_form_easing_reaches_emitted_js`)
asserts only that the NAME reaches JS — a source assertion that cannot see
the missing body (BUG-252's exact failure mode).

* Fix (PLAN-135 W3)

Collect `@form easing` declarations from the merged AST; emit a runtime
registration so the easing map gains the declared curve (camelCase key per
easing.js convention; cubic-bezier → factory, spring(...) if supported).
An easing reference with NO declaration and NO runtime-map entry → loud
compile error, never a silent linear fallback.
