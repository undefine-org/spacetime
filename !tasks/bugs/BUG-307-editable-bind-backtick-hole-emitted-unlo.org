* The failing gate
tests/v8_runtime_test.rs → `v8_runtime::per_instance_compiled_tests::editable_bind_is_per_instance_across_two_compiled_instances` — the ONLY red test in the 469-test v8 suite (as of a1878e40).

The test compiles a page with `@template &fld($f)` whose `.fld { @editable(bind: `$f.value`); }` is instantiated twice ({value:"alpha"}, {value:"beta"}), via raw `Compiler::from_ast` (no stdlib import). Assertion 1 passes (`js.contains("f.value")`); assertion 2 FAILS: `!js.contains("`$f.value`")` — the bind's backtick hole is emitted UNLOWERED as a literal string into the compiled JS.

* Root cause (two breaks, per prior-session investigation)
1. `%binds` targets `editable-surface`, which lives in opt-in `stdlib/editable` — not resolvable via a raw `Compiler::from_ast` compile with no stdlib import, so the bind never lowers.
2. The test's negative assertion can also false-positive on the primitive's own doc comment if the literal ever appears in bundled prelude JS.

* Verified
Pre-existing at HEAD a1878e40; untouched by the BUG-297/PLAN-135 W3 diff (no editable files changed there). The fix likely belongs in the per-instance template compile path (the bind must lower against the instance's scope even when editable-surface's %binds registry row is absent), or the test needs the stdlib/editable import it implicitly assumes.
