* Found
2026-08-05, while building the BUG-297 easing behavior gate.

* Evidence
`window.scrollTo is not a function` under --headless. `grep scroll src/headless_shims.js` → 1 hit (a comment). There is no scroll model: no scrollTo/scrollY/scrollTop/scrollHeight shims, no scroll-event dispatch.

Consequence: ZERO scroll-driver behavior tests exist in the suite. tests/unit/primitives/scroll-scope.test.st (9 tests) asserts only `have_timeline` — registration, never a driven value. The scroll scrub driver is the ONE driver proven to tick end-to-end in a real browser (BUG-297 verification: scrollTo → exact curve values on elements), and it has no in-harness mid-animation gate.

* Suggested shape
Mirror the IntersectionObserver shim's "honor the inline-style declaration" heuristic: derive a virtual scrollHeight from fixture content (or a test-declared viewport/content height), implement scrollTo/scrollY + scroll-event dispatch, and let the scroll driver compute progress from it. Geometry precision stays a layout-rung (CDP) concern; progress MONOTONICITY and mid-run values are logic-rung and testable today.
