A plain apostrophe in file-scope HTML text content silently breaks compilation — the page emits 0 bytes of CSS (and JS is corrupted downstream), so a styled page renders completely unstyled.

REPRO (minimal):
  <main><p class="d">the compiler's OWN registry</p></main>
  .d { color: red; }
  body { color: white; }
→ `cargo run -- build` produces spacetime.css of 0 bytes. Remove the apostrophe
  (or write &apos;) → 46 bytes, correct.

DISCOVERED: demos/spacetime-docs rendered with no CSS on localhost:3333; the
"Tap me" buttons were unstyled. Root-caused by bisection to one apostrophe in the
gallery panel body text ("compiler's OWN macro registry", index.st:96). Escaping
it to &apos;s restored the full 4003-byte stylesheet. (An apostrophe inside a
/* comment */ is fine; only HTML *text content* triggers it.)

LIKELY CAUSE: the HTML-text lexer/tokenizer treats `'` as a string-delimiter
start (as it would in a directive arg / expression), consuming everything until
the next `'` or EOF. That swallows the following `</p></main>` + the entire CSS
section into a phantom string, so the style rules never parse and CompiledSpacetime.css
is empty. The same class as BUG-070 (file-scope text vs directive-token confusion)
but for the quote lexer in HTML text runs. Double-quote `"` in text likely has the
same risk; needs checking.

FIX DIRECTION: in the file-scope HTML skeleton collection (the CST html_element
text-run lexing, src/syntax/cst/parser.rs parse_html_element / collect_skeleton,
or the html5ever TreeSink feed), `'` and `"` inside element TEXT content must be
literal characters, not string delimiters. Add regression: apostrophe + double
quote in file-scope <p> text must round-trip and must NOT suppress CSS/JS.
Metasystem fix, no Rust special-case for the docs page.
