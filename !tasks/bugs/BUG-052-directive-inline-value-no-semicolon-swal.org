* Symptom
A directive with an inline VALUE and no trailing =;=, followed by a =//= comment
or further statements, captures the trailing content INTO the value. Concretely:

#+BEGIN_SRC
@data fetch $terms T[] : "/data/x.{locale}.json"
// a trailing comment
.foo { color: red; }
#+END_SRC

emits a fetch URL of ="/data/x.{locale}.json"// a trailing comment// ..."= — the
quoted string plus everything after it. Same family as BUG-047 (greedy directive
inline capture without a =;= terminator), here in the directive VALUE path
(=@data fetch ... : <value>=).

* Impact (real)
Broke the ora-ventures hero: =@data fetch $heroTerms : "/data/hero-terms.{locale}.json"=
(no =;=) fetched =/%22/data/hero-terms.en.json%22//...comments...= -> 404 -> heroTerms
empty -> =@cycle= had no data -> split-flap never cycled -> =@value-change= never
fired. Looked like a value-change bug; was actually a fetch-URL capture bug.

* Workaround (applied in FEAT-053)
Terminate the directive with =;=. =@data fetch ... : "...";= captures the URL
precisely. This is the documented convention (stdlib/AGENTS.md recommends =;= on
bodyless directives), but the parser should not silently swallow comments.

* Root cause (suspected)
The directive inline-value / inline-arg consumption loop (src/syntax/cst/parser.rs
and src/syntax/events/grammar/directives.rs) does not treat a line comment =//=
(or a following statement after a complete string value) as a value boundary. The
W3 fix (BUG-047) added a newline guard for =.=/=#= selector starts; it did NOT
cover =//= comments or a string-value directive followed by arbitrary tokens.

* Proper fix
Stop inline value/arg capture at a line comment, and (for a `: <value>` inline
value that is a complete string/expr) at the newline that ends it. Mirror in BOTH
parsers (CST + events). Add tests: directive-with-inline-value + trailing comment,
+ trailing directive, with and without =;=.

* Verification
- =@data fetch ... : "url"= followed by =// comment= and =.scope {}= -> URL is exactly =url=.
- ora-ventures hero: heroTerms fetch 200, flap cycles, value-change animates
  (verified manually post-workaround).
