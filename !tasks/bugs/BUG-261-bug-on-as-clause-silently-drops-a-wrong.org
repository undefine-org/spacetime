* Reproduced

Same page, three spellings of the `as` clause:

| written | publishes | verdict |
|---------+-----------+---------|
| =as $reveal= | ="reveal"= | ✓ |
| =as &reveal= | ="__drive_visible_1"= | ✗ SILENT |
| =as reveal=  | ="__drive_visible_1"= | ✗ SILENT |

All three compile clean. Two of them drop the author's name and publish under
the counter fallback instead.

* Cause

`stdlib/macros/on.st:64`:

: %capture_type on_as { "as" $name:binding }

`binding` is the `$`-sigil capture. `on_as` is OPTIONAL in both `@on` forms
(`$as:on_as?`), so a wrong-sigil name fails the capture and the whole clause
vanishes — no diagnostic, because an optional capture that does not match is
not an error.

`src/pipeline/drivers.rs:307` then compounds it: it strips a leading `$`
(`trim_start_matches('$')`) but not `&`, so even if the capture were widened
the name would arrive with its sigil attached.

* This is the SAME defect already fixed once

W4's review swarm found `@score … as &film` vanishing for exactly this reason,
and the fix was a dedicated `score_as_name` capture type accepting `$element`.
The `@on` side was never audited. One defect, two sites, one fixed.

The sigils are doing their job and the grammar is not listening:
- =as $reveal= names a progress SIGNAL (correct — this is a value that flows)
- =as &reveal= names a TIMELINE ENTITY

For `@on` the published thing IS a signal, so `$` is the RIGHT sigil and `&`
should be REFUSED — but refused LOUDLY, naming the correct sigil. Silence is
the bug, not the sigil rule.

* Fix

1. `on_as` accepts either sigil, and the pipeline REFUSES `&` with a
   diagnostic naming `$` — "a driver's `as` clause names a progress signal;
   write `as $reveal`". Bare `as reveal` gets the same treatment.
2. Audit every OPTIONAL capture in a directive head for the same shape: an
   optional capture whose failure mode is silence is a silent-drop generator
   by construction. This is the fourth instance of the family (BUG-216,
   BUG-229, BUG-253, FEAT-170/BUG-256).
3. Gate with a NEGATIVE: `as &reveal` must produce a diagnostic, not a
   counter-named signal.

* Found via

Migrating `tests/unit/macros/on-hover.test.st` off the retired
`@on visible NAME(800ms)` syntax. The mechanical migration produced
`as &test-reveal` (an entity-looking name), which compiled clean and published
nothing — so the migrated test still failed, and the failure looked like the
test's fault rather than the compiler's.
