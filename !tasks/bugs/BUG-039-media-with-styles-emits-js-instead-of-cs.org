* ROOT CAUSE (verified 2026-06-07, main thread — by reading emitted CSS/JS + stdlib)

The =media= primitive (=stdlib/primitives/media.st=) emits BOTH branches
unconditionally:
- =%emit css { @media (%query) { %self { %styles } } }= — the CSS path
- =%emit js { window.matchMedia('%query') ... %yield -> $matches }= — the JS path

Two concrete defects:
1. The =%emit css= branch is DEAD: the =%self= and =%styles= placeholders inside a
   =%emit css= body are NOT handled by the pipeline (grep: no handler in
   src/pipeline/expand.rs or src/emit/css.rs). So a style-only @media emits NO CSS
   @media rule at all — only the JS matchMedia path fires. (Confirmed: a
   `.responsive { @media("max-width: 1023px") { font-size: 14px } }` fixture builds
   to dist/spacetime.css with NO @media rule, and dist/spacetime.js with
   `window.matchMedia('max-width: 1023px')` + `ST.set(el,'media',...)`.)
2. The query string is passed verbatim to matchMedia WITHOUT parenthesising:
   `matchMedia('max-width: 1023px')` instead of `matchMedia('(max-width: 1023px)')`.
   (The macro %form takes `$query:string`; callers pass `"max-width: 1023px"`
   unparenthesised; the primitive does not wrap it.)

** Correct design (the fix, deferred — see DECISION)
The =@media= macro (responsive.st `media-query`) should lower a STYLE-ONLY block to a
native CSS @media rule (no JS), and only emit the matchMedia primitive when the
block's =$matches=/=$media= exports are actually CONSUMED by reactive code. This needs:
(a) wiring =%self=/=%styles= placeholders in =%emit css= so the CSS @media rule is
    produced from the block's properties (the infrastructure exists — animations wrap
    output in @media at expand.rs:728), and
(b) a usage check so the JS matchMedia path is emitted only when an export is read,
    OR splitting into two macros (static @media -> CSS; reactive @media-bound signal
    -> JS), mirroring the @on style/behavior split.
Always parenthesise the query when building the matchMedia string.
