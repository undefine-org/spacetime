VERIFIED root cause (source-traced 2026-06-19, post-review). The composition path silently discards mount `input`.

SYMPTOM (live): st_mount name=greeter host=inst-1 region=stage input={"name":"Reviewer"} → guest renders empty $name. GET /bundles?region=stage → "input": {}.

ROOT CAUSE (two edits, one path):
1. src/mcp/tools.rs::st_mount — when `host` is present (the compose branch, ~L511-537), the parsed `input` (L482) is NEVER passed to mount_into_host. `input` only reaches the STANDALONE path (mount_function, L539). So composing always drops input.
   CodePath: src/mcp/tools.rs::st_mount  (the `if let Some(host_id) = non_empty_arg(args,"host")` block)
2. src/mcp/live.rs::LiveServer.mount_into_host (L694-745) — signature takes (host_id, region, function_key) only; it inserts region_mounts but has no input param and never writes region_mount_input.
   CodePath: src/mcp/live.rs::mount_into_host

The READ side is correct: instance_bundles (live.rs:1059) seeds the guest from instance.region_mount_input.get(region) → registerBundle. Only the WRITE from mount input is missing. (mcp_param DOES write region_mount_input, live.rs:1232 — so inspector param edits seed correctly; ONLY the initial mount input is dropped.)

FIX: thread `input` (object → map<string,string>) through st_mount's host branch into mount_into_host, which seeds host.region_mount_input.entry(region).or_default() before inserting region_mounts. Mirror the mcp_param write shape.
