#+TITLE: Filter pipe (`expr` | filter(args)) leaks as literal text node in @template/@each interpolation
#+STATE: DONE
#+SESSION_ID: 153497c78a510229
#+CUSTOM_ID: BUG-188-filter-pipe-leaks-as-literal-text
#+COMPLETION_HASH: de798c90ccdf9deb

* Source
GitHub issue #1 (undefine-org/spacetime). Surfaced while building
projects/sakazuki. Canonical examples (examples/data-binding/styles.st) ship
the broken shape, so users copy a silently-corrupting pattern.

* Symptom
In `@template` / `@each` body interpolation, a filter pipe like
`` `price` | currency("$") `` is NOT applied. The value interpolates raw, and
the pipe source itself (`` | currency("$") ``) is appended as a LITERAL text
node sibling. Visitor sees e.g. =49.99 | currency("$")= on the page. No
warning, no error.

* Root cause (verified 2026-07-18)
Two divergent codegen emitters for the same interpolation grammar:
- The `text <-` binding path correctly emits
  `ST.filter("currency(\"$\")", __v)`.
- The template/`@each` body interpolation path emits
  `document.createTextNode(" | currency(\"$\")")` as a literal sibling after
  the (correct) value node.
Verified via `cargo run -- inspect --layer emit examples/data-binding/styles.st`.

* Impact
Silent visitor-facing output corruption with zero diagnostics; contradicts
the shipped canonical demo; affects all filters (`| currency`, `| uppercase`,
`| truncate(100)`, `| if(...)`). Forced workarounds in sakazuki.

* Test pin (RED)
tests/bugs/BUG-188-filter-pipe-leaks-as-literal-text-in-template-each.test.st
- 1 green control (`text <-` path applies filters), 3 RED (template/@each

Run: `cargo run --features headless -- test <file> --headless --format json`
Authoring note: `@assert`'s `$message` is literal-only -- string
concatenation in the message silently empties the test body. Backticks in
@test names also break parsing; both avoided in the pin.

* Fix direction
Unify the two interpolation emitters so template/@each body pipes route
through ST.filters exactly like the `text <-` path; then fix the shipped
examples/data-binding/styles.st demo. Pending user decision (asked
2026-07-18): prioritize fixing the filter paths vs documenting the
workaround first.
