* Found via
Round-2 pressure test (post FEAT-151 fix wave), continuing the audit started
by BUG-160 into every reactive-source-resolving primitive in the stdlib
touching `$signal.field` shapes. `@view $sig.field { ... }` (the re-render-
on-change sibling of `@match`, both share the same arm-resolution idiom)
silently rendered NOTHING — not even the initial pane — for a dotted-path
subject.

* Repro (isolated, confirmed RED on pre-fix code, GREEN after)
#+begin_src
@template &pane-a() { <p class="a">A</p> }
@template &pane-b() { <p class="b">B</p> }
.host {
  @view $wrap.kind {
    "a" => &pane-a();
    "b" => &pane-b();
  }
}
#+end_src
With `$wrap = { kind: "a" }`: `.host` innerHTML was EMPTY before the fix
(should show `<p class="a">A</p>`); correctly mounts pane A after.

Notably, `@match` (`stdlib/primitives/match-render.st`, the render-ONCE
sibling with an IDENTICAL arm grammar) was ALREADY CORRECT — confirmed by
direct source read, it already does `path.split('.')` + `path.slice(1)`
walk. Only `@view`'s `view-mount` (`stdlib/primitives/view.st`) had the bug
— a case of the same idiom implemented twice, once correctly, once not.

* Root cause (identical shape to BUG-155/BUG-160, traced not guessed)
`stdlib/primitives/view.st::view-mount`'s `resolveValue()` checked
`sig in window.SpacetimeLocal` (a literal dotted string like `"wrap.kind"`
is never a real property name) and `ST.get(host, sig)` (same issue, no
split). The reactive channels were ALSO keyed by the literal string:
`document.addEventListener('local:' + sig + ':updated', ...)` and
`ST.watch(host, sig, ...)`.

* Fix
Derive `sigHead = sig.split('.')[0]` and `sigTail = sig.split('.').slice(1)`;
`resolveValue()` now resolves the HEAD from `SpacetimeLocal`/`ST.get` then
walks `sigTail` as property access; the `local:<sig>:updated` listener and
`ST.watch` call both key off `sigHead` (re-deriving the full path via
`resolveValue()` on every fire, same as BUG-155/160's fix — the watched
value itself is a superset (whole head object), never used directly).

This is the THIRD independent fix of this exact bug shape (BUG-155 in
`each-with-templates`, BUG-160 in `each-inline`, this one in `view-mount`).
