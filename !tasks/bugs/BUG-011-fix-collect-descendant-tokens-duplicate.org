* Problem
~collect_descendant_tokens~ (form_compiler.rs:1364) recursively collects tokens from a ~ChildNode~'s ~tokens~ field AND all its children's tokens. When a parent node and its children share the same tokens (which they do for body captures), every token appears twice. After sorting by position, the sequence becomes ~IDENT IDENT COLON COLON~ instead of ~IDENT COLON~, which breaks multi-token extractors like ~PropertiesExtractor~.

PLAN-009 worked around this by adding a dedicated ~CaptureType::Properties~ arm that re-lexes the text. But the bug is latent in the catch-all for any future ~$var:fields~, ~$var:params~, or ~$var:states~ body capture.

* Implementation

** Option A: Deduplicate by text_range (recommended)
After collecting all tokens, deduplicate by ~(text_range.0, text_range.1)~ since duplicate tokens share identical byte ranges:

#+begin_src rust
fn collect_descendant_tokens(node: &ChildNode, out: &mut Vec<TokenData>) {
    out.extend(node.tokens.iter().cloned());
    for child in &node.children {
        collect_descendant_tokens(child, out);
    }
    // Deduplicate: parent and child nodes may share the same tokens.
    // Sort by position first, then remove duplicates by range.
    out.sort_by_key(|t| (t.text_range.0, t.text_range.1));
    out.dedup_by_key(|t| (t.text_range.0, t.text_range.1));
}
#+end_src

Then remove the sorting at every call site (lines 1060, elsewhere) since tokens are now pre-sorted.

** Option B: Collect only leaf tokens
Change ~collect_descendant_tokens~ to only collect from leaf nodes (nodes with no children). This avoids duplicates by construction but changes semantics — need to verify no body_node has tokens that AREN'T in its children.

** Recommended: Option A
Dedup is simpler and preserves existing semantics. Sort+dedup in one place rather than at every call site.

** Cleanup after fix
Once ~collect_descendant_tokens~ produces clean tokens, remove the dedicated ~CaptureType::Properties~ arm (form_compiler.rs:1018-1050) and let Properties fall through to the catch-all ~_ =>~ arm like other extractor-based types.
