* Root cause
The `--headless` fast V8 backend is a bare JS VM (logic-fidelity per
docs/testing/FIDELITY_LADDER.md). It lacks DOM/Web-platform APIs (DOMParser,
Element.animate, IntersectionObserver in some paths) and some ST debug globals.
Tests that need these APIs run on it and fail with ReferenceError/TypeError
instead of either (a) being gated to a higher-fidelity backend (--cdp) or (b) the
backend providing a minimal shim.

* Why it matters
These failures are NOISE in the headless signal: they mask real regressions (a
genuine break is hard to spot among ~62 known-environmental failures). A clean
headless baseline is essential for attributing future changes (this session had to
run an Element-vs-Scoped probe to separate 1 real delta from 62 environmental
failures).

* Verified NOT a regression
Present independent of recent template-scope work (FUP-094): the Element-vs-Scoped
attribution probe showed 62 vs 63 failures, i.e. these ~62 predate and are
orthogonal to template emit changes.

* Options (pick the elegant one)
1. SHIM (preferred for logic-level tests): provide minimal DOMParser (parse to the
   existing lightweight DOM the backend already has), a no-op el.animate returning
   a stub Animation, and seed __ST_DEBUG__/__stDebugHook in the headless harness
   bootstrap. Keeps these tests on the fast backend.
2. GATE: mark the API-needing tests as requiring layout/paint fidelity so they
   REFUSE on --headless (like the existing layout-fidelity refusals) instead of
   erroring — honest, but loses coverage on the fast path.
3. SPLIT: a `dom`-fidelity tier between `logic` and `layout` (jsdom-backed) for
   tests that need DOM APIs but not real layout.

Recommend (1) for DOMParser/animate/debug-globals (cheap shims, keep fast
coverage) + (2) for anything genuinely needing layout.
