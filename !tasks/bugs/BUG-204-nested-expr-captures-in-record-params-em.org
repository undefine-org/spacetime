* BUG: record-typed primitive params (e.g. derive-match's `arms: expr` receiving the cond_block record) serialized nested `CapturedValue::Expr` values VERBATIM. The emit pass then re-tokenized the substituted record and Signal-lowered bare `$sig` → `ST.get(el, "isOrange")` — with `el` unbound in the IIFE scope. Guards became runtime values/throws; dep discovery found nothing; `@data derive $x T : @match {…}` never recomputed (always the catch-all).

* Repro (pre-fix): `spacetime test stdlib/enum/tests/ --headless` → 3 failed; emitted JS showed `guard: { expr: ST.get(el, "isOrange") }`.

* Root cause: two record serializers — `captured_to_js` and `captured_to_js_with_registry` (src/pipeline/expand.rs) — recursed into Named/Array children with the SAME top-level treatment (Expr = verbatim code splice). Inside a record, an Expr is DATA (source text the runtime re-evaluates), not code.

* Fix (DONE, 2026-07-20): added `captured_to_js_data` / `captured_to_js_data_with_registry` — nested Expr → quoted escaped JS string with `$` intact (runtime dep-scan/eval needs it); Named/Array/Block recurse via the data variant; top-level param splices unchanged (Expr verbatim + macro/keyframe expansion).
