A `.st`-only page that opens with `@import "x"` (no semicolon) IMMEDIATELY followed by file-scope `<tag>` markup compiles to an EMPTY body — the served page is blank.

REPRO (minimal):
  @import "stdlib/text"
  <main><p class="x">hi</p></main>
  .x { color: red; }
→ served <body> has NO markup (0 elements). The dev page is completely blank.

BISECTED (matrix):
  A: `@import "x"`  then `<main>`              → EMPTY   (bug)
  B: `@import "x";` then `<main>` (semicolon)  → renders ✓
  C: `@import "x"` + `// comment` + `<main>`   → EMPTY   (comment does not terminate)
  D: `<main>` first, then `@import "x"`        → renders ✓ (import is last; nothing after to swallow)
  E: `@import "x"` + `@type`/`@data`/`@template` decl + `<main>` → renders ✓ (decl terminates)

∴ a terminator-less `@import` directive's argument span extends to consume the
following file-scope HTML element literal. A semicolon, or any intervening
directive/decl, bounds it correctly. This is why demos/spacetime-docs renders
(it has @type/@data/@template between the import and the markup) but a bare
import-then-markup page is blank.

IMPACT (#A): silent, total — a blank page with no diagnostic. Bites the simplest

the first thing a new user / a generated doc page does. Discovered while building
