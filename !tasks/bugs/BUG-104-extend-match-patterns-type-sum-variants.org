* Scope (W0)
1. Extend match_pat capture: add number literal, bool literal, RANGE (`200..299`
   and `2xx` sugar), CONSTRUCTOR (`Created($x)`), STRUCT (`{ status: 200, body: $b }`),
   BINDING (`$x` whole-subject), GUARD (`$pat when <expr>`). Each a bounded leaf
   capture (per match-block.st authoring rule: bounded leaves before literals).
2. Generalize match_arm body: `=> &template(args)` (exists) | `=> { statements }`
   (effects) | `=> Variant(expr)` (construct). One arm grammar, three consequences.
3. @type SUM form: `@type AddResult { Created(Todo) | Invalid(Errors) | Failed }`
   registers variants (name + optional carried type). Reuse the type registry that
   @type product form already writes.
4. `as` ASCRIPTION leaf: `<expr> as Type` in arm RHS; registers the output type,
   which flows to the binding type at the consuming match (decl↔use).
5. Exhaustiveness: a match over a known sum @type must cover every variant or carry
   `_` → compile error (new diagnostic; mirrors metasystem ArgTypeMismatch path).
6. ONE shared resolveArg walking dotted paths (closes BUG-074 in passing).

* Edge cases

- nested constructor/struct (`Created({ id: $i })`): recursion through the same capture.

- sum @type with a nullary variant (`Failed`): no carried type; binds nothing.
- `as` on a non-sum (plain ascription `$.body as Todo`): allowed (type hint only).
- a match NOT over a sum (e.g. @match on a string): exhaustiveness NOT required (open).

NOTE [2026-06-13]: SCOPE REFINEMENT (2026-06-13, §S1 TYPE CREATION): there is NO anonymous sum. @type sum variants are ONE type-creation mechanism at TWO scopes — `@type Name { A(T) | B(U) }` (file scope, shareable) and `receive Name { pat => A($.x as T); }` (signal-local scope; the decode arms ARE the variant definition). Both register ONE named sum in the type registry; the reifier gathers variants from arms identically and binds a NAME (never a nameless sum). This DELETES the anonymous-sum special case → leaner. W0 deliverable: the variant-gathering + registry binding must accept BOTH a file-scope @type decl and a signal-scoped `receive Name` decl, producing identical registry entries differing only by scope. `as` in an arm is the in-scope carry-type declaration (not mere ascription). Composition: an arm may spread a referenced sum (`_ => $.body as ApiError`). Name optional → auto-named scoped type. Keep external @type fully powerful (sharing/recursion).
