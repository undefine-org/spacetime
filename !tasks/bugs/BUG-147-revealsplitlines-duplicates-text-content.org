Same repro independently reproduced on a fresh page (demos/3d/genesis/) using
=@reveal(split: "lines", trigger: visible, stagger: 80, duration: 700, from:
"bottom")= on an =<h1 class="headline">= — duplication scaled with the number
of times the page navigated/hot-reloaded during dev iteration, suggesting the
reveal init may be re-running and re-appending split spans without clearing
prior ones, OR the underlying line-split (pretext-backed per stdlib/text) is
being invoked multiple times and concatenating results instead of replacing.

Note also that spaces are being lost between originally-separate words
("No human modeled" → "No humanmodeled") in addition to the duplication —
two possibly-related defects in the same code path (word-boundary handling +
duplication).

* Suspected area
=stdlib/macros/reveal.st= (=reveal-with-keyframes=/=reveal-simple=) →
its bound primitive (likely =reveal-engine= — grep the primitive backing
=%binds { reveal-engine(...) }=). Possibly interacts with =stdlib/text=
(pretext) line-computation when that module is imported, since
reveal-lines-reflow-free imports =stdlib/text= for exactly this fusion
(FEAT-051 "Fuse reveal split:lines onto pretext"). Worth checking whether
the bug is specific to the pretext-fused path or also reproduces with the
plain offsetTop fallback (no stdlib/text import).

* Workaround in use
demos/3d/genesis/index.st switched from =@reveal(split:"lines", ...)= to
=@load in(duration:, threshold:, ...) { opacity: 0 -> 1; translate-y: ...; }=
— a different, unaffected on-visible primitive (whole-block fade, not
per-line kinetic stagger). Not a fix, just an avoidance; @reveal split:lines
remains broken for any consumer that needs the kinetic-per-line effect.

* Impact
Affects ANY page using =@reveal(split: "lines", ...)= — confirmed on at least
2 independent pages. Given FEAT-051 explicitly fused this path onto pretext
as a headline feature, this is a real regression/defect in a documented,
advertised capability, not an edge case.

- Repro at both authoring surfaces: with and without =@import "stdlib/text"=
