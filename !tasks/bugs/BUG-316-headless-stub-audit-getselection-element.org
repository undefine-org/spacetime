a stub returning a plausible empty/success value instead of refusing is a false-green
generator — a test can pass against it for the wrong reason.

* The three that fake rather than refuse
1. Element.animate — the clearest false-green: a test asserting an element is animating
   (be_animating, playState) passes against a stub that never renders or advances. The
   assertion's claim is a timing/paint fact; the logic backend answers it with a fake.
   These assertions are NOT gated today — be_animating is absent from assertion_min_rung's
   layout list (rung.rs) — so they pass for the wrong reason. Should be gated to a higher
   rung, or animate() must refuse when a real timeline is claimed.
2. getSelection — returns a collapsed empty selection. A contenteditable read of the edited
   text gets ''/null instead of refusing. Selection presence is arguably Logic-faithful, but
   a CONTENT read should refuse or the shim should grow a settable range.
3. IntersectionObserver — declared heuristic (inline-style visibility). Documented, gives a
   deterministic headless contract, but `@on visible` firing depends on it so a visibility
   claim can pass headless and fail in a real browser for geometry the heuristic can't see.
   BUG-305 extends the scroll half; this records the visibility half.

* Fix direction (not implemented)
rung.rs assertion_min_rung should grow timing/layout entries for be_animating / getAnimations
(animation-behavior) so those claims refuse on the logic backend instead of passing against
Element.animate's always-'running' stub. Selection content reads should refuse or be settable.
IntersectionObserver stays declared-heuristic pending BUG-305.
