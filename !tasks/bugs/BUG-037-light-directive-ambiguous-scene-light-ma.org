* Symptom
integration test responsive_nested_directives::light_with_nested_loop_emits_guarded_js FAILS:
`@light { @loop pulse(3s) { ... } }` does NOT emit a matchMedia('(prefers-color-scheme: ...)')
guard. The sibling `@dark { @loop ... }` (dark_with_nested_loop) PASSES with identical structure.

* Root cause
`@light` is bound by TWO macros:
- stdlib/macros/scene/light.st  `%macro light`      form: `@light $type:light_type($params:light_params*)`  (3D scene light source)
- stdlib/macros/responsive.st   `%macro light-mode`  form: `@light { $styles:properties $children* }`         (prefers-color-scheme: light)
The brace-body form `@light { ... }` is being dispatched to (or ambiguously resolved against)
the scene `%macro light`, so the responsive color-scheme guard is never emitted. `@dark` has
no scene-namespace collision, so it resolves cleanly → asymmetry in the test results.

* Pre-existing
Reproduces at HEAD (verified via clean `git worktree add /tmp/verse-head2 HEAD`), independent
of PLAN-023 W0 CST work. Surfaced while gating PLAN-023 Wave 0.

* Fix direction (to confirm)
Form-based disambiguation: the two `@light` forms are structurally distinct (`@light IDENT(...)`
vs `@light { ... }`). Macro dispatch SHOULD pick by form shape, not first-registered. Either:
(a) make form-matching prefer the form whose shape matches the call site (brace vs call), or
(b) rename/namespace the scene macro so `@light` color-scheme is unambiguous at file scope.
Prefer (a) — it is the general fix (form shape is the discriminator the metasystem already has).
