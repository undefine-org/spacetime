* Summary
After BUG-107 (per-file V8 isolation) made the headless suite signal HONEST, the largest remaining real failure cluster was ~76 tests failing with "X is not defined" (counter/form/modal/easing/binding: `counter`, `form`, `page`, `modal`, `app`, `easingNames`, …) plus "X is not defined" for `__obj`/state-machine helpers. Two distinct root causes, both fixed here.

* Root cause 1 — @let bindings do not persist across test steps
Every @test body step (@let / @eval / @then / @when / @assert) compiles to a SEPARATE file-scope directive that the pipeline wraps in its OWN IIFE — `(function(){ const el = document.body; <step> })()` — deliberately, so two `@media` `const mql` can't clash (the IIFE isolation BUG-107-era guard relies on).

The `@let` macro (stdlib/testing/test.st) emitted `const %$assignment` where `$assignment:expr` captured the PARENTHESIZED expr `(counter = document.querySelector(...))`. `const (counter = …)` is invalid JS, so the whole @let step was silently DROPPED — the following `@eval`/`@then` referenced an undeclared `counter` → "counter is not defined". (Some tests "passed" only because they used the name `el`, which every step IIFE injects as `const el = document.body` — a coincidence, not a binding.)

* Root cause 2 — headless harness missing test helpers
`main::new_headless_runtime` (the --headless V8 path) defined only `__spacetime_register_test`. The helpers `__obj`, `__st_register_machine`, `__st_dispatch`, and the `SpacetimeStateMachine` class lived ONLY in the HTML/CDP path (`test_runner::generate_test_runtime`). So every state-machine test (modal) and every `__obj(...)` test failed `X is not defined` under --headless.

* Fix
1. @let now emits a BARE assignment `%$assignment;` (the parenthesized `(name = value)` is a valid assignment EXPRESSION). In the non-strict test runtime this creates a property on the global object that every later step's IIFE closes over by the same bare name — one binding, visible step-to-step. (commit before this one had it as `const`, which silently emitted invalid JS.)
2. The `el` collision: a bare `el = …` would REASSIGN the per-step preamble `const el = document.body` → "Assignment to constant variable". Fix in src/pipeline/emit.rs: when a body-scope fragment's statements REASSIGN `el` (detected: a top-level `el = ` / `(el = ` line), the preamble is emitted as `let el = document.body` instead of `const`, so the reassignment is legal. A plain fragment keeps `const` (immutable, the common case; snapshots unchanged).
3. Injected the SAME test helpers (`SpacetimeStateMachine`, `__obj`, `__st_register_machine`, `__st_dispatch`) into `main::new_headless_runtime` so both backends agree.
4. Converted test-authoring antipatterns that trap scope the same way: raw `const arr = …` test-body statements (assert-custom meta) and `var X` inside a nested eval() (easing) → @let.

* Follow-up
FUP filed: test-body steps share ONE scope (drop per-step IIFE + the `const el` preamble for test directives) so `el` (and any name) persists cross-step uniformly — the principled successor that would clear the residual `el`-cross-step binding failures without the per-name workaround.
