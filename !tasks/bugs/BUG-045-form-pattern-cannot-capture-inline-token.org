* Symptom
A `%form` pattern with a capture BETWEEN the parenthesized arg-list `)` and the body `{`
is silently dropped — never compiled into the matcher, never captured at match time.

Concretely, both stdlib macros that use the shape `@name($params) : $returnType { $body }`
lose `$returnType`:
  - `@fn $name:ident($params:params) : $returnType:typeref { $body:expr }`
  - `@compute $name:ident($deps:param_list) : $returnType:typeref { $body:expr }`

`@fn` SURVIVES only because its primitive (fn-registry) declares `returnType: typeref?`
(optional), so a missing capture is tolerated. `@compute` BREAKS: compute-fn declares
returnType REQUIRED, so the missing capture raises:
  error[E0804]: Missing required parameter 'returnType' (provided: deps, body, name)

* Repro
  @compute total($cart): number { return 0; }      -> E0804
  @fn fp(price: number): string { "x" }             -> parses but returnType is NOT captured
                                                       (caps = name, body, params only)
Impact: projects/jallete (the only real @compute user; checkout-helper.st) has NEVER compiled.

* Root cause (verified)
src/parser/meta_ast.rs::FormClause (line ~286) models a directive form as THREE ordered
segments only:
    @name  <inline_elements>   ( <params> )   { <body_params> | body_capture }
            (before `(`)          (inside ())     (inside {})
There is NO field for tokens AFTER `)` and BEFORE `{`.

src/parser/mod.rs::parse_form_pattern (~3476) computes `after_params = &pattern[)+1..]`
then only does `after_params.find('{')` to grab the body — the run between `)` and `{`
(`: $returnType:typeref`) is never parsed into inline elements. So the FormClause built at
mod.rs:3594 has no record of returnType, and the matcher (form_compiler.rs::try_match) has
nothing to match it with (its segments are: inline_elements before ARG_LIST, params from
ARG_LIST, body_params/body_capture from BODY).

* Fix direction (design — see PLAN)
Add a fourth segment, e.g. `FormClause.post_arg_inline: Vec<FormInlineElement>` (serde
default for back-compat), parse the `)`..`{` run in parse_form_pattern via the existing
parse_form_inline_elements, and match it in try_match AFTER step 3 (ARG_LIST params) and
BEFORE step 4 (BODY) against the main inline cursor — including the no-arg-list path. Then
@fn/@compute returnType is captured generally. Operator-algebra note: `: T` here is a type
annotation, consistent with `:`-is-type.

* Acceptance
- `@fn fp(p: number): string {…}` captures returnType == "string".
- `@compute total($cart): number {…}` compiles (returnType captured) and projects/jallete
  builds clean.
- A regression test for each (capture present + correct value) + golden snapshots updated.
- No regression in existing forms that have NOTHING between `)` and `{`.
