* Symptom
In the MCP builder, selecting a navigator node does NOT filter the inspector to
that node. Live (2026-06-21, post-restart): clicking card node id 1 sets
$selectedNode = "1" correctly, but:
- the SELECTED NODE detail (B3) shows ALL nodes (main, card, card), not just the
  selected one;
- the B4 editable param rows show ALL 4 rows (both cards' params), not the
  selected node's 2;
- the navigator highlight `data-active` is "" not "true" for the selected node.

* Root cause (VERIFIED live)
The structure projection emits node `id` as a JSON NUMBER (the usize walk counter:
0,1,2 — confirmed via input.json: `node id= 1 type int`). The selection signal
`$selectedNode` is sourced from `$.dataset.node` — a DOM attribute, which is
ALWAYS a STRING ("1"). The reactive comparisons:
  - `@each($mcpStageStructure as $node, when $node.id == $selectedNode)` (B3 detail)
  - `@each($mcpStageNodeParams as $p, when $p.node_id == $selectedNode)` (B4 rows)
  - `data-active="`$node.id == $selectedNode`"` (B2/B3 highlight)
all compare int(1) == string("1"), which is FALSE in the ST runtime's equality.
So every filter either matches nothing (or, where the container shows unfiltered
children, shows everything).

* Fix (LANDED)
Emit the structure node `id` as a STRING (`id.to_string()`) in
stage_structure_from_bundle (both the template-node and extern-node push sites,
src/mcp/live.rs ~754/785). `stage_node_params_from_structure` inherits it via
`node.get("id")` -> node_id string. DOM dataset values are always strings, so a
string id is the NATURAL type for the selection comparison — no runtime equality
change needed. Updated the B4 projection test to assert node_id.is_string().
mcp::live 52 green.

* Impact
