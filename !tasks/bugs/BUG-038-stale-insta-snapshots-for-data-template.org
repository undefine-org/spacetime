* RESOLUTION (2026-06-07, main thread)

** Corrected root cause — NOT stale snapshots
The "stale snapshot" hypothesis was WRONG. The true root cause of all 5 snapshot
failures (and, it turned out, the 3 `compiler::tests::html_*` failures too) was a
SINGLE duplicate macro name: `%macro wait-for` defined in BOTH
`stdlib/testing/automation.st:57` (directive `@wait-for <sel>`) and
`stdlib/testing/test.st:968` (directive `@wait_for <sel> timeout:`). Both load into
the shared stdlib registry → E0812 "Duplicate macro definition 'wait-for'" →
EVERY test that compiled against a fresh stdlib registry failed with a pipeline error
(snapshots asserted `pipeline_errors.is_empty()`, html_* asserted clean compiles).

The two are genuinely DISTINCT directives that happened to share a MACRO name. Directive
dispatch keys on the %form first token (resolve.rs `get_macro_by_form_directive`), not the
macro name — so the names can be made unique with zero behavioral change.

** Fix
Renamed `automation.st`'s macro to `%macro wait-for-appears` (its `@wait-for` directive
surface is unchanged; `@wait_for ...timeout:` in test.st keeps `%macro wait-for`). Added a
doc comment explaining the name-uniqueness requirement. No snapshot regeneration was
needed — the committed emit was already correct; the registry was simply poisoned.

** Verification

  now green.
- @wait-for and @wait_for both still resolve (distinct directives, callers unaffected;
  @wait_for has real callers in stdlib/testing/meta/wait-timing.test.st).
- Files: stdlib/testing/automation.st.
