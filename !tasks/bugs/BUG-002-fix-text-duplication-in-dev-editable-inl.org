NOTE [2026-03-30]: Fixed text duplication by: (1) Adding data-st-editing guard to i18n.st, each.st slot binding, and data-binding.js bindSlot to prevent reactive text updates during active edit; (2) Fixing MutationObserver to use innerHTML/textContent based on edit type and removing stale oldValue fallback; (3) Fixing blur handler to not auto-finish edit when MutationObserver has recovered session to replacement element.

* Scope

** In scope
- Root-cause and fix the text duplication bug in dev-editable contenteditable editing
- The bug: editing certain locale-bound text elements produces duplicated content (e.g., "You can makeYou can mak")
- Affects ~stdlib/__dev__/primitives/dev-editable.st~ lines 327-345 (MutationObserver recovery path)
- When reactive re-render replaces the DOM element during an active contenteditable session, the observer copies text from the old element to the new one, causing duplication

** Out of scope
- Rich text formatting toolbar (separate item)
- Structural editing changes to dev-save.st

** Boundary rationale
This is a foundation bug: every editing feature built on top of dev-editable inherits this defect. Must be fixed before any WYSIWYG expansion.

* Implementation

** Root cause investigation
1. Read ~stdlib/__dev__/primitives/dev-editable.st~ lines 105-142 (startEdit/finishEdit) and lines 327-345 (MutationObserver recovery)
2. Reproduce: serve ora-ventures.com in debug mode, click edit on locale text, type replacement text
3. Trace whether ST.setData() or locale-dict re-render fires during contenteditable session
4. Check if MutationObserver on dev-editable re-triggers startEdit or concatenates old+new content

** Fix approach
- Add guard flag (e.g., ~__stEditActive~) on the element during contenteditable session
- Suppress reactive text updates (data-binding.js bind-text, i18n re-render) when guard is active
- Clear guard on finishEdit/cancelEdit
- Ensure MutationObserver recovery path checks guard before copying text content
