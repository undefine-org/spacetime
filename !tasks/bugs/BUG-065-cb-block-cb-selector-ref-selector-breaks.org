* Divergences
1. [P1] cb_block + cb_selector_ref use `$sel:selector` (SelectorExtractor), which STOPS at an
   L_PAREN at depth 0 (reference.rs:120). A CSS block/ref whose selector has a functional
   pseudo-class (`.foo:not(.bar) { }`, `.card:nth-child(2) { }`, `:is()`, `:has()`) fails to
   classify: cb_block -> no arm -> segment LEAKS into html (lost from stylesheet); cb_selector_ref
   -> falls to cb_template_ref -> parse_template_ref None -> wrong E0900. Old parser used
   find('{'), keeping the full selector. FIX: capture the selector run verbatim up to `{` via
   `balanced('{')` (like cb_inject's balanced('<') target), not SelectorExtractor. reify keeps the
   verbatim selector string.
2. [P2] cb_content_bind = `ident ":" "$" balanced(';')` requires `$` IMMEDIATELY after the colon,
   narrowing the old `rhs.contains('$')` gate. A block reactive binding whose RHS is not
   `$`-leading (`text: currency($count);`, `text: 5 + $count;`) degrades to a css_rule. FIX:
   cb_content_bind captures the whole RHS verbatim (`ident ":" balanced(';')`); reify checks
   `rhs.contains('$')` (value-semantics) to decide content-binding vs css \u2014 BUT a non-$ plain CSS
   decl (`color: red`) must still NOT become a binding. So the reify gate is `contains('$')`.
   NB: this needs cb_block to expose the FULL inner so reify can re-split + apply the gate; the
   current cb_block_item path already segments + the cb_content_bind arm must widen.
3. [P2] parse_nested_each still string-parses @each(...) in Rust (extends FEAT-080 purity).
4. [P3] split_arrow dead code (parse_injection/parse_self_property_binding deleted).
