* Follow-up to PLAN-137 W4 / I4 (capture-consumption lint E0964)

The capture-consumption lint now runs over ALL of stdlib with ZERO violations. 30
genuinely half-implemented macros had their unconsumed `%form` captures
`_`-prefixed (the established intentionally-unused convention) to reach zero.
Each one below is a REAL finding of the same genus as gh-18: a capture bound and
never consumed — author intent that silently vanishes at compile time. The
`_`-prefix is a lint-exemption, NOT a fix. These need wiring.

Deeper root cause worth attacking once: the macro-body clauses `%transitions`,
`%template`, `%iterates`, and `%includes` are DROPPED by the parser
(`convert_cst_directive_to_macro_body_item` returns None for them). That is why
the each/fade-in/conditional families are half-implemented — their wiring clause
never reaches the AST. Wiring these clauses (and the `media`/`now`/etc. primitives
to accept the dropped inputs) is the class fix.

## Wired (not deferred) in this wave
- breakpoint $name, on-event-dispatcher $event — the lint's `%if` scan now emits the
  sigiled LHS operand ($name / $event), so a genuinely branch-consumed capture is seen.
- data-derive-match $uitype — marked `%pipeline-consumed`: the pipeline reads `$uitype`
  (inline_union_variants) for the type registry, the lint's name-scan cannot see it.

## Deeper parser gaps recorded (not this wave's scope)
- `%transitions` / `%template` / `%iterates` / `%includes` macro-body clauses dropped by
  the parser → the each/fade-in/conditional macros can never wire their bodies without
  first teaching the parser to store these clauses.
