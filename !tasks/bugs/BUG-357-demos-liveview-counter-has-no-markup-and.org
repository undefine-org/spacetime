* Summary

`demos/liveview-counter/index.st` declares `@host`, two `@data signal`s, a
`.counter` rule with a `> .value` child and two `@handle` arms — but contains
ZERO markup elements. It renders nothing.

`spacetime check` passes (the file is valid), and `build` used to print:

#+begin_example
✓ Export complete:
  Pages: 0
#+end_example

and exit 0. Its committed `dist/` contains `spacetime.css`, `spacetime.js` and
the contract JSON — and **no `index.html`**, which is the artifact of that
silence: the demo has been shipping an empty site.

* How it surfaced

The BUG-351 fix (a build that exports zero pages now exits 1) turned this from a
green build into a red one. Of 28 demos, 20 build, 8 fail — and 7 of those 8
fail for reasons that predate the change (`No index.st found`, `unknown
primitive: cms`). This is the ONLY build whose status the refusal changed, and it
changed it correctly: the demo genuinely emits nothing.

That is also the exact tradeoff weighed when choosing refuse-over-warn. The
"legitimate zero-page project" that argued for a warning did not turn out to
exist here; the one project it caught was broken.

* Fix

Give the page markup. It needs a `.counter` host element with a `.value` child
for the existing rule and handlers to bind to, e.g.

#+begin_src spacetime
<main>
  <div class="counter">
    <span class="value"></span>
    <button class="inc">+</button>
    <button class="dec">-</button>
  </div>
</main>
#+end_src

…plus whatever fires `$inc()` / `$dec()`. The intent is documented in the file's
own header comment (a self-validating LiveView handshake), so the demo is worth
completing rather than deleting.
