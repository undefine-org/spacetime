* Symptom (live, :3335/brand/)
  Uncaught (in promise) ReferenceError: resolvedLocale is not defined
      load  /__spacetime/comments/runtime.js:7153

* Root cause (c51a096e, 2026-04-07 — latent ~4 months)
stdlib/primitives/data/source.st: `const resolvedLocale` was declared INSIDE
the fetch `else { … }` branch of load()'s try, but read in the `catch` —
a different block scope. ANY fetch rejection (404, network blip, JSON parse
error, server restart window) crashed the error REPORTER with ReferenceError
before it could record/report the real error. The real error stayed masked.

The masked underlying error on /brand/ was the comments pill's
/__spacetime/comments/status.json source failing transiently (server restart
window); endpoints verified 200 + valid JSON after.

Deeper smell (same lesson as BUG-273): THREE parallel expressions of "resolve
the locale" existed in one file (init `__loc`, branch `resolvedLocale`, catch
`resolvedLocale || 'en'`). Duplication is what let one binding dangle.

* Fix
Resolve {locale} ONCE per load at load() function scope; the fetch path and
the catch reporter read the SAME binding. The branch-local const and the
catch's redundant `|| 'en'` fallback are gone.

* Verification (RED↔GREEN both proven)
tests/bugs/BUG-274-data-source-error-path-reference-error.test.st:
  - store.error recorded (both worlds — cannot discriminate alone)
  - __ST_DEBUG__.recordError rail reached (post-fix only — sits AFTER the
    formerly-crashing line)
  - error report carries the {locale}-resolved URL (/data-en.json)
RED proven by restoring HEAD's source.st (gate fails), GREEN on the fix.
