NOTE [2026-04-05]: Fixed by adding form-directive lookup fallback in both evaluate_match (evaluate.rs) and resolve_evaluated (resolve.rs). The root cause was that form_match.macro_name contains the directive name (e.g. \"on\") but macros are registered by their full name (e.g. \"on-event-dispatcher\"). * Problem

=evaluate_match()= in =src/pipeline/evaluate.rs= (line 117) looks up macro definitions using:

#+begin_src rust
let macro_def = registry.get_macro(&form_match.macro_name);
#+end_src

For =@=-prefixed directives, =form_match.macro_name= is derived from the directive name (e.g. ="on"= from =@on=), NOT the macro's registered name (e.g. ="on-event-dispatcher"=). The registry stores macros by their actual names, so =get_macro("on")= returns =None=.

This causes =evaluate_match= to skip the macro body entirely (returning an empty =EvaluatedMatch= with =body_was_evaluated = false=). Any macro that:
1. Uses =@directive= form syntax (where the directive name differs from the macro name)
2. Has conditional =%binds= (inside =%if=/=%elif= blocks in the body)

...silently drops all its binds. The resolve stage later finds the macro via form-directive lookup, but =resolve_single= only handles top-level =%binds=, not conditional ones.

** Affected macros (5)
- =on-event-dispatcher= (=@on= form) — breaks =@on visible=, =@on hover= (animation form), =@on click= (animation form), =@on focus= (animation form)
- =responsive= — breaks responsive conditionals
- =state-machine= — breaks state machine transitions
- =waapi-on-event= — breaks WAAPI event animations
- =waapi-timeline= — breaks WAAPI timelines

** Why @after and @on click (mutation) work
- =@after= macro has top-level =%binds= (no conditionals), so =resolve_single= handles it directly
- =@on click { mutations }= matches =on-mutation-dispatcher-simple=, which also has top-level =%binds=

** Observable symptom
On ora-ventures.com, the hero animation chain starts with =@on visible line-1(600ms, immediate: true)=. Since =load-driver= is never instantiated, the =line-1= timeline is never created. All downstream =@after= timelines wait forever, leaving all hero content at =opacity: 0=. * Implementation

** File: =src/pipeline/evaluate.rs=

*** The fix (line 117)

Replace:
#+begin_src rust
let macro_def = registry.get_macro(&form_match.macro_name);
#+end_src

With form-directive-aware lookup that mirrors =resolve_single='s logic:
#+begin_src rust
let macro_def = registry.get_macro(&form_match.macro_name)
    .or_else(|| {
        // Form-directive macros: form_match.macro_name is the directive name
        // (e.g. "on" from @on), not the macro's registered name (e.g. "on-event-dispatcher").
        // Use form-directive lookup with scoring to find the right macro definition,
        // matching the same logic used in resolve_single().
        let matching = registry.get_all_macros_by_form_directive(&form_match.macro_name);
        if matching.is_empty() {
            return None;
        }
        // Score each candidate against the form match captures and pick the best
        let input = crate::syntax::events::form_compiler::CaptureMapInput {
            captures: &form_match.captures,
        };
        matching.into_iter()
            .filter_map(|m| {
                crate::syntax::events::form_compiler::score_macro_form(m, &input)
                    .map(|s| (m, s))
            })
            .max_by_key(|(_, score)| *score)
            .map(|(m, _)| m)
    });
#+end_src

*** Required imports

At the top of =evaluate.rs=, add (if not already present):

Verify =CaptureMapInput= and =score_macro_form= are =pub= in =src/syntax/events/form_compiler.rs=. They should already be since =resolve_single= uses them. Check lines around the struct definition and function definition.

*** Edge case: multiple matching macros

When multiple macros share the same =@= directive (e.g. =on-event-dispatcher=, =on-mutation-dispatcher=, =on-mutation-dispatcher-simple= all use =@on=), the scoring picks the best-fit based on capture overlap. The =on-event-dispatcher= will score highest for =@on visible fade-in(600ms)= because it has the most matching parameters (=name=, =duration=, =threshold=, etc.).

*** What NOT to change

- Do NOT change =resolve_single= or =resolve_evaluated= — they already work correctly when =evaluate_match= provides the right output
- Do NOT change =FormMatch.macro_name= — it's used elsewhere and changing it would be a wider refactor
- Do NOT change the =get_macro= method — direct name lookup is correct for macros that use their actual name

fn test_evaluate_match_finds_form_directive_macros() {
    // Simulates @on visible: form_match.macro_name = "on" (from @on directive),
    // but the macro is registered as "on-event-dispatcher" with form @on ...
    use crate::metasystem::registry::MetaRegistry;
    use crate::parser::ast::*;
    use crate::syntax::form_match::CapturedValue;

    let mut registry = MetaRegistry::new();

    // Register a macro named "test-dispatcher" with form @test ...
    // that has a %if $event == "visible" { %binds { ... } } body
    let macro_def = MacroDefAst {
        name: "test-dispatcher".to_string(),
        form: Some(crate::parser::ast::FormDef {
            directive_name: "@test".to_string(),
            params: vec![
                FormCapture { name: "event".to_string(), capture_type: "ident".to_string(), default: None },
            ],
            body_capture: None,
        }),
        binds: vec![], // No top-level binds — they're in the %if body
        body: vec![
            MacroBodyItem::If(MetaIfClause {
                condition: MetaIfCondition::Equals("event".to_string(), "visible".to_string()),
                then_body: vec![
                    MacroBodyItem::Binds(vec![
                        BindDecl {
                            primitive: "test-driver".to_string(),
                            args: vec![],
                            outputs: vec![],
                            span: crate::parser::SourceSpan::default(),
                        },
                    ]),
                ],
                elif_clauses: vec![],
                else_body: None,
            }),
        ],
        order: Some(700),
        scopes: vec![],
        derives: vec![],
        requires: vec![],
        registers: vec![],
        states: None,
        source_file: Some("test.st".to_string()),
        span: crate::parser::SourceSpan::default(),
    };
    registry.register_macro(macro_def);

    // Create a form match with macro_name = "test" (from @test directive)
    let form_match = FormMatch {
        macro_name: "test".to_string(), // Directive-derived name, NOT "test-dispatcher"
        captures: [
            ("event".to_string(), CapturedValue::Ident("visible".to_string())),
        ].into_iter().collect(),
        capture_spans: Default::default(),
        selector: Some(".hero".to_string()),

        source_file: None,

    assert!(
        result.body_was_evaluated,
        "evaluate_match must find the macro via form-directive lookup"
    );
    assert!(
        !result.bind_decls.is_empty(),
        "The %if $event == \"visible\" branch must produce bind_decls. Got: {:?}",
        result.bind_decls
    );
    assert_eq!(
        result.bind_decls[0].primitive, "test-driver",
        "Must resolve to the conditional bind's primitive"
    );
}

#[test]
fn test_on_visible_produces_load_driver() {
    let source = r#"
.hero {
    @on visible fade-in(600ms) {
        opacity: 0 -> 1;
    }
}
"#;
    let (matches, _css, _registry) = compile_to_form_matches(source);

    // Find the @on match
    let on_match = matches.iter().find(|m| {
        m.macro_name == "on" && m.captures.get("event").map_or(false, |v| v.to_string_value() == "visible")
    });
    assert!(on_match.is_some(), "Should have an 'on' FormMatch for @on visible. Got: {:?}", matches.iter().map(|m| &m.macro_name).collect::<Vec<_>>());

    // Now check that resolve produces load-driver
    let registry = load_test_registry(); // Or however the integration tests get a full registry
    let evaluated = crate::pipeline::evaluate::evaluate(&matches, &registry).unwrap();
    let resolved = crate::pipeline::resolve::resolve_evaluated(&evaluated, &registry).unwrap();

    let has_load_driver = resolved.iter().any(|p| p.primitive_name == "load-driver");
    assert!(has_load_driver, "Must resolve to load-driver primitive. Got: {:?}",
        resolved.iter().map(|p| &p.primitive_name).collect::<Vec<_>>());
}
