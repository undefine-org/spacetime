* Problem
Commit =ac5bb3e8= (March 8 2026) changed the =@scroll= macro's default =scope= parameter from =cover= to =entry= in =stdlib/macros/timeline.st=.

For tall scroll-locked sections (e.g., ora-ventures =.ora-scroll-section--work= at =min-height: 300vh=):
- =cover= scope: scroll range = =vh + 300vh ≈ 3072px=. Sub-ranges like =start: 0.05, end: 0.25= map to ~60vh of gradual animation.
- =entry= scope: scroll range = =vh ≈ 768px=. The same sub-range maps to ~150px, causing all sequential panel animations (in at 5%, hold, out at 45%, next in at 50%) to fire in under one viewport height of scroll.

Result: users see "final states always shown" because animations complete before they're visible.

All 34 =@scroll= blocks in =ora-ventures.com/index.st= rely on the default scope. The 2 blocks that need =entry= (=cta-reveal=, =footer-reveal=) already specify it explicitly. Sites written after the change (=ora-ventures.com/landing/=, =undefine.org=) also specify =scope: entry= explicitly.
