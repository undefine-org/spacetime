* Symptom (OPEN, worked around in the demo)
A multi-line CSS value containing a `$data` reference fails E0952 ("the compiler emitted JavaScript that does not parse"):

  .stage {
    background:
      radial-gradient(60% 50% at 50% 42%, rgba(94, 234, 212, 0.07), transparent 70%),
      $brand.bg;
  }

Error tail: `Expected(,, "string literal ( + ST.resolve(__node, 'brand').bg); } catch (e) { return; }, \" + ST.resolve(...))")` — the interpolation emitter breaks the string literal across the newline inside the value.

* Repro
demos/score-launch/index.st.md carried exactly this in `.stage`; collapsing the value to ONE line compiles fine. The workaround (single line) is in place with an NB comment; remove the NB when this bug closes.

* Expected
Multi-line CSS values with $refs are ordinary CSS formatting; the emitter must not care about the newline.

* Notes
Single $ref values on one line work (used throughout the same file). The failure needs the newline INSIDE the value before the $ref (or between the gradient and the color stop). Likely the CSS-value→JS-string emitter joins segments without escaping/concatenating across the raw newline.
