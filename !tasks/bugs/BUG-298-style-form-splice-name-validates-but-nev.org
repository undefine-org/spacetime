* Symptom

A statement-position style form splice validates but NEVER expands:

#+begin_src
@form style --card-surface { background: #121722; border-radius: 9px; }
.card { --card-surface; color: white; }
#+end_src

compiles GREEN; the emitted CSS is only `.card { color: white; }` — the spliced
body's declarations are silently dropped. Verified empirically 2026-08-05
(/tmp/formprobe, `cargo run -- build`).

* Root cause

`--name;` in a scope parses to FORM_REF (BUG-241) and `validate_form_refs`
(src/parser/mod.rs:2187) rejects unknown names with E0947 — but expansion was
deferred: `src/parser/ast.rs:98` — "Validated by `validate_form_refs`;
expansion is W3 scope." That wave never landed. `form_refs` are read nowhere
in src/emit or src/pipeline.

This is the arc's banned silent-acceptance class: the page compiles green
while the author's declarations vanish.

* Fix (PLAN-135 W2)

Splice the declared body's declarations into the scope at the splice's source
position (CSS order matters), with param substitution for parameterized forms
(`--surface(pad: 2rem);`). Non-style kinds in bare-scope statement position →
hard error naming the kind that belongs there (motion → @on driver slot,
score → @score body).

* Gate

RED first: the probe above must emit background+border-radius. E0947 stays
hard for unknown names. Params substitute. CDP: the element is actually
styled (BUG-252: source assertion ≠ behavior assertion).
