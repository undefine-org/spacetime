* Summary
`:root { --x: red; }` at file scope fails with "expected scope block, directive, or declaration" at the closing brace. The leading-colon pseudo-class selector isn't recognized as a scope selector head.

* Repro
printf ':root {
  --x: red;
}
' > /tmp/rt.st && spacetime check /tmp/rt.st  → error
printf 'html {
  --x: red;
}
' > /tmp/rt2.st && spacetime check /tmp/rt2.st  → OK

* Impact
Minor. `:root` is the idiomatic home for CSS custom properties (design tokens). Authors must use `html { }` or `[data-theme] { }` instead. Functionally equivalent for custom props (both cascade to document root), so low severity.

* Likely cause
The scope-selector parser (src/syntax/cst/parser.rs / convert_cst_scope) doesn't accept a bare pseudo-class (`:root`, presumably also `::before` at top level) as a selector head — it expects an element/class/id/attr start. A leading `:` is likely consumed as a value-colon or type annotation.

* Workaround
Use `html { }` for :root-level custom properties (adopted in projects/backdesk-v2/modules/theme.st).
