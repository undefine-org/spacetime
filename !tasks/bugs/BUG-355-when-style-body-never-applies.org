#+TITLE: BUG-355: @when with a style-rule body compiles to runMutations and never applies
#+CATEGORY: bugs
#+STATE: ITEM
#+PROPERTIES:
#+CUSTOM_ID: BUG-355-when-style-body-never-applies
#+PRIORITY: #A
#+END:

* Symptom

#+begin_src spacetime
.proj--1 { @when &self.scrollSpy.isActive { .idx--1 { color: #191714; } } }
#+end_src

compiles clean and does nothing at runtime. The guard FIRES (the spy signal
flips — observed live: =ST.get(el,'isActive') === true=, progress tracking
correctly), but the target styles never reach the page.

* Cause (observed emission)

The style-rule body is compiled to:

#+begin_src js
const body = { js_statements: [".idx--1 { color: #191714", "..."], macro_calls: [] };
ST.watch(host, sig, (v) => { if (!v) return; ST.runMutations(host, body); });
#+end_src

Two defects:
1. CSS rule text is passed to ~runMutations~ as =js_statements= — it is not
   JS, nothing applies, and nothing errors (the try/catch would log
   =[ST] @when guard body error=; the console stays clean, so the statements
   are silently ignored).
2. ~if (!v) return~ — there is no false arm, so even a working body could
   never UN-apply. The documented use (nav theming per active section)
   requires both.

The doc example in stdlib/macros/scroll-spy.st
(~@when &self.scrollSpy.isActive { .nav { background: navy; } }~) is exactly
this shape, so the documented feature ships dead — BUG-252 lineage again: a
compile-emission gate cannot see a runtime no-op.

* Evidence

demos/portfolio (PLAN-146 W3): four @when guards over @scroll-spy, signal
verified true in a real browser, computed styles unchanged.

* Fix direction

Either teach ~runMutations~ a CSS-rule arm (parse selector + declarations,
toggle a generated class while truthy, remove when falsy), or make @when with
a non-expression body a COMPILE REFUSAL until it works. A silent no-op is the
worst of the three.

* Addendum — three facets of one gap (2026-08-08)

While pivoting demos/portfolio:
1. ~data-spy <- $isActive;~ written in the SAME rule as ~@scroll-spy~ is a
   grammar error: "directive does not match its declared grammar: Unexpected
   5 extra inline token(s) after directive".
2. The same binding in its OWN rule (~.proj { data-spy <- $isActive; }~)
   compiles clean but resolves nothing at runtime: the attribute renders
   ~""~ on two panels and ~null~ on the others. Primitive-yielded signals
   (~{ $isActive, $progress, $direction }~) apparently cannot be referenced
   from a style-rule binding at all — only from ~@when~ (whose style body is
   itself dead, per this bug).
3. So today there is NO working path from a primitive's yields to the
   cascade. The showcase tabbed pattern binds ~@data inline~ signals
   (~data-panel <- $panel~) successfully — the gap is specific to
   primitive-yielded signals.
