* Source
GitHub issue #4 (undefine-org/spacetime), enhancement gap.

* Symptom
There is no declarative way to show wall-clock time (e.g. "JAPAN, HH:MM:SS"
in a footer). `stdlib/primitives/tick.st` yields only the rAF timestamp $t;
`interval.st` yields only a fire count. Neither exposes Date/timezone.
Sakazuki had to ship a static "JAPAN, HH:MM:SS" label.

* Verified 2026-07-18
tick.st contains zero Date.now / new Date; interval yields counts only. The
`@clock` name is TAKEN by the testing DSL (stdlib/testing/timing.st), so a
wall-clock primitive needs another name (@now used in the pin).

* Test pin (RED)
tests/bugs/BUG-191-no-declarative-wall-clock-primitive.test.st
- 1 green control + 1 RED (a @now-style primitive yielding HH:MM:SS).
Run: `cargo run --features headless -- test <file> --headless --format json`
Authoring note: headless performance.now() is epoch-scale (harness
artifact); a third control relying on it was dropped. See BUG-196.

* Fix direction
Add a small stdlib primitive (e.g. `@now(interval: 1s, format: "HH:MM:SS",
tz: "Asia/Tokyo") -> $text`) mirroring tick.st's structure, backed by
Date/Intl.DateTimeFormat. Additive, no new subsystem (passes the elegance
bar: same machinery as tick, deletes the "static label" workaround).
