* Symptom

A `.st` file that declares signals and styles but contains no markup builds to
NOTHING, and the build reports success:

#+begin_src
$n number: 0;

body { color: red; }
#+end_src

#+begin_src
$ spacetime build .
✓ Export complete:
  Pages: 0
  Files copied: 0
  Total size: 0 bytes
#+end_src

Exit code 0. No warning. `dist/` is created but empty. Adding any markup element
flips it to `Pages: 1`.

* Why this matters more than it looks

It defeats VERIFICATION, not just authoring. This is how I twice produced a
vacuous "confirmation" while investigating BUG-334/BUG-331: I built a
styles-only repro, grepped the empty `dist/`, found nothing, and read that
absence as evidence the feature was broken. The absence was my own empty build.

A tool whose failure mode is "silently produces nothing, says ✓" will keep
manufacturing false negatives in exactly the situations where someone is trying
to prove something is missing.

* The judgment call

It may be CORRECT that a page with no markup emits no page. But then it must SAY
so — `Pages: 0` next to a ✓ is not a statement, it is an omission. Compare the
existing rail: `check` refuses unknown directives loudly; `build` should at
minimum warn "no page emitted: <file> declares no markup".

Decide deliberately:
1. WARN on a zero-page export naming the file and why (recommended — cheap,
   preserves current behavior, kills the false-negative class), or
2. REFUSE a build whose every input produced zero pages (stronger; may break
   legitimate stylesheet-only or prelude-only projects), or
3. Document it as intended and leave it (weakest — the trap stays).

* Repro

: mkdir -p scratch/x && printf '$n number: 0;

body { color: red; }
' > scratch/x/index.st
: cd scratch/x && spacetime build .

Observed `Pages: 0`, exit 0, empty dist/.

* Gate

A build whose export is zero pages must emit a diagnostic naming the file.
Assert on the RUN (stdout/exit), not on a source string.
