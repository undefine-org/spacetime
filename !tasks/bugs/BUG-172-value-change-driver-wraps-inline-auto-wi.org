* Initial Message

it still looks weird

* Symptom

`@value-change` (`stdlib/macros/timeline.st::value-change-timeline`, backed by
`stdlib/primitives/animation/drivers.st::value-change-driver`) applied to an
inline-level, auto-width element (e.g. `display: inline-block` word-cycle
"flap" with no explicit `width`) produces a visible "ghost text" double-line
artifact on every text-change transition when the incoming text is wider than
the outgoing text.

First observed on =projects/ora-ventures.com='s hero =.ora-hero__flap=
(=@cycle= + =@value-change= word rotation): "stalls" transitioning to "dies in
decks." rendered with both words overlapping across two visual lines instead
of a clean single-line crossfade.

** Live reproduction (dev server, not test harness)

Sampled =.ora-hero__flap='s =getBoundingClientRect().height= every 100ms
across one text-change cycle:

#+begin_example
0ms:100px  100ms:101px  ...  1400ms:76px(*)  1500ms:76.8px(*)  1600ms:37px settle
#+end_example

(*the ora-ventures probe used a shorter flap; a synthetic isolated probe with
=font-size:32px= measured 37px steady-state -> 76.8px peak -> 37px settle,
i.e. peak = 2.08x steady-state height — a false 2-line wrap.)

* Root cause

=stdlib/primitives/animation/drivers.st::value-change-driver=, in the
=animateChange= inner function (around L807 pre-fix):

#+begin_src js
var containerWidth = %&el.offsetWidth;
#+end_src

This value is fed into pretext's line-breaker
(=ST.text.layout(prepared, containerWidth, lineHeight)=) as the wrap
constraint for laying out the INCOMING text.

For a BLOCK-level element, =offsetWidth= is a real, meaningful line-box width
— the element stretches to its container regardless of content, so
measuring it before vs after the text change gives the same number and the
wrap decision is correct.

For an INLINE-level, AUTO-WIDTH element (=display: inline-block=/=inline=
with no explicit =width=), =offsetWidth= is the SHRINK-TO-FIT width of the
CURRENT (old) text — not a real line-box constraint. By CSS auto-width
semantics, such an element never force-wraps its own content on its own; it
only wraps if an ANCESTOR constrains it, which =offsetWidth= (a property of
the element ITSELF) cannot express.

When the incoming text is wider than the outgoing text's shrink-to-fit width,
pretext's line-breaker (correctly, given the wrong input) wraps the new text
to 2 lines. The driver then:
1. Animates the element's =height= via WAAPI from =currentHeight= (1-line) to
   =targetHeight= (the falsely-computed 2-line height) — a real, visible
   height doubling.
2. The absolutely-positioned EXIT layer (still showing the OLD text, per-word
   spans) stays pinned at its own 1-line position while the IN-FLOW enter
   layer wraps to 2 lines beneath/around it — producing the visual overlap
   ("ghost text").
3. On cleanup (=animateChange='s =setTimeout= -> =heightAnimDone.then=), the
   driver resets =%&el.style.height = targetHeight + 'px'= then immediately
   sets =%&el.textContent = newText= and clears the height/overflow/clip-path
   overrides — the element SELF-HEALS back to single-line height because the
   plain textContent, unconstrained, naturally renders on one line again. This
   is why the bug is only visible DURING the transition, not after it settles
   — a naive "measure before, measure after" test misses it entirely; only a
   mid-transition sample catches it.

* Fix (applied)

Only trust =offsetWidth= as a wrap constraint when the element's computed
=display= is genuinely block-level (stretches to container width regardless
of content): =block=, =flex=, =grid=, =list-item=, =table=, =flow-root=.
Otherwise (inline, inline-block, inline-flex, etc. with auto width), pass
=Infinity= — matching the element's real CSS layout behavior (single line,
no self-imposed wrap).

#+begin_src js
var elDisplay = cs.display;
var elIsBlockLevel = elDisplay === 'block' || elDisplay === 'flex' ||
  elDisplay === 'grid' || elDisplay === 'list-item' ||
  elDisplay === 'table' || elDisplay === 'flow-root';
var containerWidth = elIsBlockLevel ? %&el.offsetWidth : Infinity;
#+end_src
