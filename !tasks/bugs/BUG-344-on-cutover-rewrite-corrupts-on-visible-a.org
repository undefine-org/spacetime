Two independent defects in one rewrite:

1. *Data loss.* ~name: as~ — the literal keyword `as` is captured as the
   animation name, and the actual binding `$reveal` is DROPPED entirely. Any
   reference to `$reveal` elsewhere in the file is silently orphaned.
2. *Wrong target driver.* `&.visible` → `&.load`, when `&.visible` is the
   correct CURRENT surface for this code (see below).

* Root cause

`%rewrite on-visible` (stdlib/migrations/entries/2026-07-26-on-cutover.st:636)
matches:

#+begin_src spacetime
@on &.visible $name:ident ( $duration:time, ... ) { $body }
#+end_src

i.e. the name comes BEFORE the parens — the retired named form. The modern
form puts the binding AFTER, with `as`:

#+begin_src spacetime
@on &.visible(600ms) as $reveal { ... }
#+end_src

The `$name:ident` capture is unanchored, so it happily matches the trailing
`as` token, the paren group lines up, and the rule fires on a shape it was
never meant to claim.

* Why `&.visible` must not be rewritten here

`visible` is a REGISTERED, CURRENT driver — `stdlib/macros/drivers.st:94`:

#+begin_quote
An ENTRANCE, not a sensor. `@on &.visible(300ms)` means "when enough of me is
on screen, play this over 300ms"
#+end_quote

And the capsule's own `%hint for @on` says it outright:

#+begin_quote
`@on &.visible` maps to `&.load` (its behavior was always the load driver —
**for viewport-entry reveals use `&.visible`**)
#+end_quote

So the intended scope of `on-visible` is the RETIRED `@on visible $name(...)`
spelling, not every occurrence of the live `&.visible` driver. The rule is
over-matching its own documented intent.

* Fix direction (NOT YET VERIFIED)

Options to evaluate:

- anchor the match so `$name:ident` cannot bind the literal `as` (a negative
