## Audit Findings

### 1. Escaped quotes in raw strings produce broken HTML

- **What**: The locale fallback in `try_serve_locale` uses `\"` inside `r#"..."#` raw strings. In Rust raw strings, `\"` is literal — it emits a backslash followed by a quote, not just a quote.
- **Where**: `src/server.rs` lines 664, 675–676, 691–692 — the `validation_inject`, `debugger_inject`, and `spacetime_inject` blocks in the `build_scripts.is_empty()` branch.
- **Why**: The HTML injected into locale-served pages contains literal `\"` in tag attributes (`<link rel=\"stylesheet\" ...>`). Browsers won't parse these tags, so the Spacetime runtime CSS, JS, dev tools, and validation UI all fail to load on the EN/FR locale paths. **Every other path** in the same file (lines 782–797, 810–813, etc.) uses unescaped `"` inside identical `r#"..."#` blocks. This is the only path that's wrong.
- **Effort**: `trivial` — remove the backslashes from 5 occurrences.

### 2. Double compilation of .st file in locale fallback

- **What**: The locale fallback calls `compile_from_site()` (line 605) to check `build_scripts.is_empty()`, then calls `get_or_compile()` (line 642) separately for diagnostics. These are two full compilations of the same .st file on first load.
- **Where**: `src/server.rs` lines 605–655 in `try_serve_locale`.
- **Why**: Unnecessary performance cost — compiling the full site twice per first locale request. The fix is to use `get_or_compile()` from the start and check `compiled.build_scripts.is_empty()` on the returned result, which also provides diagnostics.
- **Effort**: `small`

### 3. No test coverage for locale fallback path

- **What**: The 19 server tests don't cover `try_serve_locale` when `build_scripts` is empty (the new fallback). The escaped-quotes bug (#1) would be caught by any basic test that checks the emitted HTML.
- **Where**: `src/server.rs` test module (bottom of file).
- **Why**: The most impactful new code path — the one users hit on every locale page load — has zero automated coverage.
- **Effort**: `small`

### 4. Hardcoded `localhost:3333` preconnect in production HTML

- **What**: `<link rel="preconnect" href="https://localhost:3333" />` is hardcoded in the HTML head.
- **Where**: `ora-ventures.com/index.html` line 23.
- **Why**: In production, this causes a failed TLS connection attempt on every page load. It's a development artifact that should either be removed or conditional on dev mode.
- **Effort**: `trivial`

- **Why**: Known issue that causes intermittent 404s on locale pages will be forgotten without tracking. Needs a BUG item or FUP.

### 8. Double-IIFE wrapping with double-semicolons in generated JS

- **What**: The `JsScope::IIFE` change (always wrapping in IIFE) produces `(function() { const el = document.body; (function() { ... })();; })();` — an outer IIFE plus the primitive's own inner IIFE, with `;;` at the join.
- **Where**: `src/pipeline/expand.rs` line 208 + snapshot `data_directive_js.snap` lines 2234–2358.
- **Why**: The double semicolons are valid JS but cosmetically rough. The double IIFE is unnecessary overhead for primitives that already have their own IIFE — the `const` redeclaration protection the outer IIFE provides is redundant when the inner IIFE already scopes it. Not a bug, but a future simplification opportunity.
- **Effort**: `medium`
