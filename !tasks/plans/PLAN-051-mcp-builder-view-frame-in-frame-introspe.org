* TWO-LEVEL EDIT MODEL (owner-locked 2026-06-20: "from the start", "AND not but")
A selected node that is a construct instance (&card call) can be edited at TWO
levels, both through the SAME EditAst rail, differing only in the source span:
- INSTANCE: patch the call's args at the call-site origin (this node only).
  e.g. EditAst{ file: landing.st, selector: ".hero §card", patch: {title: V} }.
- COMPONENT (definition): patch the template/component definition at its OWN
  source (components/card.st) — param DEFAULTS + the body STRUCTURE; affects ALL
  instances. e.g. EditAst{ file: components/card.st, selector: "§template card",
  patch: {...} }.
The inspector header carries a [Instance | Component] segmented toggle (mockup 84
= Component mode). Instance mode (mockup TODO) shows OVERRIDDEN args bold vs
INHERITED-from-definition muted, with a per-row "reset to component default"
revert (the override model).

** Why it is one rail, not two systems
A definition is just another construct with a source span / origin. "Edit
Component" is the inspector pointed at the definition's address instead of the
call-site's. No component/override special-case subsystem (the Webflow trap) —
same introspection (read the form), same EditAst (write the span). This is also
what makes the self-host endgame possible (FUP-091): the builder's own chrome is
constructs, so Component mode can target a builder panel.

** UNVERIFIED prerequisite (promote, do not assume): the instance COUNT
The "affects N instances" affordance (mockup 84) requires a DEFINITION->CALLSITES
index ACROSS the project. v1's structure projection (W3) walks ONE mounted
guest's template graph; counting all call sites of a definition project-wide is a
BROADER query. Build task: a definition->callsites index (likely a registry/graph
query over the parsed project), feeding both the count + a "jump to instances"
affordance. Until it exists, Component mode may show "affects all instances"
without a count. NOT a free UI label.

** Scope
The two-level TOGGLE + Instance-mode override view + Component-mode definition
edit are PLAN-051 scope (owner: from the start). The cross-project instance INDEX
is a prerequisite build task (sibling to FUP-089's write-path work). Self-host
(Component mode on builder chrome) is the end-of-plan experiment (FUP-091).
