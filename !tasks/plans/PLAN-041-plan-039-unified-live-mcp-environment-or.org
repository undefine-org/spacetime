* Initial Message

please look at the work done in the Spacetime MCP and realise that it is *user-hostile*.
I want the MCP to be able to nest UI concerns: the UI of the MCP itself (being able to navigate between environments, and betyween tabs of that environment) with the UI of communicating with the agent (buttons and affordances and signifiers that the agent sent that are hooked back to any of the hook types we are envisioning), with the UI that is being shown (the actual contents of the live environment, which sometimes are linked to the MCP and other times they are linked to whatever we are doing).

Do a review of the coe and compare it to PLAN-038 + BUG-104/102, FEAT-110/111/112/113/114, FUP-049. What was achieved, what was forgotten, what should be implemented, and what would that free us to do?

Turn the Spacetime MCP from isolated per-function pages into ONE persistent warm-dark living studio page where every loaded Spacetime (stdlib prelude, env functions, agent-sent, kit) composes INTO it as region-mounted bundles. Not a dev tool — an *organic interface birthplace*: live content is the organism; navigation/comms/inspection/provenance recede into warm extensible drawers orbiting the stage. C1/C2/C3 nest in one page, one DOM, one runtime.
