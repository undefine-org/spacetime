---

- **What**: Stale `cargo run -- serve site/` / `check site/` / `build site/` and "Site Directory (`site/` and subdirectories)" ownership in agent context prompts.
- **Where**:
  - `.claude/agents/site-designer.md` — multiple, including `## Tools & Technologies` "`cargo run -- serve site/` for live development server", `## Owns / Site Directory (`site/` and subdirectories)`, `## Notes / Development Workflow` step 1 "Start dev server: `cargo run -- serve site/`", debugging tips `RUST_LOG=trace cargo run -- serve site/`, plus `site/examples/todo-app` example.
  - `.claude/agents/pipeline-engineer.md` — the shell block under `## Notes / Key Debugging Commands` contains `RUST_LOG=spacetime::pipeline=trace cargo run -- serve site/`, `cargo run -- check site/`, `cargo run -- build site/`.
  - `.claude/agents/code-quality-guardian.md` — 1 example mention `site/examples/todo-app`.
- **Why**: `site/` no longer exists in the repo. Subagents loaded under these identities will paste broken commands and propose changes to a non-existent directory. This is precisely the work item FEAT-014::update-skills was meant to cover (the plan explicitly listed "Update only verbatim copy-paste-ready commands"); execution missed `.claude/agents/`.
- **Effort**: trivial (3 files, literal find/replace `site/` → `projects/<name>/`, plus rename "Site Directory" ownership stanza to point at `projects/`).

---

- **What**: `# Or from the Spacetime repo root: cargo run -- serve <cd_target>` hint in `run_init` success output assumes the caller's cwd is the Spacetime repo root.
- **Where**: `src/main.rs::run_init` ~line 1782–1783.
- **Why**: When `cd_target = projects/<name>` the hint is correct only if cwd was already the repo root (so `projects/` was the in-repo gitignored dir). When `cd_target = <name>` (no `projects/` parent), the hint prints `cargo run -- serve <name>`, which only resolves to the right place if the user's cwd happened to be the Spacetime repo root. Misleading for users who installed `spacetime` and ran `init` from a personal scratch dir without `projects/`.
- **Effort**: trivial (gate the "Or from the Spacetime repo root" hint behind the `cd_target.starts_with("projects/")` branch, or drop the hint entirely).

---

- **What**: `resolve_init_target_returns_pathbuf` test is a tautological type assertion duplicating `resolve_init_target_no_projects_dir`.
- **Where**: `src/main.rs` ~lines 3736–3741.
- **Why**: Adds noise without coverage. The function signature already declares `-> PathBuf`; the cargo build proves the type. Dead test.
- **Effort**: trivial (delete).

---

- **What**: No test for `projects/` being a broken symlink (target missing).
- **Where**: `src/main.rs::init_target_tests`.
- **Why**: `std::fs::metadata` follows symlinks; on a broken symlink it returns `Err`, so `unwrap_or(false)` falls back to cwd/name. Behavior is correct but unverified. Adjacent to the existing `with_projects_symlink_to_dir` test, easy to add.
- **Effort**: trivial.

They look like the older equivalent of the `!tasks/bugs/` org-mode bug tracker. Demoting them to gitignored `scratch/` removes them from the main repo's history going forward and from anyone cloning the repo. The plan scoping called this a "decision" but the deletion is irreversible after the next prune; consider whether they should instead be archived under `!tasks/` or `docs/legacy-bugs/` before falling out of git visibility.
- **Effort**: small (move tracked-but-still-needed entries into `!tasks/bugs/` legacy area; or `git mv scratch/bugs docs/legacy-bugs` and adjust .gitignore exception).

This plan implements the accepted recommendations from [[id:AUD-006-audit-implementation]]. AUD-006 audited the PLAN-015 projects/ reorganization commit and found small correctness/documentation gaps that should be cleaned before agents or users copy stale =site/= commands, before legacy compiler bug notes disappear into gitignored scratch, and before =spacetime init= gives misleading fallback instructions.

Two choices were clarified before planning:
1. Legacy compiler bug markdown currently in =scratch/bugs/= should be preserved as markdown under tracked =docs/legacy-bugs/=, not converted into org items.
2. The borderline stale historical summaries should be deleted, not patched. The files are =tests/PHASE8_SUMMARY.md= and =.serena/memories/STDLIB_JS_EMISSION_TRACE.md=.

** Settled decisions
1. Agent prompt cleanup targets only =.claude/agents/site-designer.md=, =.claude/agents/pipeline-engineer.md=, and =.claude/agents/code-quality-guardian.md= for the stale command/ownership examples called out by AUD-006. Generic English uses of "site" may remain when they mean websites, not the removed =site/= directory.
2. =run_init= keeps the primary output =cd <target>= and =spacetime serve .= for all workflows. The repo-root =cargo run -- serve <target>= hint is gated to targets under =projects/= only, because only those are guaranteed to be relative to the Spacetime repo root convention.
3. =resolve_init_target_returns_pathbuf= is removed as dead coverage. A broken =projects= symlink test is added beside the existing symlink-to-dir test.
4. Legacy compiler bug markdown is preserved in =docs/legacy-bugs/= with a README. If ignored local files in =scratch/bugs/= are absent during execution, recover exact contents from =HEAD~1:bugs/<filename>=.
5. =tests/PHASE8_SUMMARY.md= and =.serena/memories/STDLIB_JS_EMISSION_TRACE.md= are deleted per user clarification. No wider historical-doc cleanup is included.
6. Execution should close [[id:AUD-006-audit-implementation]] to DONE after all four child items pass verification.
