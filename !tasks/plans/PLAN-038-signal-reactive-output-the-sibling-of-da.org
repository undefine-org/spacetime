* North star

Spacetime is a reactive-INPUT language today: @data (inline/fetch/derive/fold/query)
covers SOURCE→STATE→VIEW. The INTENT→OUT arc has no home — pages drop to imperative
`@on click { fetch() }`. @signal is the missing half: the author-level OUTWARD verb,
mirroring @data, completing the reactive loop:

    SOURCE ──→ STATE ──→ VIEW ──→ INTENT ──→ (SOURCE) …
   (@data in) (signals) (render) (@signal out)

Payoff for the MCP: an "interface" stops being a frozen Rust tool and becomes a .st
FUNCTION loaded live — it declares input (params), renders UI, declares signal-back
(@signal). picker / form / confirm collapse from 4 bespoke Rust tools into library
functions called through 2 generic verbs (st_mount / st_await).

** Why this order

The previous PLAN-038 ordering put the full matcher/type/language foundation before the user could feel the live environment. The revised order cuts a narrow vertical thread:

#+begin_src text
st_fn_put(source)
  -> compile + store Function revision
st_mount(fn,input)
  -> serve live Instance URL
human/browser POST /__mcp/signal/{instance}
  -> EventStore
st_await(instance)
  -> typed event to agent
st_inspect(instance)
  -> contract + diagnostics + event history
#+end_src

This preserves the final architecture while reducing risk. The first slice uses an explicit/declared contract object; later FEAT-110/FEAT-113 replace that producer with compiler introspection. The shape is the same, so no user-facing conceptual migration.

** Non-negotiable invariants

- One generic event sink: =/__mcp/signal/{instance}=.
- One function registry; no bespoke Rust contract per interface.
- Pages communicate via Spacetime/prelude primitives, not custom JS.
- Rust owns transport/registry/compile/event queues; Spacetime owns UI/interface functions.
- A function update that preserves the contract fulfills the same role; a breaking contract change is explicit.
- Compatibility wrappers are allowed only as migration shims.
