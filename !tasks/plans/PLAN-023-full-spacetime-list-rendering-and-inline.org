* North star (design-session decisions — the heart of this plan)

** valid HTML is valid Spacetime
`<` becomes a top-level sigil in the meta-syntax. The CST recognises an HTML element
literal exactly as it recognises a scope block, directive, or decl. HTML correctness
(nesting, void elems, raw-text script/style, implied tags, error recovery) is delegated to
**html5ever** via a custom `TreeSink` that builds `ir::HtmlExpr` DIRECTLY (no RcDom round
trip → fast, fully type-aware, introspectable). lol_html was evaluated and REJECTED: it is
a streaming rewriter with no tree, so it cannot SSG-unroll or re-inject holes. (lol_html
may earn a seat later for runtime hole-hydration into a served stream — not now.)

** SSG by default; <template> only for dynamic data
A data source declares its own staticity. The @each emitter branches on it:
- static source  → UNROLL the loop into real HTML in the page (crawler sees content).
- dynamic source → emit a skeleton + Spacetime.templates factory + hydrate at runtime.
This makes the SEO win load-bearing and reserves the (single) <template> discovery path for
genuinely dynamic lists. The original plan's "synthesize <template> for everything" is
retired.

** holes are the ONE bridge from HTML into Spacetime
Inside HTML, embed Spacetime with a backtick hole: `<li>`$x`</li>`, `<a href="`$url`">`,
`<div>`&content`</div>`. The hole's inner tokens are parsed as a FULL Spacetime expression
(Option C — one expression grammar, one correctness layer; no string re-scanning, no split
AST/CST correctness across layers). Holes appear ONLY inside HTML. Everywhere else,
Spacetime syntax is already the host language and is written bare (e.g. `@data derive
$total: sum($items)` — no backticks).

This also resolves the `&` / HTML-entity collision: html5ever parses a pure HTML skeleton
with holes pre-extracted as placeholders, so it never sees bare `&content` as a
(broken) entity. `&` only means "element binding" INSIDE a hole; `&amp;` stays a real
entity in text.

** sigils encode the TYPE of a binding (not a tag)
- `$x`   value-typed binding   — any reactive value (may be a function).
- `&x`   element-typed binding — points to a DOM node, or a factory "curried to become" a
         node. `&card($p)` = APPLY the element-binding `card` to `$p` → an element. The text
         after `&` is a VARIABLE NAME, never a tag name. (Runtime today:
         `&name → document.querySelector('[data-st-ref="name"]')` or
         `Spacetime.templates.get(name)(...args)` — see form_match.rs:1408, template.st:155.)
- `<…>`  element literal — html5ever-parsed structure.
- `` `expr` `` hole — embed a Spacetime expr (which may use $ or &) into HTML.

** operators are an algebra split across the use/definition boundary
END-USER surface:
- `:`   type / static bind / CSS decl     `$name: string[]`, `color: red`
- `<-`  reactive assignment               `$x <- $x + 1`
- `->`  transition / yield / reducer step `0 -> 1`, `(…) -> step`
META-LAYER ONLY (defining the language — %primitive / %macro / %form / %capture_type):
- `=`   default-assignment at DEFINITION time   `params: array = []`, `easing: $e:ident = ease-out`
∴ `=` is the sigil of the meta-layer. A page author writing a .st site NEVER types `=`;
only someone authoring stdlib primitives writes it, to give a parameter a default. Seeing
`=` tells the reader "this is a definition, not a use." The operator set itself encodes the
use/definition split — reinforcing design goal #1 (compiler = meta-syntax, stdlib =
end-user language) at the syntax level.

** types: postfix [], never <> generics
Collection types are postfix: `string[]`, `Product[]`, `CartItem[]` (already the
convention — local-state.st:80). There are NO angle-bracket generics in end-user Spacetime.
∴ `<` is UNAMBIGUOUSLY the start of HTML. This is why `@data inline $products string[]:
["a","b"]` parses with zero ambiguity against `<ul>`.

** @data is one construct: a named reactive source<T>
Surface (kind-word discriminator like @on's event word; typed decl like
parse_variable_decl `$name <type> : value`):

    @data <kind> $name <type>? : <value>

    @data inline   $products string[] : ["a","b"]
    @data fetch    $api      Product[]: "/api/products" refresh 30s
    @data derive   $total    number   : sum($items)
    @data fold     $running  number   : ($cart, acc, x) -> acc + x.price
    @data inline   $seats             : 3                 // type omitted, still valid

Note: NO `=` (type before `:`, value after `:`). `@computed` keyword is DELETED → folds
into `@data derive` / `@data fold`. The kinds are stdlib %macros, one per kind — the KIND
IS THE MACRO (no `%if $src == "inline"` string-switch). Each binds a `source-<kind>`
%primitive that DECLARES its own `{ static, trigger }` contract:

    inline  → static: true,  trigger: none
    fetch   → static: false, trigger: poll(refresh)
    derive  → static: AND(deps.static), trigger: deps      (transitive const-fold)
    fold    → static: false (stateful), trigger: deps

Staticity is therefore a PROPERTY OF THE SOURCE PRIMITIVE — not a Rust enum, not a `%`
predicate. The @each SSG branch just reads `source.static`. This is the user's "scope-local
boolean of staticity at the @data macro", realised via the existing %registers/scope-lookup
affordance.

computed FAMILY (sub-words, NOT operator overload). SHIP NOW: derive, fold.
ROADMAP (grammar reserves space; not built this plan):
  debounce ($q ~> 300ms) · throttle ($s <~ 16ms) · delay (lag N) · await (flatten
  source<source>) · sample (gate by control source) · merge (latest-any of N sources).
Pressure-tested orthogonality: derive=stateless, fold=stateful, debounce/throttle=timed,
delay=historical, await=async, sample/merge=combinatorial — six real categories. derive+fold
cover every current demo (list count, cart total, configurator).

** capture types: Rust owns the ALPHABET, stdlib owns the GRAMMAR
The %capture_type engine (custom.rs `compile_pattern`) is already a real PEG/combinator
compiler: Literal · CharClass · reference-to-another-type · Sequence · Choice(|) · Group ·
`*` `+` `?` · recursion via registry lookup. The Rust `CaptureType` enum (meta_ast.rs:386,
37 variants) conflates THREE categories:

  (A) IRREDUCIBLE LEAVES (the alphabet — terminals recognised by char/token scanning):
      Ident String Number Bool Time Length Duration Color Easing Expr Binding Selector
      Typeref Event Preset  + operators Union, PatternMatch  + the Custom hook.
      → KEEP in Rust (efficient, genuinely terminal). This is the pragmatic core.

  (B) COMPOSITIONS IN DISGUISE (Rust hand-rolls loops the PEG already expresses):
      Params Fields Properties Keyframes ParamList States Transitions MutationActions.
      complex.rs = ~900 lines of brace/paren-depth while-loops. param_list PROVES the
      redundancy: it exists BOTH as Rust ParamList AND stdlib param_list.st.
      → MOVE to stdlib %capture_type; DELETE the Rust loops; resolve the param_list double-path.

  (C) THE HTML/TEMPLATE ZOO (semantic — not capture types at all):
      HtmlBlock ComponentBody Template TemplateInvocation.
      → DELETE. HTML → html5ever HtmlExpr; template semantics → stdlib %macro over HtmlExpr.
      (JsBlock: KEEP as a Rust leaf — JS is genuinely opaque to Spacetime; "balanced JS
       until matching brace" is a terminal. Used only inside %primitive %emit js. — user call.)

Test for the boundary:
  terminal (scan chars, no sub-structure)?            → Rust leaf
  structure over other capture types (Seq/Choice/*)?  → stdlib %capture_type
  semantic ("an HTML element", "a template")?         → not a capture type (html5ever / macro)

** %balanced — the ONE new PEG leaf that unlocks category B
complex.rs's loops do depth-aware "collect tokens until a delimiter AT depth 0, respecting
() [] {} nesting" (see complex.rs:129-151). PEG has Choice/CharClass but lacks depth
tracking. Add ONE primitive:

    %balanced(until: ';')        // collect until ';' at nesting depth 0

This single, general primitive lets EVERY category-B type be re-expressed in stdlib and
retires ~900 lines of bespoke Rust. It is the user's "improve %capture_type" — one
well-chosen leaf rather than N hand-rolled extractors. on-actions.st already composes the
non-nesting cousin (`raw_until_semicolon = [^;]+`); %balanced is the nesting-aware version.

%balanced MUST be property/fuzz tested (user mandate): generators for arbitrary nested
bracket strings assert (1) returns at the correct depth-0 delimiter, (2) never splits inside
nesting, (3) handles unbalanced input without panic (graceful error), (4) round-trips with
the existing complex.rs behaviour on the current stdlib corpus (differential test:
old-extractor output == new-%capture_type output for params/keyframes/properties across all
stdlib + fixtures before deleting the Rust paths).

** ITEM W2 structured-output %capture_type — the reifier boundary
:PROPERTIES:
:CUSTOM_ID: PLAN-023-full-spacetime-list-rendering-and-inline::reifier-boundary
:END:
DISCOVERY (recon contradicted the plan): category-B extractors are NOT delimiters — they
produce TYPED structured CapturedValue (Properties(Vec<PropertyDef>), Params(Vec<ParamDef>),
Keyframes(Vec<KeyframeDef>), ParamList(Vec<TemplateParamDef>)) consumed by ~43 sites
(resolve/expand/form_scoring/visitor/sync/lsp/timeline_lint). A PEG %capture_type produces
only generic Array/Expr/String. The param_list "redundancy" the plan cited is actually a
SHAPE-MISMATCH: Rust ParamList wins (parse_capture_type hardcodes the enum), stdlib
param_list.st produces Array and is SHADOWED/dead. So the obstacle to "grammar in stdlib"
was never verbosity — it was the typed-output contract.

THE REIFIER BOUNDARY (three legitimate categories, extending the alphabet/grammar split):
  TERMINALS (alphabet)   — Rust   — scan chars -> CapturedValue (Ident, Number, %balanced)
  PRODUCTIONS (grammar)  — stdlib — compose terminals (%capture_type bodies)
  REIFIERS (type adapters) — Rust — generic record (Named) -> domain struct (PropertyDef)
A reifier is the seam where a generic parse-result becomes a Rust-owned domain TYPE. It
belongs in Rust because the TYPE is Rust (consumed by Rust pipeline). The GRAMMAR (shape of
a property line) belongs in stdlib. Reifier honesty rule: rename/restructure fields + split
scalars ONLY; the moment a reifier must parse (track depth/nesting), the grammar leaked ->
push back to stdlib. ~10 lines each.

THREE-LAYER ARCH:
  L1 PEG named-capture retention — RecordSequence/RecordRepeat collect ($var -> value) into
     Named; (..)* over a record -> Array(Vec<Named>). DECISION: named-retention is DEFAULT
