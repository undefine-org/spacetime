* Thesis

"A value that is one of N named states" is expressed FOUR incompatible ways today
(boolean reactive-class chains, `@state(when: "str")`, `@state(when: $x is Variant)`,
`@match`/`@view` template dispatch), each with its own lowering and gaps (FUP-074's
own diagnosis). They converge on ONE mechanism: a `@type` sum-typed signal, produced
by EITHER a primitive's `%yield` (existing: `@socket`) OR a new derive form
(`@data derive $x T : @match { guard => Variant; ... }`), consumed uniformly by
`@match`/`@view` (render dispatch, unified into one primitive) and `@state(when: $x is
V)` (CSS reflection). `@state(when: "str")`'s bespoke `dataset.stState` carrier is
retired outright — a bare string becomes a degenerate 1-field union under the SAME
attribute-reflection path, not a parallel mechanism.

named states, produced by a derive or a primitive, reflected to CSS via one attribute,
dispatched to templates or destructured in effects — exactly the `stdlib/dnd`-shape

* Grammar surface (concrete syntax, all four new/widened shapes)

** 1. Dispatch-mode `@match`/`@view` — variant pattern + widened consequence

```spacetime
@type BadgeState { Blue | Orange | Turquoise | Green }

.st-host-widget__panel {
  @match $badge {
    Blue                          => &loginPrompt();
    Orange                        => &progressSpinner();
    Turquoise                     => &previewNotice($statusData);
    Green                         => &liveBadge();
  }
}

// payload destructuring, reusing the existing is-Variant{bindings} shape verbatim:
@view $ws {
  Connected { $send, $received }  => &chatPane($send, $received);
  Error { $error }                => &errorPane($error);
  Disconnected                    => &offlinePane();
}

// widened consequence — a bare expr (no leading &) is a VALUE, not a template:
@data derive $badgeLabel string : @match $badge {
  Blue      => "Logged out";
  Orange    => "Working…";
  Turquoise => "Preview ahead";
  Green     => "Live";
}
```
Note the third example: dispatch-mode `@match $subject { }` used AS the RHS of
`@data derive` — this is DISTINCT from cond-mode `@match { }` (no subject) below. Both
share the widened consequence grammar; they differ in whether a subject is present
(pattern-vs-value dispatch) vs guard-cond (boolean-vs-value dispatch). Grammar IS the
discriminator (no Rust dispatch branch), exactly as `@type`'s product/sum split
already works.

** 2. Cond-mode `@match { }` (guard-cond, no subject) — the new derive form

```spacetime
@type BadgeState { Blue | Orange | Turquoise | Green }

@data derive $badge BadgeState : @match {
  ($isOrange)       => Orange;
  ($isUnauthorized) => Blue;
  ($isTurquoise)    => Turquoise;
  _                 => Green;        // REQUIRED — E0931 if absent (totality)
}
```
Guard = arbitrary boolean expr, PARENTHESIZED (W1 as-built amendment, SWARM GATE 1):
`($statusData && $statusData.preview_hash != null)`. The parens are forced by the
lexer — there is no `=>` token (it lexes as EQUALS+GT), so ExprExtractor's boundary
set (`;` `)` `}` `,` `->`) cannot terminate a bare guard, which would greedily swallow
`=> Variant`. The `_` catch-all stays bare (unambiguous at the choice point). Every
arm's `;` is REQUIRED (a payload-less consequence would otherwise gobble the next
arm's parenthesized guard as payload args — `Blue ($h) =>` misparses as `Blue($h)`).
First-truthy-guard-wins, `cond` semantics. Consequence = a bare variant constructor
(`Ident` or `Ident(args)`), NOT a template — cond-mode never renders, it only
produces a value.

** 3. Inline anonymous union type (declSurface: both)

```spacetime
@data derive $badge (Blue | Orange | Turquoise | Green) : @match {
  ($isOrange) => Orange;
  _           => Green;
}
```
Parenthesized to disambiguate from a plain `typeref` ident (forcing parens per user's
explicit allowance) — reuses the `( )` grammar-combinator sigil meaning already
established for `%form`/`%capture_type` groups (AGENTS.md sigil-harmony rule), applied
here at the AUTHOR level for the first time in a typeref position. Anonymous: not
registered in `TypeRegistry` under a name, valid only at this one derive site. If
reused elsewhere, promote to a named `@type`.

** 4. Payload-carrying variant construct (cond-mode)

```spacetime
@type FetchState { Idle | Loading | Loaded(Todo) | Failed(string) }

@data derive $fs FetchState : @match {
  $loading        => Loading;
  $error != ""    => Failed($error);
  $data != null   => Loaded($data);
  _               => Idle;
}
```

** 5. Mutation lowering — `$x <- Variant(args)`

```spacetime
$status BadgeState : Idle;

@on click {
  $status <- Orange;                    // nullary variant
}
@handle $ws {
  receive { Open() => { $conn <- Connected($send, $received); } }
}
```
`parse_meta_on_body_items` (`src/parser/mod.rs:7053`) currently treats everything
right of `<-` as an opaque expr string. This plan adds a NARROW special case: when the
RHS matches `Ident` or `Ident(args)` AND `Ident` is a capitalized bareword AND the
target signal's declared type (resolved via `TypeRegistry` from the signal's
registered `binding(...)` type fact) is a known sum whose variants include `Ident` —
lower to `{type: 'Ident', ...namedPayloadFields}` instead of passing the bareword
through as a (broken) JS identifier reference. A bareword that is NOT a known variant
of the target's declared type falls through to the existing opaque-expr behavior
UNCHANGED (no regression for non-enum `<-` assignments) — the special case is
strictly additive and gated on a positive TypeRegistry match, never a guess.
