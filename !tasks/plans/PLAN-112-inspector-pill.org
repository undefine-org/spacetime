* Goal

A shared Inspector pill bringing the MCP workbench's auto-generated editing UI (typed param editors) + tree/structure seeker to (a) EVERY dev-served page via the `.st-dev-dock` (next to the host + migrations pills), and (b) the workbench itself, whose inspector/navigator drawers converge onto the same shared component.

Decisions locked (user-confirmed):
1. Shared pill component: dock-mounted on every dev page AND consumed by the workbench.
2. Write rail: source span-patch only (persistent file edits → watcher reload). No ephemeral override rail in the pill.
3. Rich typed widgets hoisted out of the admin drawer into a shared =stdlib/fields/= module; admin + workbench + pill all consume it.
4. v1 tree granularity: template invocations only (one node per template call + its params). Element/binding granularity deferred.
5. Bidirectional selection: tree click → highlight live-page element AND page element click → select tree node (dev-only DOM stamping).
6. Write on commit (change/blur); user's git is the safety net (migrations-pill precedent).

* Non-goals (v1)

- Element-level nodes + per-binding editing: element/hole StructureNodes carry =source_span: None= (src/introspect/html_walk.rs); element editing needs span enrichment first. The workbench itself only edits elements via the ephemeral region-override rail we excluded.
- Subtemplate ELEMENT stamping: invocation-base threading through nested builders is unsolved in the workbench too (src/mcp/bundle.rs:275-291 stamps only =main=).
- richtext/select/chips/relation widgets in the pill: hydration-provider contract needed; template params are scalars.
- Compile-gate on EditAst disk writes: follow-up hardening (precedent: migrations + /save write blind; watcher surfaces errors).
- Workbench literal dock chrome: the pill FORMAT replaces the drawer CONTENT; whether workbench also mounts the dock wrapper is cosmetic, deferred.
