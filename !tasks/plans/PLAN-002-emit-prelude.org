# Design Integrity

Design integrity means the code tells the truth about what the system currently is — not what it used to be, not what was convenient to patch. Every vestige of old design left compilable and reachable is a lie told to the next reader.
- **The unit of change is the design decision, not the feature.** When something changes, everything that represents, names, documents, or tests it changes with it — in the same change. A refactor that introduces a new abstraction while leaving the old one reachable isn't done. A feature that requires a compatibility wrapper to land isn't done. The work is complete when the design is coherent, not when the tests pass.
- **One concept, one representation.** Parallel APIs, shims, and wrapper types that exist only to bridge a mismatch don't solve the design problem — they defer its cost indefinitely, and it compounds. Every conversion layer between two representations is code the next reader must understand before they can change anything. Pick one representation, migrate everything to it, delete the other.
- **Abstractions must cover their domain completely.** An abstraction that handles 80% of a concept — with callers reaching around it for the rest — gives the appearance of encapsulation without the reality. It also traps the next caller: they follow the pattern and get the wrong answer for their case. If callers routinely work around an abstraction, its boundary is wrong. Fix the boundary.
- **Types must preserve what the domain knows.** Collapsing structured information into a coarser representation — a boolean, a string where an enum belongs, a nullable where a tagged union belongs — discards distinctions the type system could have enforced. Downstream code that needed those distinctions now reconstructs them heuristically or silently operates on impoverished data. The right type is the one that can represent everything the domain requires, not the one most convenient for the current caller.
- **Optimize for the next edit, not the current diff.** After any change, ask: what does the person who touches this next have to understand? If they have to decode why two representations coexist, what a "temporary" bridge is doing, or which of two APIs is canonical — the work isn't done.

* Problem

Primitives have no way to declare code that should run exactly once regardless of how many
times the primitive is invoked. Every =@reduced-motion= block, every scroll timeline, every
template registration emits its full JS body per invocation. This causes:

- BUG-003: =reducedMotion()= emitted 3× (3 =@reduced-motion= blocks → 3 matchMedia listeners)
- BUG-004: 78 eager =querySelectorAll= calls (each selector init IIFE includes its own query)
- Scroll driver: =__stScrollHandlers= registry + window listener setup duplicated per element
- State transition: =__stDocTransitions= registry setup duplicated per transition
- Template system: =Spacetime.templates= namespace init duplicated per template IIFE

These all share the same workaround pattern: runtime singleton guards
(=if (window.__stFoo) return; window.__stFoo = true=). But this is a runtime tax for a
compile-time problem. The compiler knows which primitives are used; it should emit setup code
once.

* Design: =%emit prelude-js=

** Syntax

#+begin_src spacetime
%primitive myPrimitive($param: string) {
  %emit prelude-js {
    // Runs once per page, before any per-element init.
    // No access to %&el or %param — no element/instance context.
    window.__myRegistry = window.__myRegistry || [];
  }

  %emit js {
    // Runs per element/invocation, as today.
    // Has access to %&el, %param, etc.
    window.__myRegistry.push(%&el);
  }
}
#+end_src

Similarly: =%emit prelude-css= for global CSS that should appear once.

** Semantics

- *Deduplication key:* primitive name. If =reducedMotion()= is invoked 3 times, its
  =%emit prelude-js= block appears exactly once in the output.
- *Ordering:* All preludes are emitted BEFORE any per-element IIFEs. This guarantees
  shared registries, listeners, and namespaces exist before any per-element code runs.
- *No element context:* Prelude blocks have NO =%&el=, no =%param=, no =%yield=.
  They receive only static content. Parameters are forbidden. =%cleanup= is forbidden.
  The block is a pure setup function.
- *Idempotent by construction:* The compiler guarantees single emission. No runtime
  guards needed. The prelude IS the guard.

The pipeline =compile= function returns a new =PipelineOutput= field: =prelude_js=.

In =emit_typed= (or a new =emit_preludes= function), prelude fragments are:
1. Deduplicated by primitive name (=HashSet<String>= of seen primitive names)
2. Emitted as simple IIFEs with =const el = document.body= (no selector, no init guard)
3. Placed BEFORE the per-element IIFEs in the final output

The dedup key comes from =ResolvedPrimitive.primitive_name= which is available in
the expansion step. The expand phase can tag each =ExpandedPrimitive= with its
primitive name, and the emit phase can dedup.

*** Compiler (=src/compiler.rs=)

Prelude JS is prepended before both =file_js= (metasystem) and =js= (pipeline) output:
=final_js = format!("{}\n{}\n{}", prelude_js, file_js, js)=

** Migration Plan

After the feature lands, migrate existing runtime singleton guards:

*** =stdlib/primitives/media.st= — =reducedMotion()=

Move the =matchMedia= + listener setup to =%emit prelude-js=. Per-invocation code
just reads =window.__stReducedMotion=.

Actually, better: the prelude creates and exports the signal. Per-invocation
code is empty (or just reads the signal for CSS conditional application).

#+begin_src spacetime
%primitive reducedMotion() {
  %emit prelude-js {
    const mql = window.matchMedia('(prefers-reduced-motion: reduce)');
    const update = () => {
      const reduced = mql.matches;
      ST.set(document.body, "reduced", reduced);
      ST.set(document.body, "allowed", !reduced);
    };
    mql.addEventListener?.('change', update) || mql.addListener?.(update);
    update();
  }

  // Per-invocation: nothing needed — signal is on body, already set by prelude
}
