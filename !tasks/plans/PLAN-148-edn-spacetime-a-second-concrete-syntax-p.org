* Thesis

Spacetime's grammar is ALREADY DATA. There are no hardcoded parsers for language
constructs — every construct is a =%form= pattern declared in =.st= stdlib files
(=src/syntax/ARCHITECTURE.md=: "All user-facing syntax in Spacetime is defined
via %form patterns. There are no hardcoded parsers for specific syntax
constructs.").

Therefore EDN<->Spacetime is NOT a hand-written per-construct translator. It is
a PROJECTION OF THE FORM REGISTRY: write it once, it covers all 415 registered
forms, plus every form anyone adds later, for free.

#+begin_example
      %form registry  (415 forms — the single grammar authority)
              |
      +-------+-------+
   .st text        EDN text          <- two concrete syntaxes, peer status
      +-------+-------+
         Vec<FormMatch>              <- the waist; both directions meet here
              |
    pipeline (resolve->sort->expand->emit)   <- UNTOUCHED
#+end_example

** The waist

| stage | type | lossless | serde |
|-------+------+----------+-------|
| 0 bootstrap | =SyntaxRegistry= <- =%form= | grammar authority | =FormClause= yes |
| 1 text->CST | =ParseResult{root: SyntaxNode}= rowan | yes, trivia+comments | no |
| 2 CST->AST | =parser::ast::StFile= | no, drops trivia | partial |
| 3 match | =StFile.matches: Vec<FormMatch>= | semantic only | *YES, full* |
| 4 resolve | =ResolvedPrimitive= | no | yes |
| 5 emit | =PipelineOutput{js,css,html}= | terminal | yes |

=FormMatch= (=src/syntax/form_match.rs:505=) derives =Serialize, Deserialize=
(verified directly at =form_match.rs:20= and =:505=). =pipeline::compile(matches:
&[FormMatch], ctx)= (=src/pipeline/mod.rs:1227=) consumes EXACTLY this and nothing
else from the parse. That is why it is the correct insertion point: an EDN-origin
program compiles through the IDENTICAL backend. No second pipeline, no divergence.

* Decisions (settled)

- *A — semantic bijection*, not textual. Round-trip preserves MEANING:
  =edn -> st -> compile= == =st -> compile=. Comments/formatting not preserved.
  Spans retained so diagnostics point at real source. Textual bijection (B) would
  need CST anchoring + trivia model + formatter, ~3-4x the work, and buys only
  clean git diffs. A does not foreclose B.
- *Mechanical wire, idiomatic sugar on top.* Wire is total and generated; sugar
  must be DERIVABLE from the pattern, never hand-written.
- *Key on =macro_name=, not =@directive=.* See measurement above.
- *Sugar is derivable-only*: positional captures (order from the pattern) and
  =(sel "..." forms...)= (selector is a =FormMatch= field, not a capture).
  REJECTED: =(st/data :inline ...)= kind-word-as-argument.
- *Codec lives in verse* (single implementation; two would drift silently).
  =st/connect!= and the =.bl= reader/writer live in *beam-lisp* — verse stays purely
  the codec.
- *Fail loud, no fallback policy.* See below.

* Fail-loud, no fallback

EDN NEVER reconstructs an =Expr= it did not author. In the EDN surface a JS
expression is an explicit opaque leaf — =[:st/expr "$a + $b"]= — a STRING, carried
byte-verbatim both directions. Faithful by construction, not a fallback.

Therefore the "fallback" only ever fires when printing a =FormMatch= PARSED FROM
=.st= whose capture text is mangled — e.g. the observed =Expr("{ $a + $b")=
(unbalanced brace, and =params= dropped =$b=). That is a VERSE PARSER BUG, not a
translator gap.

W2 rules:
1. pattern-print every form; cannot -> *HARD ERROR naming the macro*;
2. raw captures (=Expr=, =Balanced=, opaque bodies) print VERBATIM from capture text;
3. verbatim text that fails to re-parse -> *HARD ERROR + reproducer filed as a
   verse bug*.

The corpus test emits A LIST OF VERSE DEFECTS, not a fudge factor.

Deferred to FUP spike (own plan): structured =Expr= / opaque-body IR. =swc_ecma_ast=
is already a dependency so it is feasible, but it changes what =.st= authors may
write and what diagnostics say — a language-design project. Coupling it here
means neither ships. Payoff beyond EDN: diagnostics inside expressions, safe
refactoring, checked =%emit= substitution.

* Zero-change guarantee for regular .st users

Structural, not a promise:

| axis | effect |
|------+--------|
| =.st= lexer/parser/CST | untouched — EDN never enters this path |
| =%form= / stdlib | untouched — EDN READS the registry, never mutates it |
| =pipeline= / =compiler= | untouched — receives =Vec<FormMatch>= exactly as today |
| new failure modes for =.st= | none — =src/edn/= is additive, no existing call site changes |
| build cost | one small pure-Rust dep (=clojure-reader=), no C, no V8 |

EDN cannot express anything =.st= cannot: the registry is the ceiling. A new
=%macro= reaches EDN with no EDN-side change, so divergence is impossible by
construction.

*RISK*: EDN must consult the SAME =STDLIB_REGISTRY= instance
(=src/syntax/stdlib_registry.rs:50=). Two registries = silent drift on custom
macros. Single-instance discipline, asserted in test.

* W2 residual: grammar-driven body rendering (measured 2026-08-13)

** The generalisation

The remaining body shapes (=variant_list=, =score_entry=, =arm=) are NOT ad-hoc.
Each is a declared =%capture_type= pattern carrying its own literal separators:

: %capture_type variant_list { $head:variant_def $tail:variant_alt+ }
: %capture_type variant_alt  { "|" $v:variant_def }
: %capture_type arm          { $pat:match_pat "=>" $inv:template_invocation ";"? }
: %capture_type score_line   { $head:score_step ( "->" $next:score_step )* ";" }
: %capture_type score_step   { $subject:score_subject $places:score_placement* }

So the printer now WALKS THE CAPTURE-TYPE GRAMMAR (=grammar_text=,
=render_by_capture_type=, =render_array_by_grammar=): it emits each literal in its
declared position and substitutes captures from the value. ONE function replaced
what would have been four hand-written body renderers, and a NEW body grammar
needs no printer change at all. This is the grammar-as-data thesis paying out a
second time, in the same shape as the =on_motion_body= alternation walk.

Result: =type-sum= (4), =form-score= (3), =score-block= (3), =view= (3) all cleared
in one change — 11 forms, zero per-macro code.

** W6a — add-watch / remove-watch (lib/beam_lisp/refs.ex)

Atoms had deref/swap!/reset!/compare-and-set! but nothing could OBSERVE a change

The watch table lives in the AGENT's process dictionary, not the Agent's state,

are untouched. Watches fire in the CALLER's process after the swap commits, as in
Clojure: running them inside the Agent would block it, and a watch touching its
own atom would deadlock.

** W6b — spell.st (the connector) and spell.st-edn (the wire)

: (def state (atom {:messages [] :status "idle"}))
: (st/connect! state {:messages '$messages :status '$status})
: (swap! state assoc :status "thinking")   ; the browser updates

`connect!` diffs the DECLARED keys old->new and pushes only what changed: an atom
with twenty fields where one moved sends ONE update, and an undeclared key sends
nothing. `on`/`dispatch!` close the cycle inbound — the handler mutates state and
nothing else; the interface update is a consequence, not a call.

built by `map` and transformable by the Specter optics already in `priv/specter/`.

the translation, and a second implementation of a bijection drifts silently.
`form-captures` even declines to expand POSITIONAL arguments, since their meaning

** Gap A did not exist: the template language ships, twice

*verse* — `stdlib/migrations/entries/*.st`:

: %rewrite scroll {
:   %drops ( _ duration threshold speed trigger )
:   %match { @scroll $name:ident ( scope: $scope:ident = cover, ... ) { $body:on_motion_body } }
:   %into  { @on &.scroll(...) { ... } }
: }

The template language, written IN Spacetime, as data — the same thesis as `%form`.
`src/migrate.rs` is 1879 lines of engine: `instantiate_template`, `plan_file_apply`,
`render_pending_hunk`, `write_apply_plans`, `collect_hint_pending`.
`FileApplyPlan { old_source, new_source, changed, content_hash }` — the diff IS the
log record, with a staleness guard. Exactly the user's parenthesis.

*beam-lisp* — `priv/optics.bl`, self-hosted van Laarhoven optics:

: (over (*> (in :app) (in :users) traversed (in :hits)) inc data)

`in` `idx` `fst` `snd` `traversed` `filtered` `optional`, `*>` composing outside-in
in Specter order. With `examples/optics.bl` and `test/bl/optics_test.bl`.
`compiler.ex`, `rt.ex`, `reader.ex` all carry Specter comments. I grepped none.

*Structural addressing needs no identity.* A template says what SHAPE to match; an
optic rewrites every match. Nothing is REFERRED to, so nothing needs a stable name.
My three identity candidates answered a question that dissolves.

** Gap B did not exist either

Same error one level down. Structural rewriting is verifiable by construction — the

** Root cause, and it is not carelessness

~15 verification calls, all on things I BELIEVED (FormMatch fields, the absent
stable-id, contract_hash_of, fence). Marked `#verified[]`. Never once searched for
WHAT ALREADY SOLVES THIS.

Worse: I had written, in THIS session, at `src/syntax/registry.rs:266`:

: This belongs HERE and not in the parser: `%match` patterns (migration rules) are
: `FormClause`s built by the same code, but their optionality means something

I edited the line naming the exact mechanism Gap A needed and drew no conclusion.
Evidence in hand is not evidence consulted.

The `#verified[]` blocks made it WORSE — a doc with two invented examples and a
fabricated gap looked checked. Rigor on details is camouflage for an unexamined frame.

** Lesson saved

`CON-search-for-what-solves-it-before-designi` — before designing a mechanism, grep for
the CAPABILITY (`%rewrite`, `optics`, `migrat*`), not just the absence you suspect
(`stable_id`, `node_id`). Read sibling dirs (`priv/`, `stdlib/`, `examples/`, `test/`).
Re-read your own comments from this session. An example in a doc about a grammar must
come FROM that grammar.

** What is actually left

Not "close two gaps". The substrate is built: `%rewrite`/`%match`/`%into` + migrate.rs
in verse, optics + fence + contract-hash in beam-lisp, EDN as the addressable form from
W0–W6. The open question is what the loop IS — and the user's fourth annotation is the
candidate: a REPL. read -> eval -> print -> loop, where "eval" is a structural rewrite
and "print" is the diff. `BeamLisp.repl/0` already exists (`lib/beam_lisp.ex:94`).

Not designing further until that framing is confirmed. One wrong document is enough.
