## Summary

`discover_st_entries` (src/mcp/state.rs) lists every `.st` file under an environment root as a clickable "+ tab" entry in the workbench drawer, with no filter for Spacetime TEST spec files (`*.test.st`, containing `@test`/`@assert` blocks, no `@template`). Clicking one registers a function that "compiles" (empty bundle, no templates) and is technically stage-composable, but produces nothing useful when composed — pure clutter with no functional value.

## Repro (verified this session)

`projects/ora-ventures.com/landing/` alone contributes 4 such entries (`landing-alignment.test.st`, `landing-hero.test.st`, `landing-performance.test.st`, `landing-sections.test.st`) to the drawer's file list, plus 2 more at the project root (`ora-ventures-motion.test.st`, `soft-sticky-viewport-matrix.test.st`) — 6 of the ~24-entry CAP consumed by files that can never produce a meaningful composed page. `st_tab_open{env, entry:"landing/landing-hero.test.st"}` registers fine (`compile_ok: true`) but the resulting function has zero templates/contract params — an empty, pointless stage guest.

## Fix direction

`discover_st_entries` should skip `*.test.st` files (mirrors the existing `.md`/dotfile/`dist`/`node_modules`/`target` skip-list already in `is_skippable`) — they are test specs, not page/component entries, and belong in the (separate, not-yet-existing) test-runner surface, not the tab-open picker. Low priority: functionally harmless (no crash, no data loss), just wasted picker real estate + a confusing empty compose result if clicked.
