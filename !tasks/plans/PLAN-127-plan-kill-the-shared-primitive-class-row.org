* Root cause — the wrong ROW is consulted, deterministically

src/pipeline/drivers.rs:2072 `driver_param_args()` finds its registry row by
PRIMITIVE NAME:

  .find(|(_, c)| matches!(registry.entry_field(c, "primitive"),
                          Some(Ident(p)) if p == primitive))

`.find` returns the FIRST match. All five event rows declare
`primitive: event-driver`, so all five read HOVER's row. It is not that an
argument is missing — the wrong row is read, by first-match. Any per-row data
added to `submit` today would still be unreachable. `param_map` on a shared
primitive is dead surface.

Three sibling lookups in the SAME FILE (lines 183, 696, 1486) key correctly on
`registry.entry_key(c) == Some(member)`. Exactly ONE deviates, and it is the
broken one. A one-off inconsistency in a codebase that already knows the idiom.

Confirmed in-scope: all three call sites (572, 1392, 1857) already resolve
`clause` by `entry_key(member)` (site 3's resolution is at :1486) and then
DISCARD it in favor of the by-primitive search. The correct row is already in
hand at every call site. That is what makes layer 1 surgical.

* Layer 1 — delete the miskeyed lookup (kills the class)

Change `driver_param_args` to take the ALREADY-RESOLVED row instead of
searching:

  fn driver_param_args(
      params: Option<&CapturedValue>,
      registry: &MetaRegistry,
      primitive: &str,
      clause: &RegisterClause,   // <- the row, passed in
  ) -> Vec<BindArg>

and read `param_map` from `clause` directly. Delete the `.entries_of("driver")
.find(by primitive)` block entirely.

Call sites: 572 and 1857 have `clause` in scope already. 1392
(`expand_two_slot_body`) must thread it from its single caller at 1642, which
resolved it at 1486.

WHY THIS IS STRUCTURAL: after this change NO code path searches the driver
registry by primitive. A row can only ever read its OWN data, because the
lookup that could return a sibling's row no longer exists. A future row on a
shared primitive cannot inherit a sibling's config — not "must remember not
to", but cannot.

* Layer 2 — `primitive_args`: make the row's identity declarable

Layer 1 makes per-row data READABLE; nothing yet SUPPLIES the trigger. Add a
registry slot for constant primitive arguments:

  %registers driver(submit) {
    primitive: event-driver
    primitive_args: "trigger:submit"
    ...
  }

Applied to all five event rows (hover/click/focus/submit/key). Parsed with the
same `split(',')` + `split_once(':')` shape `param_map` already uses, then
emitted as `BindArg::Named`, typed through the existing `typed_primitive_arg`
so string params quote correctly.

DESIGN NOTE — one need, one implementation (AGENTS §2). `param_map` RENAMES a
caller-supplied arg; `primitive_args` SUPPLIES a constant. Adjacent but not the
same need, and `param_map` has exactly one user (text-change:335). Evaluate
folding both into one slot during implementation; if they stay separate, both
must be read from the row (layer 1) so neither can read a sibling's.

Author-supplied args must WIN over `primitive_args` (a constant is a default,
not an override) — assert this with a test.

Then DELETE the now-unreachable hardcoded dispatch in
stdlib/primitives/animation/drivers.st:552-565 — the `if (trig === 'hover')` /
`else if (trig === 'click')` branches exist only because the trigger never
arrived. With real triggers the generic
`addEventListener(trig, forward)` else-branch handles every row. Net deletion.
CAUTION: hover's reverse-on-mouseleave and click's toggle-on-second-press are
BEHAVIOR, not dispatch — they must survive, as row data
(`reverse: true`, a toggle flag) or they are a regression. Verify with the
CDP negatives before deleting.

* Layer 3 — the bundle-identity gate (catches the whole class, forever)

Mechanize the hand-diff that found this:

  Compile one minimal page per driver row. Normalize away cosmetic
  identity (timeline names, `_st_init_<hash>` guards). Hash the result.
  TWO ROWS PRODUCING IDENTICAL LOGIC IS A FAILURE, naming both rows.

Deliberate alias exemption: mouse/pointer intentionally share `mouse-driver`.
Exempt via an explicit registry declaration (e.g. `alias_of: mouse`), NOT a
hardcoded allowlist in the test — the exemption is data, and declaring an
alias is then a deliberate act rather than an accident that looks identical.

This gate needs NO per-row expectations, so it cannot rot as rows are added,
and it generalizes past drivers to ANY registry where N entries share one
implementation.

Plus a registry invariant test: if ≥2 rows share a `primitive` and none is
declared an alias, each MUST carry row-distinguishing data — fail naming the
rows.

* Layer 4 — CDP behavior gates with NEGATIVES (per AGENTS.md, BUG-252 rule)

Every existing driver test is positive-only, which is precisely why five wrong

  - hover's reverse and click's toggle still work (guards the layer-2 deletion)
