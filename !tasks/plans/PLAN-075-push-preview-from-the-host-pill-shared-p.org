** 3. New verse dev-server route: POST /__spacetime/host/push
Dev-mode only (`AppMode::Dev { site_dir, .. }` -- 404/501 in
`AppMode::Compiled`, matching this route's own inherent "needs a
source directory on disk" constraint). Handler:
  1. `compile_host_widget_raw(Some(site_dir), ...)` -- ALREADY exists,

  2. Build the widget's `<link>`/`<script>`/markup tail (same shape
     `host_widget_inject` already produces server-side for the LOCAL
     dev page -- reuse that exact construction, don't re-derive it).
  3. `spacetime::package_site_archive(site_dir, js, css, tail)` (the
     new shared fn from step 1) -> archive bytes.
  4. `read_host_api_token()` (ALREADY exists,
     `$XDG_DATA_DIR/spacetime-host/credentials`) for the bearer token;
     401 with a clear "not logged in -- run `spacetime host login`"
     message if absent (this route needs a REAL account token, unlike
     the widget's read-only status calls which can no-op on absence).
  5. `read_deploy_project_id(site_dir)` (ALREADY exists) for the
     project id; 400 "no @deploy{} fact" if absent -- but note
     $isNoProject already hides this whole action client-side, so this
     is a defense-in-depth check, not the primary UX gate.
  6. Plain `reqwest::Client` POST to `{api_base}/api/v1/projects/{project_id}/push`
     with the archive bytes as the body + bearer auth -- inline HTTP
     call (do NOT add a dependency on spacetime-host-client just for
     this one POST; that would pull verse toward depending on
     commercial/host, the wrong direction). `api_base` = the SAME
     `SPACETIME_HOST_ENDPOINT`-or-`https://spacetime.undefine.org`
     resolution `compile_host_widget_raw` already performs.
  7. Return the upstream JSON body verbatim on success; surface
     upstream error status/text honestly on failure (no swallowing).
