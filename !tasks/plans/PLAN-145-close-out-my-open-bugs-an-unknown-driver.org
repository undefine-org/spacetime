* Thesis

Five of the eight bugs I still own are the SAME defect wearing different
clothes: *a named argument that no one reads is accepted, dropped, and never
mentioned.* `from:` on a click driver, `once:` on a visible driver, `bind:` on
`@editable`, a `%into` splice, a page with no markup — in every case the
compiler's answer to "I didn't understand that" is silence plus exit 0.

So this plan is NOT "fix eight tickets". It is: *make the silent-absorb class
impossible*, and let the individual tickets fall out of that. The tickets that
remain after are genuinely separate defects (a parse gap, a browser behavior
gap), sequenced behind it.

** Why the class matters more than the instances

A silent drop is worse than a crash for a compounding reason: it *defeats the
verification that would catch it*. While confirming BUG-334 I produced TWO
vacuous confirmations in a row — grepping an empty `dist/` (BUG-351: a
styles-only page exports zero pages with a ✓), then matching `closest(` from
the runtime library rather than page code. Both times "absence of the feature in
the output" was an artifact of my own method, not evidence.

That is the real cost. Each silent drop manufactures false negatives for the
next person trying to prove something is missing. AUD-011 records the same
lesson from the other direction (a `src/`-only grep declaring live stdlib code
dead). The fix is not more careful greppingated it is making the compiler SPEAK.

* Root cause (verified in-repo, not inferred)

`bind_driver_args` in =src/pipeline/drivers.rs= (~:2473-2525) binds a named arg
by applying the registry's `param_map` rename and pushing it:

#+begin_src rust
match text_of(a.get("name")) {
    Some(name) => {
        let name = param_map.iter()
            .find(|(from, _)| *from == name)
            .map(|(_, to)| to.clone())
            .unwrap_or(name);        // <-- unknown name passes through unchanged
        args.push(BindArg::Named { ... })
    }
#+end_src

There is *no check that the resulting name is a param the primitive declares*.
An unrecognized name is bound to nothing and disappears downstream.

Evidence this is one root, not two:

- `%primitive on-mutation-handler` (=stdlib/primitives/animation/drivers.st:1971=)
  DOES declare `target: selector?`, and the emitted JS has a complete, correct
  delegation path (`if (delegateSelector) { $ = e.target.closest(...) }`).
  The runtime was never the problem.
- `param_map` exists and works — but only *2 of 28* drivers declare one, and the
  one mapping `from:` is =text-change-driver= (`param_map:
  "stagger:charStagger,from:staggerFrom"`, drivers.st:562). The click/visible/
  hover drivers declare none, so `from:` and `once:` match nothing.
- Proof by A/B emit diff: building `@on &.click(from: ".item")` and the same
  source without the clause yields *byte-identical* `dist/spacetime.js`. Same
  for `@on &.visible(once: true)`. The clauses are parsed, accepted, discarded.

∴ the mechanism to route a named param already exists *as data*; what is missing
is the refusal when the data says nothing.

* Waves

Ordered by whether they REMOVE A CLASS or fix an instance. W1 is the plan.

** W1 — Refuse an unknown driver param (the whole point)

Add validation at the single site where a named arg is bound: after the
`param_map` rename, the name MUST be a param the primitive declares, else a
diagnostic naming the param, the driver, and the params that ARE accepted.

- Registry-driven, not a Rust allowlist: read the primitive's declared params
  (they are already parsed — `typed_primitive_arg` consults them for typing).
  A new driver gets validation for free; no Rust arm per driver. This is the
  AGENTS elegance bar: variants stay DATA.
- Deletes a special case rather than adding one — the `unwrap_or(name)`
  fall-through IS the bug.
- Diagnostic quality is the deliverable, not the refusal. `@on &.click(once:
  true)` should say `once` is not a param of driver `click`, and list what is.

*Acceptance*: a RED test first — `@on &.click(nonsense: 1)` compiles clean today
and must fail after. Seen failing before the fix, passing after.

*Risk*: this will light up currently-silent sites across the repo, including in
`projects/` and `demos/`. That is the fix working. Triage each: a real typo gets
corrected; a param that SHOULD exist gets a `param_map` entry or a primitive
param. Budget for this — it is the majority of W1's work, and each site found is
a bug that was shipping.

** W2 — BUG-334: route `from:` to `target` (falls out of W1)

Once W1 refuses unknown params, `from:` on an event driver must either be
accepted or refused deliberately. It should be ACCEPTED: the primitive param
exists, the runtime path exists, only the mapping is missing.

Add `param_map: "from:target"` to the event drivers (click, submit, focus,
keydown, pointerdown, …). One data line each, no Rust.

*Acceptance*: the A/B emit diff that is currently byte-identical must DIFFER —
`const delegateSelector = ".item"` instead of `null`. Then a `--cdp` gate: a
click on `.item` fires the handler, a click on the container does not.
Per AGENTS: this feature's job is to make a click work in a browser, so it needs
a browser gate. The emit diff is necessary, not sufficient.

** W3 — BUG-331: decide `once:`, then honor or refuse it

Unlike `from:`, there is no `once` param anywhere — the runtime has no one-shot
path for this driver (`unobserve`/`disconnect` in the bundle are the
IntersectionObserver library's own, not a once implementation).

Two honest options:
1. REFUSE it (W1 does this for free) and point at the existing spelling if one
   exists.
2. IMPLEMENT it: add `once: bool?` to the primitive and `observer.unobserve(entry.target)`
   after first fire.

Prefer (2) *only if* a real page wants it; otherwise (1) is the correct answer
and costs nothing. Do not implement a param on speculation — that is how the
unread-param class started.

*Acceptance for (2)*: `--cdp`, element scrolled in/out/in, animation fires
exactly ONCE. A headless run cannot prove this (no scroll model, BUG-305) and
must not be used.
