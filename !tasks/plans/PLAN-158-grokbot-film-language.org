* Architecture checkpoint: valid long CSS exhausts parser fuel
** Evidence / RED
=check design/surfaces.st= and =serve= panic in
=grammar::directives::scan_selector_to_brace → Parser::nth=.
A CSS property can resemble a pseudo-selector (=: polygon(…)=); the selector
probe scans its balanced arguments without consuming parser tokens. Each read
burns fuel even though the LOOKAHEAD cursor advances. A long valid polygon
exhausts 256 reads, incorrectly classified as an infinite loop.

** Design
Keep the existing guard and grammar. Track the furthest lookahead index at the
current consumed position. Advancing that index is real finite progress, just
as consuming a token is: replenish fuel only then. Repeated reads at the same
position/index still exhaust fuel. Reset the high-water mark on token consume.
No new syntax, no alternate CSS parser, no stdlib fallback.

** Gates before implementation
1. A valid CSS function with hundreds of arguments followed by another rule
   parses completely and preserves the source (the production events parser).
2. Repeated lookahead without progress still trips the guard.
3. Existing parser suite; merged library suite; build/check the actual film.

** DONE P5 Existing @audio reaches both native renderers
Problem: declared_soundtracks filters for synth-only programs, so file audio
is silently omitted from an otherwise successful export. score-audio also
attempts play after a paused seek rather than following the transport state.

Design (existing grammar/rails, no new parser or author JavaScript):
- Reuse audio_entries from the parsed score, alongside synth_program, in one
  render program. Keep src/name/at as data; no source re-parsing or JS scraping.
- The shared soundtrack module decodes file inputs through FFmpeg (already
  required by Chromium rendering), offsets/trims them in sample time, pads
  silence to the selected window, and mixes them with the existing synth WAV.
- Chromium and raea receive the same WAV through soundtrack_in. No demo mux
  script; render remains the film's one build command.
- Keep source resolution relative to the project, as live serving does.
- Browser play/pause/seek follows the existing progress + __playing signals.

  silently claim new automation support for gain/rate/pan. Existing W7 docs
  describe their unfinished automation/export parity separately.

*** Voice anatomy refinement
The quiet waveform currently scales its entire box vertically, flattening dots
into dashes. Keep a scalar --voice-activity channel, floor each bar's height at
its dot diameter, and grow only taller speaking bars. This reuses custom-property
animation and CSS, with no new primitive or author JavaScript. A CDP gate must
first fail on quiet geometry, then assert loud growth and exact reverse seek.
Voice size is one typed form parameter; bar, controls, padding and waveform
spacing scale together. Scene timing remains in scene choreography.
