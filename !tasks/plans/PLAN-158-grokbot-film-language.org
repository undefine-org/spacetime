* Architecture checkpoint: valid long CSS exhausts parser fuel
** Evidence / RED
=check design/surfaces.st= and =serve= panic in
=grammar::directives::scan_selector_to_brace → Parser::nth=.
A CSS property can resemble a pseudo-selector (=: polygon(…)=); the selector
probe scans its balanced arguments without consuming parser tokens. Each read
burns fuel even though the LOOKAHEAD cursor advances. A long valid polygon
exhausts 256 reads, incorrectly classified as an infinite loop.

** Design
Keep the existing guard and grammar. Track the furthest lookahead index at the
current consumed position. Advancing that index is real finite progress, just
as consuming a token is: replenish fuel only then. Repeated reads at the same
position/index still exhaust fuel. Reset the high-water mark on token consume.
No new syntax, no alternate CSS parser, no stdlib fallback.

** Gates before implementation
1. A valid CSS function with hundreds of arguments followed by another rule
   parses completely and preserves the source (the production events parser).
2. Repeated lookahead without progress still trips the guard.
3. Existing parser suite; merged library suite; build/check the actual film.
