Fix the foundational test-framework bug [[id:BUG-051-test-st-assertions-never-execute-block-b]]:
=$body:block= / =$content:block= capture as a raw =String=, so =%$body.js= emits
the test body as a dead string literal and nested directives (fixtures, asserts)
never compile. Every =.test.st= assertion is currently vacuous.

* Goal
=:block= yields a structured capture exposing:
- =.html= -> raw inner text (fixture innerHTML)
- =.js=   -> COMPILED nested directives (matched_children lowered to JS)
so =@test=/=@fixture=/=@assert=/=@then= execute and gate correctly.

* Approach (sketch)
1. Map ="block"= to a dedicated capture type (not HtmlBlock) that retains BOTH the
   raw inner text AND =body_node.matched_children= (compiled FormMatches).
2. Make the =.js= / =.html= field accessor in the macro emit substitution
   (=substitute_params_simple= / =captured_value_to_emit_string=, evaluate.rs)
   route =.js= through the nested-compile path (resolve.rs nested_form_matches /
   resolve_child_with_parent_scope) instead of stringifying. The simple path's own
   doc-comment says nested .js expansion "is handled during Expand" — wire that.
3. Preserve =.html= raw-text behavior for fixtures.
