* Initial Message

How would you use https://github.com/chenglou/pretext to make @value-change (especially in the ora-ventures website) work better and more reliably across browsers without using big hacks like this one?

* Context

The =@value-change= animation primitive — Spacetime's split-flap character animation system — works but relies on a chain of hacks to measure text dimensions and manage overflow:

1. *cloneNode height pre-measurement*: Creates an invisible DOM clone to read =offsetHeight= for the target text. Forces synchronous layout reflow.
2. *measureSpan + getBoundingClientRect per character*: Creates hidden spans and reads bounding rects for each character. Multiple forced reflows.
3. *font-kerning: none*: Disables kerning on the entire element to make canvas-less measurement consistent. Degrades typography.
4. *paddingTop/marginTop overflow headroom*: Box-model mutation every animation cycle to create space for enter characters sliding in from above. Causes Firefox WebRender compositing flashes (documented in =@tasks/bugfixes/BUG-firefox-value-change-compositing-flash.org=).
5. *letter-spacing margin-right workaround*: Documented in =@tasks/attempts/value-change-firefox-letter-spacing.org=. Per-character margin-right to avoid Firefox inline-block letter-spacing quirks.
6. *Per-cycle <style> injection*: Creates and removes a =<style>= tag with =@keyframes= every animation cycle.
7. *.split('')*: Breaks on emoji and multi-codepoint graphemes.

** Approach

Replace all DOM-based measurement with [[https://github.com/chenglou/pretext][pretext]] — a ~15KB pure-TypeScript library that uses canvas =measureText()= for widths and arithmetic-only =layout()= for height computation. It has 7680/7680 cross-browser accuracy (Chrome/Safari/Firefox).

Pretext is vendored into the value-change-driver via =%emit prelude-js= — emitted once per primitive type, only when =@value-change= is used on the page. This is compile-time tree-shaking: pages without =@value-change= pay zero cost. No Rust compiler changes needed (=src/pipeline/emit.rs=, =src/main.rs= untouched). Follows the established pattern (scroll-driver already uses =%emit prelude-js= at line 37 of =drivers.st=).

Exposed as =ST.text= with =prepare()=, =layout()=, =measureWidth()= methods for use in the =%emit js= block.

The value-change-driver =%emit js= is rewritten to:
- Use =ST.text.prepare()= + =layout()= instead of cloneNode for height (zero DOM reads)
- Use =ST.text.measureWidth()= (canvas) instead of measureSpan + getBoundingClientRect for word widths
- Use =clip-path: inset()= + =overflow: visible= instead of paddingTop/marginTop for overflow headroom (no box-model mutation, no Firefox flash)
- Use =Intl.Segmenter= for grapheme-correct character splitting (handles emoji)
- Register =@keyframes= once per instance instead of per cycle
- Check =prefers-reduced-motion= for accessible instant swap
- Remove font-kerning and letter-spacing hacks

** Key Decisions

- *Prelude-js embedding*: Pretext IIFE is built once via =bun build= and pasted into the =%emit prelude-js= block of value-change-driver in =stdlib/primitives/animation/drivers.st=. No runtime module changes, no Rust changes. Only ships when =@value-change= is used.
- *Overflow strategy*: Driver sets =overflow: visible= (overriding CSS =overflow: hidden=) + =clip-path: inset(-Xpx 0 0 0)= during animation. After animation, both are cleared and CSS takes over. Zero consumer site CSS changes needed.
- *V8/headless tests*: Pretext lazily initializes canvas — loading is safe. Codegen tests check string presence only. Behavioral tests run in real browser via =--headless= flag.
- *Grapheme segmentation*: =Intl.Segmenter({ granularity: 'grapheme' })= everywhere: char iteration, prefix/suffix detection, word splitting. All major browsers support it since 2022+.
- *Font string*: =getComputedStyle(el).font= with manual fallback for Firefox.
- *Height animation preserved*: Container height still animated via WAAPI when text wraps differently. Pretext provides the target height; WAAPI animates to it.

** Risks
- *Canvas accuracy vs DOM*: Pretext measures via canvas =measureText()= which may differ by sub-pixel amounts from DOM rendering. For short animation text, this is imperceptible. Pretext's research notes document this and show the error is <1px for typical text.
- *system-ui font*: Pretext warns =system-ui= is unsafe on macOS. ora-ventures uses named fonts (Inter). Document the limitation for other consumers.
- *RTL text*: Current driver is LTR-only (exit layer uses =left: 0=). This is a pre-existing limitation, not a regression. Out of scope for this plan.
