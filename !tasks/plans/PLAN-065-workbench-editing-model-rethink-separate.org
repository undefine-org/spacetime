** ROOT FAULT (oracle-confirmed)
The workbench made the poll-repaint snapshot the OWNER of interaction DOM. Server truth, client selection, draft input value, focus, action acknowledgement, and canvas visibility all share ONE ~1s repaint loop. So every real edit races the next server publish (bug 1), and server-action failures vanish unless the poll happens to produce visible UI (bug 3). Bug 2 is a modal-dialog metaphor (stage recedes) misapplied to a side panel meant to be used WHILE looking at the canvas.

** CORRECTED MODEL — three state planes
- SERVER plane: $mcpSnapshot / published arrays = immutable remote read-model (poll-repainted). Read-only lists ONLY (navigator, gallery, cards, events).
- CLIENT plane: $selectedNode, $activeEditor(node+fields), per-field draft/dirty/pending/error. Owns focus + in-progress edits. NEVER repainted by the poll.
- CANVAS plane: mounted guest bundle, seeded ONLY from committed overrides/source (not inspector drafts). Stays bright + geometrically stable while panels are open.

Editing = optimistic-local-first: @on input updates local draft immediately; @mcp-action commits on blur/change carrying {fieldKey,target,value,baseRevision}; ack updates base + clears dirty; error keeps draft + shows field error. Poll reconciles clean fields, NEVER overwrites a dirty/focused input.

** KEEP (verified sound, do NOT rewrite)
The shared Structure IR + dotted-node selection spine: one canonical address (data-st-node) spans canvas DOM stamps + navigator rows + inspector selection + edit routing. src/introspect/mod.rs + src/mcp/bundle.rs stamping + env.st selection ring. The bug is ownership/lifecycle around repaint, NOT the id model.
