* Initial Message

Build a new chip experience, fully in Spacetime, using layers of abstraction,
that lets me fully do WYSIWYG, with a Figma-like sidebar and an explorer built
dynamically from the shape of the code. Start from scratch. It needs to work
perfectly to edit my website, reorganise lists, etc. with minimal to no code
changes to the website.

* Design

** The rule: the page is a projection, the source is the truth
Every edit rewrites the =.st= source; the file watcher reloads the page; the
studio restores scroll and selection. There is no second copy of the content
to drift, and the page can never show an edit the source does not hold.

** Addressing by content, not position
Positional ids (=data-st-origin= is a per-tag counter hash) cannot survive
templates, =when= filters, derived lists or literate prose. The browser instead
reports what it can know honestly: the text it shows, the element it sits in,
the list row it seems to come from. The server finds every place in the
page's files that could produce that text (a list string, a static markup run,
the exact characters) and applies the edit only when hints narrow it to ONE.
Rows are matched to SOURCE rows by their visible strings, so a filtered or
searched view still edits and moves the right item.

** Layers
| layer | where | what |
|---|---|---|
| source model | =src/studio/literal.rs=, =markup.rs= | lossless readers with exact byte spans |
| shape | =src/studio/outline.rs= | files, lists, markup, templates, rules of a page |
| edits | =src/studio/ops.rs= | text / field / move / duplicate / delete / decl, guarded, pure |
| transport | =src/server.rs= | =GET studio/outline.json=, =POST studio/apply= (dev only) |
| client runtime | =stdlib/__studio__/primitives/studio-kit.st= | view model, selection, apply, canvas |
| UI | =stdlib/__studio__/index.st= | chip, explorer, inspector, bar; sum types =StuTab=, =StuSelection= |

** Reload handshake
The dev live-reload now dispatches a cancellable =st:reload= first. The studio
cancels it while text is being typed or an edit is in flight, and reloads once
both are done, so a reload never eats a keystroke or a second op.
