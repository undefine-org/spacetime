* Initial Message

Design arc from 2026-07-26 session: the user wants `@data inline $brand Brand : { ink: #e8eef7; ... }` — CSS-native values in typed data seeds — and asked what "supporting all CSS value types natively" means, whether %capture_type can absorb it, whether the lexer's domain tier could be .st-expressed, and a full pressure-test of the approach. This PLAN records the resulting design. FEAT sub-items W0–W4 to be linked below.

* Goal

CSS values become citizens of the language — parsed, typed, folded, fuzzed, edited by the same grammar that defines them — while serializing to the plain strings the browser wants. `@type` declarations become EXECUTABLE: a type is the grammar for its own literals. The lexer's domain tier (COLOR regex, unit merge, value-position promotion) dissolves into .st capture grammars over a frozen universal kernel lexer. One stdlib scalar-type table drives parser + JSON-schema + admin widgets.

* The five decisions (settled in design; do not relitigate without new evidence)

1. REPR = STRING, everywhere. `#e8eef7` → `"#e8eef7"`, `8px` → `"8px"`, `600ms` → `"600ms"`. Reasons: (a) runtime consumer is style.setProperty which needs CSS strings; (b) EditAst structural editing (cms-testbed Brand pane) rewrites literals in place — source↔runtime 1:1, no normalization drift; (c) JSON-schema mapping already string+format (src/type_system.rs:791-804); (d) color algebra (FEAT-108 darken/mix/alpha) already parses from string at compute time (src/color/mod.rs). NOT {r,g,b} objects. No compile-time unit normalization. Duration: string in storage; ms-conversion at the animation boundary ONLY (settles BUG-138/FUP-099 by decision, then by fix).
2. VALIDATION-BY-CONSTRUCTION. A typed seed parses only if each field matches its capture type → the orphan standalone validator (E0501/E0502/E0503, src/type_system.rs:1023-1098, zero callers from @data inline) is DELETED for the inline path; kept (registry-derived) for fetch/file/subscribe runtime JSON. Type mismatches become parse errors with spans (kills the BUG-159 silent-non-binding class).
3. THREE-TIER CSS HONESTY. (a) Native leaf: color/length/percentage/angle/time/resolution/flex/number/integer/ratio/keyword-sets — full %capture_type grammars. (b) Dynamic-recognized: calc()/min/max/clamp, var()/env()/attr(), gradients/image-set/paint, color-mix()/light-dark()/color(), filter lists, basic-shape — balanced-args production tagged `dynamic`; lightningcss validates; editor widgets degrade. (c) Deferred: property-contextual grammars (width: length|%|auto), grid template sublanguage. Capture layer RECOGNIZES and spans; a separate evaluator (future) evaluates.
4. SHORTHANDS DECOMPOSE INTO RECORDS. font/transition/border/background shorthands get NO field types — a nested @type (e.g. Motion { duration; easing; delay? }) is strictly better for widgets and spans. Exception: box/text-shadow is a VALUE (comma-list, positional optionality) → needs a real grammar (expressible in PEG).
5. ONE %scalar_type TABLE, THREE CONSUMERS. stdlib declares each scalar {capture, schema, widget, repr}; validator, JSON-schema gen, and admin widgets (FEAT-107) read the same entry. Deletes the TypeExpr::Primitive string-match (src/type_system.rs:1002-1013) and the CaptureType::{Color,Length,Time,Duration,Easing} Rust arms + their extractors (src/syntax/events/extractors/simple.rs:150-172, 426-474; form_compiler.rs:1935-1988). Kinds-as-data per AGENTS.md corollary.

* Grammar/surface notes

- Typed record seed shape `{ ink: #e8eef7; radius: 8px }` IS the existing properties %capture_type (stdlib/capture-types/properties.st) with `$value:balanced(';')` upgraded to per-field typed leaves. `:` = value, `;` = declaration terminator — harmony preserved; learnable as "a typed record literal reads like a style block."
- Selector ambiguity (`#fff` in `.a #fff {}`) disappears STRUCTURALLY: the selector grammar has no color leaf; the value-position promotion pass (lexer.rs:405-420) is deleted, not replicated.
- %char_class / %unit_set / %capture_type bodies parse under kernel-only tokens — bootstrap honesty test: stdlib must parse with the frozen kernel.

1. Widget↔parser round-trip by construction: the %scalar_type entry generates BOTH the grammar and the EditAst color picker — admin output cannot fail to parse. No token pipeline needed; the .st file is program + database + admin-editable document.

5. Language extension with UI consequences: a project's `%scalar_type currency` immediately gets parsing + spanned errors + fetch validation + admin form field, zero Rust.
6. Self-describing docs: value-type reference rendered FROM the grammar (FEAT-084 gallery) cannot drift.

* WHAT THIS UNLOCKS ACROSS SPACETIME (2026-07-31 — downstream capability map)

Once a CSS value is a TYPED VALUE rather than opaque text, capabilities open that
are currently blocked for the same single reason. Grouped by which are already
half-built in the repo (⚑ = a live consumer is waiting on it today).

** ⚑ 1. The timeline editor (@score P4) is blocked on typed literals
stdlib/macros/score.st states the design intent outright: "the trailing words are
exactly the surface a timeline editor drags, so dragging a clip's edge rewrites
`in 4s` to `in 5.2s` in the source. The editor is a second view of the language,
not a layer over it." That rewrite IS EditAst over a typed literal — the same
mechanism as the Brand color picker (W2's demo). Without typed measures, a drag
must regex the source. With them, `at`/`for`/`in`/`out` are structurally editable
spans. ONE mechanism serves the color picker, the spacing stepper, and the
timeline scrubber — because all three edit a typed literal in place.

** ⚑ 2. Interpolation dispatched by TYPE, not by primitive name (kills BUG-202)
BUG-202 is live: animate-color calls ST.lerpColor, which does not exist → TypeError
on tick. The root shape is that the animation layer learns "this is a color" from
the primitive's NAME. Give %scalar_type an `interpolate:` column and the runtime
picks the lerp from the registry: color→oklch-space blend, length→numeric+unit
check, angle→shortest-arc, integer→stepped, keyword→discrete snap. Adding a new
animatable type stops meaning "write a new primitive". Compile-time bonus: two
keyframe endpoints of DIFFERENT types (or a non-interpolable pair) become an
error at the keyframe, not a snap at runtime — the BUG-192 class by construction.

** 3. Compile-time accessibility + design-system conformance
Contrast ratio is computable from two typed colors; it is NOT computable from two
opaque strings. So `@type Brand { ink: color; bg: color }` + a lint yields WCAG
contrast as a COMPILE ERROR ("ink on bg is 3.1:1, below 4.5:1"). Same shape for
the rest of the design system, which src/analysis/visual_lint.rs already gestures
at with its own shadow classifier: off-grid spacing (13px on an 8px scale),
colors outside the token set, font sizes off the ramp. Design-system violations
become diagnostics with spans — the thing every other stack needs a linter+config
for, Spacetime gets from its type table.

** 4. Derived tokens become STATIC CSS (a no-JS win, AGENTS-aligned)
FEAT-108 derives ($hover : $brand.scarlet | darken(0.12)) currently compute at
runtime because the input is a string parsed at compute time. With typed literals
these constant-fold at BUILD: the page emits plain CSS custom properties and ships
NO JS for token derivation. Pages get smaller and more static — directly serving
the house rule that a Spacetime site relies on Spacetime, not on shipped script.

** 5. Type-directed generative testing of the whole style layer
docs/testing/GENERATIVE.md's @property/@fuzz generate + shrink FROM A TYPE. Today
they cannot generate a color, because `color` has no generator — only a Rust
extractor. A %capture_type grammar IS a generator (and its near-misses are the
negative corpus). Result: property tests over every value type, plus shrinking
that reports the minimal failing literal.

** 6. LSP quality that no CSS tooling gives for free
With grammars as data, the language server answers value-position questions
structurally: completion offers exactly the legal units/keywords AT THE CURSOR
(inside `duration` → s/ms; inside `color` → named colors + functions), hover
renders the grammar, and the color swatch comes from the same entry that parses.
src/lsp/colors.rs stops being a private hex scanner (one of the five shadow
classifiers) and becomes a registry read.

** 7. Build-time asset validation via the same table
`media`/`url` scalars (C9 — the table is the LANGUAGE's scalar table) can carry a
build-time check: does the file exist, what are its dimensions, is there a poster
frame. @score clips (`&broll(src: "city.mp4") in 4s out 9s`) then fail at COMPILE
for a missing or too-short source instead of rendering a black frame — trim
bounds are checkable against real media duration.

** 8. THE BOLD ONE — values become RETARGETABLE beyond CSS
This is the capability that only exists if values are typed. PLAN-128 wants a
score to render as a FILM, not just drive a page. A renderer (canvas/WebGL/ffmpeg/
PDF) cannot reliably consume "8px"/"oklch(…)" text, but it can consume a typed
length or color. Let %scalar_type carry a repr MAP rather than a single string:

    %scalar_type color { capture: color, repr: { css: hex-or-fn, canvas: rgba-tuple,
                                                 render: linear-float4 } }

and one authored value serves the browser, the canvas compositor, and the film
render — each backend reading its own column. Same for length (css px · canvas
device px · render frame-relative). That makes "a website and a video differ only
in WHICH SIGNAL DRIVES THE TIMELINE" (score.st's stated bet) true at the VALUE
layer too, which is where it would otherwise break. Nothing else in the repo makes
non-CSS backends tractable; the value layer is the last text-shaped seam.

** 9. Cross-language seam (spacetime_lv)
The Elixir side validates payloads against the contract sidecar. Scalars-as-data
means the seam can share value types (a `color` field arriving from a LiveView is
checkable server-side by the same declaration) rather than degrading to "string".

* The finding

Probed at HEAD (bc2941ee), then removed the probes. In every position where a colour is actually WRITTEN — after a `:`, inside a value function's parens, after a value comma — the lexer emits ONE ATOMIC `COLOR` token. A stdlib grammar `"#" [0-9a-fA-F]{3|4|6|8}` returns None on it: both the literal `"#"` and the counted class fail, because `ExtractResult` returns tokens-CONSUMED (a whole number of tokens) and there is no half-token in the protocol. The W0 terminal scans bytes and crosses token boundaries, but only from a token START; it cannot begin INSIDE one.

Net: the terminal works where nobody writes colours (bare `#e8eef7` at statement level → HASH+IDENT) and fails everywhere they do. Identical shape for `NUMBER_WITH_UNIT` — `8px` is one token, so `$n:number $u:unit(length)` can never match it.

FEAT-165 said "blocked by W0"; FEAT-167 said "blocked by W1 (grammars must own the domains before the lexer stops pre-committing them)". That mutual block is not a stylistic preference — the lexer pre-commits the domain by MERGING, and a merged token is opaque to any grammar. **A grammar cannot own a domain the lexer has already fused.** The demotion of the tier-2 passes and the grammars that replace them are ONE cutover.

Revised sequence (detail on FEAT-165): W1.0 demote behind a flag (default-on old path) → W1.1 golden token baseline, C2 e-notation settled first → W1.2 grammars against demoted tokens → W1.3 flip default, migrate ~13 consumer files, delete merge passes + harness.

REJECTED alternative: sub-token consumption in the extractor protocol (byte offsets instead of token counts). Would avoid touching the lexer, but changes `ExtractResult` for every extractor, keeps domain knowledge in the lexer permanently, and leaves two mechanisms for "what is a colour" — the parallel-implementation failure this arc exists to remove.

* The wave got a user-visible justification it did not have

There is NO hex validation anywhere in the pipeline. Verified end to end: `.probe { color: #e8ee1; background: #zzz; }` passes `cargo run -- check` with ✓ and lands verbatim in the emitted `spacetime.css`. `#e8ee1` is a 5-digit hex (illegal in every CSS spelling); `#zzz` is not hex at all. The browser drops both declarations and the author sees an element rendering wrong with no diagnostic anywhere. lightningcss validates at stylesheet level and misses this path.

So W1 is not a refactor that relocates behaviour — it is the first thing in the system that would ever REJECT a malformed colour. That reframes the arc's pitch: PLAN-122 has been justified as complexity-removal (five Rust arms → data). It also BUYS a diagnostic class that does not exist today. `{3|4|6|8}` makes `#e8ee1` a spanned parse error, and the 4/8-digit alpha forms keep working — which is precisely why the count set is DATA and not a hardcoded "3 or 6".

* Answering the standing ASK — "prioritize FUP-166's repr-map to unblock video rendering?"

Not yet, and the finding above is why. FUP-166 (values retargetable beyond CSS — a `repr` map with css/canvas/render columns) reads its columns off `%scalar_type` entries, which are W4, which reference W1 capture types, which now require the lexer demotion. Prioritizing FUP-166 today means building a table with no rows.

The honest ordering, given that the three ASK options collapse onto one prerequisite:

1. **Expanded grammar scope** (the ASK's third option) — but specifically the W1.0/W1.1 demotion+baseline, NOT more terminals. W0's terminal is already sufficient for every W1 grammar; what blocks is the lexer, not the pattern language. Adding more grammar surface now would add unmatched grammars.
2. **Pattern-driven validation** (second option) — falls out of (1) at near-zero extra cost, and is the first user-visible win in the whole arc: `#e8ee1` becomes an error instead of a silently broken page. This is the wave's demo.
3. **Dynamic colour theming** (first option) — needs W1 grammars (colour recognition) plus W4 (`interpolate:`/repr columns). Downstream of both. FUP-160's runtime half already landed with BUG-202, so the live break is fixed; the registry half waits.

** FUP-176 — declaration validation — DONE (5f27f9ac, 960270e1)

Deferred as "needs spans threaded through a subsystem". FALSE: I had measured
`StatePropertyAst`, which is not the CSS declaration path (4 refs, one file,
`@state`/`@transition` only). The real path is `CssDeclaration`, which ALREADY
carries `span: SourceSpan` covering exactly the value's range. A leaf change.

Deferred also as "needs a stdlib property -> type table". CANCELLED, and this is
the better outcome: lightningcss can be ASKED rather than mirrored — probe
whether `<property>: <known-good sentinel>` parses cleanly. Complete for every
property the crate knows, zero rows, improves when the dependency is bumped, and
no seventh hand-synced list. The user's instinct ("can you ride lightningcss?")
deleted the largest piece of the plan.

The naive form of this rule flags 45 VALID corpus declarations (`color: inherit`,
`box-shadow: none`, `text-rendering: optimizeLegibility`), because lightningcss
reports CSS-wide keywords and its own gaps as `Unparsed`. The rule is therefore
RELATIVE: a value is wrong only when a sentinel of the same type succeeds on the
same property. 45 -> 1, and the 1 was a regex misreading a `@type` field.

** FUP-164 — shadow classifiers — DONE (2edbeca4)

`lsp/colors.rs` had THREE hand-written parsers behind a byte scanner; `hsl()`,
`oklch()`, `color-mix()` and every named colour got no swatch at all.
`visual_lint.rs` (the SIXTH classifier, found in recon — the original count of
four was wrong) knew 8 named colours out of 148, and the contrast lint SKIPS a
colour it cannot read, so pages with unreadable text in the other 140 were never
linted while the suite stayed green. It also returned `transparent` as opaque
BLACK — a wrong answer, worse than none.

Both now use the same parser as the declaration validator. The gates were
verified to FAIL against the old cascade before being kept.

** FEAT-166 — CSS-native typed seeds — DONE (db6de850, f13a9783)

    @data inline $brand Brand : { ink: #e8eef7, radius: 8px, reveal: 600ms };

Byte-identical JS to the quoted form, asserted as an EQUIVALENCE rather than a
compile — two surfaces that merely both compile are two features that will drift.

The discriminator is POSITION: the `{` follows the COLON that introduces a VALUE,
and a body never does. The first attempt used `last_was_value_colon` and was
wrong — `@type Brand { ink: color }` sets that flag from the type's OWN field
colons, so it swallowed every `@type` body.

Separator is `,` not `;`, settled by sigil harmony: a record is a VALUE and `,`
separates value elements; `;` TERMINATES a declaration. With `;` the value
greedily swallowed the rest of the record.
