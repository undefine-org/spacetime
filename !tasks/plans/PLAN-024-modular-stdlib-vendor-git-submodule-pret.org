* Philosophy (gingerbill, reconciled with repo reality)

gingerbill's 4 distinctions: package ≠ repository ≠ build-system ≠ package-manager.
The /package manager/ is the evil (automation of dependency hell). Spacetime already
lives the Go-style ideal: batteries-included stdlib vendored into the binary
(=stdlib_embedded.rs= via =include_str!=), no resolver, no lockfile, no transitive
graph. The build system IS the compiler. AGENTS.md "no custom JS in sites" = the same
instinct: don't import liabilities you don't own.

∴ We do NOT add a package manager. We add a DISCIPLINED VENDORING UNIT:
- pin (git submodule @ commit) · provenance · own-behind-a-primitive · manual bump (friction = feature)
- each dependency is a liability we are responsible for (José Valim's point)

* Decisions (locked with user)

1. Vendoring source = GIT SUBMODULE, not npm. The existing
   =@chenglou/pretext= devDependency + package-lock.json are DELETED.
2. pretext repo ships TS =src/= (dist/ is gitignored). A one-shot bundle
   (=bun=) flattens src → a single JS artifact. This is a MAINTAINER build
   step, not "npm in spacetime": no resolution, no lockfile, no transitive graph.
3. Bundle artifact = GENERATED, not committed-by-hand. build.rs regenerates it
   from the pinned submodule — but LAZY: skip rebundling when
   =vendor/pretext.bundle.js= exists AND matches the submodule commit. Keeps
   =cargo build= working without bun for anyone not touching pretext.
4. Delivery to browser = embed/concat the bundle as an IIFE exposing a global,
   into the page runtime blob — ONLY when a text primitive fired (demand-driven
   "lean rail"). Non-text pages stay lean.
5. =cargo run -- vendor build text= = a STDLIB HOT-RELOAD concern, NOT a site
   =build= concern. It regenerates =vendor/pretext.bundle.js= on disk; the stdlib
   incremental-cache hot-reload picks it up and re-emits the affected primitive.
   No binary recompile, no site rebuild.
6. ONE bundler routine, TWO triggers (DRY): build.rs (embed path) and
   =vendor build= (filesystem/hot-reload path) call the same code.
7. Module name = =text/= (measurement+layout, broader than "typography").
8. =*.test.st= live in a per-module =tests/= subfolder (new convention,
   codified in stdlib/AGENTS.md). Tests run via the EXISTING playwright_st
   harness (real Chromium → Intl.Segmenter + Canvas present); harness updated
   if needed.
9. stdlib/AGENTS.md written LAST, against settled reality.

* Hot-reload wiring (makes decision 5 literally true)
