* The three cleanup tasks (parallel, no blockers)

** FUP-063 — comment-aware %emit js statement splitter  [compiler]
`find_semicolon_at_depth_zero` in src/emit/js_parser.rs tracks strings + brace/paren depth but NOT `//` or `/* */` comments. A `;` inside a comment is mis-read as a statement boundary → tail loses its `//` prefix → runtime SyntaxError. Same family as BUG-040/041.
HARD CONSTRAINT: a prior fix attempt REGRESSED the 4 template snapshots (`template_definition_js`, `template_def_invocation_js`, + the css pair) with `return element;;`, lost indentation, broken `} else {`. The new fix MUST keep those snapshots byte-identical (no `cargo insta accept`).
Acceptance: new unit test — `;` inside `//` and inside `/* */` does NOT split; 4 snapshots UNCHANGED; `cargo test --lib js_parser` + `cargo test --lib snapshot_tests` green.

** FUP-066 — single shared compile in put_function_from_args  [mcp]
`put_function_from_args` (src/mcp/tools.rs) compiles the source TWICE: once via `super::bundle::compile_to_bundle` (contract params) and once via `compile_option` (html/css/js). Both run `Compiler::from_ast(&ast).compile()` on the same source. Real risk = divergent error semantics (`has_errors` vs `compile_ok`), already papered over by a `!has_errors` gate.
Fix: one shared compile/extract that runs the pipeline ONCE and yields both projections (html/css/js/diagnostics + bundle/contract_params) from the same CompiledSpacetime+AST. Keep `compile_to_bundle`'s public API (used by /bundles endpoint + tests); add a combined helper used by put.
Acceptance: put compiles source exactly once; contract extraction + page compile read the SAME result; existing tests green (`cargo test --lib mcp`).

** FUP-064 — headless harness can drive @each data sources  [testing]
Re-scoped (2026-06-18): NOT a runtime render bug. Runtime `@each` renders correctly on a live serve — it re-renders on a dispatched `data:{src}:loaded` / `local:{src}:updated` CustomEvent (detail=array), see stdlib/primitives/data/each.st. The headless tests in tests/unit/templates/collection-ref-each.test.st seed `window.SpacetimeLocal.crefItems = [...]` directly and never dispatch that event → @each never renders → the test was in the 251 pre-existing-failure baseline.
Fix: make the headless harness able to drive an @each data source the way a live page does (dispatch the documented CustomEvent). Prefer an EXISTING testing-vocabulary affordance (@drive / @when data probe) over hand-dispatch; fall back to dispatching the documented event from @eval + document the convention. DO NOT modify runtime each.st render logic.
Acceptance: collection-ref-each.test.st passes headlessly (`cargo run --features headless -- test tests/unit/templates/collection-ref-each.test.st --headless`); the seeding convention is documented.
