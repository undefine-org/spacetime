* North star
Not "a list of macros." A LIVING, EXPLORABLE MAP OF THE DISPATCH MACHINE. Every
directive is a node you search, click, expand, and PROBE. The reference is itself
a projection of ~score_form_match~, so it CANNOT ROT: change the scorer or add a
~%macro~ and the reference updates next build. Reading the reference and
understanding how Spacetime resolves a call become the same act.

This extends demos/spacetime-docs (the FEAT-086 reader) from "renders prose about
directives" to "lets you SEE the dispatch machine think."

* What dispatch IS (the thing being surfaced)
Spacetime resolution is PREDICATE DISPATCH, not nominal lookup.
~registry.rs::find_macro_for_match~ scores EVERY macro whose ~form.directive_name~
matches, over (arg TYPES × selector SCOPE × literal KEYWORDS), and takes argmax.
Real weights from ~src/syntax/form_scoring.rs::score_form_match~:
  literal token matched      +3   (exact keyword: "fetch","query" — strongest)
  required capture present   +2
  comparison capture         +2
  optional/defaulted present +1
  param present              +1
  literal NOT matched      −100   (wrong keyword → form eliminated)
  required missing / type mismatch → None (hard reject)
Winner = ~max_by_key(score)~. Today this is INVISIBLE: ties silently first-wins; a
new %macro can shadow an existing call unnoticed; you can't ask "why this macro?".

* Architecture — five layers, each on an EXISTING rail
** Substrate (Rust) — reusable win for ALL macro authors
- ~inspect --layer dispatch~ (new ~InspectLayer::Dispatch~), mirrors
  ~cli/inspect.rs::build_registry_output~. Catalog mode (every macro grouped by
  directive + serialized ~FormClause~ + doc + scopes + %binds); ~--probe "<call>"~
  mode (parse via ~parse_matches~, score all candidates, emit resolution table).
- ~explain_form_match(form, input) -> ScoreExplanation{ total, terms[] }~ sibling
  to the fast ~score_form_match -> Option<u32>~. ONE source of truth: fast path
  becomes ~explain(...).map(|e| e.total)~ so they cannot diverge. Introspection-only.
- ~E09xx ambiguous-dispatch~ diagnostic: top-two viable candidates tie → warn
  (today silent). The real correctness payback — catches shadow bugs.
** Data plane (Rust) — one function, mirrors FEAT-084
- ~format_form_signature(&FormClause) -> String~ (walks inline_elements/params/
  post_arg_inline using CaptureType + CaptureModifier) + ~build_dispatch_json~.
- ~@data dispatch $macros~ source (sibling to ~@data registry~) → catalog into the
  page with zero fetch, SSG path identical to FEAT-084.
** Markup plane (pure .st) — the delight
- Search: ~@data inline $q~ + ~<input>~ two-way (~value <- $q; @on input { $q <- value }~).
- Filter chips: ~@data inline $kind~ + ~@on click~.
- Grouped cards: ~@each-filtered($macros as $m, when match($q,$kind,$m))~ →
  ~&macro-card($m)~. @each-filtered reactively display:none's non-matches —
  LIVE SEARCH, ZERO CUSTOM JS.
- Detail expand: ~@on click~ toggles a signal → form-sig + @doc prose + probe.
- Form-signature rendering: each token a styled CHIP ($name teal · :type dim ·
  literal bright · ? ghosted) so a signature is SCANNABLE, not a wall of text.
** Live plane (#5) — the playground (going deeper)
- ~/__spacetime/dispatch?call=<urlenc>~ route (mirrors runtime_js_handler):
  parse_matches + explainer over the live registry → resolution JSON.
- ~%primitive dispatch-probe(&el)~ (%emit js posts input → renders table; winner
  glows, −100 rows show WHY they lost) behind ~@dispatch-probe~ macro.
- UX: type ~@on cdick~ → all-red no-winner; fix to ~@on click~ → ~+3 ✓~ lights up.
  You watch multiple dispatch resolve keystroke by keystroke. Honest to "no custom
  JS": the only JS is inside %primitive %emit js (the sanctioned escape hatch).
