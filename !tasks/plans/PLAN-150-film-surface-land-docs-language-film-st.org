* Design invariants (non-negotiable)
- =->= = a step between values. =at= = a position (score line OR keyframe stop). =--name= = a form reference. =&name= = an element (DOM, stage object, or audio entity). =@word= = a directive. =:slot { }= = a named sub-body inside a directive (the =@each= =:entering= shape). No proposal adds a second meaning to any of these.
- Motion is written in ONE place: the =@on <driver> { … }= body. Camera moves, post-processing, 3D object props, audio gain are all PROPERTIES inside that body or forms consumed by it. No new driver kinds.
- Every new variant is a =@form <kind>= (=post=, =camera=, =transition=, =shot=) registered through =stdlib/macros/form.st='s existing =%registers form($name, kind: …)=. Adding a kind = one macro arm + one body capture type. No Rust match arm per kind.
- Determinism: everything must be a pure function of clip progress + compile-time data. =random()= resolves at compile time; =--noise-1d= is a pure function of progress. =tests/render/render_test.rs= (bit-identical two-run hash) must stay green after every wave — it is the film's regression net.
- FOUC/frame-0: every keyframeable property must produce a correct progress=0 initial state through =generate_initial_state_css= (BUG-382's path). New property kinds (=@post= props, camera, stage-object props) need an initial-state emitter or an explicit "runtime-only, first tick before first paint" proof under =render=.
