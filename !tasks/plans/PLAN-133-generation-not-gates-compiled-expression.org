* Ruling (design run 2026-08-04, user-directed)

NO detection scaffolding. No validator wiring, no %smoke gates, no coverage
harness, no template lint. The route is GENERATIVE: improve what the compiler
emits so the bug class is unrepresentable. The pipeline ends up SMALLER than
today — mechanisms must delete, not add (elegance bar).

Principle: every layer is compiled by the layer above it, never re-parsed by the
layer below it. Runtime regexes / char-scans / `new Function` are the compiler
abdicating to a dumber consumer.

* Move 1 — expressions are parsed by the grammar, not captured as text

derived-signal.st: `expr: string` → `expr: expr` (one-word declaration change;
computed-source is the working model).

Consequences:
- `$comRecords.filter(($r) => $r.status == "open").length` parses into a real
  CST. A lambda-bound `$r` is a structurally different node from signal
  `$comRecords` — no rewriting because nothing is ambiguous.
- Deps discovered from the tree at COMPILE time. Typo `$comRecord` → compile
  error (unknown name), instead of a badge that silently never updates.
- Emitter emits `ST.derive(["comRecords"], (comRecords) => …)` — deps as
  positional function args (the existing ST.derive contract).

DELETED: deps regex, char-scan rewriter, lambdaBound heuristic (tactical patch
reverted into structural shape), `new Function` + try/catch eval, runtime
pipe-desugar. The entire BUG-273 mechanism.

Grammar extension required: arrow expressions `($r) => …` (and multi-param) as
a binding form introducing scope for the body. Lexer ready; the work is grammar
+ lowering to JsExpr. Conservative: arrow params only, not arbitrary JS.

* Move 2 — the runtime owns behavior; templates emit calls
The fetch lifecycle (locale resolution → fetch → parse → publish → error
report) is one recurring shape, repeated for every `@data source` usage. It
moves into the primitive's OWN `%emit prelude-js` block — emitted ONCE per
compilation, deduplicated by primitive name (first occurrence wins), before all
per-usage fragments. This mechanism already exists and is in use
(src/pipeline/mod.rs:1397-1412; source.st:22 already uses it for
`window.__spacetimeData` init).

  // source.st after:
  %emit prelude-js {
    function __stResolveLocale() { /* written once */ }
    function __stDataSource(opts) { /* fetch → publish → error-report, once */ }
  }
  %emit js {
    __stDataSource({ url: %src, bind: %name, interval: %refresh });
  }

USER RULING (2026-08-04): shared template JS does NOT go into st.js — it goes
into `%emit prelude-js`, so the primitive carries its own once-per-page runtime
and stays self-describing (code as data, inside the primitive, not in the
toolchain's runtime file).

DELETED: locale triplication (`window.__st_locale || document…lang || 'en'`
written 3× in one template), hand-rolled error path, the BUG-274 hoist patch
(subsumed by __stResolveLocale defined once in the prelude).

The hand-declared-local-crossing-scopes shape that produced BUG-274 no longer
exists in generated code: the prelude defines plain top-level functions;
per-usage code declares no locals — it passes arguments.

Standing rule for primitives (corrected): if a JS shape repeats across USAGES
of one primitive, it moves into that primitive's `%emit prelude-js`.
Per-usage `%emit js` = calls + data. An `if`/loop/scan in per-usage code means:
move it to the prelude, then call it. Nuance: dedup is PER PRIMITIVE NAME, so
a helper shared by two DIFFERENT primitives would duplicate across their
preludes — that cross-primitive case still argues for st.js or a shared
prelude-owning primitive (decide when the first real case appears; do not
pre-build).

* Why "structurally impossible" rather than "better checked"

The two places scoping ever mattered are gone: inside expressions (now resolved
on the syntax tree, once, at compile time) and inside template lifecycle code
(now one tested runtime implementation, called by reference). No text-level name
manipulation remains anywhere in the pipeline. A bug needs a habitat; this
removes it. Nothing new to wire or maintain.

Pattern-consistency (learnable-by-pattern): after Move 1, derive takes a
function the same way fold takes stepFn, the same way computed-source takes
reduce. One pattern for "expression over signals".

* RULING (2026-08-04, user): one `=>` for BOTH lambdas and match arms — this is
sigil unity, not overload. The arrow has ONE meaning: left side introduces
bindings, right side produces a value. Match arm = pattern-strength binding
form; lambda params = the irrefutable special case. The textually-identical
case (`x => x+1` as catch-all arm vs as lambda) is harmless because the two
readings are the same function. Disambiguation is POSITIONAL (inside a
match/receive block → pattern; expression position → params), not sigil-based.
W1 must accept BOTH param spellings seen in the wild: bare `item => …`
(examples/cart-demo, on_mutation_demo) and parenthesized `($r) => …`
(pill). Fold's reducer doc migrates `->` → `=>`. AUDIT separately: `->` in
macro-call output position (`dnd-runtime() -> { }`) is a different role
(yield routing, not value mapping) — likely keep; only unify actual lambdas.
Existing `parse_arrow_fn_balanced` (cst/parser.rs:3553) consumes arrows WHOLE
as opaque EXPR blobs for @eval/@when payloads — W1 replaces blob-consumption
with a real binding-form node (params as scope-introducing children), which
nested arrows (`Some(x) => xs.filter(y => y > x)`) require.
