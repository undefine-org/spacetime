* Design

** The DocRanker trait (the one seam)

#+begin_src rust
struct DocRow { name: String, kind: String, doc: String, signature: String, exports: Vec<String> }
struct Scored { row: DocRow, score: f32 }

trait DocRanker {
    fn rank(&self, query: &str, rows: &[DocRow], limit: usize) -> Vec<Scored>;
}
#+end_src

Default impl this PLAN ships: `Bm25Ranker`. Future `EmbeddingRanker`
(feature-gated) and `RemoteRanker` (opt-in) implement the same trait; the tool
never knows which is live.

** Ranker B algorithm

1. Tokenize query + each row-document (`format!("{name}. {doc}")`, optionally
   append signature). Lowercase, split on non-alphanumerics, drop a tiny
   stopword set.
2. Expand query tokens through a curated synonym map BEFORE scoring:
   reload/refetch→refresh, popup/modal→dialog, fade/appear/reveal→transition/scroll,
   list/array→collection, click/tap→on, loop/repeat→each, etc. Keep the map
   SMALL and data-shaped (a `&[(&str,&[&str])]` const, not code branches) so it
   is auditable and grows by data.
3. BM25 over the row-documents (classic k1=1.2, b=0.75). Add a small bonus when a
   query token matches the construct NAME/directive exactly (name hits matter
   more than doc hits).
4. Sort desc, truncate to `limit`. Normalize score to 0..1 for the result.

** Corpus assembly

Prefer refactoring `build_dispatch_json` to expose a `Vec<Row>` builder that both
the JSON path and `corpus()` call (one source). If that refactor is too wide for
this PLAN, fall back to parsing the two existing JSON arrays and merging by name
— but leave a NOTE that the Vec builder is the harmonious end state.

** MCP tool surface

tool `spacetime_query_docs`:
- `query` (required, string) — plain-language intent
- `kind` (optional) — pre-filter: data|events|animation|motion|scene|text|test
  (applied as a cheap structured retain BEFORE ranking)
- `limit` (optional int, default 8)
returns `structuredContent { query, matches: [{name,kind,score,signature,doc,exports}] }`,
`matches` sorted score-descending.
