* Context

PLAN-007 fixed 5 critical CMS bugs and wired schema-driven editing, but browser testing revealed two pre-existing PLAN-006 bugs that prevent the dev panel from functioning:

** Problem 1: Dev panel never initializes (BUG-009)
Global phase primitives (dev-panel, dev-ws, dev-save, dev-editable, etc.) use ~%yield~ and ~%cleanup~ directives that compile to ~ST.set(el, ...)~ and ~ST.onCleanup(el, ...)~. But when a primitive has no selector (~selector: None~), the expand phase sets ~el_init = None~, so the IIFE wrapper is generated without ~const el = document.body;~. The ~el~ variable is undefined at runtime, causing a ReferenceError that silently kills the primitive's initialization. Since ~window.__stDevPanel~ never gets set, all downstream primitives (content tree, data editor, save) also fail to initialize via their ~setTimeout(init, 200)~ retry loops.

Fix: In ~src/pipeline/expand.rs:189~, check if ~ir.exports~ or ~ir.cleanup_stmts~ is non-empty before defaulting to ~None~. If either is present, use ~Some(ElInit::Body)~ (i.e., ~const el = document.body~).

** Problem 2: TypeRegistry produces empty field lists (BUG-010)
~CaptureType::Properties~ in ~src/syntax/events/form_compiler.rs:1013~ is short-circuited to ~CapturedValue::String(inner)~ instead of being routed through ~PropertiesExtractor~. This causes ~TypeRegistry::from_form_matches~ (which calls ~get_properties("fields")~) to get ~None~ (pattern match fails on String), producing types with zero fields. All JSON schemas have ~{"properties": {}}~, so schema-driven forms never render.

Fix: Remove ~CaptureType::Properties~ from the short-circuit arm. Keep ~CaptureType::HtmlBlock~ in the short-circuit (its extractor produces a different CapturedValue variant that would break template invocations). Properties then falls through to the extractor-based path where ~PropertiesExtractor~ correctly parses field definitions.

** Key Decisions
- Use ~document.body~ as ~el~ for selectorless global primitives — safe because ST.set uses per-signal-name slots in a WeakMap, and signal names across dev primitives are disjoint
- Keep HtmlBlock in the short-circuit — Daedalus validation identified that removing it changes the CapturedValue variant from String to Expr, which would break template invocation body codegen
- Check ~ir.exports.is_empty() || ir.cleanup_stmts.is_empty()~ as condition — exports are populated from ~%yield~ declarations at codegen time, canonical proxy for "this primitive uses ST.set(el, ...)"
- An additional parse fix was already applied in PLAN-007 commit ~061a8414~: ~/"/g~ → ~/\x22/g~ in escHtml functions to fix ~%emit js~ brace nesting

*** Deviations
- BUG-010 fix was more complex than planned. The plan specified simply removing =Properties= from the short-circuit arm so it falls through to the catch-all =_ =>= path. However, the catch-all uses =collect_descendant_tokens= which produces DUPLICATE tokens (parent ChildNode and its children share the same tokens). This caused =PropertiesExtractor= to fail (it expects =IDENT COLON type SEMI= but saw =IDENT IDENT COLON COLON type type SEMI SEMI=). The fix adds a dedicated =CaptureType::Properties= arm that re-lexes the trimmed body text to produce clean, deduplicated tokens.
