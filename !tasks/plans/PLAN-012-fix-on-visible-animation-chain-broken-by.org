* Context

** Problem
The hero animation on ora-ventures.com never fires — all content below the first headline stays at =opacity: 0=. The =@on visible= directive, which starts the animation chain, silently produces no JS output.

** Root Cause
=evaluate_match()= in =src/pipeline/evaluate.rs= line 117 uses =registry.get_macro(&form_match.macro_name)= to look up macro definitions. For =@on= directives, =form_match.macro_name= is ="on"= (derived from the =@on= directive prefix), but the macro is registered under its full name ="on-event-dispatcher"=. The HashMap lookup returns =None=, so =evaluate_match= returns an empty result without processing the =%if/%elif= conditional =%binds= blocks.

The downstream =resolve_single= function DOES find the macro (it uses form-directive lookup with scoring), but it only handles top-level =%binds= — not conditional ones inside =%if/%elif= blocks. Result: zero primitives are emitted for =load-driver=, the =line-1= timeline is never created, and the entire =@after= chain stalls.

** Why other @on directives work
- =@after= has top-level =%binds= (no conditionals) → =resolve_single= handles it
- =@on click { mutations }= matches =on-mutation-dispatcher-simple= which also has top-level =%binds=
- The 5 affected macros (=on-event-dispatcher=, =responsive=, =state-machine=, =waapi-on-event=, =waapi-timeline=) all use conditional =%binds= inside =%if/%elif= blocks

** Approach
One-line fix with fallback: when =get_macro()= returns None, use form-directive lookup + scoring (the same approach =resolve_single= already uses). This ensures =evaluate_match= finds the correct macro definition and processes its conditional =%binds=.

** Key Decision
- Fix in =evaluate_match= only — do NOT change =FormMatch.macro_name= or =get_macro=. The directive-derived name is used elsewhere and changing it would be a wider refactor.

** Locale /en/ 404
Confirmed as the pre-existing V8 thread degradation (FUP-007). The =/en/= route returns 200 on a fresh server; 404s only after V8 runtime degrades from repeated requests. No new regression from PLAN-011.
