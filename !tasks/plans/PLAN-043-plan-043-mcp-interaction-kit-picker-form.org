* Non-negotiable constraints (AGENTS.md + FEAT-123)
- NO new JS outside %primitive. The kit composes EXISTING primitives
  (@mcp-host, @mcp-input, @mcp-action, @each, text:) — zero new primitive unless a

- NO new bespoke Rust routes per interaction (no st_pick / st_confirm). The agent

- ONE generic sink: every kit emits `mcp-action` (or a typed click) through

  /__mcp/choose, no per-kit route names.
- Region-isolated: a kit mounts into a region (`data-st-instance` root); two kits on
  one page carry independent host bridges (already true of @mcp-host).

* Data contract (how options come IN, choice goes OUT)
The agent mounts a kit function with `input.json` carrying the kit's shape:
  picker  → { kind:"picker",  prompt, options:[{id,label,detail?}] }
  confirm → { kind:"confirm", prompt, confirmLabel?, cancelLabel? }
  form    → { kind:"form",    prompt, fields:[{name,label,type,placeholder?,value?}] }
The page reads these via `@mcp-input`. To render them with the proven list/text idiom,
`@mcp-input` must publish the kit sources alongside the workbench arrays.

DECISION (kit publish): extend `publishWorkbenchSources` in
`stdlib/__mcp__/primitives/host.st` to ALSO publish generic kit sources from the input
object — `mcpPrompt` (scalar), `mcpOptions` (array), `mcpFields` (array). One input
primitive, no per-kit JS. (Rename the fn to `publishSources` since it now serves both.)
This is a small, data-driven extension of an existing primitive (passes the elegance bar).

OUT (choice): each option/button carries its id in a data attribute and emits
`@mcp-action(action:"kit-choice", valueAttr:"data-choice-id")` — the existing
attr-driven action path. st_await returns `{type:"mcp-action", payload:{action:"kit-choice",
value:<id>, ...}}`. confirm emits action "kit-confirm"/"kit-cancel"; form is S0
(emit per-field is deferred — see scope).
