** The architectural fork (why W3a isn't a one-liner)
`data-subscribe` and `data-subscribe-seeded` are DISTINCT %forms. The bodyless
one hardcodes `local-state-impl(initial: null)`; only the seeded one threads a
`$seed`. To auto-seed a typed bodyless subscribe I must get `zero_value(type)`
(Rust) INTO the emitted `local-state-impl` initial. stdlib can't call zero_value.
Options:
  A. Rust pre-emit pass rewrites a typed bodyless subscribe FM to carry the
     zero-value as a seed capture — but the bodyless %binds doesn't READ a seed,
     so the injection wouldn't emit. Would need the macro to read an (optional)
     value capture.
  B. MERGE the two subscribe macros into one with an optional seed, and have Rust
     fill the zero-value when the seed is absent+typed. Cleaner end state (one
     macro, harmony) but a bigger refactor of data-kind.st + the expand path.
  C. A targeted Rust hook at the @data expand site (pipeline/mod.rs ~3095) that,
     for a typed null-seeded subscribe, substitutes the zero-value into the
     local-state-impl initial capture. Most surgical, but pipeline/mod.rs is a
     LARGE file the concurrent BUG-229 agent is actively editing.
