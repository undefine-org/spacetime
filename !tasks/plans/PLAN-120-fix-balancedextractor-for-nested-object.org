* Scope
The two faces of BUG-228 (see !tasks/bugs/BUG-228-...org):
1. Bare-identifier object keys: `@data inline $x : { a: 1 } ;` fails; `{ "a": 1 }`
   works. Seed-expr parser stricter than the @on statement-body JS parser.
2. Nested object values in body captures: `{ initial: { "a": { "b": "" } } }`
   fails in BOTH `@data fetch` and `@data subscribe … { initial }`.

* Root cause (from FUP-144 W1 investigation)
`balanced(';')` (BalancedExtractor, src/syntax/events/extractors/custom.rs): a
nested `{...}` VALUE is pre-split by the parser into a child BODY node, so it's
absent from the extractor's flat inline token slice — scan_end stops before the
nested content and the brace balance never closes.

* Fix steps
1. scan_end: include pre-split child-BODY tokens so nested `{…}` balances close.
2. Seed object-literal parsing: reuse the @on statement-body JS parser path so
   bare identifier keys are accepted (parity, not a second grammar).
3. Confirm across @data inline / fetch default / derive / subscribe seeds.

* RED→GREEN
- `@data inline $x : { a: 1, b: 2 } ;` compiles, seeds {a:1,b:2}.
- `@data fetch … { initial: { "a": { "b": "" } } }` compiles (nested).
- Byte-stability: existing quoted-key seeds unchanged.
