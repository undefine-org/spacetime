** #11 — SSG filter parity
Static lists render twice: once at build time (real HTML in view-source) and once at
runtime. Filters are stdlib-defined Spacetime; the runtime can apply them, the build-time

the build-time path to evaluate stdlib filters, not to port them.
This is the wave's biggest unknown — scope it with a spike before committing, and if the
evaluation seam is not ready, say so in the issue rather than shipping a Rust shortcut.

* W8 — delete the LSP's parallel registry   [#28 root; #29, #30, #31, #32, #33]

** The duplication
The compiler builds its registry by loading stdlib + the project overlay. The LSP maintains
a hand-written `include_str!` list, silently skips files that fail to parse, and serves
completion/hover/diagnostics/definition from that snapshot. Its workspace manager has a
project-aware registry that is created with no roots, whose `add_root` does not mutate
roots, whose `scan_workspace` is never called, and whose registry no handler uses.
Reporter's measurement: compiler 97 leading form tokens vs the LSP's advertised set.

** Order matters — #28 first
1. #28: the LSP consumes the compiler's live registry, project roots included. Delete the
   static list. Every other item shrinks after this.
2. #29: generate completion snippets FROM the form grammar (positional captures, sigils,
   literal words, typed body) instead of the flat `name: ${n}` shape. Note the loop this
   closes: the editor was generating exactly the malformed shapes that used to compile
   silently; #25 made them E0946, so today the editor's own output is a build error.
3. #30 + #31 together: store canonical absolute path + exact capture span at definition-
   registration time; give `register_definition` a production caller; stop `UsageVisitor`
   double-walking `file.matches` and scoped matches; use the capture span, not
   `FormMatch.span`, for `@each`.
4. #32: publish the COMPILER's diagnostics rather than an approximation. Target state is one
   diagnostic engine, two front-ends. (The `~preset` false-positive half is already fixed by
   SIP-001c: 783fc242, e111f172.)
5. #33: drive colors and semantic tokens from lexer/CST context — colors only in CSS value
   positions, comments excluded; split multi-line comment tokens per line as LSP requires.

** Acceptance
A project-defined macro appears in completion, hover, and go-to-definition. LSP diagnostics
for the W2 cases (unknown signal, false ambiguity) match `check` exactly. No `include_str!`
registry remains.

* Sequencing and rationale

W0 -> W1 -> W2 -> W3 -> W4 -> {W5, W6, W7} -> W8

- W1 first: highest blast radius, actively destroying a production stylesheet.
- W2 second: cheapest, and it makes every later wave's failures VISIBLE. Doing it after W3
  would mean fixing the matcher while `check` still cannot show you what it found.
- W3 before W4: W4's capture-consumer lint assumes matches are trustworthy; W3 makes them so.
- W5/W6/W7 are independent of each other and can run in parallel once W4 lands.
- W8 last by dependency, not by importance: the LSP should serve the compiler's registry and
  diagnostics AFTER W2/W3 have made those diagnostics correct — otherwise the editor faithfully
  reproduces the wrong answers.

Cross-cutting rule for every wave (AGENTS.md, BUG-252): assert the CONTRACT in Rust and the
BEHAVIOR on --cdp. Write the gate RED, watch it fail, then fix. A source-string assertion
proves a string was written, not that anything ran.
