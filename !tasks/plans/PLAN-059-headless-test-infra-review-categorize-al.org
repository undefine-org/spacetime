C1 DEEP ANALYSIS (scoped-state plane, 12 failures) — RESOLVED
═══════════════════════════════════════════════════════
Question was: is `$x: v` in an element scope element-signal or body-local?
ANSWER (proven): body-local is CORRECT and the product is CONSISTENT. The TESTS are wrong.

EVIDENCE:
1. Compiled a REAL page `.counter { $count number: 0; .display{text:$count} @on click{...} }` via `cargo build`. It lowers `$count number: 0` to `window._localState["count"] = 0` + `local:count:updated` dispatch — IDENTICAL to the test `@given` path. The reactive binding reads via `ST.resolve(node,'count')` + `ST.watchScoped(node,'count',...)`, NOT `ST.get(el,'count')`.
2. Probed the test runtime AFTER an init flush (`@wait 30ms`): `ST.resolve(el,'count')===0`, `SpacetimeLocal.count===0`, `_localState==={"count":0}`. Scoped state IS correctly populated — the product works exactly as the live page does.

ROOT CAUSE of the 12 failures (two test-authoring bugs):
(a) Tests read `ST.get(el,'count')` — the RAW element-signal store — which scoped state never populates. They should read `ST.resolve(el,'count')` (the plane-agnostic read that checks element-signals THEN SpacetimeLocal). `ST.get` returns undefined for body-local scoped state.
(b) Tests assert SYNCHRONOUSLY right after `@given`, before the async selector-init runs. Need a flush (`@wait`/`@flush`) first.

DEEPER FRAMEWORK INCONSISTENCY (the elegant fix):
The canonical assertion `@then $signal on .sel should equal` (stdlib/testing/assertions/binding.st:39) ALSO uses `ST.get(__el, __signalName)` — so it too only sees element-signals, not scoped state. Meanwhile `ST.resolve` (st.js) is the UNIFYING read: walks element-signal ancestors AND falls back to SpacetimeLocal. 
→ ELEGANT FIX: change the binding-assertion vocabulary (`should equal`/`not_equal`/`be_gt`/… in binding.st) to read via `ST.resolve(el,name)` instead of `ST.get(el,name)`. This makes `@then $x on .sel` correct for BOTH element-signals (ST.set, e.g. microtask-storm) AND scoped state (`$x: v`, e.g. component-model) — one read, both planes. Then rewrite the 12 component-model tests to use `@then $count on .sel should equal 0` (+ a flush) instead of the raw `@assert (ST.get(...))`.

This is harmonious (one read path) and removes the foot-gun permanently. The microtask-storm `@then $sigA on .chain should equal 20` already works because that test uses ST.set directly (element-signal) — ST.resolve still finds it (element-signal checked first). No regression.

VERDICT C1: 12 = test-contract bug. Fix = (1) binding.st assertions read via ST.resolve; (2) rewrite 12 component-model assertions to `@then $x on .sel` + flush. Product unchanged.
