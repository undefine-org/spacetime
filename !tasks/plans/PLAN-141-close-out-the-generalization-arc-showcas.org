* W1 — The showcase demos [#A]

** Why this is not "write ten demos" (read before starting)

The request was to showcase the G1 primitives. Investigation says most of them CANNOT be
showcased as they stand, and building demos anyway would produce pages that teach a surface
authors cannot use:

  $ printf '@import "stdlib"
<div class="x">hi</div>
.x { @graphql() }
' > index.st
  $ spacetime check index.st
  ✓ All 1 file(s) passed          # ...and it emits NOTHING

`@graphql`, `@css-property`, `@sanitize-html`, `@signal-arms`, `@animate-color` have no
author-facing `%macro`. They are primitives with no directive bound to them. A demo would
require INVENTING the macro — a design decision about the language's surface, not a showcase
of it.

Worse, that `check` output is itself a defect (see W2): an unknown directive passes silently
even with `--deny-warnings`, which is the same class as GH-13/GH-22.

** Therefore, in order:

*** W1.1 Triage the 24 into three buckets
For each of the 24 unreachable primitives, decide:
  - REACHABLE ALREADY via a mechanism the classifier cannot see → teach the classifier, drop
    the baseline.
  - WORTH A SURFACE → needs a `%macro` designed first. That is a language-design item with the
    elegance bar applied (extends existing grammar · variants as data · deletes a special case
    · testable by the same machinery), not a demo task.
  - DEAD → delete. `element-ref` is the strongest candidate: reachable by nothing, in a file
    stdlib does not import, and the thing BUG-328 mis-expanded. Deleting it removes surface a
    matcher bug can land on.

*** W1.2 Build demos ONLY for the bucket that has a surface
Folder: `demos/showcase-<topic>/` with `index.st.md` — literate Spacetime, so the prose and the
program are the same artifact and the explanation cannot drift from what runs (docs/language/
literate.md). Each demo must:
  - be runnable: `cargo run -- serve demos/showcase-<topic>/`
  - showcase the primitive AND something about Spacetime as a whole (reactivity, one-definition
    build/runtime parity, declarative animation) — a demo that only exercises one call is a test,
    not a showcase
  - carry a `.test.st` sibling proving the page does what the prose claims
  - use NO custom JavaScript (project rule)

Strong candidates once surfaced: `graphql` (data pipeline + reactive list, pairs with `@each`),
`css-property` (a computed CSS custom property driving an animation), `score-window` (the score
system's windowing, visually legible), `signal-arms` (lifecycle arms — teaches the `@on` model).

*** W1.3 The index
`demos/showcase-*/README.md` alone is not discovery. Add the set to the existing demo index so
someone can find them without knowing they exist.

* W2 — An unknown directive must not pass silently [#A]

Found while triaging W1, and it is the reason the demos could not be verified by `check`:

  .x { @totally-not-a-real-directive() }   →  ✓ All 1 file(s) passed   (even with --deny-warnings)

GH-13 and GH-22 established that an unresolvable construct must diagnose rather than degrade
into nothing. That rule was applied to unknown PRIMITIVES (E0956) but not to unknown
DIRECTIVES in a selector scope. The consequence is exactly the GH-13 experience: forget an
import, get a blank page and a green build.

Gate: a directive matching no registered `%macro` produces a diagnostic naming it, with a
did-you-mean over the registry. Must not fire on legitimately-unknown-at-check-time shapes —
check `validate_document_is_silent_for_unknown_directive_like_check` in the LSP suite first,
which asserts the CURRENT silence and will need to change with it.
