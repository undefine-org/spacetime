* Context

Spacetime is a Rust-based declarative web framework that compiles .st files through a
6-layer pipeline (Parse → FormMatch → Resolve → Sort → Expand → Emit) into JS/CSS.
The metasystem (%primitive/%macro in stdlib) enables user-defined directives without
custom JavaScript. Content is stored as JSON data files consumed via @data/@each/@template.

** The Spacetime CMS Vision

The CMS follows the "Spacetime way":
- .st files define site structure, behavior, types, and templates (developer domain)
- JSON files hold all content data (content editor domain)
- WYSIWYG editing modifies JSON files directly via the dev debug panel
- Publishing = push modified JSONs + rebuild via CI/CD
- Admin UI is generated from @type definitions, extending the existing dev debug sidebar
- No custom JavaScript — all features are Spacetime directives

** What Already Exists

- PROJ-107 inline editing (DONE): three edit types (locale/data/content) via
  data-st-bind, data-t, data-st-id attributes. WebSocket-based EditJson/EditAst protocol.
- Dev debug panel: Shadow DOM sidebar with timeline inspector, error tracker,
  element inspector, data tree viewer. Compiled conditionally in debug mode.
- TypeRegistry with JSON Schema generation (src/type_system.rs)
- CompileAnalysis tracking @type/@data/@each relationships
- @data + @each + @template pipeline for data-driven rendering
- HTML sanitizer primitive with configurable tag whitelist
- Rich text already works via HTML strings in JSON fields (locale files use <br/>, etc.)
- Build command for single-file .st → JS/CSS compilation

** Key Design Decisions

- Rich text is HTML strings in JSON, sanitized by a configurable whitelist via @rich-editor macro
- Admin panel extends the existing dev debug sidebar (Shadow DOM, same injection mechanism)
- Collection CRUD extends the sync protocol (new EditJsonArray message type, not EditJson)
- Asset upload is HTTP POST (not WebSocket) at /__spacetime/dev/upload
- Site introspection via two GET endpoints that piggyback on DevCompileCache
- Export extends the existing build command (auto-detects site-level vs single-file)
- Button-based reorder in @each (not drag-and-drop — DnD deferred to FUP)
- All features are dev-mode only; zero overhead in production builds

** Critical Implementation Notes

- axum needs ~multipart~ feature flag added to Cargo.toml for upload endpoint
- blake3 crate needed for content-hash asset naming
- TypeRegistry is computed per-compilation; extend DevCompileCache to store it
- dev-ws.st and dev-save.st need client-side updates for every new protocol message
- The text duplication bug (BUG-002) MUST be fixed before rich text work — every editing
  feature inherits this defect
- Toolbar lives in main document (not Shadow DOM) for Selection API compatibility
- @each already has :entering/:exiting/:move animation hooks for CRUD transitions
