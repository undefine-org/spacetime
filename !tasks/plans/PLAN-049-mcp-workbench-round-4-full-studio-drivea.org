* The findings (what is driveable vs what should be)

** F1 — st_tab_open: resolver exists, NO UI emitter (the headline)
`st_tab_open` is registered Audience::Server (actions.rs:65) with a complete
resolver `open_tab_action` (live.rs:1480) + routing test — but `grep st_tab_open
stdlib/__mcp__` finds only a doc-string. NOTHING fires it. The server seam was
built end to end; the button was never attached.

** F2 — tab cards are inert; no tab switching, no active-tab concept
`mcp-tab-card` / `mcp-open-env-card` / `mcp-instance-card` have ZERO @mcp-action
binding (actions.st). `Tab` (state.rs:28) has no "active" field. There is no path
from a tab to the stage. User's exact complaint ("can't even switch tabs") is
structurally true.

** F3 — TWO disconnected object models (the architectural crux)
"Tabs" (env entry points; st_tab_open COMPILES and discards — returns sizes, no
mountable artifact) and "Functions" (registry; mountable to the stage via
mcp_compose/mount_into_host) are parallel universes that never meet. The stage
only speaks `function_id`. So env→tab is a dead-end inspector path while the real
studio loop (gallery→compose→stage) only works for pre-registered functions.
mount_into_host is TEMPLATES-ONLY (live.rs:774; whole-page mounts blocked by
FUP-061).

** F4 — no lifecycle verbs (CR__ not CRUD)
In-page you can open envs, compose guests, mount instances. You CANNOT: close an
env, unmount an instance, remove a tab, clear the stage, delete/duplicate a
function. No st_unmount / st_env_close / st_tab_close TOOL exists either — a
server-side gap, not only UI. Every card is a one-way door.

** F5 — creation is agent-only; no "+"
st_fn_put (register a function) and st_tab_open code=… (scratch inline .st) have
no in-page surface. The human can only rearrange agent-seeded frames, never START
one. Squarespace/Framer begin with "add a block."

** F6 — instance management is a raw <a href target=_blank>
"Open preview" escapes the workbench entirely. No in-workbench focus, no unmount,
no re-input.

* The decision this plan turns on (D0 — tab/function model)
F3 forces a choice before any tab wiring. Two readings:

- BRIDGE: keep tabs as a browse-files concept; opening a tab on the stage means
  "compile it as a function and mcp_compose it." Two models persist; we glue them.
- COLLAPSE (preferred): a tab IS a function-registration of a file entry. Opening
  a tab = put_function(origin=Env, source=file-or-inline) → it appears in the
  gallery + is stage-mountable like any function. The "tab" becomes a VIEW over
  env-origin functions (filter functions by origin.kind=="env" + env id), not a
  second registry. ONE object model, one mount path, one inspector.

COLLAPSE is the AGENTS-harmony answer (one need, one impl; kill the parallel
registry). The Origin enum ALREADY distinguishes Env(env_id) / Agent / Stdlib
(origin.rs) — env-origin functions are exactly "tabs" with provenance. Risk:
file-entry functions may be file-scope pages, not @template — blocked by
FUP-061 (templates-only). Mitigation: ship COLLAPSE for @template-bearing
entries now; a file-scope page entry shows a clear "wrap in @template / FUP-061"
state (same message mount_into_host already returns), and FUP-061 lifts it later.

DECISION OWNER: confirm COLLAPSE vs BRIDGE at plan kickoff (it changes S1–S2's
shape). Plan below assumes COLLAPSE; BRIDGE fallback noted per step.

** W1 — Lifecycle verbs (server floor: the missing half of CRUD)
The studio needs delete/close/unmount before more create surfaces, else every new
affordance adds another one-way door. Registry-as-DATA (AGENTS): each new action
is a REGISTRY row + a resolver arm + a card button, never a parallel subsystem.

S1. st_unmount tool + mcp_unmount action.  [tools.rs, live.rs, actions.rs]
   - LiveServer::unmount_instance(instance_id) → remove from store.instances;
     if it is a region guest of a host, also clear that host.region_mounts entry.
   - Tool st_unmount{instance_id}; server action mcp_unmount (Audience::Server)
     resolved at the sink against event payload target.
   - Test: unmount removes the instance; a stage guest unmount clears
     region_mounts["stage"] (stage returns to empty-state). Live: mount, then
     unmount → stage empty.

S2. mcp_stage_clear action.  [live.rs, actions.rs, env.st]
   - Clear the originating host's region_mounts[region] (default "stage") +
     region_mount_input[region]. Server action; resolver arm; a "clear stage"
     glyph on the stage chrome (only visible when a guest is composed —
     CSS :has on the region, mirror existing reactive-class pattern).
   - Test: compose then clear → stage empty-state returns. Live-verify.

S3. mcp_env_close + mcp_fn_delete (+ tools st_env_close, st_fn_delete).
   [state.rs, live.rs, tools.rs, actions.rs]
   - WorkbenchSession::close_environment(env_id) → drop env + its tabs; refuse
     (clear message) if an env-origin function is currently mounted (or cascade-
     unmount — pick the conservative refuse-with-reason first).
   - Store::delete_function(fn_id) → refuse if mounted (point at unmount first).
   - Card buttons: env card gets a close (×) action; function/origin card gets a
     delete action. Both server-audience.
   - Tests: close env drops its tabs; delete refuses while mounted, succeeds
