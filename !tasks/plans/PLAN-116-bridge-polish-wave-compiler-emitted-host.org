** FUP-121 — Emit the LV host DOM skeleton from the Spacetime compiler
Deletes rot spot: ~Spacetime.LiveView.render_host/1~ hand-mirrors each page's
DOM skeleton, with an ~if @__root__ == ".board"~ per-page match arm that drifts
silently from the ~.st~ and grows one arm per page (closed-enum rot; violates
AGENTS "kinds-as-data" + bridge principle 6 "even the scaffolding comes from the
page").

Fix: the compiler already knows the page's static structure. Emit a
~skeleton.html~ artefact alongside ~spacetime.{js,css}~ at build time; have
~render_host/1~ read + ~Phoenix.HTML.raw~ it (still inside the
~phx-update="ignore"~ / ~phx-hook="SpacetimeBridge"~ wrapper). The
~if @__root__~ branch dies; every future page is zero-Elixir scaffolding.

Acceptance:
- `spacetime build board.st -o …` also writes `…/skeleton.html` (the static
  root subtree the bundle binds onto by selector).
- `render_host/1` has NO per-page branch; it injects the emitted skeleton.
- Board + counter render identically to today (byte-diff the served host HTML
  before/after is behaviourally equivalent — same selectors present).
- Couples to FEAT-138: the batch/watch build must emit this artefact too.

** FUP-132 — @flip visibly glides on @each re-renders (node identity investigation)
The demo's one broken promise: "other users' moves GLIDE on your screen". Sync +
toast + cursor work; the glide never visibly happens. On any ~$items~ write
(optimistic local projection OR remote assign diff) the moved ~.card~ is already
at its FINAL position with ~transform: none~ at the first 33ms sample — no
intermediate FLIP frames, ever, in a real browser. @flip's @clock headless test
(FEAT-161) passes and the DRAG path animates, so the gap is specifically keyed
~@each~ re-render vs FLIP node persistence.

Investigate (from the FUP):
1. Does keyed @each preserve node identity across source-array writes, or does
   it RECREATE the row node? FLIP needs a persistent node to measure First/Last.
2. Does @flip hook the signal write before/after the @each re-render, and does
   it see a persistent node?
3. RED→GREEN: a @clock test that writes a keyed @each source and asserts
   intermediate transform frames on the moved row (the missing coverage — the
   existing @clock test drove @flip on a subscribe path, not a keyed @each
   re-render with node reconciliation).

Acceptance:
- New @clock/@timeline test: RED before fix (asserts ≥1 intermediate transform
  frame on a keyed @each row after a source write; currently 0), GREEN after.
- Two-browser board: a remote move visibly glides (manual/CDP confirmation).
- Fix is in the renderer's @each reconciliation or @flip hook ordering — NOT a
  board.st-local hack.
