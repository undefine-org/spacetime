* Problem

Three legacy types/functions survive in src/metasystem/ after PLAN-001 unified the pipeline:

- =compile_macro_call()= + =DeclarationGraph= (compile.rs) — zero production callers, 6 test-only call sites
- =ExpandedDirectives= + =expand_macro()= (expand.rs) — zero production callers, test-only usage
- The pipeline Resolve layer returns =Ok(vec![])= for macros with =%states=, silently dropping their CSS+JS

These are dead code with live tests. The work is: port the missing =%states= codegen to the pipeline, add integration tests, delete the old paths.

* Key Findings

** What =compile_macro_call= generates for =%states=

Both CSS and JS:
- CSS: =selector[data-st-state="name"] { prop: val; }= via =generate_state_css()= (emit/metasystem_codegen.rs:805)
- JS: =ST.bindState(el, 'signal', 'state_name')= — hardcoded in compile.rs:812-815
- Pattern-match states also generate =generate_pattern_match_css()= and =generate_pattern_match_js()=

** Pipeline state

- =EvaluatedMatch.states= is already populated by Evaluate layer (evaluate.rs:136)
- =resolve_evaluated()= in resolve.rs never reads =ev.states= — it short-circuits to =Ok(vec![])= for states-only macros (resolve.rs:204)
- The Expand layer (pipeline/expand.rs) operates on =ResolvedPrimitive= — it has no concept of states

** Phase 1: Port =%states= codegen to pipeline

*** ITEM Wire states CSS+JS generation into compile_verbose
:PROPERTIES:
:EFFORT: 2h
:END:

In =pipeline/mod.rs::compile_verbose()=, after the Evaluate step:

1. Iterate =evaluated= matches. For each with =ev.states.is_some()= AND =ev.form_match.selector.is_some()=:
   - Extract each =MetaStateDecl= from =ev.states.states=
   - Generate CSS via =generate_state_css(selector, &state.name, &state.properties)= from emit/metasystem_codegen.rs
   - Generate JS: =ST.bindState(el, '{condition}', '{state_name}')= — wrap in JsFragment with appropriate scope
   - Push CssFragment (Raw) and JsFragment into the output collectors

2. For macros that have BOTH =%binds= and =%states= (like @drag), the resolve_evaluated path handles binds already; states CSS/JS is additive.

3. Remove the =Ok(vec![])= short-circuit in resolve.rs:204 for states-only macros — those macros may still have =%binds= or other primitives after evaluation.

Key decisions:
- States CSS/JS goes into =compile_verbose= directly (not a new layer) — it's a simple map from =MetaStatesClause= to fragments
- Use =generate_state_css()= from emit/metasystem_codegen.rs (already exists, tested)
- Pattern-match states (=condition.starts_with("match:")=) need =generate_pattern_match_css/js= too
