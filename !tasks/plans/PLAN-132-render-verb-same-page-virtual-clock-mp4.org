* D5 RULING — the render verb adds NO author-facing syntax

The thesis: a website and a video differ only in WHICH SIGNAL drives the
timeline. Therefore render CANNOT be a page-level construct — the page must not
know it is being rendered. The render clock is a substitution at the DRIVER
source, not a new score domain.

CLI surface:
  spacetime render <project|page> --out film.mp4 [--fps 60] [--width W --height H]

Mechanism (reuses src/cdp.rs — the SAME Chromium backend as `test --cdp`;
a second browser stack would violate AGENTS.md §2 one-need-one-impl):
1. Compile + serve the page exactly as `test --cdp` does.
2. Emulation.setVirtualTimePolicy(policy=pause) → the page's rAF/timers now
   advance ONLY when told.
3. Per frame: advance virtual time by exactly 1000/fps ms
   (setVirtualTimePolicy with budget), wait for rAF quiescence,
   Page.captureScreenshot → PNG bytes → ffmpeg stdin (image2pipe, -r fps).
4. Duration = the longest @score total on the page (data the compiler has).
5. ffmpeg muxes to h264 mp4. Audio lands later via the D4 filtergraph backend
   (ruled: one graph, two backends) — video-only first.

* GATES (the negative discipline applied to video)
- frame count: 2s fixture @ 10fps → ffprobe says exactly 20 frames / 2.0s
- MOTION: frame 0 vs frame 10 must differ — a FROZEN video must FAIL, exactly
  as a frozen page fails the CDP gates (BUG-252 doctrine)
- determinism: two renders of the same page → identical per-frame hashes
- discrimination: run the motion gate against a static page → it must fail
- thesis gate: render a fragment that ALSO runs under .time in the browser —
  one fragment, two clocks, zero page changes (P10's render half)

* Non-goals
- No new sigils, no @render, no render: keys in .st files
- No WebAudio render until the D4 audio graph lands
- No parallel screenshot stack outside src/cdp.rs
