* Thesis
Rich text is a missing INPUT primitive — the analogue of =@input= for =<input>=. Today
the admin uses =contenteditable= + deprecated =document.execCommand=. The Spacetime
version must be declarative, compositional, and AST-true (the editor edits a constrained
document AST; HTML is a projection; the server sanitizes against the registered
mark/block set, which IS the allowlist).

* Key design move (user-directed 2026-06-06)
Marks and blocks are ELEMENT-REF FUNCTIONS, not an opaque enum:
=&bold(&sel)= wraps the selection; =&link(&sel, &href)= wraps it AND takes an extra
EDITABLE argument (=&href=) surfaced as an inline editing affordance. A mark/block is
"a named transform over a selection that declares an AST node + a toolbar affordance +
an HTML projection" — i.e. a =&template= with a selection parameter. So @editable
composes from the same primitive everything else does; no special-case registry; the
sanitization allowlist falls out of the registered set for free (self-describing
metasystem discipline, AGENTS.md).

marks∪blocks; every attr ∈ that node's declared attrs."

* Design round 3 (2026-06-10) — marks ARE partially-applicable templates
USER CHALLENGE upheld: the round-2 decl-record body (node:/toolbar:/attr x <- &arg)
was a closed vocabulary one level up — re-encoded what a template body already
states, and the attr-projection DSL couldn't even say where children go.

NEW MODEL: a mark/block IS a template whose first param is the selection; the
template BODY is the projection. No projection DSL at all:
  @mark &bold(&sel) { <strong>&sel</strong> }
  @mark &link(&sel, $href: url) { shortcut: "mod+k"; <a href="$href">&sel</a> }
  @block &figure(&sel, $src: url, $alt: string) {
    <figure><img src="$src" alt="$alt"><figcaption>&sel</figcaption></figure> }

Two load-bearing principles:
1. TEMPLATE BODY = BIDIRECTIONAL LENS. Forward = render (invoke template).
   Backward = pattern-match (paste lift: html5ever tree matched against mark
   bodies). Compiler derives editable-schema.json from the body's HtmlExpr —
   which it ALREADY parses via treesink.rs. Invertibility statically checked:
   single root, attrs literal-or-single-hole, one &sel hole; non-invertible →
   excluded from paste lift (wave 2: explicit match clause).
2. CURRYING BOUNDARY = DATA/CONFIG BOUNDARY. At the @editable site,
   marks: &mention(source: $teammates) — bound params are projection-time
   CONTEXT (never persisted); FREE params are CONTENT attrs (persisted into the
   AST node, schema-validated, typed). Partial application decides what is data
   vs config.

Affordances from types: free param's TYPE dispatches its inline editing widget —
$href: url → url input; $ref: relation<Author> → admin's relation picker; same
type→widget mapping as the drawer (widget_for). `url` type makes javascript:
rejection a TYPE ERROR server-side (replaces richtext.rs scheme sniffing).
Template params gain type annotations (param_list already parses them for @fn —
small grammar extension).

Metadata shrinks to 2 optional meta lines in body head: shortcut: + toolbar {}.
@mark ≡ @template with a different registry (+ sel convention + invertibility
check + schema emission). @block same but multi-hole allowed: each &hole = a
nested editable region (figure caption, columns). Editor commands = signal
methods riding the existing signal_call capture: $doc.apply("bold"),
$doc.setBlock("h2") — custom toolbars are plain @each + @on click anywhere.

Advanced edge cases recorded: live-data marks (price/sku — AST stores sku,
projection binds live signal), animated marks (:entering in body, free from
template rail), &mention with reactive relation source, mark-combination render
order = registration priority over flat marks[] set.

** Architectural finding (grounds FEAT-103)
TWO grammar engines exist and have diverged:
- %capture_type → CapturePatternAst{Group,Choice,Sequence,CharClass,Capture}
  (meta_ast.rs:951) → compile_pattern (extractors/custom.rs) → token-cursor PEG.
  FULL PEG: groups, alternation, modifiers, recursion. `cb_nested_each` proves
  optional-literal-led-group + greedy-tail already works.
- %form → FormClause (flat: inline_elements/params/post_arg_inline/body_capture/
  body_params; meta_ast.rs:319) → try_match (form_compiler.rs) against CST nodes.
  WEAK: PseudoSelector/KeywordBlock are hardcoded special-cases; no general group.
∴ FEAT-103 = route the %form BODY region through the CapturePatternAst PEG that
already exists, instead of bolting Group onto FormClause. One need → one impl.
Removes the body_capture-string + pseudo-selector divergence (net simplification).

** Resolution efficiency (answers the open question)
Groups are INTRA-form (ordered-choice within one form's match), NOT expanded into
sibling forms. Cross-form resolution UNCHANGED: prefix bucket O(1) → static
specificity sort → first-match-wins (registry.rs:56, form_compiler.rs:3872).
- optional-absent group contributes FLOOR (0) to specificity → a form cannot win
  resolution by claiming optional content it didn't match.
- the "multiple macro versions" pattern COLLAPSES: @fn($p)(: $rt)?{} = ONE form,
  not two ranked siblings → fewer forms per bucket → resolution gets cheaper.
- determinism via literal-led discipline: optional groups MUST be literal-led
  (the `shortcut`/`,`/`key` anchor), same rule already documented in
  component-body.st ("BOUNDED leaf types before a literal").
