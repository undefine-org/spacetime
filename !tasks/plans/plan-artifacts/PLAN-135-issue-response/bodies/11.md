**Confirmed and staying open** — this one is deliberate, and I want to explain why rather than leave it looking neglected.

Reproduced just now. Build-time output for `@each` with a filter pipe:

```html
<li><span data-st-hole="0"></span> | uppercase</li>
```

The filter leaks into the page as literal text. The runtime bundle *does* know `uppercase` — so the same list is correct once JavaScript runs, and wrong in view-source.

**The tension worth understanding.** Spacetime renders a static list **twice**:

1. **At build time**, so the HTML in view-source is real content — good for SEO, and it works with JavaScript disabled.
2. **At runtime**, so the same list can react to data changes.

Filters like `| uppercase` are defined in **stdlib, written in Spacetime** — not in the compiler. The runtime can apply them because the runtime evaluates Spacetime. The build-time unroller can't, because it has its own small interpolation path that knows how to substitute a value but not how to evaluate a stdlib construct.

**There are two ways out, and only one is permitted.** Re-implementing the filters in the compiler would be fast and wrong: a standing project rule says the compiler never re-implements a construct that stdlib defines in Spacetime. The moment two implementations of `uppercase` exist, they begin to drift, and the metasystem stops being self-describing. (This backlog contains four separate bugs that are all that same mistake — see #28, where the editor kept its own copy of the macro registry.)

So the correct fix is to give the build-time path a real seam for evaluating stdlib filters — the same evaluation the runtime performs, hosted at build time. That's a genuine piece of work rather than a patch, which is why it hasn't been rushed.

**In the meantime**, the practical workaround: apply the transformation in your data rather than the template, or accept the runtime-only rendering if SEO isn't load-bearing for that list. I'd rather give you an honest workaround than a compiler shortcut we'd be unpicking in six months.
