**Fixed — closing.**

`$user object: { name: "Ada" };` no longer vanishes silently — the initializer is diagnosed rather than dropped.

**Your fix direction was right, and worth restating as a principle:** don't add a local-state-specific parser in Rust. The stdlib form already declares `$value:expr`, so the question was never "how do we parse objects here". It was **"why does the expression capture stop early, and why is stopping early treated as success?"**

That second half is the real bug, and it was shared with #37 and #36 — three issues, one defect. A capture that consumes *part* of its input and leaves the rest was treated as a match.

The rule that fixes all three: **a bounded region must be fully consumed, or the match fails with a diagnostic.** With that in place, your case either parses properly or fails loudly. Either is fine. Silence was not.

This also connects to a project rule worth knowing if you contribute here: Rust never re-implements a construct that stdlib defines in Spacetime. When a stdlib pattern seems not to work, the fix is in the pattern or the machinery that loads it — never a hardcoded Rust fallback. The metasystem is meant to be self-describing, and a Rust shortcut is how that stops being true.
