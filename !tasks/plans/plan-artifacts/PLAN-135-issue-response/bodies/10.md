Verified with `tests/repro/gh-10-template-each-twice/`: a template containing `@each`, invoked twice on one page, renders all 3 rows in **both** instances.

**Why this class of bug happens**, because the shape recurs: a template invocation is not a copy of markup. It's an *instance*, with its own scope. Anything cached per-template instead of per-instance produces exactly your symptom — the second invocation checks the cache, concludes the work is already done, and renders nothing.

When you hit something like this again, the diagnostic question is always the same: **what key is this cache using, and does that key distinguish the two things I can see on screen?** If the key is "the template" and the screen shows two instances of it, you've found the bug.

**Related but separate:** the build-time version of this is #11, which is still open. Static unrolling at compile time runs through a different evaluation path than the runtime, and that path can't yet apply filter pipes. Details are in that issue.
