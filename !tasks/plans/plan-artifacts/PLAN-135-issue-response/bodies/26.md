**Fixed — closing.**

`check` now emits `E0408` for an undefined signal. The analysis is wired into the check chain, where before it was never called.

**Why this tiny fix mattered a lot.** Spacetime's reactive lookups resolve **by name at runtime**, walking up from the node. That's what makes signals composable — a template doesn't need to know where its data comes from, so you can drop it anywhere and it finds its context.

The tradeoff is that a typo can't fail at runtime either. It resolves to nothing and renders empty. **The compiler is the only place in the entire system that can catch it** — and the analysis to do so existed, was correct, and was unreachable.

**The structural repair, not just the wiring.** There is now a test asserting that every public `analyze_*` function has a production caller. An analysis with no caller is indistinguishable from a missing feature, and now the build says so.

That check is the generalization of your issue: you found one orphaned analysis; the test makes orphaned analyses impossible to add.

This shipped with #27 and #34 as one "make `check` honest" change, because all three were the same failure — diagnostics that exist and never reach you.
