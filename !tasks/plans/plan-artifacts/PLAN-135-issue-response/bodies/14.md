**Fixed — closing.**

`@object torusknot(size: 1.2)` now produces `error[E0946]` instead of compiling clean and emitting the default icosahedron. The canonical form `@object(shape: "torusknot", …)` compiles and emits a torus knot.

**Two lessons, and the second one is the root cause.**

**1. A form either matches your call, or it doesn't.** When it doesn't, every capture keeps its default — so if nothing complains you get a *plausible* result rather than an error. That is the worst possible failure mode, because it looks like it worked. You asked for a torus knot and got a sphere-ish blob, with a clean build and no output to grep.

**2. The docs described a grammar that was never implemented.** `@object`'s documentation taught `@object <shape>(…)` — shape as a leading keyword. The macro's actual grammar was named-arguments-only. The docs weren't describing a broken feature; they were describing a feature that never existed, and the silent-default behavior is what let that go unnoticed for so long.

Doc examples are only as trustworthy as the last time someone compiled them. The examples are rewritten to the real form, and I compiled them to check. Spacetime has a better answer for this — literate `.st.md` files, and `@doc(src:)`, where the example **is** the program and a lie fails the build — and stdlib doc examples should migrate there.

**The structural fix is the interesting part.** A first attempt at this was reverted, because tightening the rule broke a legacy shape that a retired macro relied on. The real fix makes the tolerance **declared data** rather than an inference: a macro now carries its `%drops` — the arguments it deliberately accepts and discards — and the matcher consults that declaration instead of guessing from token positions.

One rule, both cases: a retired shape that declares its drop keeps working; an undeclared extra argument is refused. No per-macro special case in the compiler.

**A finding worth passing on**, since it's the kind of thing that hides for years: the `%drops` that justified the old behavior turned out to live on the *migration rewrite*, not on the macro. So the bareword form was never declared anywhere — it survived purely on an accidental tolerance, and a single test was pinning it. Nothing anyone had written actually used it.
