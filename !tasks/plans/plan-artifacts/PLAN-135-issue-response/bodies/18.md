**Fixed — closing.**

`@reveal`'s custom keyframes body now reaches the engine and appears in the emitted output.

**The anatomy, because it generalizes to every macro in the language.** A macro has two halves:

```spacetime
%form  { @reveal(…) { $body:keyframes } }   // what the author may write
%binds { reveal-engine(&self, …) -> { } }   // what gets handed to the primitive
```

`%form` **captured** `$body`. `%binds` never passed it on. Parsing succeeded, so nothing complained — but a capture with no consumer is a promise the compiler doesn't keep.

The immediate cause was narrower and more interesting than it sounds: the code that decides what starts a selector didn't recognise `&` (the self-reference used inside keyframes), so the body was captured and then quietly discarded downstream.

**The structural fix, which is the real answer.** Rather than wiring up this one macro, there is now a lint requiring that **every** `%form` capture is either consumed in `%binds`/`%emit`, or explicitly declared as dropped. That turns a whole genus of silent half-features into build errors, and it was cheap because the information was already in the registry.

Running it across stdlib found **79 violations**, now driven to zero. Some were fixed; 30 were genuine "declared but deliberately unused" cases which now say so in the source; and the remainder were real dropped-capture bugs of exactly your kind — including `@breakpoint`, `@dark-mode` and `@media-query` all silently discarding their `$children`. Every one of those is recorded rather than quietly patched.

Your issue was one instance. The rule it produced closes the category.
