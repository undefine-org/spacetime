**Fixed — closing.**

Your report was that a directive written inside HTML markup produces nothing: zero primitives, zero JS, zero CSS, no diagnostic — and inside a fixture its raw source text renders as page content. Confirmed, and it now produces `error[E0900]` naming the shape, with a hint showing the rewrite.

**The mental model, since this is one of the first things that trips people up.** A `.st` file has two kinds of region, and they are not interchangeable:

```spacetime
<div class="hero">…</div>        // markup — literally what ships as HTML

.hero { @on &.scroll(…) { … } }  // selector scope — behavior attached to matching elements
```

Markup describes what the page **is**. A selector scope describes what elements **do**.

Directives bind through selectors, never through nesting, and there's a concrete reason: a directive must be able to attach to elements that don't exist yet — a row rendered later by `@each`, a fragment spliced in at runtime. Nesting can only describe what is already there, so it cannot express the common case.

So the shape you wrote is unsupported by design. But "unsupported" must never mean "silently ignored", and that was the actual bug. It now names the shape and shows you the selector-scope form.

**How it got fixed structurally.** Rather than special-casing this one shape, the compiler now requires that every construct either binds to something or produces a diagnostic. This was one of two rules landed together; the other (`E0964`) requires every captured value in a macro to have a consumer. Same principle from two directions: nothing in the pipeline is allowed to silently evaporate.
