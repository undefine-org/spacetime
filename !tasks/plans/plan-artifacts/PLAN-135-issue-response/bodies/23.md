Your report: a non-matching descendant rule causes **every macro after it in the file** to be dropped, with `check` passing throughout. Reproduced end to end, fixed, and gated by both a behavioral test and three parser-level tests.

**The actual mechanism was narrower and more interesting than the diagnosis.** When the parser saw `body:hover`, it had to decide between two readings:

- an element scope block — `body` with a `:hover` state, containing rules
- a CSS property — `body:` with the value `hover`

It used a two-token lookahead (identifier, then colon) and picked **property**. And a CSS property's value runs to the end of the declaration — so everything after it in the file became part of that value. Your 2100-line stylesheet didn't lose 20 directives to a scoping failure; it fed them to a property parser as text.

**The tell, for next time:** the body parser already had a guard for exactly this (`is_element_scope_block`) and got it right. Only the root path diverged. **When two code paths answer the same question, the one used less often is where the bug lives** — it gets less traffic, so it gets less correction.

**Why this was first in the queue** — not because it was the most interesting, but because its blast radius is "everything below this line", with every gate green. Two features gone, a passing build, and no way to tell. That combination is the worst thing a compiler can do to you.
