* Goal
Bring `@data subscribe` to PARITY with every sibling `@data` kind: accept an
optional `$type:typeref?` and seed a non-null initial value, so:
  - a subscribed signal can be TYPED (kills the decorative `@type` / W0203),
  - nested reads (`$form.errors.email`) are TOTAL, not guarded by try/catch
    against a null seed,
  - local patterns that need a well-shaped object before the first server diff
    (the forms `@field` values pattern, FUP-142 Finding B) work from mount.

This is the KEYSTONE for the forms vertical (FUP-142) and benefits EVERY
subscriber, not just forms.

* Verified facts (from agent://0-SubscribeInternals + my own probes)
- Grammar is self-hosted in stdlib. Adding `$type:typeref?` to subscribe's
  `%form` is a STDLIB edit; the Rust parser (src/parser/mod.rs ~6535-6624) maps
  `typeref` + `?`-optional GENERICALLY — no Rust special-case for subscribe.
- Current subscribe form: data-kind.st L538-556:
    %form { @data subscribe $name:binding from $host:binding : $assign:ident ; }
    %binds { local-state-impl(name: $name, initial: null) -> { $state as $name }
             signal-subscribe(name: $name, host: $host, assign: $assign) }
    %registers binding($name) { … NO type arg … }
- local-state-impl (stdlib/syntax/local-state.st) seeds
  `window._localState[name] = initial` and dispatches `local:<name>:updated`.
- signal-subscribe (stdlib/primitives/signal.st L581+) writes every bridge value
  through `window.SpacetimeLocal[target]` and REPLAYS an already-present assign.
  ∴ a non-null seed is SAFELY overwritten by the first server diff — seed is just
  the pre-first-diff value. No reconciler change needed.
- No typeref→zero-value machinery exists today (TypeRegistry in src/type_system.rs
  stores fields but exposes no per-type default synthesiser). ∴ automatic
  zero-value-from-type is OUT of the minimal scope → the seed is EXPLICIT.
- REGRESSION RISK (my probe): the CURRENT grammar SILENTLY DEGRADES a subscribe
  whose shape doesn't match — `@data subscribe $form Env from $h : form ;` today
  does NOT match subscribe (extra token before `from`) and falls through to a
  PLAIN LOCAL (no `__stLiveSubscriptions` emitted), passing check with no error.
  Baseline confirmed: `@data subscribe $form from $h : form ;` emits 3×
  `__stLiveSubscriptions`; the typed-but-unslotted variant emits 0. ∴ the fix
  MUST make `$form Env from …` MATCH subscribe (real subscription + type),
  and a test must assert the subscription is still emitted (guard the degrade).

* Design decision — seed grammar (RESOLVED)
Two shapes considered:
  A. type-only, derive zero-value from the type → needs NEW Rust (zero-value
     synthesiser). REJECTED for minimal scope (no such machinery; violates
     "smallest correct change").
  B. explicit optional seed tail → PURE STDLIB, mirrors @data inline's `: value`.
     CHOSEN.
Chosen surface (mirrors sibling optionality; `:` stays the assign selector, seed
rides an optional `=` tail like param-defaults elsewhere):
    @data subscribe $name:binding $type:typeref? from $host:binding : $assign:ident ( = $seed:balanced(';') )? ;
Examples:
    @data subscribe $count from $counter : count ;                 // unchanged, seed defaults
    @data subscribe $count number from $counter : count ;          // typed, default seed
    @data subscribe $form FormEnvelope from $auth : form = { "values": {}, "errors": {}, "valid": false } ;  // typed + explicit seed
Default seed when `= …` omitted: keep BACKWARD-COMPAT — if no seed AND no type,
seed stays `null` (existing behaviour, so all existing pages are byte-stable). If
a seed is given, use it. (Type-driven default deferred to a follow-up with the
zero-value machinery.)
NB the `( = $seed )?` optional-group tail must be validated to PARSE in a %form;
if the balanced-capture optional-group tail is unsupported there, fall back to a
separate macro variant (specificity-ordered, like host-http vs host-http-opts) —
decide during W1 with a spike.

** What WORKS (verified by build + emitted-JS inspection, in scratch/fup144/)
- Untyped bodyless: `@data subscribe $count from $h : count ;` — unchanged, real
  subscription (3× __stLiveSubscriptions on board.st; 2 on counter.st). Byte-stable.
- Typed bodyless: `@data subscribe $count number from $h : count ;` — real
  subscription, type registered. (Fixes the silent-degrade: pre-fix, a token
  between $name and `from` fell through to a plain local; now it MATCHES.)
- Scalar seed: `@data subscribe $count number from $h : count { initial: 0; }`
  → `_localState["count"] = 0` + real subscription. CLEAN.
- One-level object seed: `{ initial: { "email": "", "valid": false }; }` — works.

** What does NOT work — nested-object seeds (SCOPED OUT, pre-existing limitation)
- Two-level seed `{ initial: { "errors": { "x": "" } }; }` → PARSE ERROR
  ("expected scope block, directive, or declaration").
- ROOT CAUSE: `initial: $seed:balanced(';')` uses the shared BalancedExtractor.
  A nested `{...}` VALUE is pre-split by the directive grammar into a child BODY
  node, so it's missing from the flat inline token slice; `scan_end` (bounded by
  the last slice token) stops before the nested content and the balance never
  closes. This is NOT introduced by FUP-144 — the SAME failure reproduces in the
  EXISTING `@data fetch … { initial: { "a": { "b": "" } }; }`. Same family as
  BUG-228 (object-literal parsing in @data seeds).
- Seed-by-reference (`initial: $someInlineSignal;`) also does NOT resolve — emits
  the literal string "$someInlineSignal". The seed is a literal expr, no signal
  interpolation. (Documented; not a regression.)

** SCOPING DECISION
W1 ships type-slot + scalar/one-level-object seed (real, tested value). Nested
object seeds are BLOCKED on the BalancedExtractor/BUG-228 limitation → filed
against BUG-228 (updated to note it also blocks nested subscribe/fetch seeds),
deferred. Forms impact: the envelope's nested `errors`/`values` can't be seeded
directly, BUT the `@field-error` reader already GUARDS a missing `.errors`
(`errs && typeof errs === 'object'`), and the `values` object is a separate
`@data inline` (one-level, seedable). So forms are unblocked for the common path;
the nested seed is a nice-to-have gated on the parser fix.
