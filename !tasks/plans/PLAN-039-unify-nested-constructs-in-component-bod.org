* Root cause (one mechanism, three symptoms)
A component body is parsed by reify_component_body (src/syntax/events/form_compiler.rs:2261):
  1. segment_component_body splits body into HTML runs vs CONSTRUCT segments;
  2. each construct segment is classified by the stdlib `component_item` Choice
     (stdlib/capture-types/component-body.st);
  3. a small reify_* adapter maps the matched branch into the typed ComponentBodyDef IR.
The `component_item` Choice enumerates only the KNOWN constructs (state, exports, toggle,
@on, @match, selector_ref, css block, template_ref). A nested @editable/@richtext/@each
matches NO arm → falls to reify's `None`/`is_directive` branch → SILENTLY DROPPED (`// drop
(parity)`). Anything that leaks into body.html is then rendered literally by the reactive
builder (component_html_to_exprs, which sees only the html string).

THREE divergent nested-construct handlers exist today (the rot):
  (i)   cb_nested_each grammar — ONLY inside cb_selector_ref blocks, not top-level body;
  (ii)  src/html/ssg_unroll.rs find_nested_each/expand_nested_each — a HAND-ROLLED @each

  (iii) the silent-drop fallthrough in reify_component_body for everything else.
