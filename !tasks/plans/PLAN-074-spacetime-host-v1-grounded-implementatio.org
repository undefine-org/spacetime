* Key decisions

1. push-online reuse is THIN, not wholesale: only Project/Domain struct
   shapes, the tar-entry validation loop (retargeted to write to R2
   instead of local disk), the SQLite schema shape (trimmed), and the
   SslStatus/CreateCustomHostnameRequest TYPES survive. Auth, serving
   (serve.rs/host_router.rs/DomainCache), the local-disk write path, and
   the Cloudflare API calling code are either dropped or built net-new.
2. Media is a first-class two-lane design: R2 for site bytes (HTML/CSS/
   JS), Cloudflare Images for photos, Cloudflare Stream for video --
   NEVER routed through the routing Worker (spacetime-host-edge), fully
   offloaded to Cloudflare's specialized CDNs for those content types.
3. Video is recommended as a v1 LAUNCH feature, not deferred -- Stream's
   free ingress/encoding removes the actual cost/complexity blocker that
   justified deferring it in the original ask.
4. Accounts/auth is minimal-viable for v1: magic-link email + CLI
   session-code polling handoff (not full OAuth/device-flow against a
   third-party IdP) -- sized as real but small work, explicitly flagged
   as a new wave (Wave 1) since it has zero prior art.
5. Cloudflare-for-SaaS custom-hostname API calling code must be written
   net-new (Wave 4) -- push-online's version is a stub, not a working
   integration, despite earlier assumption it could be forked wholesale.
