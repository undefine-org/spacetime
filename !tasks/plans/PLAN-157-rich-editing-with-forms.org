* Decisions

** D1 · No mark construct. A mark is a form whose SIGNATURE wraps text.
=@form markup --accent(&sel) { <mark class="accent">`&sel`</mark> }= is a mark
because of its shape, read like a type: exactly one content slot, every other
param a typed scalar, one root of HTML phrasing content holding the slot once.
No kind word (=mark= would be about the tool, not the thing), no annotation to
BE a mark. Arity also explains blocks without a kind:

| slots | root | what an editor can do |
|---|---|---|
| 1 | phrasing (strong, em, a, mark, span…) | wrap a selection — the bar |
| 1 | flow (p, h2, blockquote, div…) | turn a block into it — « Turn into » |
| ≥2, or =&items[]= | flow | insert it, then edit each region |

** D2 · Presentation is inferred, then =@cms= overrides — as for types
The CMS already works this way: a scalar row says what a type MEANS
(=%widget=), =widget_for= infers declaration > value > name, and =@cms(Type)=
only overrides display roles (no runtime, optional). For forms:
label from the name, doc from =///=, icon from the initial, each param's
control from its scalar row (=url= → media, =color= → colour); then

#+begin_src st
@cms(--accent) { icon: "✦"; shortcut: "mod+e"; }
#+end_src

The same macro and meaning, keyed by a form. (No =@offer=: no new semantic.)

** D3 · The standard marks are ordinary forms in the stdlib
=stdlib/editable/marks.st=: =--bold= =--italic= =--strike= =--code= =--link($href url)=,
each with its =@cms=. A page's own form wins by name. Nothing about bold lives
in Rust.

** D4 · Prose writes a mark in its own syntax, from ONE table
A mark whose projection is a bare element prose can write is written that way
(=**x**=, =/x/=, =[x](href)=, =[[href][x]]=); otherwise Markdown takes the markup
and Org refuses. The table is the renderer's: =literate::ORG_MARKS= is what the
Org reader reads (=emphasis()= uses it), =MD_MARKS= mirrors the vendored
snarkdown. Writers read it backwards, so writing and reading cannot disagree
(the studio once wrote Org underline as =_x_=, which the reader leaves literal).

** D5 · Edit what the AUTHOR wrote (the authored-content contract)
A primitive that rebuilds its host's children hands them back:
=host.__stAuthored = { nodes, skip, project }=. =@reveal= does. The canvas
selects the host, edits the author's nodes, the primitive rebuilds from them.

** D6 · The text NAMES the form: =<--accent>software</--accent>= (decided: B)
Today the editor writes the form's EXPANSION (=<mark class="accent">…</mark>=),
and recognises it back by tag and classes: change =--accent= later and old
phrases don't follow. Forms keep their name in source everywhere else
(=--role-shout;=). The fix is an inline call in text, per host language:

| host | reference | the language's own |
|---|---|---|
| =.st= markup | =`--accent { software }`= (one hole, a body-slot call) | =<strong>= … |
| Markdown prose | =:accent[software]= (CommonMark generic directive) | =**x**= … |
| Org prose | ={{{accent(software)}}}= (Org's own macro) | =*x*= … |

Decided (2026-11-09): *B*, the form as an element, in markup and in Markdown
prose alike (=<--link href="/who">Me</--link>=). It nests like HTML, params are
attributes, and the sigil after =<= says what it is: =<--x>= a form, and later
=<&x>= a template (identity, behaviour), which is the inline template call
markup lacks (BUG-130's territory). Org prose waits. The rejected options:
a hole with a body (=`--accent { x }`=: nesting needs balanced backticks), the
form named on a real element (=<mark --accent>=: the tag written twice), and
prose-only syntaxes (=[x]{--accent}=, =:accent[x]=, ={{{accent(x)}}}=).

* How it fits PLAN-156 (reflect, rewrite, widgets)
PLAN-156 deletes =src/studio/= for two dev-server facilities: *reflect* (one typed
projection with spans, docs, registry entries) and *rewrite* (one guarded
writer, re-parse, undo). Everything here lands on them:
- « which forms wrap text » is a query over reflect's =form= registry entries
  (params with types, the body's root with its span), not =src/studio/marks.rs=;
  the phrasing/flow content model becomes a stdlib table.
- =mark= / =unmark= are rewrite transactions (address, expected text, words).
- A param's control is PLAN-156's widget for its scalar row (=&w-text=,
  =&w-color=, =&w-asset=), the same in the bar, the inspector and the admin.
- =@cms= display hints are what reflect returns next to a declaration's docs.
