* Intention & Purpose

Make Spacetime's registries — every sigil-space — addressable, introspectable,
and build-optimisable through ONE reference grammar that the language already
half-implements.

The driving case: *define =$host= in one file, use it across the app*, with the
compiler able to (a) const-fold it when it is never written, (b) eliminate it
when never read, (c) show its provenance in =inspect=, and (d) REFUSE the
program when two files declare it ambiguously.

The governing principle (now in AGENTS.md): *the language must be learnable by
pattern — knowing one thing should tell you the next.* Today =@b/badge= works
and =$b/host= does not. That gap is the whole plan.

** The design in one table

| axis        | meaning                                  | phase        |
|-------------+------------------------------------------+--------------|
| sigil       | WHICH registry (=@= =%= =$= =&=)         | selects      |
| =/=         | address WITHIN the registry              | compile-time |
| =:=         | collection prefix, INSIDE an import string only | compile-time |
| =.=         | descent INTO the resolved thing          | runtime      |

Reference forms, one shape per registry:

#+begin_src spacetime
@3d/stage          %3d/env-form        app/$host         app/&rail
@stage             %env-form           $host             &rail          /* bare */
#+end_src

The sigil ALWAYS hugs its leaf. =@=/=%= already lead their path because their
leaf IS the whole invocation (=@scene/camera= is one name); =$=/=&= are
referents, so the qualifier sits in FRONT and the sigil stays glued to the cell
it names: =app/$host=.

** Why =:= never enters reference position

=:= carries SIX live roles in expression zone (verified counts):

| role                        | evidence                            |
|-----------------------------+-------------------------------------|
| CSS declaration             | ubiquitous                          |
| CSS pseudo =:hover= =::before= | 181 lines (stdlib+demos)         |
| value-introducer            | =$open bool: false=, =@data inline $x : 3= |
| *meta capture type*         | =$preset:string= — *618 lines*      |
| macro named args            | =@env(preset: studio)=              |
| ternary                     | =a ? b : c=                         |

Collection prefixes survive ONLY because they appear inside a quoted import
string — a sealed lexical zone. Verified: exactly 2 occurrences of =coll:= in
the whole repo, both inside doc-comments; ZERO real uses. Normative rule:

#+begin_quote
=:= appears only inside a module address, and a module address appears only
inside a quoted import string. =as= collapses the long key for everything else.
#+end_quote

∴ =local:config/$session= is NOT a supported reference. Write
=@use "local:config" as app= then =app/$host=.

** Namespace expansion works in four stages, and is ALREADY sigil-agnostic

1. *Lex/parse* — =src/syntax/cst/parser.rs:636-652=. The qualifier is glued into
   the directive head by a *tight-adjacency* loop: consume =/IDENT= segments
   ONLY when no trivia surrounds the =/=. =src/syntax/cst/ast.rs:283= enforces
   the mirror: "Trivia ends the name run (a spaced =/= is NOT a qualifier)."
2. *Form matching* — =src/syntax/events/form_compiler.rs:379-398=.
   =match_directive_prefix= skips the =qualifier/= prefix so the LEAF matches the
   =%form=, and RETURNS the qualifier into =FormMatch.namespace_qualifier=.
3. *Canonicalize* — =src/pipeline/mod.rs:2878-2896=.
   =ImportScope::resolve_qualifier= rewrites alias → namespace key
   (=[b]= → =[./badge]=). Handles alias AND literal path-suffix.
4. *Lookup* — FQN-first (=./badge/badge=), falling back to the bare name.

*The sigil is consumed at stage 1 as =AT_SIGN= and never participates in
resolution.* Stages 2–4 operate on a sigil-less path + leaf. This is why
extending to =$= is cheap: only stage 1 needs a new production.

* Notes

- Reversal on the record: the sigil-hug rule was briefly abandoned in favour of
  =$app/host= (sigil leads, matching =@=). Reverted — =$app= is a valid OPERAND
  (=@app= is not), so a leading =$= makes =/= genuinely ambiguous with division.
  Putting the qualifier in FRONT (=app/$host=) keeps the sigil on its leaf AND
  makes the =/$= sequence unambiguous, because =$= never begins a divisor.
- =app.$host= was also evaluated and rejected: =.= in expression position already
  heads live bare-ident member access — verified
  =@data fold $t from $cart : acc + (item.price * item.qty)=, where =acc= and
  =item= occupy exactly that space.
- Flooding is CORRECT for grammar and WRONG for addresses. A module can change
  what a file's language IS (=$preset:string= inside a =%form= has no head to
  qualify — the parser is matching bytes while still deciding what they mean).
  That is a dialect being spoken, not a scope being polluted. Cells are
  addresses; grammar is dialect. =@use= borrows a dialect; =$= binds by name.

** The verdict model

Three verdicts, decided per page-global cell from readers/writers/initial:

| verdict | condition | W4 action |
|---------+-----------+-----------|
| =const= | no writers AND literal initial | inline at every read, emit no cell |
| =reactive= | has a writer, or a computed initial | stays a live cell |
| =dead= | no readers | emit nothing |

Sound because Spacetime has NO custom JavaScript: no =eval=, no foreign call, no
escape hatch, so a cell's write-set is CLOSED and a whole-page scan settles it.
This is the optimisation a general-purpose language cannot make.

Deliberate conservatism: an EXPRESSION initial (=$b: $a + 1=) stays =reactive=
even with zero writers, because folding it would mean evaluating arbitrary
expressions at build time. Only literals fold.
