* Steps (each = a bug, smallest shipped-primitive + glue; mostly independent)

** S1 — BUG-113: seed mount input into the composed region.  [src/mcp/tools.rs, src/mcp/live.rs]
Thread `input` through the compose path so a guest mounts WITH its values.
- live.rs::mount_into_host: add an `input: &Value` (or HashMap<String,String>)
  param; before inserting region_mounts, write
  host.region_mount_input.entry(region).or_default() with the input's string
  fields (mirror the mcp_param write at L1232). Coerce JSON values to strings the
  same way the bundle seed expects (region_mount_input is HashMap<String,HashMap<String,String>>).
- tools.rs::st_mount: in the `if let Some(host_id)` branch, pass the already-parsed
  `input` into mount_into_host.
- Test: live.rs unit — mount_into_host with input seeds region_mount_input; the
  bundle endpoint then returns it. Acceptance (live): st_mount name=greeter2
  host=inst-1 region=stage input={"name":"World"} → stage shows "Hello, World".
  (greeter2 MUST declare the param in the template signature: `&main($name string = "")`.)

** S2 — BUG-118: cache the compiled region bundle per (function_id, revision).  [src/mcp/live.rs, src/mcp/bundle.rs]
Stop recompiling guest source on every 1s /bundles poll.
- Add a cache: either a field on FunctionRecord (Option<CachedBundle> invalidated
  on revision bump in update_source/put) OR a Store-level HashMap<(fn_id,rev), Bundle-json>.
  Prefer caching on FunctionRecord (revision is the natural key; update_source
  already rebuilds html/js/css there — extend it to stash the region bundle too).
- instance_bundles: look up cache by (target_fid, function.revision); compile only
  on miss, then store. region_input merge stays per-request (cheap).
- Verify compile is NOT held under the Store mutex longer than needed.
- Test: instance_bundles for an unchanged function compiles AT MOST once across N
  polls. Acceptance (live): sustained 1Hz workbench polling holds CPU near idle,
  HTTP responsive over a multi-minute session.

** S3 — BUG-114: source editor only edits on INTENT.  [stdlib/__mcp__/workbench/*, env.st]
Stop the hydration-set textarea value from dispatching mcp_source_edit.
- Cleanest: replace `on:"change"` auto-dispatch with an explicit SAVE affordance —
  a "save source" button (@mcp-action click) reading the textarea value — so merely
  selecting/inspecting never writes. Keep the textarea `text: $mcpStageSource`
  binding for display.
- If keeping change-dispatch: add a dirty-guard in the source-edit path (skip when
  the new value equals the loaded $mcpStageSource). The explicit button is preferred
  (removes ambiguity; one obvious gesture).
- Test/Acceptance (live): select a stage guest, open inspector, wait 3 polls → the
  guest source + revision are UNCHANGED (no spurious mcp_source_edit in the event
  log). Editing + clicking save DOES recompile + bump.

** S4 — BUG-115: scope the inspector contract list (no host internals).  [src/mcp/live.rs]
- Minimal: in workbench_snapshot, exclude mcp-workbench from the `functions` slice
  feeding contract_params (same filter the gallery uses at L327-330).
- Preferred (more Figma-true): the inspector's primary contract view binds the
  SELECTED frame (stage_mount.contract_params already exists); keep "all contracts"
  but exclude the host. Do the minimal exclusion first; the selected-frame emphasis
  is already wired (M3'), so this is a one-line filter + maybe a label tweak.
- Test: workbench_snapshot.contract_params contains no template whose function is
  mcp-workbench. Acceptance (live): inspector ALL CONTRACTS shows only user fns.

** S5 — BUG-116: standalone template-only mount renders its main template.  [src/mcp/live.rs]
- instance_page: when the function's page html is empty but its bundle has a `main`
  template, emit a region root the runtime can mount into — i.e. give the standalone
  page the SAME region-root + bundle-poll/@view wiring the host stage has, OR
  server-render an invocation of `&main()`. Decide by reading how the host stage
  mounts (env.st @mcp-region @view $stageTpl) and reusing that minimal shell for a
  standalone instance.
- Edge: a function WITH file-scope html keeps current behaviour (render html). Only
  the template-only case needs the shell.
- Test/Acceptance (live): st_mount source="@template &main(){ <button ...>Approve</button> }"
  agent_control=true → the page renders the button; clicking it emits an event that
  st_await drains.
