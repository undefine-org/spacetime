** Genuine gap found (not a reviewer catch this time — found during the implementer's OWN verification, exactly as the discipline intends)

All 5 `@pose-track`s silently bound to the SAME last-created object
(`canvas._stObject`) instead of their own sibling `@object`. Root cause,
confirmed via `inspect --layer emit`: **the compiler emits sibling
primitives grouped by TYPE, not interleaved author source order** — a
`@stage` with N `@object`+`@pose-track` pairs compiles to ALL N
`three-object` init blocks FIRST, then ALL N `three-pose-track` init blocks
after (confirmed by grepping the emitted bundle's `console.warn` markers by
primitive name). `canvas._stObject` (a single "most recently created" slot —
`three-object.st`'s own documented design, built for ONE hero object + a
behavior like `@orbit` acting on it, NEVER for N independent object+behavior
PAIRS) is therefore the wrong mechanism once a scene has more than one
object each needing its own pose-track — every zellijist-2 tile avoided this
because they're built inside ONE primitive's own loop (never relying on
`_stObject` across multiple `@object` calls), and Wave 3's own tests only
ever used a single object, so this gap was invisible until Wave 5's
genuinely-different scene shape exercised it — exactly what a second-
consumer proof is FOR.

** Fix

Added an explicit `objectIndex: number = -1` param to `three-pose-track.st`
+ the `@pose-track` macro — indexes into `canvas._stObjects` (the append-
ordered array, populated in CREATION order regardless of the init-grouping
quirk, since each `@object`'s own init still completes before any
`@pose-track`'s init runs in a scene). Default `-1` preserves the ORIGINAL
single-object behavior (`canvas._stObject`) unchanged for the common case —
zero behavior change for Wave 3's own shipped tests. New regression test
(`stdlib/3d/tests/pose-track-multi.test.st`, 2 tests): proves `objectIndex`
resolves each pose-track to its own DISTINCT object (checked via
`geometry.type` — box vs sphere) and that the default `-1` still works for
the single-object case. 3/3 CDP runs green.
