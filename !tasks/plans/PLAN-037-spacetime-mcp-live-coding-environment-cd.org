* Vision

`cargo run -- mcp` exposes Spacetime as an MCP server (stdio JSON-RPC 2.0) that
Spell attaches to via `spell.kdl`. It is simultaneously:
  1. an *MCP server* — tools over stdio
  2. a *CDP server* — drives a warm Chromium (reuses the existing `cdp` feature)
  3. a *live coding environment* — send Spacetime code, work with it live

** Mental model (one concept, reused)

  Environment  ≡  an import path (workspace root)       — discover · spin-up · attach
     └─ Tab    ≡  an entry point (a file OR inline code) — discover · spin-up · attach
          └─ webhooks → generic interactivity → rich choice data back to the agent

Generic webhooks (same family as stdlib/__admin__ comms) let the agent add
interactivity to a live page. First demo usecase: the agent proposes several
component *options* for a file; the human picks; the choice returns to the agent
as rich structured data (MCP `structuredContent`).

* Protocol facts (verified against Spell src @ packages/coding-agent/src/mcp)

- stdio transport: newline-delimited JSON-RPC 2.0 over stdin/stdout (transports/stdio.ts)
- handshake: `initialize` → reply {protocolVersion, capabilities, serverInfo}
            → client sends `notifications/initialized`
- protocolVersion the client offers: "2025-03-26" (echo it)
- discovery: `tools/list` → {tools:[{name,description,inputSchema}]}
- invoke: `tools/call` {name,arguments} → {content:[...], isError?, structuredContent?}
- `structuredContent` is surfaced by Spell on the `data` channel (machine-readable)
- KDL registration: `mcp { server "spacetime" type=stdio { command "..." args "..." } }`
- stdout MUST carry protocol bytes ONLY; all logging → stderr.
