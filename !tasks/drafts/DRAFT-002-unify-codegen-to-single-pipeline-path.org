* Problem

Three codegen paths exist in the Spacetime compiler:

1. *Pipeline* (=src/pipeline/=): Resolve→Sort→Expand→Emit for selector-scoped directives. Produces typed =JsFragment=/=CssFragment= IR. The canonical, newer path.
2. *Metasystem expand_macro* (=src/metasystem/expand.rs=): Handles file-level directives (=@template=, =@data=, =@test=, =@fixture=). Produces raw =ExpandedDirectives= (=Vec<String>=). Older path, still active.
3. *compile_macro_call* (=src/metasystem/compile.rs=): Uses =DeclarationGraph=. Test-only, never wired into the live compiler.

Both (1) and (2) call =generate_primitive_ir()= from =emit/metasystem_codegen.rs= at the primitive level. The divergence is in orchestration: pipeline uses typed IR throughout; metasystem works with raw strings.

This causes:
- Duplicate =PrimitiveArgs= construction in 3 places (resolve.rs:1104, compile.rs:733, expand.rs:124)
- Parallel implementations: =process_bind= (metasystem) vs =resolve_via_binds_with_decls= (pipeline)
- Split template validation (E0402) between compiler.rs and pipeline/mod.rs
- Manual CSS/JS assembly in compiler.rs duplicating the emit layer
- Two error type hierarchies (=MacroExpansionError= vs =ResolveError=/=ExpandError=)

* Design Decisions

- File-level directives get synthetic =Phase::Global= scope (no element binding)
- =Phase::Global= always sorts before =Phase::Selector= (preserves current output ordering)
- =ExpandedDirectives= type is killed — everything becomes typed =JsFragment=/=CssFragment= IR
- Compile-time metaprogramming (%when/%for/%if/%derives/%states) becomes a formal pipeline layer: *Layer 0: Evaluate* (not "Desugar" — these constructs require runtime evaluation of bound values, not syntactic rewriting)
- =@template= goes through the pipeline, producing a dedicated fragment type
- Big bang approach — accept temporary breakage during refactor
- Diagnostic errors unified to whichever structure is cleanest

* Critical Findings (from analysis)

** Prelude deduplication key mismatch
Pipeline deduplicates by =primitive_name=. Metasystem deduplicates by =fm.macro_name=. Unified pipeline uses =primitive_name= (correct behavior).

** body_was_consumed flag
=ExpandedDirectives.body_was_consumed= is set by metasystem but never read by compiler.rs. Verify this is dead code and delete it.

** %registers side effects
Template macros use =%registers template($name)= to populate a compile-time template registry (for E0402 validation). When file-level macros route through the pipeline, =%registers= processing must move to the Resolve layer.

** Layer 0: Evaluate is NOT syntactic
=%when= checks =ctx.resolve(&condition).is_truthy()=. =%for= iterates =CapturedValue::Array=. =%if= evaluates =MetaIfCondition=. This requires the same binding infrastructure as =MacroContext=. The Evaluate layer takes =MacroDefAst= + captured values → flat =Vec<BindDecl>=/=Vec<EmitBlock>= with no control flow remaining.

** %for produces variable-count bind declarations
A =%for= loop over N items produces N =BindDecl= entries. Evaluate must run before Resolve, outputting flat =Vec<BindDecl>=. Resolve then maps each to a =ResolvedPrimitive=. The 1:N expansion happens at the Evaluate→Resolve boundary.

** Inline condition evaluation in resolve.rs
resolve.rs already has a mini-evaluator for conditional =%binds= (~line 320+). When the Evaluate layer is added, this must be removed to avoid double-evaluation.

** Template ordering invariant
Template DEFINITIONS must precede template INVOCATIONS in JS output. Assign explicit order values: =register-template= gets =order=100=, =invoke-template= gets =order=200= (already has =%order 200= in stdlib). Sort is already stable for equal =(phase, order)= pairs.

** No snapshot tests for file-level macro output
compiler.rs lines 659-828 have no dedicated unit/snapshot tests — only covered by integration tests. Add snapshot baseline BEFORE refactoring.

** ITEM Phase 3: Build the Evaluate layer (Layer 0)
:PROPERTIES:
:EFFORT: 12h
:END:

Extract =expand_macro_body()='s control-flow evaluation into a formal pipeline layer that runs before Resolve.

*** Input/Output contract
- *Input:* =Vec<FormMatch>= where each =FormMatch= may reference a macro with =%when=, =%for=, =%if=, =%derives=, =%states=, =%includes=, =%emit=, =%binds= body items
- *Output:* =Vec<EvaluatedMatch>= — a flat list where all control flow has been resolved. Each =EvaluatedMatch= is a =FormMatch=-like struct with only concrete =BindDecl= and =EmitBlock= entries (no =%when=, =%for=, =%if= remaining). A single input =FormMatch= with a =%for= over N items becomes N =EvaluatedMatch= entries.

*** What moves into Evaluate
Extracted from =expand_macro_body()= (=src/metasystem/expand.rs:1774-1832=) and =expand_body_item()= (lines 2371-2512):
- =%when= → conditional evaluation → include/exclude items
- =%for= → loop unrolling → N copies with different bindings
- =%if/%elif/%else= → branch evaluation → include one branch
- =%derives= → parent macro inheritance
- =%states= → generate CSS for state-based styling
- =%includes= → recursive macro expansion (calls Evaluate recursively)
- =%emit= → raw JS/CSS with param substitution → becomes an =EmitBlock= in output
- =%binds= → pass through as =BindDecl= for Resolve to handle

*** What Evaluate needs
- =MacroContext= (or a subset) for binding resolution, =resolve()=, depth tracking
- =MetaRegistry= for macro/primitive lookup during =%includes= and =%derives=
- =MAX_MACRO_DEPTH= (100) for recursion guard

*** Files
- Create =src/pipeline/evaluate.rs= — the new Layer 0
- =src/pipeline/mod.rs= — wire Evaluate: =evaluate → resolve → sort → expand → emit=
- =src/metasystem/expand.rs= — extract =MacroContext= binding infrastructure; =expand_macro_body()= and =expand_body_item()= become dead code (but not yet deleted — Phase 6)
- =src/pipeline/resolve.rs= — remove inline condition evaluation (~line 320+) that becomes redundant

*** Acceptance criteria
1. =src/pipeline/evaluate.rs= exists with =pub fn evaluate(matches: &[FormMatch], registry: &MetaRegistry) -> Result<Vec<EvaluatedMatch>, CompileError>=
2. =pipeline::compile()= calls =evaluate()= before =resolve()=
3. =%for= loops produce N =EvaluatedMatch= entries (test with a macro that =%for=-iterates over a 3-element array → 3 outputs)
4. =%when= with a falsy condition produces 0 =EvaluatedMatch= entries
5. =%if/%elif/%else= produces only the matching branch's entries
6. =%includes= triggers recursive evaluation (test with nested macros)
7. =%derives= inherits parent binds/states (test with a macro that derives from another)
8. Inline condition evaluation in =resolve.rs= is removed (grep confirms no =MacroBodyItem::If= / =MacroBodyItem::When= in resolve.rs)
9. Snapshot tests produce identical output

*** Testing strategy
- Unit tests for each construct in =evaluate.rs=:
  - =%when true= → items included; =%when false= → items excluded
  - =%for= over empty array → 0 items; over [a, b, c] → 3 items with correct bindings
  - =%if= with true/false/elif/else branches
  - =%includes= with a known macro → recursive expansion
  - =%derives= from parent → inherited binds present
  - Depth guard: 101-deep recursion → =CompileError::MaxDepthExceeded=
- Integration: snapshot tests unchanged
