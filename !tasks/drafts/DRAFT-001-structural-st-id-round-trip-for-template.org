#+STATE: DONE

#+EFFORT: 3h
#+PRIORITY: #A
#+LAYER: backend

* Problem

When the debugger's select tool edits a text element inside a =@template= body,
the server uses the element's *tag name* (e.g., ="a"=) as a CSS selector in lol_html.
Because tag selectors are non-unique, =set_inner_content= fires on *every* matching
element, silently corrupting all siblings. Filed as =BUG-content-edit-ambiguous-template-selector=.

The two-pass count guard (committed in =b796d8a2=) catches this at runtime and rejects,
but the root cause is that there is no unique element identity flowing through the edit path.

* Current flow (broken)

1. =inject_template_provenance= (=form_match.rs:1219=) annotates the served DOM:
   - =data-st-id="st-HASH"= (unique, derived from =file:ast_offset:tag:occurrence_idx=)
   - =data-st-origin="file.st::scope §directive tag"= (NOT unique — tag name only)
2. Browser =readProvenance= (=dev-editable.st:47=) extracts the locator from origin.
   For =.st= files, locator IS the selector: =" §template a"=.
3. Browser sends =EditAst { selector: " §template a", patch: {__content: "..."} }=.
4. Server parses selector → =AstContent { element_path: "a" }= → uses ="a"= as lol_html selector.
5. ALL =<a>= elements in the template body get replaced.

* Design: st-id round-trip

The =data-st-id= hash is already unique by construction. We round-trip it through the edit:

1. Browser sends =__st_id= alongside =__content= in the patch object.
2. Server re-derives provenance on the template body HTML (in memory) using
   =inject_template_provenance= with the same inputs it had at serve-time.
3. Server uses =[data-st-id="st-HASH"]= as the lol_html selector on the annotated HTML.
4. Server strips injected =data-st-id= / =data-st-origin= attributes from the result.
5. Splices clean HTML back into source.

This makes element identity structurally unique — ambiguity is impossible, not merely caught.

* Key invariant

=inject_template_provenance= is *deterministic*: given the same =(file, ast_offset, tag, idx)=,
it produces the same =st-id= hash. The server can always re-derive the exact provenance the
browser saw, because all inputs are available from the parsed AST:
- =source_file=: from =file_path= arg
- =scope_selector=: from =form_match.selector= (or =""= for root scope)
- =macro_name=: from =form_match.macro_name=
- =ast_offset=: from =form_match.span.start=
