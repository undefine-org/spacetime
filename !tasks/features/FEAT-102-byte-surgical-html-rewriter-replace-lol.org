* Why this is separate
The remaining lol_html sites REWRITE HTML and WRITE IT TO DISK (user source files
and prod export). lol_html is a SURGICAL STREAM rewriter: it touches only matched
elements and emits every other byte VERBATIM (comments, whitespace, doctype,
attribute quoting/order, entity encoding, void-element form preserved). html5ever
is a full parse→tree→reserialize that NORMALIZES the whole document. Routing a
user's hand-written .html through parse→serialize would silently rewrite their
entire file on every CMS edit = data-loss regression. So these CANNOT be a naive
html5ever swap; they need a byte-surgical primitive we own.

* Target
- NEW: src/html/surgery.rs — a byte-surgical rewriter primitive: parse with
  html5ever to LOCATE element byte-spans + attr spans (html5ever can yield
  positions via the tokenizer/tree with source offsets, OR a lightweight
  span-tracking tokenizer), then perform targeted string splices on the ORIGINAL
  bytes (set/remove attr, replace inner content, append child, remove element).
  Unmatched bytes are copied verbatim. This is the lol_html behavior, owned.
