* Purpose
The keystone of the Spacetime⇄Phoenix LiveView design (@research/spacetime-phoenix-liveview-bridge.org §4):
make the integration VALIDATE ITSELF at compile time. A `@host $b : live("Mod")`
page declares which events it fires (`send emit "move"`) and which reply variants
it decodes (`receive to MoveResult { Moved | Blocked }`). Wave B unifies that page
contract against the server's introspected `__spacetime_contract__` and FAILS the
build on mismatch — turning 6 runtime footguns (catalog #1-5,#14) into compile
errors. It is the ONLY wave buildable in pure verse, no Elixir, RED→GREEN testable.

* Design — one comparator, two contract sides
1. Server side (fixture for now): a `<page>.contract.json` checked in beside the
   .st — the exact shape `__spacetime_contract__/0` will emit:
     { "module": "...", "events": [{"name":"move","payload":{...}}],
       "pushes": [{"name":"flash",...}], "fingerprint": "..." }
2. Page side: walk FormMatches for `@data signal/stream` whose `host:` resolves to
   a `live(...)` @host. Extract verb+target (the emitted event name) and the
   receive arms' variant names (the decoded replies).
3. Comparator (new, ~one module): every `send emit "X"` ⊆ server events (name);
   nothing fires an event the server doesn't handle. Emit E0928 via the existing
   format_compile_errors rail on mismatch.
