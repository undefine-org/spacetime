NOTE [2026-03-30]: Implemented floating rich text toolbar (Bold/Italic/Code/Link) positioned above contenteditable elements, and media picker with hover overlay on images, file upload to /__spacetime/dev/upload, object URL preview, and EditJson persistence.

* Scope

** In scope
- Floating rich text toolbar for contenteditable elements in dev mode
- Formatting buttons: Bold (<strong>), Italic (<em>), Link (<a> with URL input), Code (<code>)
- Configurable HTML whitelist via @rich-editor macro (per-project allowed tags/attributes)
- Sanitizer upgrade: use project whitelist instead of hardcoded ALLOWED_TAGS
- Image click-to-replace: clicking <img> elements with data-st-bind opens file picker
- Upload via asset upload endpoint (item #3), update JSON field with new path
- Asset browser section in admin panel showing uploaded assets

** Out of scope
- Block-level formatting (headings, lists, blockquotes) - FUP
- Markdown support - FUP
- Image cropping/resizing - FUP
- Video/audio media management - FUP

** Boundary rationale
Rich text is already working via HTML strings in JSON. The toolbar just makes it editable visually. Media management covers the most common non-text content type (images). Block-level editing is significantly more complex and deferred.

* Implementation

** Step 1: Rewrite @rich-editor macro (~stdlib/__dev__/macros/rich-editor.st~)
- Replace stub with real macro definition
- %form: ~@rich-editor(allow: $allow:tag_list? = [strong, em, a, code, br])~
- %binds: dev-hooks() to get dev mode state
- The macro configures the toolbar and sanitizer whitelist for the project

** Step 2: Rich text toolbar primitive (~stdlib/__dev__/primitives/dev-rich-toolbar.st~)
- New %primitive that creates a floating toolbar
- Toolbar positioned above the currently-edited contenteditable element
- Buttons: Bold (B), Italic (I), Link (chain icon), Code (</>)
- Uses Selection API: ~document.getSelection()~ to read current selection
- Bold: wraps selection in <strong> (or removes if already bold)
- Italic: wraps selection in <em>
- Link: prompts for URL, wraps in <a href="...">
- Code: wraps in <code>
- Toolbar appears when element enters edit mode (coordinates with dev-editable)
- Toolbar hidden when edit mode exits
- Shadow DOM boundary: toolbar lives in main document (not Shadow DOM) for Selection API compatibility

** Step 3: Media picker primitive (~stdlib/__dev__/primitives/dev-media-picker.st~)
- New %primitive for image click-to-replace
- In dev mode, <img> elements with data-st-bind or data-st-id get an overlay on hover
- Click opens native file picker (~<input type=file accept="image/*">~)
- On file selected: upload via fetch() to /__spacetime/dev/upload
- On upload success: update JSON field via EditJson with new image path
- Show loading indicator during upload
- Preview: update <img> src immediately with object URL, then replace with server path on confirm

** Step 4: Sanitizer whitelist integration (~stdlib/primitives/data/sanitize.st~)
- Extend sanitize-html primitive to accept a configurable whitelist
- If @rich-editor defines a whitelist, use it; otherwise use default ALLOWED_TAGS
- Expose whitelist configuration via a global: ~window.__stRichEditorConfig~
- Sanitizer reads from global when available

** Step 5: Asset browser (extend admin panel)
- Add "Assets" section to the Data Editor tab (or new tab)
- List uploaded files from assets/uploads/ with thumbnails
- Click asset to copy path to clipboard
- This is a lightweight addition to the admin panel, not a full asset management system

* Edge Cases
- Selection across multiple elements: toolbar should only work within a single contenteditable
- Nested formatting (bold inside italic): should produce <em><strong>text</strong></em>, not malformed HTML
- Link editing: clicking an existing <a> should pre-fill URL in prompt
- Image upload failure: revert to original src, show error message
- Large image upload: show progress indicator, respect size limit from upload endpoint
- SVG images: upload works but preview may have different behavior
- No toolbar on non-editable elements: toolbar only appears when dev-editable activates an element
- Touch devices: toolbar should work with touch selection (deferred if complex)
