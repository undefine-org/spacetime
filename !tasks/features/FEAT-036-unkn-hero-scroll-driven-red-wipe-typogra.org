* Intention & Purpose

Implement signature motion #2: as the visitor scrolls past the hero, a solid red rectangle wipes upward from the bottom edge — height proportional to scroll progress (=scrub: true=) — sitting above the hero background but beneath the typography/lockup. By exit, the entire hero frame is solid scarlet. Typography cross-fades from ink-black to paper-cream to maintain legibility against the rising red.

* Context & Narrative

The current =modules/_hero.st= hero is static cream paper with a =@scroll hero-monogram-drift= effect on the lockup and a words-split =@reveal= on the lede. The reference manifesto specifies a scroll-bound color wipe — *the* signature hero motion — that's completely missing. The hero also has copy duplication ("Where Talent Moves Culture" appears as both meta and headline) and a structurally wrong =unkn-hero__tag= split.

This item rewrites =_hero.st= to match the PDF spec (single headline, single meta line, two CTAs, optional est line right of headline) and adds the scroll-driven wipe + typography cross-fade as two coordinated =@scroll= timelines on the hero element.

The wipe is implemented as an absolutely-positioned full-width =<div class="unkn-hero__wipe">= inside the =<section class="unkn-hero">=, with =bottom: 0; left: 0; right: 0; height: 0= as start state and =height: 100%= as end state, animated via stdlib =@scroll wipe(start: 0, end: 1, scrub: true) { height: 0% -> 100%; }=. Z-index ordering: =.unkn-hero { isolation: isolate }= creates a stacking context; wipe gets =z-index: 1=; typography children get =z-index: 2=.

Typography cross-fade is a sibling =@scroll= timeline on the typography wrapper: =color: var(--unkn-ink) -> var(--unkn-paper);= scrubbed from start: 0.3, end: 0.85 (so color is full ink while wipe is below 30% scroll, transitioning to full paper by 85% — when wipe is high enough that ink against red is hard to read).

* Edge Cases

- *Browser color interpolation*: Chrome and Firefox interpolate CSS =color= via RGB linear; Safari may differ. Test all three. Worst case: typography color jumps mid-cross-fade. Mitigation: use the CSS-variable-driven approach (animate the var, not the color directly) so the interpolation happens on a custom-property string transition (browsers handle this consistently as discrete... actually no, custom-prop transitions are also browser-dependent unless typed via =@property=). Mitigation: register the var via =@property --unkn-hero-fg { syntax: '<color>'; inherits: true; initial-value: #0D0D0D; }= which forces consistent color interpolation in supporting browsers, and degrades to a snap transition in non-supporters (acceptable).
- *Hero shorter than viewport*: at very tall mobile devices, hero may be < 100vh because of =padding-bottom=. =scope: cover= still maps correctly. Verify at iPhone Pro Max (430x932) viewport.
- *Anchor scroll into hero*: if a future link points to =#hero=, the section may snap into view skipping the entrance reveal. Acceptable — entrance reveal triggers on next scroll.
- *Wipe overshooting hero bottom*: =bottom: 0= anchors wipe to section bottom; =height= grows upward. If section box-shadow or margin extends below =bottom: 0=, wipe aligns to padding-box. Use =bottom: 0= on the absolute element with =position: absolute= relative to =.unkn-hero { position: relative; }=.
- *Performance*: animating =height= triggers layout. For 60fps, =height= should ideally be replaced by =transform: scaleY()= with =transform-origin: bottom=. *Decision*: use =transform: scaleY(0) -> scaleY(1)= for performance; no layout thrash. Update CSS accordingly: =.unkn-hero__wipe { position: absolute; inset: 0; transform: scaleY(0); transform-origin: bottom; will-change: transform; }= and timeline =transform: scaleY(0) -> scaleY(1);=.
