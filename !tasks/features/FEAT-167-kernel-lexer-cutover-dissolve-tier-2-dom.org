* W1.2/W3 MERGED CUTOVER — IN FLIGHT (session 153f5ed0)

The review swarm caught a sequencing error and it is worth recording as the
wave's main lesson: I flipped NAME resolution (parse_capture_type arms deleted,
scalars resolve to stdlib) BEFORE flipping the LEXER tier. That cannot work, and
it is the same lesson W1 already recorded one level down — a grammar cannot
match tokens the lexer has fused. `@fade-in(distance: 40px)` failed with
E0946 "Expected `$distance:Custom(\"length\")`, got token NUMBER_WITH_UNIT".
Full suite at that point: lib 3072/14 FAILED, integration 188/15 FAILED.

∴ the name flip and the tier flip are ONE cutover. Landed together.

** Three P1s found by review, all verified in source, all fixed

1. `time` had NO stdlib production. The deleted Rust arm mapped BOTH "time" and
   "duration" to Duration; css-values.st declared only `duration`. An
   unregistered %capture_type resolves through form_compiler.rs's
   `.or_else(|| extractors.get(&Expr))` — a SILENT lenient fallback. So ~69
   `$x:time` sites would have quietly accepted arbitrary expressions.
   Fixed: `%capture_type time { $d:duration }`. The gate is NEGATIVE
   (`duration: banana` must be REFUSED) because a positive-only test passes
   just as happily with the alias absent.

2. Scalars reified to RECORDS, not strings. Sequence/Choice extractors return
   CapturedValue::Named when a grammar has named parts, so `8px` became
   `{n:"8", u:"px"}` and codegen emitted a JS object where every consumer wants
   "8px". Contradicts PLAN-122's core decision (repr = CSS string, always).
   Fixed: reify_scalar_source_text in wrap_reifier, registry-keyed exactly like
   param_list/properties/keyframes.

3. Every scalar needed a `( $ref:binding )` arm. A value position in Spacetime
   is reactive (`duration: $speed`); literal-only grammars rejected ordinary
   corpus usage. Arm is listed LAST so a literal always wins the alternation.

** The token-shape migration (the actual remaining work)

At Kernel tier `300ms` is NUMBER("300") IDENT("ms") and `50%` is NUMBER PERCENT.
Every position that consumed ONE fused NUMBER_WITH_UNIT token must now consume
the adjacent pair. Two distinct layers, both needed:

- CST parser (src/syntax/cst/parser.rs) — DONE. Added `bump_value_atom()` +
  `next_is_adjacent_unit()`: adjacency is decided by POSITION (prev.offset +
  prev.len() == cur.offset), with NO opinion about which units exist. That
  opinion now lives in css-values.st, once. Wired into parse_meta_default_value
  and the primary-expression value arm. This fixed
  `duration: time = 300ms` in signal-flip.st/websocket.st.

- Form matcher arg collection (src/syntax/events/grammar/directives.rs:~443) —
  OUTSTANDING. The per-token bump loop splits `500ms` into two ARG children,
  giving "Unexpected N extra inline token(s) after directive".

Corpus signal on examples/mobile-tasks: 8 errors -> 6 after the binding arms.
