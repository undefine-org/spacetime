* Motivation
PLAN-023 W3/W4 emits dynamic HTML that HYDRATES at runtime (static SSG-unroll vs <template>
clone+hydrate). To verify hydration, a test must assert on the DOM AFTER reactive updates
settle. Recon (agent 2-MapTestSt) found: @snapshot captures DOM BEFORE reactive updates (no
post-hydration snapshot), and there is no rendered-output/visual diff — parity checks only
timing. The native harness DOES support post-update assertions via @when→@wait→@then (see
tests/component-model/reactive-props.test.st), but there is no first-class "snapshot the
hydrated subtree and diff against expected markup" assertion.

* Proposal
Add a @then ... should match_dom \"<expected html>\" (or @snapshot_after / @then $sel should
have_html) assertion that:
- runs after @wait/microtask flush (post-hydration),
- normalizes whitespace + attribute order,
- compares the element's innerHTML/outerHTML against expected markup,
- on mismatch prints a structural diff.
This gives W4 a precise gate: "@each over static data SSG-unrolls to exactly <li>A</li><li>B</li>"
and "@each over dynamic data hydrates to the same DOM the SSG path produces" (the SSG==hydrate
invariant central to PLAN-023).

* Acceptance
- a .test.st can assert post-hydration innerHTML of a hydrated list equals expected <li>s.
- whitespace/attr-order-insensitive; diff on failure.
- TDD: reactive-list-style test using the new assertion, green headless.

* Relation
Directly supports PLAN-023 W4 test gates (SSG-unroll vs hydrate equivalence). Without it, W4
hydration verification falls back to ad-hoc curl/innerHTML grepping (what W1 had to do).
