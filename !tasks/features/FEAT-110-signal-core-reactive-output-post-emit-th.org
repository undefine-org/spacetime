* SUPERSEDES the earlier @signal design
This FEAT was originally "@signal post/emit". The dialogue (2026-06-13) REJECTED a
top-level @signal directive. The model is now: reactive output = TWO new @data
kinds + ONE consumer directive, powered by the W0 matcher. See §S1 for the full
rationale (PureScript Aff/Event split, Elixir case/with, @each:@handle analogy).

* Why
@data is reactive INPUT (5 kinds). The INTENT→OUT arc had no home — pages dropped
to imperative `@on click { fetch() }`. @data signal/stream + @handle complete the
loop AS @data's own machinery, not a parallel construct (harmony).

* The five pillars (this FEAT builds pillars 1,2,4,5; pillar 3 = W0/BUG-104)
1. @host $api : http(url) { headers: … }  /  @host $mcp : ws($sock)  /  : mcp
   — transport+config binding; declares the wire ENVELOPE type that types the
   decode subject `$.`. ONE owned %primitive per transport (http/ws), sibling of
   dev-ws; demand-injected.
2. @data signal $name(params) to $host { send; receive; policy; optimistic }
   — kind 6 (ONE correlated reply). @data stream — kind 7 (MANY replies). Yields a
   CALLABLE $name + $name.pending/$name.error/$name.cancel(), mirroring @data fetch's
   $x/_loading/_error/_refetch.
   - send: request builder (`POST "/url" { body }` http; `emit "type" { payload }` ws).
   - receive [SumName] { pat => Variant(expr); }: DECODE — @match (W0) over `$.`,
     each arm CONSTRUCTS a variant (with preprocessing); optional SumName publishes
     the response @type (the introspectable interface).
   - `final` arm-modifier marks a TERMINAL outcome (stream); one-shot signal =
     all-arms-final implicitly.
4. @handle $name { optimistic{}; receive{}; final{} } — the CONSUMER directive.
   RE-OPENS the signal's @data clauses for THIS scope (nearest-scope cascade, like
   CSS; a fire resolves to its nearest enclosing @handle, else def defaults).
   receive here is @match over the VARIANT SUM → effect statements (bindings typed
   by the carried types, decl↔use). final{} runs when a terminal arm fires / on
   cancel/timeout (DRYs cleanup across terminal arms).
   @each : collection-in-space  ::  @handle : signal-responses-in-time.
5. policy latest|queue|parallel|drop [timeout T] [retry n] — race/lifecycle.
   latest = killFiber in-flight; correlation id runtime-invisible (≈ makeAff fiber).

* Typing (one optional knob, flows decl→use)
`as Type` on send body / receive arm RHS / optimistic exprs; optional. The decode
arm's output type BECOMES the @handle arm binding type (inferred, not restated).
optional SumName after `receive` names the response @type. `Created(Todo)` is sugar
for `Created($.body as Todo)`. See §S1 TYPING.

* Edge cases
- @data signal with NO receive: bare fire-and-forget (`$ping()` sends, ignores reply).
- @handle absent at a fire site: def-level defaults apply (warn if def has no receive).
- two @handle scopes for one signal: each owns optimistic/receive/final independently.
- stream with no `final` arm: never terminates until cancel/timeout (document).
- exhaustiveness: @handle receive missing a variant w/o `_` → compile error (W0 check).
- http non-2xx with no matching arm → `_` arm (or Failed); never throws.
- payload/body type violation at fire → arg type-check (reuse metasystem ArgTypeMismatch).
- SSG page (no host bridge yet) → emit noop + console.debug, never throws.
