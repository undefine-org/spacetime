* Intention & Purpose

Promote =project-style-protocol.md= from "color tokens only" to a multi-tier asset protocol so the skill behaves like huashu-design's brand-asset rule: *Logo > product/hero imagery > UI screenshots > color > font > vibe*. Brand recognizability is a function of the assets present, not of the color tokens alone. Today the protocol asks the agent to grep var/literal usage and freeze a tokens file — but it never asks "is there a logo? is there a hero image?". An =index.st= that imports =tokens.st= correctly but renders without the brand's logo or hero photography is structurally clean and still off-brand.

* Context & Narrative

The huashu-design analysis (this session) showed the v1.1 升级 in their SKILL.md is exactly this: from "extract colors and fonts" to "logo + product image + UI screenshots > everything else". The DJI Pocket 4 example: an animation that walked the (color-only) protocol still produced a "generic black-bg + orange-accent + rounded rectangle" tech ad with zero DJI identity, because no DJI logo or product render was sourced.

Spacetime websites typically hold their assets under =projects/<name>/images/= or =projects/<name>/assets/=. The asset-tier inventory step:
1. =ls projects/<name>/= and identify image directories.
2. Look for =logo.svg= / =logo.png= / =logo-*.png= patterns; if missing, halt and prompt user.
3. For implied content types (product / portrait / scene), scan for hero imagery; if missing AND the site is content-driven, prompt user.
4. Compose =projects/<name>/brand-spec.md= recording resolved asset paths + token references.

The doctor finding is light: when a project root has =brand-spec.md= AND that file references asset paths that don't exist on disk, doctor emits a =CheckDiagnostic= with =severity: "warn"=, =rule: "brand-asset-missing"=. This is a check-phase diagnostic, NOT a runtime walker.
