* What it is
A collaborative kanban in elixir/spacetime_lv: `SpacetimeLvWeb.BoardLive`
(server-authoritative board state: columns, cards, positions) +
`frontend/board.st` (the ENTIRE view) + `frontend/$hosts.st` gains
`@host $board : live("SpacetimeLvWeb.BoardLive")`. PubSub broadcasts board
changes to every connected socket. No HEEx view logic, no phx-click, no custom
JS beyond the SpacetimeBridge hook.

* The three wow moments, concretely
1. *Optimistic drag.* Drag a card → it snaps to the target column INSTANTLY
   (@handle optimistic arm, FEAT-161) while `send emit "move_card"` round-trips;
   on {:reply, %{tag: "ok"}} it stays, on a rejection (card locked / version
   conflict) it glides back. Server applies the move and broadcasts.
2. *Cursor trails.* Every connected client's cursor renders on every other
   client as a labelled trail (ephemeral presence channel, FEAT-161 §3;
   Presence tracks join/leave so trails appear/disappear with users). Your own
   cursor is pure .st — zero wire cost.
3. *Animated transitions between server states.* When another user moves a
   card, the assign diff streams in (FEAT-159) and the card GLIDES to its new
   column on your screen (@clock/@timeline, FEAT-161 §2) — never a snap, never
   a full re-render. A typed push ("Mara moved 'Write docs' → Done") fires the
   @data stream toast (FEAT-160 §2) exactly once.

* Contract
BoardLive declares its sections via the FEAT-160 DSL (events: move_card,
add_card, lock_card…; assigns: items, presence; pushes: flash) —
`mix spacetime.contract` emits BoardLive.contract.json; the .st build checks
against it (E0928-family, all three rules).
