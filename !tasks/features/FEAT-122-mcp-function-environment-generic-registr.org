This item is the first executable vertical slice: one registry, one mount, one sink, one awaited event, one .st function replacing one Rust-specific interface.

* Goal
Make the MCP live environment feel like a small NREPL/function host without waiting for the full reactive-output language implementation.

Definitions:
- Function = Spacetime source + compile artifacts + introspected/declared contract + revision.
- Instance = mounted Function + input JSON + URL + event queue.
- Event = typed envelope emitted by the mounted page to the host.

This slice intentionally allows a lightweight declared contract (JSON from st_fn_put/st_mount args) while the compiler-level contract registry from FEAT-110/FEAT-113 is still pending. The data shape must be forward-compatible with the later introspected contract.

* Scope
IN:
1. Add generic function registry to the MCP session state.
2. Add generic instance/event store to the live HTTP server.
3. Add tools:
   - st_fn_put(source, name?, contract?) -> {fn_id, revision, contract, diagnostics}
   - st_mount(fn_id OR source, input?, title?) -> {instance_id, url, contract}
   - st_await(instance_id, timeout_secs?) -> next event or timeout
   - st_inspect(instance_id? fn_id?) -> function/instance/event diagnostics
4. Add one generic signal sink: POST /__mcp/signal/{instance_id} accepting JSON or form fields and pushing an event envelope.
5. Serve mounted functions as live pages with sibling input.json and assets.
6. Keep current st_propose/st_proposal_status/st_await_choice working; optionally implement them as compatibility wrappers only after the generic path is solid.

OUT:
- Full @host / @data signal / @handle syntax (FEAT-110).
- Full compiler-introspected signal registry (later phase).
- CDP browser server (PLAN-037 W3).
- Hot module replacement over WebSocket; simple remount/reload semantics are enough here.

* Design constraints
- No custom JavaScript in Spacetime pages except inside %primitive. If a mounted page needs host communication, it must use stdlib/__mcp__/host.st (or a temporary native HTML form during this slice).
- Rust owns transport, registry, compilation, and event queues. Spacetime owns UI/interface functions.
- One generic event sink. No new picker/form-specific Rust route.
- Compatibility is allowed only as a wrapper; do not create a second long-term interface system.
- Tool results must always include structuredContent.

* Acceptance criteria
- st_fn_put accepts inline .st source, compiles it, stores revision 1, and returns function id + compile lengths/diagnostics.
- st_mount mounts a stored function with input JSON and returns a URL.
- Opening the URL serves the compiled page and /input.json.
- POSTing to /__mcp/signal/{instance_id} records one typed event.
- st_await returns that event with {decided:true,event:{type,payload,instance_id}} within the timeout.
- st_inspect returns function metadata, instance metadata, and event history.
- Existing MCP tools still list and work.
- cargo build passes.
- A JSON-RPC smoke test proves st_fn_put -> st_mount -> POST signal -> st_await -> st_inspect end-to-end.

* Risk register
- Risk: Contract introspection is not available yet. Mitigation: store a forward-compatible `contract` object explicitly and later replace its producer with compiler introspection.
- Risk: st_mount(source) and st_fn_put(source) duplicate compile paths. Mitigation: one helper compiles and registers; st_mount(source) calls the same helper implicitly.
- Risk: Generic signal sink becomes under-specified. Mitigation: envelope contract is small and stable: {type, payload, correlation?}; form fallback maps fields into payload.
- Risk: Long polling blocks MCP loop. Mitigation: same bounded poll pattern as st_await_choice; timeout under client deadline.

  -> FunctionRecord { fn_id, revision, contract, compile artifacts }

  -> InstanceRecord { instance_id, url, input, event stream }

  -> next unconsumed event
st_inspect(...)
  -> functions/instances/events/contracts/diagnostics
