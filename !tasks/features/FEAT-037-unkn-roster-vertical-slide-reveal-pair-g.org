* Intention & Purpose

Implement signature motion #3: each talent in the roster is a vertical pair =[image-square on top, name-square below]=. Hovering the image: it slides smoothly downward into the name slot, revealing the talent's name in the now-empty top square. Cursor moving onto the name keeps the image slid; only leaving the entire pair returns the image to its top position.

* Context & Narrative

The current =modules/_roster.st= renders a 4-column decorative checkerboard of fake CSS tiles (=--ink= gradient noise, =--rule= single-line, =--cream=, =--script=). No real photography. No talent names. No hover behavior. This violates the manifesto's third signature motion *and* fails the brand-spec requirement that real photography drives the roster section.

This item rewrites =_roster.st= to use the new =$talents= dataset (FEAT-034) and adds the slide-reveal pair as a CSS-only interaction. Spacetime macro-driven animation isn't necessary here — pure CSS =:hover= with =transition= and =transform: translateY()= handles slide + reveal cleanly, with naturally-correct =prefers-reduced-motion= degradation.

The "horizontal" alternative was considered (image slides right into adjacent name slot) but the user-confirmed direction is *vertical* (image slides down). This produces taller, more cinematic cards and aligns with the editorial feel of the rest of the page.

* Edge Cases

- *Image aspect ratio mismatch*: portraits in =Home_Images/= range from 3:4 to 9:16. =object-fit: cover= with =object-position: center 30%= centers on the upper third (faces). Verify each talent visually; tune =object-position= per talent if necessary via =data-pos= attribute + CSS attribute selectors.
- *Hover during slide-back*: rapid mouse-in/mouse-out should not cause stutter. CSS transitions handle this — the transform interpolates from current value to target value smoothly.
- *Touch device "sticky hover"*: on touch, =:hover= persists after tap until next tap elsewhere. This is acceptable — tap reveals the name; tap elsewhere hides it. Document in brand-spec.
- *Dark mode preference*: roster uses cream paper background with dark talent cards. =prefers-color-scheme: dark= isn't honored by UNKN brand (always cream paper). Don't add a dark-mode override.
- *Large image network cost*: 9 talent images at original size could be 1MB+ each. =loading="lazy"= helps below-fold. Future optimization (FUP): generate WebP variants + =<picture>= responsive. Not in this item.
- *Focus trap in keyboard nav*: each pair is an =<a>= so Tab/Shift+Tab moves naturally. Ensure no =tabindex= overrides break order.
- *Empty talent name*: =$t.name= must always be present (validated in =@type Talent=). If somehow blank, reveal shows just headline. Acceptable.
