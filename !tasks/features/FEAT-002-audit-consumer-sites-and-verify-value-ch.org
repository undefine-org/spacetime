* Tests
** =tests/unit/animations/value-change.test.st= — new test
#+begin_src spacetime
@test "value-change handles emoji graphemes correctly" {
  @fixture {
    <div class="vc-emoji">hello</div>
  }
  @given .vc-emoji {
    @value-change(duration: 100ms, stagger: 10ms) {
      :entering { opacity: 0 -> 1; }
      :exiting { opacity: 1 -> 0; }
    }
  }
  @eval (eval("document.querySelector('.vc-emoji').textContent = '👋🌍'"))
  @wait 300ms
  @then .vc-emoji should have_text "👋🌍"
  @assert (eval("document.querySelector('.vc-emoji').querySelectorAll('span').length === 0")) "should be plain text after emoji animation"
}
#+end_src

* Edge Cases
- Some consumer sites may rely on =overflow: hidden= for layout purposes beyond animation clipping. The driver temporarily sets =overflow: visible= during animation but restores after. If a site depends on overflow: hidden during animation (e.g., to clip unrelated sibling content), the temporary override may cause a brief visual glitch.
- Sites with =translateZ(0)= on @value-change targets should have it removed — it was causing Firefox compositing flashes with the old driver and is unnecessary with the new approach.
