* Intention & Purpose

Implement signature motion #1 from =projects/unkn/_references/Spacetime Movement effect - UNKN website.md=: an infinite horizontal conveyor of square talent thumbnails with a 7-category sequence (Fashion, Beauty, Lifestyle, Entertainment, Sport, Travel, Food). Hovering any image pauses the entire row and fades out that single image to reveal its category word centered in the empty square; un-hovering resumes from the paused position.

This is the *first* below-fold motion the visitor experiences. It must feel constant, unhurried, and tactile.

* Context & Narrative

Current build has a static =unkn-talent-grid= (8 cream tiles, no motion, decorative-only) sitting in the wrong place in the section order (between statement and identity instead of directly under the hero). That static grid will be deleted; this section replaces it with a dedicated =modules/_strip.st= that owns the marquee.

The motion is best authored *pure-CSS-first* using a single =@keyframes= track animation + =animation-play-state: paused= on parent =:hover=. This pattern natively pauses the entire row when any descendant is hovered (because all descendants trigger the parent's =:hover=), preserves position on resume (no JS state management), and degrades automatically with =@media (prefers-reduced-motion: reduce)=. A custom =%primitive= would add cost without benefit here — Spacetime macros are for reactive bindings, not cosmetic CSS animation.

Per-cell behavior (image fades + word appears) is also pure CSS using =:hover= transitions on opacity. No JavaScript at all.

The seamless conveyor effect requires two duplicates of the cell list inside the =__track= so that when the track has translated by exactly =-50%=, the second copy is in the position of the first — looping the keyframe back to =0%= produces no visual jump.

* Edge Cases

- *Image fail-to-load*: if a talent image 404s, =img.onerror= isn't accessible without JS. Mitigation: cell background is =--unkn-paper-warm=; if image fails, the warm cream square shows; category word still reveals on hover. Acceptable degradation.
- *Cell width drift*: if Spacetime's CSS doesn't preserve =flex: 0 0 ...= width on different browsers, the loop won't be seamless. Mitigation: =flex-shrink: 0; flex-grow: 0; flex-basis: clamp(...); width: clamp(...);= belt-and-braces.
- *Hover during transition*: hovering and unhovering quickly should not stutter. CSS transitions handle this naturally; verify.
- *Tab focus*: keyboard users can't trigger =:hover=. Add =:focus-within= sibling: =.unkn-strip__cell:focus-within .unkn-strip__image { opacity: 0; } .unkn-strip__cell:focus-within .unkn-strip__category { opacity: 1; }= and make cells =tabindex="-1"= so they're not in tab order but =:focus-within= still works for screen-reader tools that probe focus. Decision: keep cells out of tab order; reduced-motion mode already shows categories permanently.
- *RTL languages*: animation direction would be wrong. Out of scope (UNKN is English-only) but document in brand-spec.md.
- *iOS Safari =position: sticky= bug + animation*: not used here, but if any parent has sticky, animation can stutter. None of the home parents are sticky.
- *Loop seam visible at low-res devices*: if device pixel ratio causes =-50%= to land on a sub-pixel boundary, a 1px gap can appear. Mitigation: add =margin-right: -1px= on every cell EXCEPT the last in each copy; or use =transform: translate3d(-50%, 0, 0)= for sub-pixel rendering. Use the translate3d approach.
