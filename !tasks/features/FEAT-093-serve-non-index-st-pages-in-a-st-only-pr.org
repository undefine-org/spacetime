* Goal
In a `.st`-only project (no hand-written `.html`), the dev server serves the root
`/` by synthesizing a shell for `index.st` (FEAT-043, ~server.rs:1299). But a clean
path like `/reference` for a sibling `reference.st` 404s: `catch_all_handler` only
serves existing `.html` files. Generalize so `/<name>` (and `/<name>/`) serve
`<name>.st` (or `<name>/index.st`) via the SAME `synthesize_st_only_shell` path.

* Target
- src/server.rs `catch_all_handler` final `else` (~line 1175): before NOT_FOUND,
  resolve the clean path to a candidate `.st` entry and, if it exists, compile +
  `synthesize_st_only_shell(entry, compiled.html)` (mirror index_handler's FEAT-043
  branch). Honour the dev-tools/live-reload injection already done elsewhere.

* Resolution order for `/<p>`
  1. `<site>/<p>.st`            (reference -> reference.st)
  2. `<site>/<p>/index.st`      (guide/ -> guide/index.st)
  Trim a trailing slash. Only fire in AppMode::Dev. Path traversal guarded (no `..`).

* Acceptance
- `cargo run -- serve demos/spacetime-docs/` → GET /reference renders the
  reference.st page (cards present), 200; GET /missing still 404.
- The existing `/` (index.st) path is unchanged.
- Full lib + integration green; a server unit/integration test for the new route.
