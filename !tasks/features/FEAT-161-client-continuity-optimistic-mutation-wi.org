* Problem
The substrate is already right (phx-update="ignore"; Spacetime's signal
renderer patches exactly the bound nodes — finer-grained than HEEx diffing).
But the .st AUTHOR has no spelled-out machinery for the three things that make
a data-fed client feel alive: (a) acting before the server answers, (b)
moving smoothly between two server states, (c) ephemeral local-only
interaction (your own cursor, hover ghosts) that never touches the wire.

* Deliverable — three patterns, each landing as stdlib machinery + tests, not
demo-only code:

1. *Optimistic mutation with reconciler rollback.* @handle's optimistic arm
   already exists; this FEAT makes the round-trip sound over the live
   transport: fire → apply optimistic value immediately → correlated {:reply}
   confirms (keep) or a rejection/Fail arm restores the pre-fire value
   (rollback). Deliver as a documented, tested pattern in
   stdlib/primitives/signal.st (a `send emit … optimistic:` affordance or a
   composeable @handle idiom — pick per the elegance bar: prefer the idiom if
   zero new grammar). Server must be able to REJECT an event with a tagged
   reply ({:reply, %{tag: "err", reason: …}}) — already possible post-FEAT-137.
2. *Animated transitions between server states.* When a subscribed assign
   diff lands (FEAT-159), the affected view transitions via @clock/@timeline
   (docs/testing/ANIMATION.md) instead of snapping: a card that moved columns
   on someone else's screen GLIDES. Deliver the stdlib affordance that binds a
   signal-write to a timeline (FLIP-style: measure old position → apply new →
   animate the delta), testable with @clock virtual time.
3. *Ephemeral presence channel.* Cursor trails and drag ghosts: high-frequency
   ephemeral payloads that other clients see but the server never persists.
   LiveView-native answer: Phoenix Presence + push_event relay (server relays
   without storing) decoded via the @data stream surface (FEAT-160). Local
   cursor rendering is pure .st (no wire). Rate-limit/coalesce in the bridge
   (one outbound frame per animation frame, latest-wins).
