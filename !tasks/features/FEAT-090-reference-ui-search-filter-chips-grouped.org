* UX spec (the delight)
1. SEARCH: ~@data inline $q : ""~ + ~<input class="ref__search">~ with two-way
   bind ~value <- $q; @on input { $q <- value }~ (verified pattern, stdlib/macros/data.st:30).
2. FILTER CHIPS: ~@data inline $kind : "all"~; a chip row (all/data/events/scene/
   text/test/animation…) each ~@on click { $kind <- "data" }~; active chip styled
   via the signal.
3. GROUPED CARDS: ~@data dispatch $macros from …~ (FEAT-089) →
   ~@each-filtered($macros as $m, when match($q,$kind,$m))~ → ~&macro-card($m)~.
   @each-filtered reactively display:none's non-matches as $q/$kind change
   (stdlib/macros/each.st:103) — LIVE SEARCH/FILTER, ZERO CUSTOM JS.
   The ~when~ expr: ~($kind == "all" || $m.kind == $kind) && ($q == "" ||
   $m.name.includes($q) || $m.directive.includes($q))~ (expr is JS-evaluated).
4. CARD: directive chip + signature rendered from ~$m.tokens~ (one styled <span>
   per token by role: $binding teal · :type dim · literal bright · ? ghosted ·
   delim faint). One-line doc. Hover lift (@on hover).
5. DETAIL EXPAND: ~@on click~ on a card toggles a per-card open signal (or a single
   ~$openMacro~ holding the active name) → reveals full signature + rendered
   ~@doc(content: $m.doc)~ (FEAT-086 md module) + scopes + %binds target + (if
   FEAT-091 landed) the dispatch probe. @scroll / transition for delight.

* Form-signature chip rendering (the scannability win)
Render ~$m.tokens~ (FEAT-089 structured tokens) with @each into per-token spans:
~@each($m.tokens as $t) { <span class="sig sig--$t.role">$t.text</span> }~.
CSS classes sig--directive/binding/type/literal/optional/param/delim carry the
palette. A signature becomes a row of colored chips, not a string.

  lands, cards become SEO/no-JS-correct for free.
- ~$m.tokens~ nested-array @each inside a &template body: verify the nested @each
  hydrates (it may hit FEAT-085 too). FALLBACK: render the flat ~$m.signature~

- Search over a large catalog (~300 macros): @each-filtered display:none is O(n)
  per keystroke but fine at this scale; no virtualization needed.
