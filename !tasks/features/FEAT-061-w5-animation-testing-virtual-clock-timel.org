* Why it's a moat
Traditional tools assert on wall-clock-sampled PIXELS: flaky, slow, endpoint-only.
Owning the drivers + clock lets us assert the ANIMATION ITSELF: exact curve value
at t, monotonicity, overshoot, stagger deltas, frame budget — none expressible in
Playwright-alone.

* Virtual @clock (the spine — K2 approved)
- Inject a test-controlled clock seam at the RAF coordinator: in test mode, =rAF=
  is driven by the harness, not the browser. Drivers already accept settable
  progress; route both JS-drivers and WAAPI (=Animation.currentTime= / =timeline=)
  through the seam.
- Surface:
  - =@clock advance <time>= — step virtual time deterministically.
  - =@clock run-to-end= — run until all drivers complete.
  - =@clock sample <n> frames= — step n frames, recording each.
  - works on BOTH backends: logic (fake-but-seekable) for curve math; CDP/timing for
    real layout-coupled timing.

* Timeline sampling + assertions
- =@record-timeline <name> as $t= — capture =ST._timing.driverUpdates[name]= as a
  sampled {t, progress} series.
- claim forms over a timeline (extend W3 grammar):
  - =deltas all >= 0= (monotonic), =overshoot == 0=, =ends-at == 1.0=,
  - =mean-delta ~= 30ms ± 3=, =progress all in 0..1=.
- =@then @frame-budget { max-delta < 20ms; dropped-frames == 0 }= from
  =ST._timing.report()= (jitter/fps already computed).
