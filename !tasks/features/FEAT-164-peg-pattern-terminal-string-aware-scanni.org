* Initial Message

Wave 0 of PLAN-122 (native CSS value types). The PEG combinator engine (%capture_type) has no char-level terminal: leaves today are ident/string/number/expr/balanced/skip_block etc. (src/parser/meta_ast.rs CaptureType enum). Hex colors (`#e8eef7` — 3/4/6/8 hex digits) are inexpressible: `#e8eef7` lexes as HASH+IDENT but `#123456` as HASH+NUMBER, and a PEG cannot count digits. This FEAT adds the ONE new engine leaf that turns every domain-lexer concern into stdlib data, plus fixes the string-awareness bug class that would otherwise ship inside typed seeds.

* Target

- src/parser/meta_ast.rs — CaptureType: add ONE data-parameterized variant (e.g. Pattern(PatternSpec)), sibling to how Balanced(char) is parameterized. NOT one variant per domain type — this is the last leaf the engine ever needs.
- src/syntax/events/extractors/custom.rs — BalancedExtractor: string-aware scanning.
- src/syntax/events/form_compiler.rs — compile `%char_class` / pattern productions from stdlib.
- Kernel number token (src/syntax/cst/lexer.rs) — audit only this wave.

* Change

1. Pattern terminal: char classes ([0-9a-fA-F]), counted repetition ({3|4|6|8} — exact-set counts, not just {n,m}), literal chars, ordered choice. REGULAR-ONLY: no backreferences, no nesting → guaranteed linear time (PLAN-122 C8). stdlib authors must not be able to write catastrophic-backtracking lexers.
2. Case-fold flag on patterns and keyword sets: CSS units/functions/keywords are ASCII case-insensitive (RGB(), PX, RED are legal). Declared once on the terminal, not per-grammar (C9).
3. String-aware balanced/pattern scanning (C1): delimiters inside string literals must not split. This is the BUG-225 / BUG-040 / BUG-041 class — RED repros already exist in the tracker; adopt them as this FEAT's regression tests. Without this, typed seeds like { quote: "a;b" } ship a silent-corruption class.
4. AUDIT kernel number token (C2): CSS numbers include -5px, +.5rem, .5, 1e3px (sign, leading dot, e-notation). Verify the number token covers the CSS <number> production BEFORE any lexer cutover; fix now if short so the W3 golden baseline isn't wrong.
5. AUDIT unit-bag fossils (C7): the global merge list (lexer.rs:252-264) includes `m` — CSS has no `m` (only s/ms). Grep stdlib/demos/examples/tests/projects for bare-`m` duration literals and decide: minutes-extension (declare in %unit_set) or fossil (fix call sites). Must be settled before %unit_set time { s ms us fps } freezes in W1.

* Edge

- Pattern terminal operates on RAW TEXT spans, not lexer tokens → the lexer's context-sensitivity (COLOR only in value position, lexer.rs:405-420) becomes unnecessary later; don't build on token kinds.
- First-char dispatch keeps PEG cost bounded: a grammar only tries `#`-led productions where a color leaf is expected. Memoize at # / number starts.
- Error messages are DATA on the terminal ("expected 3/4/6/8 hex digits") — diagnostics quality is part of the deliverable, gate on diagnostics snapshots.

NOTE [2026-08-02]: 2026-07-31 SOURCE RE-VERIFY before implementation — this FEAT is SMALLER and more precisely located than filed. Three corrections:

(1) `CapturePatternAst::CharClass { chars, negated }` ALREADY EXISTS (src/parser/meta_ast.rs) with a working parse surface (src/parser/mod.rs) and a compiled `CharClassExtractor` (src/syntax/events/extractors/custom.rs:796). So "add char classes" is DONE. What is missing for a hex-colour grammar is only: (a) COUNTED REPETITION — CaptureModifier has Required/Optional/ZeroOrMore/OneOrMore, no `{3|4|6|8}` counted form, which is exactly what a hex literal needs; (b) a CASE-FOLD flag; (c) CharClassExtractor matches only the FIRST CHAR OF A TOKEN and consumes the whole token (`text.chars().next()`), so it cannot walk digits within a token — a counted-rep hex match needs sub-token, byte-level scanning.

(2) `BalancedExtractor` IS ALREADY string-aware AND comment-aware (custom.rs:574-690): it byte-scans from the first token's offset, skips '"'/'\''/'`' strings with backslash escapes, skips // and /* */ comments, and bounds the scan to the token slice. That work landed with BUG-100/BUG-225. Crack C1 as originally written ("balanced is not string-aware") is therefore ALREADY FIXED for the extractor path. Do not redo it.

(3) BUG-040/BUG-041 are NOT in the extractor — they are one layer lower, in `emit_body` (src/syntax/events/grammar/meta.rs), which counts L_BRACE/R_BRACE TOKENS produced by the Spacetime lexer. A JS regex char class containing a quote or backtick (/[&<>"']/g, /(['"`])/g) makes the LEXER open a STRING token that swallows braces, so the depth counter never reaches 0 → "expected R_BRACE, found EOF" (BUG-040) or a silently dropped primitive (BUG-041). The fix is the same SHAPE as the one BalancedExtractor already uses — byte-level scanning with foreign-code awareness (JS strings, template literals, regex literals incl. char classes, comments) instead of trusting Spacetime STRING tokens inside a foreign-code body. BUG-040's own "Option A/B" analysis says exactly this.

REVISED SCOPE for this FEAT: (i) counted repetition `{n}` / `{a|b|c}` on capture modifiers + byte-level sub-token matching in CharClassExtractor + case-fold flag — the minimum that makes a hex-colour grammar expressible in stdlib; (ii) foreign-code-aware emit_body scanning, closing BUG-040 + BUG-041 (the RED gates); (iii) the C2 number-completeness and C7 unit-fossil audits, unchanged. Note (i) and (ii) share the principle "a delimiter's meaning belongs to the grammar that owns the text, not to the outer lexer" — which is PLAN-122's thesis in miniature, arriving twice.
