`unroll_static_each` (src/html/ssg_unroll.rs) SSG-unrolls an `@each` whose body is INLINE HTML (`@each($xs as $x) { <li>\`$x\`</li> }`) but NOT one whose body is a TEMPLATE INVOCATION (`@each($xs as $f) { &feature-card($f); }`). The latter renders only via client-side hydration, so the cards are absent from the static (no-JS / SEO) HTML.

REPRO: demos/spacetime-docs uses `@data registry $features` + `.grid { @each($features as $f) { &feature-card($f); } }`. Served HTML has an empty `.grid`; a real browser hydrates 85 cards. An inline-HTML body (`<article>...</article>`) DOES unroll statically (proven in FEAT-084 tests).

WHY: the unroller needs each-body row HTML at compile time. For a &template call it would have to resolve the template definition + substitute the row's fields into the template's markup (the template is known at compile time; the loop var fields come from the static array). Doable, just not implemented.

IMPACT (#C): cosmetic for reactive pages (hydration fills them), but breaks the SSG/SEO/no-JS guarantee for template-bodied lists. The docs gallery currently relies on hydration.

FIX DIRECTION: in unroll_static_each, when the each-body is a single `&name(args)` invocation, look up the template's markup, substitute `$f.field` holes per row, emit the rows \u2014 the same unroll==hydrate invariant the inline path guarantees.
