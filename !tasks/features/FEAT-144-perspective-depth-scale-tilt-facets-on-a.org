* Parent
FEAT-142-spatial-ecs-scene-entities-as-named-sele (Spatial ECS). This is a Wave-G+ follow-on:
the typed `@anchor`/`three-anchor` mechanism already tracks a world point's SCREEN position
and VISIBILITY per frame (Wave 1/D), but throws away the depth/off-axis information the
`vec3.project(camera)` call already computes. Anchored text today is a flat 2D billboard that
happens to move — it doesn't feel like it is IN the perspective field.

* The gap (verified in repo, not guessed)
`three-anchor.st` (both projects/everswap-clone/lib/ and projects/spatial-showcase/lib/,
byte-identical copies) computes `v.project(camera)` each frame, reads `v.x`/`v.y` for screen
position and `v.z` only to test `behind = v.z > 1`. Camera distance-to-point and NDC offset
(the two things perspective/foreshortening/off-axis-tilt would derive from) are computed then
discarded. `%exports` currently publish only `$screenX/$screenY/$visible` (number/number/bool).

* The fix (reuses the EXACT existing mechanism, no new grammar)
Same `%emit js { ... %yield x -> $sig }` / `%exports { $sig: type }` / `%binds { prim(...) -> {
$sig } }` pipeline already proven churn-safe (R1, FEAT-142 note 2026-06-30) for
$screenX/$screenY/$visible. Add sibling facets, computed from values already in scope:
- `$depth`  : number 0..1 (near..far, from `camera.position.distanceTo(world)` + `near`/`far` params)
- `$scale`  : number (foreshortening, lerp(scaleNear,scaleFar,1-depth))
- `$tiltX`/`$tiltY` : number degrees (off-axis lean, derived from the SAME NDC `v.x`/`v.y` already
  computed for screen position — camera-relative, NOT terrain-normal, so L1 stays mountain-free
  per the FEAT-142 pressure-test battery)

Visual application is OPT-IN (`depth: bool = false` param on `@anchor`/`three-anchor`, default
false) so existing everswap-clone tuned legs are UNCHANGED: when true, the primitive composes
`perspective(900px) rotateX() rotateY() scale()` onto the SAME transform string it already owns
(compositor-only, matches the existing translate-only write). Additionally — ALWAYS, cheap,
harmless when unused — the primitive writes 4 CSS custom properties on the anchored element
every frame (`--anchor-depth/--anchor-scale/--anchor-tilt-x/--anchor-tilt-y`), the exact same
reactive-custom-prop pattern already established by `stdlib/syntax/element-ref.st` (`--st-name-width`
etc). This is the "bind to text" surface: any descendant text can read
`calc(var(--anchor-depth) * ...)` in PLAIN CSS — zero new Spacetime binding grammar, reuses the
custom-prop facet idiom that already exists.
