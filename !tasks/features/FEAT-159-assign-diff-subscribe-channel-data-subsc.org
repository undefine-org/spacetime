* Problem
Server→client state flows only as (a) the one-time mount seed (st-set) and
(b) {:reply} payloads to the page's own fires. Server-INITIATED assign changes
— PubSub broadcasts, handle_info, another user's action — never reach the
page. LiveView's core superpower (server-pushed reactivity) is unused.

* Deliverable
`@data subscribe $items from $board : items ;` in a .st page, wired end-to-end:

1. *Client surface (stdlib/primitives/signal.st + compiler).* New @data kind
   `subscribe … from $host : assign_name` (plus dotted sugar `$board.items` if
   the grammar makes it cheap). Registers the (host-module, assign-name, target
   signal) triple; bridge applies incoming diffs via ST.set. Unreferenced
   assigns are never wired — bandwidth win by construction (design §9.2).
2. *Server reconciler (Spacetime.LiveView).* Track pushed assign values per
   socket; on every render-worthy socket change, push ONLY the diff as st-set
   messages (data, never templates — principle 3). Subsumes FUP-129's
   auto-diff push_view: the seed becomes the first diff.
3. *Bridge (assets/js/app.js).* st-set handler already exists; extend to route
   by (module, assign) so multiple hosts/pages coexist (groundwork for
   FUP-124, full per-host scoping can land here if cheap).
4. *Contract rule (src/analysis/liveview_contract.rs).* E0928-family check:
   subscribe names ⊆ contract `assigns`. RED→GREEN: subscribe a name the
   server doesn't declare → compile error.
