* User intent
The user wants preludes, not one-off tools:
1. A general prelude to browse MCP environments and tabs.
2. A communication prelude with bindings/hosts that wire any bidirectional behavior Spell supports.
3. Function-template orientation: apps are composed by injecting functions into the environment; an updated function with the same contract fulfills the same role.

* Goal
Turn the MCP live environment into a self-hosting Spacetime workbench. The environment browser and interaction kit are themselves Spacetime functions mounted through the same generic function environment.

* Prelude split
** stdlib/__mcp__/host.st
Minimal communication substrate. No UI.
- Provides a host bridge primitive mirroring stdlib/__dev__/primitives/dev-ws.st.
- Exposes connection/capability/message signals.
- Sends envelopes to the generic /__mcp/signal/{instance} sink.
- Receives server->page stream messages when supported.
- Later becomes the implementation substrate for canonical @host $mcp / @data signal/stream.

** stdlib/__mcp__/env.st
Workbench/browser prelude. UI built from templates/functions.
- Browse discovered/open environments.
- Browse tabs.
- Browse registered functions and revisions.
- Browse mounted instances and event history.
- Mount or update a function.
- Inspect contracts, diagnostics, and emitted events.
- Uses host.st and the same generic function APIs; no parallel admin protocol.

** stdlib/__mcp__/kit/*.st
Reusable ad-hoc agent interface functions.
- picker.st — choose one of N options.
- form.st — typed form.
- confirm.st — yes/no decision.
- review.st — structured review/approval flow.
Each function declares/uses the same contract vocabulary and emits through host.st.

* Repair note — honest FEAT-123 S0 syntax (2026-06-15)

The previous browser demo overstated the state of the syntax. Re-checking the original plan and the emitted code showed that the parameterized `@mcp-click`/`@mcp-on-click` idea was not actually expanded by the current module/import path, so it must not be claimed as shipped.

Current accepted S0 syntax is deliberately smaller and verified:

#+begin_src st
@import "stdlib/__mcp__";

<button
  data-mcp-event="clicked"
  data-mcp-correlation="review-1"
  data-mcp-value="approve">
  Approve
</button>

@mcp-host
#+end_src

Meaning:
- Normal HTML declares the event contract via `data-mcp-*` attributes.
- `@mcp-host` installs the host bridge and delegates clicks from `[data-mcp-event]`.
- JS lives only inside `stdlib/__mcp__/primitives/host.st`.
- The bridge POSTs one envelope to `/__mcp/signal/{instance}`.

Verification performed:
- `cargo run -- check scratch/mcp_click_smoke.st` PASS.
- `cargo build` PASS.
- `cargo run -- inspect --layer emit scratch/mcp_click_smoke.st` shows the emitted delegated `[data-mcp-event]` handler and `/__mcp/signal/` POST.
- Live `inst-1` updated to `fn-1` revision 9 with this syntax.
- Browser observed heading `honest MCP click syntax`, button `data-mcp-event=clicked`, and `window.__stHost.instance=inst-1`.
- Browser click produced MCP events; latest inspected event: `type=clicked`, `payload.text="Send MCP message"`, `payload.value="demo"`, `correlation="inst-1-click"`.

Known limitation:
- A parameterized `@mcp-click(...)` macro is not shipped. It belongs later in FEAT-123 only after `inspect --layer emit` proves the macro actually expands to the `mcp-click` primitive. Until then, the honest syntax is `data-mcp-event` + `@mcp-host`.

* Repair note — remove data-mcp-* anti-pattern (2026-06-16)

The `data-mcp-* + @mcp-host` syntax was still wrong for the plan. It encoded MCP behavior in HTML attributes instead of a Spacetime directive/prelude. That is an anti-pattern.

Corrected FEAT-123 S0 syntax now uses a selector-scoped directive over a primitive:

#+begin_src st
@import "stdlib/__mcp__";

<button class="approve">Approve</button>

.approve {
  @mcp-click(type: "approved", correlation: "review-1", value: "approve")
}

@mcp-host
#+end_src

Implementation:
- `stdlib/__mcp__/primitives/host.st` owns all JavaScript in `%primitive` blocks.
- `@mcp-host` is file-scoped and installs `window.__stHost` for the mounted instance.
- `@mcp-click(...)` is selector-scoped and expands to `mcp-click-event(&self, ...)`.
- No `data-mcp-*` attributes are required or used by the public syntax.
