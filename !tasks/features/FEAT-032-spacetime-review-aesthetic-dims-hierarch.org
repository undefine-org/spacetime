* Intention & Purpose

Extend =Spacetime.review()= from 5 dimensions (idiomatic / animation / brand / a11y / compile) to 7 by adding two *aesthetic* dimensions: =hierarchy= and =detail-execution=. The current 5 dims are all *engineering correctness* checks (does it parse, does it animate, are tokens used, is alt-text present, are there console errors). The huashu-design analysis (this session) showed spacetime-design has zero coverage of "does it look good"; this FEAT closes that gap with two heuristics that are runtime-detectable.

* Context & Narrative

Two new dims use heuristics the dev runtime CAN observe (DOM + computed styles), as opposed to philosophy-coherence / innovation which can't be auto-detected:

*hierarchy* dim:
- h1 → h2 → h3 ordering (no skips; no h2 before h1; no multiple h1 unless explicit landmarks).
- Font-size monotonicity: each heading level's computed font-size strictly smaller than the previous level.
- Findings cite violating selector + computed font-sizes.

*detail-execution* dim:
- =text-wrap: pretty= or =text-wrap: balance= present on display-class headings (heuristic: text > 12 chars, font-size > 24px). Absent → info-severity.
- =oklch()= color usage on tokens (preferred over rgb/hsl). Warn if =--brand-*= tokens use rgb/hsl/hex without oklch fallback.
- =var()= coverage on font-family declarations: warn if heading font-family is literal string instead of =var(--brand-display)=.

The 5-dim score formula =clamp(10 - errors*2 - warns, 0, 10)= extends to 7 dims unchanged. Top-level score still = =min(dim scores)=.

The runtime walker lives in =stdlib/__dev__/primitives/dev-review.st= alongside existing =auditIdiomatic / auditBrand / auditAnimation / auditA11y / auditCompile=. Two new functions: =auditHierarchy= and =auditDetail=. Both run on same 250ms cache cycle.

The dev-panel "Review" tab (=stdlib/__dev__/primitives/dev-review-tab.st=) needs 2 new rows in dim-summary table.

The doc-only doctrine (philosophy-coherence + innovation as named-but-not-walked) is documented in =review-rubric.md= as "human-only review dims".

* Edge Cases

- *Walker performance regression*: 7 dims at 250ms cache, ~36µs each at p50. Test against =projects/dataiku/= (1.2 MB runtime); fall back to lazy walker if eval thread times out.
- *getComputedStyle expensive*: cache per heading; bail early on text-length / font-size threshold.
- *Brand-token enumeration via :root*: only sees applied tokens; scoped tokens missed. Document.
- *oklch detection naive*: =val.indexOf('oklch') === -1= treats =oklch( ... )= as good. Doesn't catch =oklch(0 0 0)=. Acceptable precision limit.
- *Text-wrap browser support*: feature-detect; if unsupported, emit single info "text-wrap detection unavailable".
- *Inline font-family detection captures component libraries with legitimate inline styles*: false positive risk. Mitigation: only flag h1-h3, not all elements.
- *Dim doctor pass/fail blast radius*: existing projects may now fail on hierarchy/detail. Document findings as project-side debt; not a regression.
- *Conflict with FEAT-031*: FEAT-031 documents visual rules; this FEAT operationalizes a SUBSET (oklch, inline font-family). Cross-reference FEAT-031 from rubric doc.
