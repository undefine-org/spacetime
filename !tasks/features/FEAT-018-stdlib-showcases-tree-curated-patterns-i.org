* Scope

In-scope:
- New tree =stdlib/showcases/= containing self-contained pattern files.
- Eight scenarios × three styles (24 files), modeled on huashu-design's showcase grid:
  - Scenarios: =hero=, =nav=, =features-grid=, =cta=, =footer=, =gallery=, =form=, =reveal-on-scroll=.
  - Styles: =minimal=, =editorial=, =maximal=.
  - File path: =stdlib/showcases/<scenario>/<style>.st=.
- Each showcase file:
  - Self-contained: a single `@template` or `@fn` that, when imported and invoked, produces the demonstrated pattern.
  - Top doc comment: scenario, style, dependencies (other showcases, stdlib macros), screenshot path, one-line "use when".
  - No bespoke JS; only stdlib + showcase-internal primitives.
- Index file =stdlib/showcases/index.st= that `@import`s all showcase files and exposes a registry macro `@showcases` enumerating them with metadata for the dev panel + CLI to read.
- Catalog file =stdlib/showcases/CATALOG.md= (human-readable): table of scenario × style with one-line description and link to source file.

Out-of-scope:
- Per-showcase screenshot generation (covered by =cargo run -- showcase= CLI in FEAT-019, which renders each showcase headlessly).

* Edge Cases

- Showcase imports another showcase: dependency MUST be declared in doc comment; index must `@import` deps before dependents (file order).
- Scenario × style combination genuinely doesn't make sense (e.g. =reveal-on-scroll= × =minimal= where motion conflicts with minimal aesthetic): still ship a credible variant; document trade-off in `useWhen`.
- Tokens: each style SHOULD declare its own token vars under `:root { --showcase-<style>-... }` to demonstrate the brand-protocol pattern from FEAT-021's skill.
- Fixtures grow large: keep each fixture <30 lines; use `@import` to point at the showcase rather than copy.
