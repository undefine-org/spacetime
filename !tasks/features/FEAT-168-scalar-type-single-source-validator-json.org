NOTE [2026-08-06]: POST-LANDING AUDIT (same session) — the wave's own acceptance test was FALSE when
first claimed. Fixed in 2d82722c.

I verified the four Rust maps I set out to replace and stopped there. A scalar
answers a FIFTH question — what SHAPE its captured value takes — and that one was
still a hardcoded match arm in `wrap_reifier`
(`src/syntax/events/extractors/custom.rs`):

    "color" | "length" | "duration" | "time" | "angle" | "percentage" | "easing"

So the wave that deleted six hand-synced scalar lists SHIPPED A SEVENTH, inside
itself. The acceptance test passed because it only checked type recognition,
schema, zero and widget — never the value's shape.

Measured, not assumed. A probe `%scalar_type resolution` added purely as stdlib
data:

    length     8px   -> String("8px")                  (in the list)
    resolution 96dpi -> Named({n: 96.0, u: "dpi"})     (not in it)

Downstream that record becomes `NaN` in an animation or an E0800 colour-parse
error — far from its cause, and `check` reports nothing.

FOUR ROWS WERE ALSO MISSING: `time`, `angle`, `percentage`, `easing` had
grammars and appeared in the hardcoded list but had no `%scalar_type` row. The
new gate caught this by FAILING on `percentage` before I had noticed. A name that
resolves to a grammar but has no row parses fine and then flattens differently
from its twin — the exact silent gap this wave exists to close.

IMPLEMENTATION NOTE for anyone extending this: the predicate must read
`STDLIB_REGISTRY`, NOT `cached_stdlib_registry()`. `wrap_reifier` runs WHILE the
meta registry is loading, so the cached accessor re-enters `INCREMENTAL_CACHE`'s
mutex and DEADLOCKS — observed as a test that hangs forever rather than an error,
which is why it is worth writing down. The scalar captures now ride the same
bootstrap path as the `%capture_type` definitions they name.

LESSON: an acceptance test that is a NEGATIVE ("adding a row needs zero Rust") is
only as good as the set of behaviours it exercises. Mine exercised four of five.
The generalisable form: enumerate every consumer of the thing being centralised
BEFORE writing the acceptance, and make the acceptance assert on a NEW member
(the probe row), not on existing ones — existing members pass through the old
hardcoded path and prove nothing.
