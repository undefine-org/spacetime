#+BEGIN_SRC

  @given (r = take(xs, n))
  @then r { count <= xs.length }
}
#+END_SRC

BLOCKED (the @property / @fuzz MACROS): the macros parse + resolve, but the emit
cannot bind the generated value. Two metasystem gaps hit (same family as W3's
FEAT-065):
1. `forall (n: int 0..100)` parens are consumed as an ARG_LIST so a plain
   `$name:ident : $spec` capture eats the whole `(n: int 0..100)` (name=Expr,
   spec empty). `forall($b:params)` (no space, @fn-style) DOES capture cleanly as
   Params([{name:"n", type_ref:"int"}]) \u2014 but then:
2. structured-capture FIELD ACCESS in %emit is unsupported: `%$binding.0.name` /
   `%$binding.0.type_ref` produce empty emit (same one-level/array-index limit as
   the W3 claim grammar's `%$c.prop`).
So @property/@fuzz need: (a) a single-binding capture that survives the form
parens, and (b) structured field access in %emit (or %for over the binding). This
is the SAME metasystem unlock as FEAT-065. The runtime + fuzz infra above is the
ready substrate; only the macro->emit binding remains.

The `..` range syntax also breaks the `params` capture_type (expects clean
`name: type`); the spec parser handles ranges, so the binding just needs to carry
the raw spec text through.
