* Summary
The two composition primitives the schema-driven admin uniquely needs, plus recursion.
User decision 2026-06-06: implement BOTH surfaces; @match LOWERS to dispatch; keep it
general; implement in Spacetime (stdlib macros + meta-compiler capture), extending the
meta-compiler as required.

1. *Dynamic dispatch* =&$expr(args)= — invoke a template whose NAME is a runtime value.
   #+begin_src spacetime
   .h { &$node.widget($node, $value); }   // widget name chosen at runtime
   #+end_src
2. *@match as render* — emit a template per arm; lowers to dispatch.
   #+begin_src spacetime
   @match $node.widget {
     "media"    => &media-field($node, $value)
     "relation" => &relation-field($node, $value)
     _          => &text-field($value)
   }
   #+end_src
3. *Recursion* — a template may invoke itself (directly or mutually). Required for
   nested schema (field → fieldset → field → list → field). Factories already register
   by name in =Spacetime.templates= (a Map), so lazy name resolution at call time is
   cycle-safe; the work is grammar recognition + a compile-time depth/cycle guard.

* Why these are absent today (verified 2026-06-06)
=&$w()=, =@match ... => &t()=, and =&self()= all currently parse WITHOUT error but are
swallowed into the template html field as literal text (zero codegen). check passes;
nothing runs. BUG-059's segmenter must recognize them as typed segments; this FEAT
implements their LOWERING.

* Design — dispatch
- Grammar: =&$<expr>(<args>);= where =<expr>= yields a string template name. Restrict
  =<expr>= to a binding/field-access shape (=$x=, =$x.field=, =$item.kind=) initially —
  NOT arbitrary JS — to keep it analyzable; widen later if needed (OPEN QUESTION in
  PLAN-030). Emit: =Spacetime.invokeTemplate(<expr>, <args>)= appending to the scoped
  container (reuse invoke-template primitive path).
- Validation: if =<expr>= is a literal string, resolve at compile time and validate the
  template + arg arity exist (same checks as static =&name()=). If dynamic, defer to
  runtime with a dev-mode warning when =templates.get(name)= is missing.

* Design — @match-render
- New macro =@match $sel { <lit> => &tmpl(args)  ... _ => &tmpl(args) }= distinct from
  the state-machine =@match= (which lives in state-machine.st and matches union
  variants). This is a RENDER construct in selector/template-body scope.
- Capture: arms as a list; reuse =CaptureType::Template= per arm or add a =MatchArms=
  capture (OPEN QUESTION — decide by what the segmenter can cleanly produce; prefer
  reusing TemplateInvocation per arm to avoid a new CaptureType if possible).
- Lowering: a =switch=/if-chain on the evaluated selector that calls the matching arm's
  template (i.e., dispatch). =_= is the default arm. Reactive: if the selector is a
  signal, re-render on change (mount/unmount the matched template) — model on bind-if.

* Design — recursion
- Allow a template body to reference its own name (or a mutually-recursive name).
  Resolution is lazy (Map.get at invoke time), so definition order/cycles are fine.
- COMPILE-TIME guard: detect a static self/mutual cycle and require a base case guarded
  by =@if=/=@match= (cannot statically prove termination, so EMIT a runtime depth cap +
  a dev-mode diagnostic when exceeded). Depth cap default (e.g. 64) overridable.
- Diagnostic E-code: unbounded recursion without a conditional guard → warning at
  compile, hard cap at runtime (never a stack overflow).

* Edge cases
- dispatch name not found at runtime → dev warning, no crash, no partial DOM.
- @match with no matching arm and no =_= → render nothing (document this).
- @match selector is a signal → re-render swaps the mounted arm; old arm cleaned up.
- recursion base case via @if false → stops; via @match =_= → stops.
- mutual recursion A→B→A with a guard → terminates; without → depth cap + diagnostic.
- args forwarding: =&$w($node, $value)= passes through positional + named args intact.

* COURSE CORRECTION (2026-06-07) — idiomatic metasystem, html5ever, NO Rust per-construct

** What was wrong
The first FEAT-073 attempt added per-construct RUST: `ComponentMatch`/`MatchArm` structs
(form_match.rs), `parse_match_block` + `&$` detection (form_compiler.rs), E0402 carve-outs
(mod.rs). This is a DUAL implementation competing with the metasystem — forbidden by
AGENTS.md ("DO NOT write Rust parsers/fallbacks for constructs defined in stdlib") and
metasystem/ARCHITECTURE.md ("Adding a new @directive: define primitive/macro/capture_type
in .st — NO Rust code changes needed").

** Root cause of the temptation
A @template body is `$body:component_body`, and `component_body` is a RUST-BUILTIN
`CaptureType::ComponentBody` parsed by the monolithic ~700-line `parse_component_body`
(form_compiler.rs). So every template-body construct currently MUST be hand-coded in Rust.
parse_component_body IS the central clash: a Rust re-implementation of grammar that should
be composed stdlib `%capture_type`. (Same for template_invocation/template/html_block —
all Rust-builtin; whereas on_action/keyframes/mutation are correctly stdlib %capture_type.)

** Corrected architecture (user-directed)
FULL self-describing, using html5ever (already a dep: html5ever 0.39 + lol_html 2; mature
src/html/ module with treesink.rs/parser.rs/selector.rs to reuse):
- A thin, construct-AGNOSTIC segmenter (the BUG-059 scanner, generic infra — KEEP) splits a
  template body into HTML-runs vs Spacetime-construct segments.
- HTML-runs → html5ever (spec-correct: void elements, raw-text, quoted attrs) — DELETE the
  bespoke scan_html_tag tag-walking.
- construct segments → generic %capture_type engine driven by stdlib definitions:
    %capture_type component_body { ( $item:component_item )* }
    %capture_type component_item { state_decl | injection | class_toggle | on_block
                                   | template_invocation | dispatch | match_block | html_run }
    %capture_type match_block { "@match" $subject:expr "{" ( $arms:match_arm )* "}" }
    %capture_type match_arm  { $pat:match_pat "=>" $inv:template_invocation ";"? }
- @match / &$expr dispatch / recursion-base-case → pure .st (%capture_type + %macro +
  %primitive %emit js). The runtime logic lives in %primitive %emit js (where it belongs),
  fed by metasystem-parsed data, NOT Rust structs.
