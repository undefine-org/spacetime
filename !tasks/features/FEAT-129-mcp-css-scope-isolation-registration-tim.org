* Summary
Isolate each bundle's CSS by wrapping it at registration in native =@scope ([data-st-region="{id}"]) { ...bundle css... }=. Two-tier: chrome CSS unscoped (page-level); bundle CSS scoped per region. v1 lint warns authors off the two known gaps (top-level @keyframes, :root custom properties). The PROPER =@scope= macro is [[id:FUP-062-css-scope-at-rule-as-a-spacetime-macro][FUP-062]] (replaces this special-case when it lands — harmony).

* Why
CSS is page-global today (recon-verified); two bundles' =.button= rules would collide (last-write-wins). Region-nesting requires per-origin CSS confinement. Native =@scope= does this without Shadow DOM (keeps DOM inspectable, keeps ST.watch/@view working). No class mangling.

* Target
- =stdlib/__mcp__/= (registerBundle helper, FEAT-126) — wrap bundle css string in =@scope ([data-st-region="{id}"]) { ... }= before injecting into the page <style>.
- =src/mcp/= (or compile-time lint) — warn on top-level @keyframes and :root custom-property declarations in a bundle's css.

* Edge
- Bundle css with no selectors -> empty @scope block, harmless.
- :root/body/html rules in bundle css -> stripped or warned (bundles must not touch chrome).
- @keyframes collisions -> lint warns (FUP-062 fixes properly).

* Acceptance
- Headless: two bundles both defining =.button=; mounted in two regions; styles do NOT collide (each region's .button gets its own bundle's rule).
- Lint emits warnings for top-level @keyframes / :root vars in a bundle.
- =cargo test= + headless green.
