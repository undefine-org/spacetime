* Problem
The contract sidecar (frontend/CounterLive.contract.json) is HAND-WRITTEN —
the server knows its events/assigns but doesn't SAY them, so the shared schema
can drift from the server silently. And LiveView's third message kind,
push_event (transient effects: toasts, "someone else moved this card",
confetti), has no typed surface at all — modelling it as an assign reintroduces
the sticky-state bug (effect re-fires on reconnect because assigns replay).

* Deliverable — both directions of "the compiler proves the seam":

1. *Server-side typed DSL (extends FEAT-139).* `use Spacetime.LiveView` grows
   declared sections:
     events  do event :move_card, card_id: :string, to: :atom end
     assigns do assign :items, :list ; assign :presence, :map end
     pushes  do push :flash, message: :string, kind: :atom end
   A `__spacetime_contract__/0` callback (Spark transformer or plain macro —
   pick whichever the codebase already leans toward) introspects the module and
   EMITS <Module>.contract.json (mix task `mix spacetime.contract` writes it
   into frontend/). Hand-written sidecar is deleted; the server is the source
   of truth. Compile-time warning when the emitted contract changed but the
   .st side wasn't rebuilt (fingerprint already exists — counter-v2).
2. *Typed pushes + @data stream (client).* New @data kind
   `@data stream $fx from $board { receive to Effect { "flash" => Flash($.payload); … } }`
   — the SAME receive-arm matcher as signal replies (principle 4),
   discriminator = push event name. Bridge routes push_event (this.handleEvent
   in the hook) to the stream's publishReply: uncorrelated, fire-once, NEVER
   replayed on reconnect. Server push_event calls are arity/type-checked
   against the declared pushes section.
3. *Contract completeness.* E0928-family rules now cover all three kinds:
   send emit ⊆ events (exists) · subscribe ⊆ assigns (FEAT-159) ·
   stream receive tags ⊆ pushes (new). Renaming anything on either side turns
   the other side's build RED.

* Tests
- mix: contract emission task produces JSON identical to the module's declared
