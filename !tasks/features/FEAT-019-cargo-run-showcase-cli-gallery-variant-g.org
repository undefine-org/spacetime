* Scope

In-scope:
- New CLI subcommand: =cargo run -- showcase= with three forms:
  1. =cargo run -- showcase= (no args): prints catalog table to stdout (scenario, style, description, file path).
  2. =cargo run -- showcase serve [--port 4444]=: boots a minimal dev server that mounts =stdlib/showcases/index.st= and renders a one-page gallery (card grid, 24 thumbnails). Reuses existing serve infrastructure.
  3. =cargo run -- showcase generate <scenario> [--styles minimal,editorial,maximal] --out <path>=: writes one file per requested style under `<path>/<scenario>__<style>.st`, each starting from the corresponding showcase template. Used by the skill's "fallback advisor" to spawn 3 differentiated variants.
- Output formats: pretty (default) and JSON (=--format json= for skill consumption).
- Reads catalog by parsing =stdlib/showcases/CATALOG.md= or, preferred, by parsing showcase doc comments via the same regex documented in FEAT-018's SCHEMA.md.

Out-of-scope:
- MP4/GIF export of showcases (huashu-design has it; not in our 80% target).
- In-browser side-by-side variant comparison ("design canvas") — design canvas overlay is a separate FUP.
- Editing showcases through the gallery (read-only browsing).

* Existing Patterns

- CLI subcommand registration: =src/main.rs= around lines 81-352 (existing `inspect` subcommand). Add `Showcase` variant to the enum and a `run_showcase()` dispatcher.
- Serve subsystem: =src/server.rs= already serves a project directory; reuse `compile_from_site()` and the static-file fallback.
- JSON output: existing =--format= flag in inspect (=src/cli/inspect.rs:37=). Mirror.
- Templating for generate: read the showcase file's bytes, swap a small set of comment-marker placeholders (`/* st-showcase:START */ ... /* st-showcase:END */`) — declared in FEAT-018's SCHEMA.
