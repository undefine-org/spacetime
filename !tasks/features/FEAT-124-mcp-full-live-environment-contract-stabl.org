* Goal
Complete the original vision: Spacetime MCP as a live coding environment and NREPL-like host where agents inject functions, humans interact through ad-hoc Spacetime interfaces, and the compiler's introspection makes every function testable, inspectable, and contract-stable.

* Final model
- Function source can be sent inline or referenced from stdlib/project files.
- The compiler extracts the contract: input params/types, required hosts, outbound signal/stream interfaces, response sums, docs, and tests.
- Updating a function with the same contract updates the implementation revision and preserves mount semantics.
- Breaking contract changes require a new revision with migration or a new function id.
- Mounted instances have inspectable state, events, diagnostics, and source maps.
- The environment can be used as:
  1. testing ground — mount functions with fixture inputs and run probes.
  2. ad-hoc agent interface — mount functions for human decisions or review.
  3. live coding/NREPL — redefine functions and inspect results.

* Scope
IN:
- Contract hash + compatibility checker.
- Function revision history and explicit update semantics.
- Instance remount/hot-swap policy.
- `st_inspect` deepening: contract/source/revision/events/diagnostics/state.
- Integration with reference.st so the same introspection rail documents signal interfaces.
- CDP-backed test/automation loop once PLAN-037 W3 lands.

OUT:
- Network/package distribution of third-party function libraries.
- Multi-user auth/permissions. Local MCP session only.

* Acceptance
- A function can be put, mounted, updated with compatible source, and inspected; existing instance semantics remain valid.
- A breaking contract change is detected and reported with a migration/remount requirement.
- reference.st/environment browser show the function's input and output contract from compiler data, not manually supplied JSON.
- Agent can mount an ad-hoc inline function, drive/await it, update it, and verify the same contract is fulfilled.
- Full MCP old surface collapse is complete: bespoke proposal/status/choose paths are gone or documented compatibility shims pending deletion.
