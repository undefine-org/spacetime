* Initial Message

Please explain the queue, the root causes for bugs and the strategy for features, and what each would enable. Explain how you would go about them.

* The gap

The runtime had two subscription primitives and neither expressed what animation
code actually wants:

| helper            | contract                                              |
|-------------------+-------------------------------------------------------|
| =ST.watch=        | tell me the value, INCLUDING right now, in ONE store   |
| =ST.watchScoped=  | tell me from ANY scope — once PER SCOPE                |
| (missing)         | tell me when the value GENUINELY MOVED, exactly once   |

Three primitives each needed the third and each hand-rolled it:

- =stdlib/primitives/signal-arms.st= — watch + =primed= flag
- =stdlib/primitives/animation/drivers.st= (change driver) — watch + =primed= flag
- =stdlib/primitives/effect.st= — document listener + watch + =primed= flag +
  a microtask gate to stop the two channels double-firing

All three got it wrong the SAME two ways (see BUG-252): bare =ST.watch= misses
ancestor/global ownership, and call-count priming eats the first change for any
signal this element does not own.

* Why a shared affordance, not three fixes

Per AGENTS.md §2 (one need = one implementation): the need is "a value moved".
Three copies of an idea is three chances to get it wrong, and the evidence is
that all three DID. The fix that only patches the three call sites leaves the
fourth author to re-derive it.

The affordance also DELETES machinery rather than adding it:

- =effect.st= loses its document listener, its =primed= flag, AND the microtask
  coalescing gate — the gate existed solely because two channels could deliver
  one change; with one channel there is nothing to coalesce.
- =signal-arms= loses its =primed= flag and its watchFn selection.
- the change driver loses its =primed= flag.

Net: one ~20-line runtime helper replaces three divergent hand-rolls and removes
a dedupe mechanism.

* Contract

#+begin_src js
ST.watchChanges(el, name, fn)  // fn(next, prev) — genuine changes only
#+end_src

- subscribes through =watchScoped=, so the WATCH mirrors the RESOLVE (FUP-094)
- primes from =ST.resolve= at subscribe time: STATE-based, not call-count-based,
  so it behaves identically for element-owned and globally-owned signals
- re-derives each delivery through =ST.resolve= — the same lookup the author's
  expression uses — so a fan-out delivery from a non-owning scope cannot report
  a value the author would never read
- suppresses no-op deliveries, which also absorbs watchScoped's per-scope fan-out

* Open question for review (blocking)

=effect= previously subscribed via a document listener AND fired on a microtask.
Collapsing it changes observable TIMING: the body now runs SYNCHRONOUSLY on the
write instead of on the next microtask. That is a behavior change to a shipped
feature (FEAT-074) and it broke =feat074_effect_emits_subscription_and_body=,
which asserts the emitted source contains the document listener.

Two readings, materially different — see the analysis in the session; user
decision required before commit.
