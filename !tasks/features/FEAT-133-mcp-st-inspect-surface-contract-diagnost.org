* Initial Message

Test drive the Spacetime MCP workbench and list all the actions and their expected vs. actual output. The workbench should end up feeling like a mix of Spacetime+Squarespace+Figma/Framer in the end, and it doesn't. This is a REVIEW+DESIGN+BRAINSTORM session

* Summary
`st_inspect` returns only a one-line summary ("Function fn-2 revision 1." / "2 function(s), 1 mounted instance(s)."). The rich data the tool description PROMISES — contract, compile diagnostics, input, event history, await cursor — is absent from the human-readable text. When `st_fn_put` / `st_tab_open` report "compiled with 1 error(s)", there is NO tool-call path to read that error. The agent is forced to guess source fixes blind.

* Evidence (2026-06-19)
- `st_fn_put greeter` → "registered with 1 diagnostic(s)"; `st_inspect name:greeter` → "Function fn-2 revision 1." (no diagnostic text).
- The diagnostic detail DOES exist in `input.json.functions[].compile.diagnostics` and `.contract` — so it's computed, just not surfaced via the tool.
- Took 4 blind re-registrations + stdlib grep to discover the actual error was a fabricated `@import "stdlib/ui"` (no such module). A one-line diagnostic would have been instant.

* Expected
`st_inspect` with fn_id/name returns: contract (input kind, params, events, source), compile {ok, sizes, diagnostics[]}, revision, and (for instances) event history + await cursor — as readable text, not only structuredContent.

* Impact
This is the single biggest DX failure of the live-coding loop. The whole NREPL premise (FEAT-124: "redefine functions and inspect results") depends on inspect actually showing results + errors.

* Fix scope
- Render diagnostics[] (with line/message) in st_fn_put / st_tab_open failure text AND in st_inspect.
- Render the contract block (params, events) in st_inspect text.
- Keep structuredContent for machine consumers.
