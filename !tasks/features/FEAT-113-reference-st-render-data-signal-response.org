* Why
demos/spacetime-docs/reference.st is already a LIVE, self-describing catalog: it
renders one card per compiler %form via `@data dispatch $macros` (reading the macro
registry; cannot drift). The reactive-I/O model adds a NEW introspectable surface —
@data-signal RESPONSE INTERFACES (the sum @type + variants + transport). Surfacing
these in the same catalog (a) gives developers a live map of every signal's contract
and (b) PROVES the exact registry-introspection rail st_mount(fn) depends on. One
demo, two payoffs: better DX + de-risks W2.

* Verified ground truth
- reference.st: `@data dispatch $macros` → @each over { directive, name, signature,
  doc, kind, tokens, scopes, binds, overloads }; live search/filter via @each-filtered;
  zero custom JS. Renders cards from the compiler's own registry.
- the rail: src/compiler.rs::inject_dispatch_data rewrites `@data dispatch` into the
  static registry data. The signal registry (FEAT-110 %registers binding facts:
  kind, host, response-sum/variants) extends the SAME mechanism.
- @data signal/stream register: input params (typed), host/transport, response @type
  (SumName + variants w/ carried types) — exactly the fields a card needs.

* Scope (W3)
1. A `@data dispatch $signals` (or a `from kind "signal"` filter on the existing
   dispatch) that surfaces every @data-signal/stream declaration's interface:
   { name, params:[{name,type}], host, transport, kind:signal|stream,
     responses:[{ variant, carries(type)?, terminal:bool }] }.
   Reuse the inject_dispatch_data rail; do NOT hand-roll a second introspection path.

   new dispatch data; same live search/filter; zero custom JS.
3. Keep it drift-proof: cards come from the registry, so adding a @data signal in any
   page makes a card appear next build (the reference cannot drift, same invariant).

* Edge cases
- a signal with no receive (fire-and-forget) → card shows "no response interface".
- nullary variant (`Failed`) → chip with no carried-type.
- stream vs signal → distinct badge; `final` variants marked.
- no signals in the project → section renders empty gracefully (like an empty filter).
