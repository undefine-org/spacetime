* Root cause (both complaints trace to ONE gap)
FEAT-145's occlusion test was a SINGLE ray at the anchor point, reduced to a BOOLEAN
($occluded). Two symptoms of that one gap:
1. "All or nothing" — one point answers for the WHOLE rectangular label; a label 90%
   clear of a mesh and 10% clipped by a corner still vanished completely.
2. "Glass shows nothing" — `intersectObjects` tests geometry only, never material; a
   transmissive (glass) hit occluded identically to opaque steel, even though the eye can
   clearly see through glass in the actual render.

* Design process (before implementation, per user request)
Explored and REJECTED a depth-buffer-readback design (shared low-res depth prepass in
three-stage.st + CPU readback + canvas-painted mask) — heavier, GPU→CPU sync cost, would
have expanded blast radius into the shared stage primitive. Verified empirically (a live
test page, screenshot-confirmed) that CSS `mask-image` accepts MULTIPLE gradient layers,
each independently positioned via `mask-position`/`mask-size` and reading its alpha from a
CSS custom property via `var()` — i.e. a "paint a mask with numbers" idiom using ONLY
static author-declared CSS, with the browser's own compositor doing the rendering + edge
smoothing for free. This became the actual design: no canvas, no readback, no new subsystem.

Settled via `ask` before writing code:
- Multi-hit aggregation: MAX solidity (dominant occluder wins) — simplest, comment left for
  multiplicative compounding as a documented future option, not built.
- Boolean cutover threshold (inert/pointer-events): 0.75 solidity, using AVERAGE (not max)
  of the N² grid cells — a corner-clip alone shouldn't kill interactivity.
- Footprint sampling: N×N grid over the label's OWN `getBoundingClientRect()` (adapts to
  CSS changes automatically), default 4×4 (16 rays/label/frame), 8×8 documented as a denser
  opt-in comment.
- No browser-support fallback for mask-image (Baseline since Dec 2023) — comment only,
  degrade path is `occlusionGrid:1` (scalar, FEAT-145's original path).
- All 3 spatial-showcase object tags (helmet/flux/prism) upgraded to occlusionGrid:4 for
  consistency (not just glass/prism).

* Mechanism (built)
`three-anchor.st`: new `occlusionGrid:number=1` param. `1` = FEAT-145 exact behavior
(single ray, scalar opacity dims/hides the WHOLE card — zero call-site change, zero cost
delta). `N>1` = an N×N grid of `raycaster.setFromCamera` rays sampling the label's live
screen rect; each cell's material-aware visibility (`1 - (1-transmission)*opacity` of the
MAX-solidity hit) is written as `--occ-<row>-<col>` (0..1). `--anchor-occlusion` (average of
the N² cells) is still published for aggregate consumers. `inert`/pointer-events gate on
whether that average is < 0.25 (i.e. average solidity > 0.75, per the agreed threshold).

`index.st` (spatial-showcase): a STATIC (author-declared once) 4×4 `mask-image` grid on
`.tag` — 16 `linear-gradient` layers, each positioned into one 25%×25% cell via
`mask-position`/`mask-size`, each reading `var(--occ-<r>-<c>, 1)`. Only the 16 numbers
change per frame (same "write a number to a custom prop, let CSS render it" idiom as
`--anchor-depth`, FEAT-144) — zero canvas, zero JS-side compositing.

* FEAT-147 addendum (frost) — same investigation, filed together
User, after the shaped-grid fix: "it doesn't go through the 3d shader shit that the glass
surface does tho" — correctly identifying that flat translucency ((1-transmission)*opacity)
is the CORRECT alpha but the WRONG texture: three.js's real `MeshPhysicalMaterial`
transmission renders a genuine GPU pass (samples the scene-behind into a render target, then
blurs by `roughness` and BENDS by `ior`/refraction). Investigated + presented the honest
split: the BLUR half is cheap or free to approximate (roughness is already sitting on the
same hit object the occlusion code inspects); the REFRACTION half is NOT achievable with
CSS filters on real DOM (no per-pixel UV displacement mechanism; reproducing it would mean
rendering the label onto a canvas-texture mesh, forfeiting real/selectable/accessible DOM —
the entire premise of this spatial-ECS mechanism). User approved building the frost half and
flagging refraction as a future research spike rather than solving it now.

Built: `hitInfo`/`visibilityAt` now also surface `transmission`/`roughness` of the dominant
hit (zero extra raycasts — same hit object already being inspected for solidity).
`--anchor-frost` (0=clear glass..1=fully frosted) = `transmission × roughness` of the
dominant hit, averaged across the grid same as occlusion. `.tag`'s `backdrop-filter: blur()`
rewired from occlusion-tied (wrong signal — blurred MORE as a label became MORE hidden,
duplicating what opacity/mask already carry) to frost-tied (correct signal — answers "how
textured is what I'm seen through").
