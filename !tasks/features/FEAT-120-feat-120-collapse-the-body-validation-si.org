* Architecture (why this is mergeable, and the root defect it fixes)

The 11 canonical =check_*= passes and the 1 body-validator differ on ONE axis — WHEN they run:

| pass                      | reads                       | runs at  | produces            |
|---------------------------+-----------------------------+----------+---------------------|
| 11 × =check_*=            | World A (scopes, matches)   | pipeline | canonical Diagnostic|
| =validate_component_body= | raw body text (=inner: &str=)| parse    | ComponentBodyDiag → smuggled |

Two facts forced the smuggle (the root defect):
1. =compile_verbose(matches, context)= has NO source text → cannot re-slice + re-validate
   raw body at pipeline time → body validation MUST happen at parse.
2. =parse() -> Result<StFile, ParseErrors>= and =StFile= has NO diagnostics field → a
   parse-time lint has nowhere canonical to land → it hitches a ride INSIDE the capture
   that flows forward to the pipeline, where two bridges convert it back to =Diagnostic=.

∴ The side-lane is a workaround for a MISSING CHANNEL, not an intrinsic second world.
Route A supplies the channel (=StFile.diagnostics=), generalizing it so ANY future
parse-time lint lands canonically — no new envelope is ever re-improvised.

** The single production site (the ruthless realization)

Move the validator OUT of the capture extractor (=form_compiler.rs:1365=) and INTO the
scope-building loop in =cst_to_stfile_with_registry= (=src/parser/mod.rs= ~466–564). At
that loop, for every body-bearing directive, these ALL coexist:
- =body= (the CST Body node) + =body_range= / =body_span= (byte span)

producers unify.

* Decisions

- *Route A over B*: A adds the missing channel (=StFile.diagnostics=) so the WHOLE class of
  parse-time lints lands canonically; B would relocate body validation to the pipeline but
  leave the "parse lints need a channel" gap open for the next feature to re-improvise.
  A also forces REAL spans (the validator gets =base_offset= + =span=), killing the
  =line_offset= rot as a side effect.
- *Validator runs in the scope loop, not the extractor*: only there is =tmpl_name= available
  (W0700 needs it) alongside =body= + =span= + =source=. This is the site that already
  produces every other World-A fact (html/states/exports/refs) — one producer, one place.
- *Capture collapses to a bare marker*: =ComponentBody= carries nothing. The presence of the
  capture still marks "this match has a body" for =expand.rs='s =is_component_body= branch,
  but it transports no data.
- *Byte-identical rawBody preserved*: this FEAT touches NO emit path — the factory body still
  serializes from the World-A scope (=component_body_to_js_from_scope=). The W1 oracle
  (=feat119_oracle_rawbody_js_all_field_kinds=) MUST stay green untouched.
- *Diagnostic parity is the gate*: the exact same E-codes/W-codes fire on the exact same
  inputs, only landing through the canonical path. Golden corpus snapshots re-baseline from
  =ComponentBodyDef= JSON to =Diagnostic= JSON; the SET of codes per case must not change.
