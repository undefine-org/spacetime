* Summary
The admin's add/delete/reorder each call =window.__stDevSave.saveArray*= imperatively
(4× hand-wired, each with optimistic apply + ack/reject + revert). Collapse that
PATTERN into one declarative construct over a collection signal, wrapping the ONE
legitimate JS primitive (the dev WebSocket bridge), which stays =%emit js= per AGENTS.md.

#+begin_src spacetime
@data collection $rows Product[] from "/data/products.json" via dev-ws {
  initial: [];
}
// exposes mutators that auto-persist with optimistic apply + ack/reject + revert:
.add  { @on click { $rows.insert(newItem); } }
.del  { @on click [data-i] { $rows.delete($.dataset.i | int); } }
.move { @on drop  { $rows.reorder($from, $to); } }
#+end_src

* Why a new kind (not a primitive call site)
The optimistic-apply → persist → ack/reject → revert loop is identical at every CRUD
site. It deserves ONE construct so the 4 hand-wired sites collapse and the revert logic
lives in one place. =via <bridge>= names the persistence transport (=dev-ws= here;
extensible to others later).

* Design
- New =@data collection= kind alongside inline/fetch/derive/fold/query (data-kind.st).
- Binds a reactive array signal PLUS three mutators on it: =.insert(x)=,
  =.delete(indexOrPredicate)=, =.reorder(from, to)=. Each:
  1. optimistically applies to the local signal (UI updates immediately via @each),
  2. sends the corresponding EditJsonArray op over the named bridge with an =op_id=,
  3. on ack: confirm; on reject/timeout: REVERT the local signal to pre-op state and
     surface an error signal (=$rows_error=).
- Reuses =stdlib/__dev__/primitives/dev-save.st= (saveArray*) as the dev-ws transport.
  Do NOT duplicate the WS logic; this construct ORCHESTRATES it.
- The =via= transport is a named capability; =dev-ws= is the first. Keep the seam so a
  production transport (REST/PATCH) can be added without changing author syntax.

* Edge cases
- reject/timeout → revert to EXACT pre-op array (snapshot before optimistic apply).
- concurrent ops (two inserts before first ack) → queue/serialize op_ids; revert only
  the failed op, not the whole queue.
- delete by predicate vs index; reorder bounds (from/to out of range → no-op + warn).
- empty/initial load races (mutate before first load) → buffer or reject with clear error.
- op_id REQUIRED on every EditJson message (server rejects without it — see AUD-002).
