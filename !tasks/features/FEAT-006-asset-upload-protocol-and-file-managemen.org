NOTE [2026-03-30]: Implemented POST /__spacetime/dev/upload with blake3 content-hashing, MIME validation, 10MB size limit, and deduplicating writes to assets/uploads/.

* Scope

** In scope
- HTTP POST endpoint for file uploads at ~/__spacetime/dev/upload~
- Asset directory convention: ~{site_dir}/assets/uploads/{hash}.{ext}~
- Content-hash naming using blake3 for deduplication
- MIME type validation (images: png, jpg, gif, webp, svg; configurable)
- File size limit (default 10MB, configurable)
- Return relative path suitable for JSON data fields

** Out of scope
- UI for image picking/uploading (separate item)
- Image optimization/thumbnails (FUP)
- Asset deletion/cleanup

** Boundary rationale
The upload endpoint is shared infrastructure used by both the media picker UI and the admin panel asset browser.
* Tests

** Rust unit tests (~src/assets.rs~ or ~src/server.rs~ inline)
- Upload valid PNG: file written to correct path, content-hash name matches
- Upload valid JPG, GIF, WebB, SVG: all accepted
- Upload invalid MIME type (e.g., .exe): rejected with clear error
- Upload exceeding size limit: rejected with 413 status
- Duplicate upload: same content produces same hash, no duplicate file
- Path traversal prevention: filename with ~../~ does not escape assets dir
- Missing/empty multipart body: rejected with 400

** Integration test
- POST multipart file to running dev server, verify 200 response with path, verify file exists on disk
- GET the returned path from the dev server, verify file served correctly

* Edge Cases
- Upload with no file field: return 400 with descriptive error
- Upload with multiple files: accept first only (or batch upload?)
- Empty file: reject with error
- Very long filename: truncate original name in metadata, hash is the canonical name
- Disk full: handle IO error gracefully
- Concurrent uploads of same file: blake3 hash means same content = same file, safe for concurrent writes
