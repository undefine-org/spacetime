TIER 1 — CORRECTNESS (breaks the first-run demo)
═══════════════════════════════════════════

** B1. Template value-default params render `[object Object]` / silently drop.  [BLOCKER]
Registering a component with default params is the FIRST thing anyone does. It is broken three ways:

  (a) `:` default form does not parse past the first param.
      `@template &main($a: "one", $b: "two")` → contract captures ONLY `a`; `b` is swallowed.
      Grammar (stdlib/capture-types/param_list.st) defines default as `("=" $default:expr)?` —
      there is NO `:`-default production. Yet docs/language/data-and-rendering.md tells authors
      `:` introduces a value and reserves `=` for the meta layer. Docs and grammar contradict.

  (b) `=` default form parses but the default VALUE is dropped in codegen.
      `CapturedValue::ParamList` serialization (src/pipeline/expand.rs ~1765) emits
      `{ name, kind, optional, type }` and OMITS `default`. The runtime factory
      (buildTemplateFactory, snapshot template_def_invocation_js.snap ~4450) explicitly reads
      `spec.default` and applies it — but it always arrives `undefined`. Fix is one field: add
      `default` to the ParamList object emit (TemplateParamDef.default already carries it).

  (c) Autostage passes the whole region-input object as positional arg-0.
      registerBundle autostage does `factory(regionInput || {})`; the factory binds positional
      args as `data[paramSpecs[0].name] = args[0]`, so with regionInput `{}` the first param
      becomes the object → renders `[object Object]`. Params with no arg must fall to their
      default; autostage should pass NAMED args (`{__stNamedArgs: input}`), not a bare positional.

Repro (live): `hero-card` with `$title:"Launch faster",$subtitle,$cta` → contract showed only
`title`; stage rendered blank title/subtitle/cta. Isolated 2-line template: single `:` default →
`[object Object]`; `=` default → `[object Object] — "two"` (arg-0 objectified, arg-1 quotes kept).

Acceptance: `@template &main($a:"one",$b:"two")` with no args renders `one`+`two`; contract lists
BOTH; docs and grammar agree on ONE default sigil.

TIER 2 — BUILDER PARITY (the Webflow/Framer moat)
═══════════════════════════════════════════

** B2. Structure navigator shows templates only, not the element tree.  [HIGH]
`stage_structure_from_bundle` (src/mcp/live.rs:636) walks `&child()` template-ref edges ONLY. A
hero of `<section><h1><p><button>` projects as ONE node (`main`). The layer tree is the core of
Webflow/Framer. Today the navigator is empty theatre for any single-template component. (Known:
FUP-061.) Must walk the HTML element graph (the parsed body / `builder` closure exists), giving
each element a stable node id + text/invoke span for selection.

** B3. No in-stage direct manipulation — selection is coarse + indirect.
Clicking the stage selects the WHOLE frame, never an element. No hover outline, no
click-to-select-element, no on-canvas resize/drag/text edit. The incumbents' whole value prop is
DIRECT manipulation. The selection spine ($selected/$selectedNode) is well-built but frame/
template-granular; needs element granularity (dep B2) + an on-stage selection overlay.

** B4. Per-node param editing is dead for the common case.
`stage_node_params` projects `[]` for a root single-template guest (invoke_span null on &main), so
the inspector "edit params" renders nothing. Frame-level `mcp_param` override DOES work (verified:
POST mcp_param → guest re-rendered "HELLO FROM CURL"), but node-level editing is unreachable
without B2's element/invoke spans.

** B5. Dark guests are invisible on the stage — no artboard.
Guest bg (26,20,16) vs stage (36,30,25) = 1.1:1 contrast. A dark component vanishes; no artboard
frame, no neutral backing, no elevation, no device chrome at tablet/mobile. Add an explicit
artboard surface (neutral + border + shadow) behind the mounted region, independent of the stage.

** B6. Breakpoint widths are not real device widths.
Mobile preview measured 181px; real mobile ≈ 375–390px, tablet ≈ 768px. Pin to true device widths
and show the px value.

TIER 3 — USABILITY / POLISH / A11Y
═══════════════════════════════════════════

** U1. z-index: "clear stage" + right rail paint OVER the open inspector.
clear-stage (z6) + mcp-rail-right (z6) sit above the inspector (z5) and overlap horizontally
(clear x1233 w110, rail x1297, inspector x969 w380). Controls occlude the drawer. Raise the open
drawer above edge chrome, or shift/hide same-side chrome when a drawer opens.

** U2. Two selection models visible at once ("selected node" + "selected frame").
Inspector stacks both sections, populated together after node→stage clicks. Unify into one
selection model (element-or-frame) with one detail panel.

** U3. No keyboard affordances.
Escape does not close drawers (verified). No focus trap, no tree arrow-nav, no shortcuts.
Constraint: AGENTS.md forbids custom page JS — needs a Spacetime `@on key` primitive; scope first.

** U4. Icon buttons lack accessible names; drawers lack dialog semantics.
Summon buttons have `title` but no `aria-label`; drawers have no role=dialog/aria-modal/aria-hidden;
stage not focusable. Screen readers get almost nothing.

** U5. Low-contrast secondary text.
Drawer labels rgb(122,107,84) ≈ 3.4:1 — below WCAG AA 4.5:1. Lift muted tokens or enlarge.

** U6. Server-audience actions give zero user feedback.
Param/compose/clear are server-audience → comms feed (agent-only) stays empty; user sees no
confirmation until the 1s poll re-renders. Add an optimistic echo / server-action toast.

** U7. Discoverability: edge glyphs unlabeled at rest.
Four warm glyphs, no resting label; a first-timer can't tell nav/structure/inspector/origin apart
without hovering. Add hover-peek labels or a one-time coach.
