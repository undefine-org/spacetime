GH-36 optional trailing literal in %form — VERDICT: FIXED (W3, PLAN-137)

Root causes, both fixed:
1. The `timeout:` literal is ONE `%form` token but the CST tokenizes `timeout`
   and `:` separately, so the greedy `$condition:expr` swallowed the whole
   `timeout : $timeout:time = 5000` run and the literal could never match.
2. `timeout: $timeout:time = 5000` was a REQUIRED trailing clause (the
   `timeout:` literal had to be present), so the documented bare spelling
   `@wait_until cond` matched no form and was silently dropped.

Fixes (stdlib/testing/test.st `wait-until` / `wait-for`):
- Form rewritten with an INLINE OPTIONAL GROUP: `@wait_until $condition:expr
  ( timeout : $timeout:time = 5000 )?` — the genuinely-optional trailing clause
  is grammar DATA (a `( … )?` group), not a Rust special case or sibling form.
- New inline-group support: FormInlineElement::Group (meta_ast), parsed by
  `%form` (parser/mod.rs; a `( … )?` paren is not mistaken for the param list),
  matched with rollback + in-group defaults in form_compiler.rs, and the expr
  boundary stops at the group's leading literal so the greedy `$condition` no
  longer swallows `timeout`.
- `ST.parseMs` (BUG-317) turns the `:time` scalar's "500ms" string into the ms
  number the emit needs.
