#+TITLE: Studio editing depth and usability review
#+DATE: 2026-11-15
#+STATE: REVIEWED

* Request and scope
Review the Studio's workspaces, kinds of edits, depth, intuitiveness and
improvements. This is a review and proposed direction, not authorization to
implement the proposals. Inspected main at bb12ed56, the Studio stdlib,
source projections, shared reflection/rewrite, and PLAN-154/155/156.
Opened film-grokbot and film-robot-day in Chromium at 1600x1000 using a
separate agent-browser session. Only navigation, selection and transport
were exercised: no project source was edited, no write regression suite
was rerun. This document is the only tracked addition from the review.

* Assessment
The Studio is strongest at adjusting an existing authored program:
source-backed timing, keyframes, synth patterns, typed 3D properties and
guarded edits. It is weaker at creating structure and navigating reusable
definitions. The language is more modular than the current visual editor
can express. Familiar explorer/canvas/inspector placement helps, but similar
looking properties have inconsistent capabilities and editing scope is
insufficiently explicit.

* Browser observations
** Preview does not fit the Studio's central viewport
In film-grokbot, the available horizontal preview was x=264..1300, but
.film__canvas occupied x=264..1864, width 1600 and height 900. Content
continued underneath the right inspector. The film retained viewport-sized
layout while Studio attempted to reserve sidebars around body.
Evidence: scratch/grokbot/studio-review-film.png.
Relevant surfaces: stdlib/__studio__/film.st:157 onward and
demos/film-grokbot/design/tokens.st:32 onward. A bounded preview should
preserve authored dimensions and fit/zoom independently of host chrome.

** Components omits the film's reusable markup forms
The Components panel was blank: outline.templates and stuComponents were
empty. score.json contained the project's 44 form definitions (including
motion and markup), so this was not an absence of authored abstractions.
stuComponents reads only outline.templates, and its cards offer documentation
rather than insertion, instance editing or definition navigation.
Relevant: stdlib/__studio__/primitives/studio-kit.st:121 and
stdlib/__studio__/index.st:145. Use language metadata and expansion origins
to expose definitions, instances, slots, parameters, examples and usages.

** Layers cannot reveal a current scene's form invocation
Paused at 10.5s, clicking index.st's --voice-invitation row reported
"Not on this page right now (hidden, or rendered elsewhere)." Its expanded
scene was visible. stuReveal tries a selector from the authored tag/classes;
an expanded markup-form tag is not a rendered DOM tag.
Relevant: stdlib/__studio__/primitives/studio-kit.st:487. Selection needs
source/instance provenance, with an instance hierarchy distinct from file
organization. Do not guess a source owner from identical visible text.

** Code pane opens only the entry file
score.json listed 14 local files; stuFilmSrcs contained only index.st. That
file mostly imports and composes: actual score, components, surfaces and
motion live in imported files.
Relevant: stdlib/__studio__/primitives/film-kit.st:569. Add source navigation
from the selected object/property to the owning module and guarded span;
retain an explicit file picker and show save/parse/conflict status.

** Recorded soundtrack is absent from the timeline
The first score entry, @audio, was classified as kind=other. The UI drew 132
rows and 356 keyframe diamonds, but no recorded-soundtrack lane. Playback
and native export support are separate from this missing editor projection.
Relevant: src/studio/score.rs:155 onward and
stdlib/__studio__/primitives/film-kit.st:78 onward. Audio entries should be
described by registry metadata, and retain their source addresses. Recorded
waveforms and automation need their own verified implementation; current
waveform painting uses the synthesizer.

** Driven inspector displays the base declaration
Robot Day at 8s: the robot clip field displayed Idle, the authored base,
with drive=0:5. The score channel contains a Walking stop at 25% of 24s.
stuPartFields builds the field from p.written/default, while commits to a
driven field call F.stopEdit. Thus the field presents a base value but its
edit destination is the playhead. This observation does not assert which
animation the 3D runtime was evaluating.
Relevant: stdlib/__studio__/primitives/film-kit.st:256 and :298. Show base
and evaluated values separately, an explicit animation indicator and
keyframe navigation; make the edit destination unmistakable.
Evidence: scratch/grokbot/studio-review-scene.png.

* Workspaces: current depth and proposed changes
** Canvas and Layers
Current: select DOM content, move to its parent, edit text in place, reorder
source-backed list rows. Layers is organized by files and element literals.
There is no general 2D layout drag/resize authoring tool here.
Improve: contextual instance breadcrumbs; drill into a component or slot;
collapse implementation details; add/remove/reparent with declared slot
constraints; reveal and explain content absent in the current state/time.

** Inspector and design
Current: computed size/layout/type/fill are readouts; existing matching
source declarations are editable text inputs. Applied forms are listed,
not exposed as a complete typed parameter editor. Row fields are textareas.
Improve: share typed widgets with the 3D inspector; trace computed values to
their token/form/rule/instance/animation owner; show inherited and overridden
values; choose edit scope and show affected instances before a shared edit.
Allow intentional declaration creation and override removal.

** Lists and content
Current: literal @data row fields, duplicate, delete, up/down and drag
reorder. Empty lists are omitted; duplication requires an existing row.
The format bar wraps/unwraps supported marks. Cross-mark selection, block
conversion and paste lifting remain limitations in the Studio format path.
Improve: schema-derived add-first-item, typed fields, nested data browsing,
validation and image/alt controls. Distinguish the Studio path from the
separate editable/admin modules, which have additional content capabilities.

** Components and Pages
Current: @template documentation catalog and route navigation. No complete
visual create/insert/variant/slot/definition workflow. Markup forms missed.
Improve: one reflected component browser, live examples and legal slots,
insert/duplicate, edit definition versus instance, usage search, and preview
variants. Page creation/duplication should use the same source transaction.

** Timeline and motion
Current: scrub/play/pause/frame-step/loop; drag clip start/end; move
keyframes, box-select/group-move; edit channel/stop words; pan/zoom/Fit.
The view selects scores[0], uses a fixed 30fps step and opens channels flat.
Reusable motion calls are not exposed as navigable expanded tracks: e.g.
research-title moves using --film-window/--film-focus but has zero projected
channels. There is no visual curve editor or nested composition workflow.
Improve: collapsed scene tracks first, selection-linked channels, named
markers, configurable timebase and snapping, easing previews/curves, local
timelines and reusable-motion navigation with source ownership preserved.
Offer explicit base/keyframe scope; avoid silently materializing shared
form expansions into per-instance source.

** Sound
Current: synth waveform lanes, drum step grid, melodic cells and chord
keyboard. Recorded audio has no equivalent projected lane in Grokbot.
Improve: audio source selection, recorded waveforms, trim/fades, mute/solo,
levels and beat alignment. Implement and verify automation/export parity
before offering controls that imply it exists.

** Scene / 3D
Current: stage/parts list, picking/outlines, reflected choices/ranges/colors,
default insertion, vector groups, editor camera, frame selection and moving
a part over the ground (Shift for vertical). One selected part at a time.
Improve: semantic labels for unnamed parts, hierarchy, multi-selection/mixed
values, axis constraints and rotate/scale handles, asset/animation previews.
Keep editor-camera navigation visibly separate from film-camera edits.

** Code, states, history and output
Current: entry-file textarea saved on blur/shortcut, guarded whole-file hash;
shared undo can undo the last edit of any writer, including an agent.
No dedicated general state/interaction editor, asset workspace, visual
reference comparison or integrated render-job workflow was found here.
Improve: selection-linked source files, explicit save state/errors, named
history entries with author/tool and diff, redo/checkpoints, and deliberate
state/viewport/time preview. Surface existing @on/@state/data constructs
through their declarations rather than a second behavior language.
Assets need provenance/usage/replacement/crop controls; rendering needs
reference overlays, frame comparisons and reproducible export settings.

* Recommended order
1. Restore trust: fit preview, map form invocations to instances, navigate
   all owning files, expose recorded audio, clarify base/evaluated fields.
2. Unify depth: shared reflected controls, source ownership, explicit edit
   scope and usage impact across markup/style/motion/scene/content.
3. Enable composition: insertion and slots, nested scenes/local timelines,
   collapsed tracks, predictable selection, contextual shortcuts.
4. Finish authoring loops: asset workflow, state previews, rich content,
   curves/audio controls and reference/export workflow.

* Architectural direction and future evidence
Keep source truth, one guarded writer, parser-derived addresses and shared
undo. Add missing origin/instance relationships to compiler/reflection
metadata, not a Studio-only document model or a second parser. Retire
bespoke readers/projections incrementally when their full contract is
represented by the shared language metadata. PLAN-156 explicitly leaves
markup/data lossless spans and stops-as-types unfinished.

Proposed future real-Chromium acceptance journeys (not run this review):
- Select a nested bubble, edit its instance, then its shared definition;
  inspect source and prove only the intended instances change.
- Select a scene's motion form, open its owning file, edit/undo, retain time.
- Scrub an animated property; evaluated field follows it; base edit and
  keyframe edit have distinct verified effects and one undo per gesture.
- Add the first typed list item and edit nested content without guessing
  provenance; stale/ambiguous edits leave source unchanged.
- Recorded audio trim/seek/render agrees with the shared film clock.
- Entire authored frame stays visible and selectable at multiple host sizes.
