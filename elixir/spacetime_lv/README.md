# spacetime_lv — the real Phoenix LiveView vertical (native live transport)

A **proven, runnable** vertical slice of the Spacetime⇄Phoenix LiveView bridge
(FEAT-136, extended by FEAT-137). A counter whose state is server-authoritative
in a real Phoenix LiveView, whose **entire view is a Spacetime-compiled
bundle** — no HEEx, and no `phx-click` shim: **the `.st` page itself drives the
wire** over the LiveView's own channel.

## The loop (verified end-to-end in a browser)

    click +  →  .st `@on click { $inc() }`  →  @data signal live transport
             →  window.__stLiveBridge.pushEvent("inc")  (SpacetimeBridge hook)
             →  Phoenix handle_event("inc")  →  {:reply, %{tag: "ok", reply: 1}}
             →  decode through `receive to IncResult { "ok" => Bumped($.reply) }`
             →  @handle arm: $count <- 1  →  .value re-renders  →  "1"

The correlated reply decodes through the SAME matcher family as `@match` — the
server's tagged reply IS a variant of the page's declared sum. `@data subscribe
$count from $counter : count ;` declares the other direction: the connected
mount seed and every later server assign diff route by `(LiveView module, assign)`
into `$count`. The demo's server timer advances count without a click, proving
LiveView-initiated updates redraw the Spacetime subtree.

Server log confirms one `HANDLE EVENT` per click (no double-dispatch); the
browser confirms `.value` tracks the server count (0→1→2→3→2, inc/dec).

## Collaborative board demo (FEAT-162)

Open `http://localhost:4001/board` after building `frontend/board.st`. `BoardLive` is an authoritative, versioned board: the `.st` page renders the three columns, cards, drag/drop, FLIP transitions, and one-shot flash toast while LiveView emits only data.

- `move_card` snapshots `$items`, projects the destination immediately, and restores the snapshot on a tagged lock/stale-version rejection; server PubSub broadcasts the winning items assign to every board host.
- `@data subscribe $items` drives remote state through `st-set`; `@flip $items` glides cards between columns rather than letting a template patch snap them.
- `@data stream $fx` consumes the typed `flash` push once, so reconnect/reseed cannot replay a toast.
- `send emit "cursor" ephemeral` is a generic, fire-and-forget live signal: the bridge coalesces it latest-wins to one rAF frame, and `Phoenix.Presence` reconciles the declared `presence` assign. The local ring remains pure `.st`; every client receives only remote labelled cursor trails.

Build the board bundle after editing it:

```sh
cargo run -- build elixir/spacetime_lv/frontend/board.st \
  -o elixir/spacetime_lv/priv/static/spacetime/board/
rm -f elixir/spacetime_lv/priv/static/spacetime/board/BoardLive.contract.json
```

## Optimistic rollback

`@handle` is the continuity surface — no second mutation grammar. Snapshot the
local value in `optimistic`, mutate immediately, then restore that snapshot in
the tagged rejection arm. Counter's `dec` rejects at zero and demonstrates the
complete pattern:

```spacetime
@handle $dec {
  optimistic { $beforeDec <- $count; $count <- $count - 1; }
  receive {
    Bumped(n) => { $count <- n; }
    Failed(message) => { $count <- $beforeDec; $error <- message; }
  }
}
```

For `policy latest`, each fire/reply carries a monotonic generation through the
shared signal decoder. A late reply from an earlier fire is ignored by its
handler, so its confirmation or rejection cannot overwrite a newer optimistic
state. An authoritative `st-set` assign diff remains the re-seed on reconnect.

## Server-state motion and local presence

Bind a subscribed assign to a layout transition with `@flip`; the subscription
measures before its normal signal write, then the shared rAF clock glides the
old rendered position to the new layout. A write while moving measures its
current visual rect and retargets instead of snapping or restarting:

```spacetime
.card { @flip $column(duration: 240ms) }
```

`@clock` makes this deterministic in tests. This stays data-diff based: neither
LiveView nor the bridge produces template patches.

The board renders its local pointer ring using the stdlib pointer primitive and
publishes remote presence with `send emit "cursor" ephemeral`. `SpacetimeBridge.pushEphemeral`
coalesces every declared ephemeral emit to one latest-wins frame; `Phoenix.Presence`
tracks join/leave and cursor metadata, while each client excludes its own cursor from
the remote trail assign.

## Layout

    frontend/                       ← the .st project root
      $hosts.st                     ← @host $counter : live("SpacetimeLvWeb.CounterLive")
      counter.st                    ← the page (imports ./$hosts.st)
      CounterLive.contract.json     ← generated by `mix spacetime.contract` (E0928 checks against it)
    lib/spacetime/live_view.ex      ← Spacetime.LiveView use-macro + render_host/1
    assets/js/app.js                ← the SpacetimeBridge hook (the glue layer)
    priv/static/spacetime/counter/  ← build output (spacetime.js / spacetime.css)

Pages `@import "./$hosts.st"` and fire by name — the page redeclares nothing
the server already knows.

## Run it

    cd elixir/spacetime_lv
    mix deps.get          # first time
    PORT=4001 mix phx.server
    # open http://localhost:4001

If you change the `.st` view, rebuild + restage the bundle (from the verse root):

    cargo run -- build elixir/spacetime_lv/frontend/counter.st \
      -o elixir/spacetime_lv/priv/static/spacetime/counter/

The server is the contract source of truth. Regenerate its deterministic sidecar after changing declared `events`, `assigns`, or `pushes`:

    mix spacetime.contract

The build-time contract check (E0928) runs over `frontend/`:

    cargo run -- check elixir/spacetime_lv/frontend/
    # change `send emit "inc"` to `send emit "increment"` → COMPILE error,
    # not a runtime surprise.

(Automating build+stage from `mix` is the `spacetime_nif` follow-up, FEAT-138.)

### The key design move (§8 of the bridge design)

The Spacetime view subtree carries `phx-update="ignore"`, so **Phoenix's HEEx
differ never touches it** — its diff for that subtree is permanently empty. ALL
state flows as DATA: the correlated `{:reply}` for event round-trips, and
module-scoped `st-set` assign diffs for the mount seed and later server changes.
"Diff data, never templates": the server sends `{module, assigns: {count: 3}}`,
not an iodata tree; only a page-declared `@data subscribe` target is patched,
no morphdom.
